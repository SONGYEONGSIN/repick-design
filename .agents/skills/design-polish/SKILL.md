# Design Polish — finalist 정밀 마감

대상: 인자로 받은 page.tsx (finalist). 없으면 사용자에게 확인. 참조 룰: `design-system-ref/Codex/skills/`.

## 1. 스코프 확인
- 대상 파일을 Read. 매체(랜딩/가격/대시보드/B2B), 배포 맥락, **의도된 아키타입**(발산작이면 그 스타일 — Y2K/바이퍼웨이브/클레이 등)을 파악.
- 레이아웃이 깨졌거나 미완이면 폴리시 전에 구조부터 손봐야 하는지 보고.

## 2. 4개 검토를 병렬로 (Agent 도구, 한 메시지에 동시 dispatch)
각 에이전트에 **모든 이슈를 confidence·severity와 함께 보고**하라고 지시(필터링은 3단계에서). 각 검토는 `design-system-ref/Codex/skills/<name>.md`의 기준을 따른다:
1. **accessibility-audit** — WCAG AA 대비, 시맨틱 HTML, 키보드/포커스, 모션·폼·터치타깃. (하드 게이트)
2. **hierarchy-rhythm-review** — 1·2·3차 위계(크기/색/무게/위치/밀도), 5초 테스트, 간격·타입 스케일 규율, 정렬, 반복·변주.
3. **interaction-states-pass** — 요소별 default/hover/active/disabled/focus/loading, transition 0.15~0.3s, `prefers-reduced-motion`, 액션 피드백.
4. **ai-slop-check (⚠️ 이 프로젝트 보정)** — **의도된 아키타입을 존중**한다. Y2K의 그라데이션, 소프트오가닉의 이모지, 클레이의 둥근 카드처럼 **컨셉상 의도된 요소는 슬롭이 아니다.** 오직 *의도와 무관한* 슬롭(무의미한 기본 그라데이션, 목적 없는 이모지, 근거 없는 색, off-scale 간격, 뻔한 기본 폰트 남용)만 지적.

## 3. 취합·중복제거·우선순위
- **블로커**: 접근성 실패(대비·키보드·포커스·라벨). 전부 수정.
- **품질**: 위계 붕괴, 인터랙션 상태 누락, *의도 무관* 슬롭. 전부 수정.
- **폴리시 권고**: 간격 스케일 정리·색 톤 미세조정 등. 스코프 내면 적용.

## 4. 수정·재검증
- 블로커·품질 직접 수정. 모호하면 defensible 기본값 선택 후 표기.
- 재검증: 대비 수정이 브랜드색을 죽였나? 새 focus 링이 겹치나? 주 CTA가 실제로 주가 됐나? 어긋난 것 수정, 불확실한 것 flag.
- **의도된 아키타입 미학은 보존** — 폴리시로 발산작을 밋밋하게 만들지 말 것.

## 5. 요약
- 판정: "출하 가능" / "flag 결정 검토 후 가능" / "구조부터 더 손봐야".
- 수정한 블로커·품질 카운트 / 열린 결정(폰트·톤·강조) / 스코프 밖(카피·콘텐츠).

## 금지
- 의도된 스타일을 슬롭으로 몰아 밀어버리기 (발산작 보호).
- 스코프 밖 기능 추가.
