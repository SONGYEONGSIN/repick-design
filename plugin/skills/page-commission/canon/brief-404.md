# 타입 프로파일 — `404` (오류 페이지)

> 전 타입 공통 규칙은 [[page-brief-core]]. 이 문서는 404/오류 페이지 고유 기준만 정의한다.
> 대시보드 기준([[dash-brief-v3]])을 여기에 적용하지 말 것 — 아래 §0 참조.

## 0. 대시보드 기준이 성립하지 않는 지점

| dash-brief-v3 요구 | 404에서 |
|---|---|
| 앱 셸(사이드바 + 탑바) | **조건부** — 앱 내부 404면 셸 유지가 맞고, 공개 사이트 404면 셸 없이 헤더만 |
| 정렬 가능한 데이터 테이블 · 단일 지배 시각화 | 해당 없음 |
| 인터랙션 최소 4종 | **최소 1종으로 완화** — 오류 페이지의 미덕은 장치 수가 아니라 **빠른 복귀**다 |

## 1. 페이지 구조 (필수 요소)

1. **오류 식별** — 코드(404)와 사람이 읽는 한 줄. 코드만 크게 띄우고 설명이 없으면 실패
2. **원인/상황 설명** — 왜 이 화면인지 1~2문장. 사용자를 탓하지 않는 어조
3. **복귀 CTA** — 홈 또는 직전 화면으로. **주 CTA는 정확히 하나**
4. **보조 경로** — 검색 · 인기 페이지 링크 · 문의 중 1개 이상. 막다른 길로 두지 않는다

## 2. 이 타입의 핵심 판정 기준

- **복귀 시간**: 화면 진입 후 사용자가 다음 행동을 찾기까지 시각적 탐색이 짧아야 한다
- **어조**: 자책 유도("당신이 잘못된 주소를 입력했습니다") 금지. 중립·간결
- **정직성**: 실제로 동작하지 않는 검색창을 놓지 말 것 — 놓았다면 결정론적 더미 결과라도 반응해야 한다
- 단일 `h1`은 **오류 헤드라인**이어야 한다(브랜드 워드마크가 h1을 가져가면 안 됨)

## 3. 레이아웃 아키타입 (라운드 내 중복 금지)

- **타이포그래픽** — 초대형 코드/문장 조판만으로 구성, 장식 0
- **일러스트/생성형 SVG** — 절제된 도형·패턴(외부 이미지 금지, 코드 생성)
- **검색 중심** — 검색 입력이 화면의 주인공, 추천 결과 동반
- **경로 제안형** — 최근/인기 페이지 카드 목록이 주인공

## 4. 인터랙션 (최소 1종)

검색 입력 + 결정론적 추천 · 추천 카드 hover/focus 상태 · 코드 타이포의 미세 모션(reduced-motion 게이팅) 중 **1개 이상**. 과한 연출(게임·패럴럭스)은 이 타입에서 감점.

## 5. 금지

- 스크롤 연출 — **한 화면에서 끝나야 한다**
- 사용자 책임 전가 문구
- 동작하지 않는 장식용 검색창
- 브랜드 워드마크를 `h1`으로 사용

## 6. judge 렌즈

| 렌즈 | 기준 |
|---|---|
| 1 — 프로파일 준수 | §1 4요소 + §2 판정 기준(특히 단일 h1 귀속과 복귀 경로의 실효성) |
| 2 — 상용 완성도 | 절제된 마감. 오류 페이지에서 과설계는 그 자체로 감점 |
| 3 — 아키타입 차별성 | §3 목록 중 라운드 내 중복 없음 |
