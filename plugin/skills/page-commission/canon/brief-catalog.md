# 타입 프로파일 — `catalog` (목록 · 탐색 페이지)

> 전 타입 공통 규칙은 [[page-brief-core]]. 이 문서는 카탈로그/목록 페이지 고유 기준만 정의한다.
> **스크롤 연동 연출이 허용되는 첫 타입**이다 — §5 참조.

## 0. 대시보드 기준과의 관계

카탈로그는 대시보드와 가장 가깝지만 목적이 다르다. 대시보드는 **상태를 읽는** 화면이고 카탈로그는 **후보를 좁히는** 화면이다.

| dash-brief-v3 요구 | 카탈로그에서 |
|---|---|
| 앱 셸 | 앱 내부 카탈로그면 유지, 공개 카탈로그면 헤더만 |
| 단일 지배 시각화 | **해당 없음** — 주인공은 결과 그리드다 |
| 정렬 가능한 데이터 테이블 | 선택 — 리스트 뷰를 제공한다면 테이블 규율 적용 |
| 인터랙션 최소 4종 | **최소 3종 유지** (필터·정렬·뷰 전환이 이미 3종) |

## 1. 페이지 구조 (필수 요소)

1. **결과 그리드** — 화면의 주인공. 카드는 정보 밀도를 갖춰야 한다(제목·핵심 지표·상태·보조 메타)
2. **필터** — 좌 레일 또는 상단 바. **적용된 필터가 항상 보여야** 하고 개별 해제가 가능해야 한다
3. **정렬** — 기준이 화면에 표시된 상태(“Sort by …”가 현재 값을 보여줄 것)
4. **결과 수** — 필터 적용 시 실시간 갱신
5. **빈 상태** — 필터로 결과가 0이 되는 경로를 반드시 구현. 해제 수단을 함께 제공
6. **더 보기** — 페이지네이션 또는 “Load more”. 무한 스크롤만 두면 도달 불가 콘텐츠가 생긴다

## 2. 이 타입의 핵심 판정 기준

- **필터 상태의 가시성** — 무엇이 적용됐는지 화면만 보고 알 수 있어야 한다(숨은 상태 금지)
- **결과 수와 그리드의 동기화** — 필터 조작이 카운트·그리드·빈 상태를 함께 갱신([[design-principles]]의 "조작 1회 = 복수 증거면 재계산" 원칙이 여기에도 적용)
- **카드 밀도** — 카드가 제목만 있으면 실패. 훑어보며 후보를 배제할 수 있을 만큼의 정보
- **이미지 규율** — 카드 썸네일은 [[page-brief-core]] §3(aspect-ratio 예약 · 배지 분리 배치) 필수

## 3. 레이아웃 아키타입 (라운드 내 중복 금지)

- **좌 필터 레일 + 그리드** — 고전적 커머스/검색
- **상단 필터 바 + 매거진 그리드** — 불균등 카드 크기의 편집형
- **밀도형 리스트** — 행 기반, 정렬 가능한 테이블에 가까운 형태
- **분할 탐색** — 좌 결과 목록 + 우 미리보기 페인(선택 시 우측 갱신)

## 4. 인터랙션 (최소 3종)

필터 적용/해제 · 정렬 변경 · 그리드/리스트 뷰 전환 · 카드 선택 → 상세 페인 · 결과 수 실시간 갱신 중 **3개 이상**. 전부 `'use client'` 실동작 + 결정론 + `motion-reduce` 게이팅.

## 5. 스크롤 연동 연출 (이 타입 한정 허용)

카탈로그는 세로 길이가 확보되는 유일한 타입이라, **스크롤 연동 연출을 시도할 수 있다**:

- 스크롤에 따른 필터 바 축소/고정(sticky 압축)
- 결과 카드의 순차 진입(stagger) — 단 `prefers-reduced-motion`에서 즉시 표시
- 스크롤 위치에 따른 헤더 상태 변화

**제약 (반드시 지킬 것)**:
- 스크롤 없이 초기 화면만 봐도 페이지의 가치가 전달돼야 한다 — 갤러리 카드 프리뷰는 **스크롤되지 않은 iframe**이므로, 스크롤로만 드러나는 설계는 카드에서 빈 화면이 된다
- 스크롤 하이재킹(스크롤 속도 조작·강제 스냅) 금지
- `prefers-reduced-motion`에서 모든 연출이 즉시 완료 상태로 대체돼야 한다
