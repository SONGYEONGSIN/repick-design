# 타입 프로파일 — `paywall` (한도 도달 · 업그레이드 페이지)

> 전 타입 공통 규칙은 [[page-brief-core]]. 이 문서는 페이월 고유 기준만 정의한다.
> 초안 출처: `auto-paywall-r1`·`r2` 두 라운드의 판정. 이 타입은 **막힌 사람에게 보여주는 화면**이라, 다른 어떤 타입보다 "지금 무슨 일이 일어났는가"를 먼저 답해야 한다.

## 0. 랜딩 기준과의 관계

페이월은 랜딩과 겉모습이 겹치지만(플랜 카드·기능 목록·CTA) 독자가 다르다. 랜딩은 **모르는 사람을 설득**하고, 페이월은 **이미 쓰다가 막힌 사람에게 해법을 준다**.

| design-principles 요구 | 페이월에서 |
|---|---|
| 히어로가 가치 제안 | **해당 없음** — 히어로 자리에 "무엇이 언제 멈췄는가"가 온다 |
| 사회적 증명(로고·후기) | 선택. 막힌 사람에게 남의 후기는 우선순위가 낮다 |
| 플랜 비교표 | 유지하되 **현재 플랜이 표시된 상태**여야 한다 |
| 인터랙션 최소 4종 | **최소 3종** (청구주기 토글·사이징·비교 확장) |

## 1. 페이지 구조 (필수 요소)

1. **차단 사실의 명시** — 무엇이, 언제, 왜 멈췄는가. 수치와 시점을 포함한다("500,000 중 512,340 사용", "7월 29일부터 수집 중단")
2. **손실 없음의 보증** — 이미 만든 것/모은 것이 사라지지 않는다는 문장을 **차단 사실 바로 옆**에 둔다. 이게 없으면 페이월이 협박으로 읽힌다
3. **무엇이 잠겼는가** — 멈춘 기능을 현재값 → 업그레이드값 대비로 나열
4. **추천 플랜** — 사용량에 근거한 단일 추천. 가격·청구주기·포함 내역
5. **사이징 수단** — 다음 달 사용량을 넣으면 맞는 플랜을 짚어주는 계산기. **실측치가 이미 채워진 상태**로 시작한다
6. **탈출구** — 업그레이드 외의 경로(영업 문의·플랜 전체 비교). 막다른 길로 두지 않는다

## 2. 이 타입의 핵심 판정 기준

- **설득↔사이징 분리 + 단일 계산 상태 공유 (하드)** — 설득 모듈(추천 플랜)과 사이징 모듈(계산기)을 분리하는 것은 유효한 패턴이나, **분리가 곧 우수함을 보장하지 않는다.** 두 모듈은 반드시 **단일 리프트된 계산 상태(derived value)**를 공유해야 한다.
  분리하되 사이징 모듈이 자체 계산을 갖고 다른 표시부(CTA·요약바)가 별도 하드코드 값을 쓰면, **기본값에서 우연히 일치해 정적 판정은 통과**하지만 슬라이더를 움직이는 순간 가격 불일치라는 실격급 결함으로 드러난다.
  근거: `auto-paywall-r1` 렌즈3이 모듈 분리를 최초 지목 → `r2`에서 분리는 했으나 `RECOMMENDED_PLAN_ID` 하드코드와 계산기의 독립 `recommendPlanId(volume)`가 갈린 후보가 실사용 시 모든 CTA에 낡은 플랜명을 표시했다. 2라운드 연속 재현.
- **차단 시점의 시각화** — 언제 상한에 걸렸는지 데이터로 보여줄 수 있으면 문장보다 강하다(일별 추이에서 상한 도달 지점 이후를 구분 표기)
- **현재 플랜의 표시** — 비교표·추천 어디서든 "내가 지금 무엇을 쓰고 있는가"가 보여야 한다
- **정적 판정으로 안 잡히는 결함군** — 이 타입은 조작 후에만 드러나는 상태 불일치가 특히 잘 생긴다. judge는 기본값 스크린샷만으로 판정하지 말고 **슬라이더·토글을 움직인 뒤의 정합**을 코드에서 확인해야 한다

## 3. 레이아웃 아키타입 (라운드 내 중복 금지)

- **인프로덕트 한도도달** — 앱 셸 안에서 막힌 상태. 사용량 게이지가 상단
- **상시노출 스플릿스크린** — 좌 진단(무엇이 멈췄나) / 우 해법(플랜·사이징) 동시 노출
- **모달/오버레이 게이트** — 배경에 잠긴 콘텐츠가 비치는 형태
- **전면 업그레이드 페이지** — 앱을 벗어난 독립 라우트

## 4. 인터랙션 (최소 3종)

청구주기 토글 → 전 표시부 가격 갱신 · 사용량 슬라이더 → 추천 플랜 재계산 · 시트/좌석 수 조절 · 기간 범위 전환(7/30/90일) · 플랜 비교 확장 중 **3개 이상**. 전부 `'use client'` 실동작 + 결정론 + `motion-reduce` 게이팅.

## 5. 스크롤 연동 연출

[[brief-catalog]] §5와 동일한 제약으로 허용하되 **권장하지 않는다**. 막힌 사용자에게 필요한 것은 연출이 아니라 답이고, §1의 6요소는 대부분 첫 화면에 들어가야 한다.
