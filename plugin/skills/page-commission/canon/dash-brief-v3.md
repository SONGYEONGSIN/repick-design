# SaaS 대시보드 — 브리프 v3 (서비스급 · 사용자 피드백 반영)

> **페이지 타입 프로파일: `dashboard` · `settings`.** 전 타입 공통 규칙은 [[page-brief-core]]에 있고, 이 문서는 그 위에 얹히는 **대시보드/설정 페이지 고유 기준**(앱 셸 · 컴포넌트 시스템 · 인터랙션 최소 수 · 레이아웃 아키타입 · 그리드 크래프트)만 정의한다.

**목표: 실제 상용 SaaS(Mercury, Monarch, Asana, n8n, Calendly, Coinbase, Cycle 수준)의 프로덕트급 대시보드.**
제품·브랜드는 자유 발명하되, 디자인은 "아트 컨셉/세계관 연출"이 아니라 **매일 쓰는 상용 서비스의 정제된 완성도**다.

## 사용자 피드백 (v2 세대 전원 탈락 — 원인 3가지, 반드시 교정)

1. **가짜 라이트 금지**: 크림·페이퍼·세피아 배경(#F4EFE6류) + "지면/서식/카탈로그" 연출은 라이트 테마가 아니다. **진짜 라이트 = 순백 기반** — `bg-white` / `zinc-50` 캔버스, `zinc-100~200` 헤어라인 보더, 미세한 섀도. Mercury·Asana·Calendly의 라이트를 떠올려라.
2. **세계관 연출 → 프로덕트 정제로**: 레지스트레이션 마크·재단선·타이틀블록·스탬프·베젤 같은 스큐어모픽 연출 금지. 완성도는 **컴포넌트 시스템의 정밀함**(일관된 radius/border/shadow/spacing, 정돈된 테이블, 정확한 정렬)에서 나온다.
3. **폰트 규율**: 본문·한글은 **Pretendard(전역 font-sans) 고정**. 디스플레이(헤드라인·워드마크 등 라틴 대형 텍스트)만 화이트리스트 3종(`--font-display-grotesk` / `-wide` / `-mono`) 중 **하나**를 선택할 수 있다 — 한 작품에 두 종 이상 금지. 그 외 폰트 지정은 `no-unlisted-font` 하드페일. 나머지는 종전대로 **Pretendard 단일** + 숫자/코드/ID에만 `tabular-nums`(필요시 Geist Mono는 코드·해시 등 진짜 코드성 데이터만). **세리프·디스플레이·장식 폰트 일절 금지. next/font 추가 import 금지.** 통화 ₩는 Pretendard tabular-nums로(모노에 ₩ 글리프 없음 — 크래프트 노트).

## 테마 (배정된 것)
- **라이트**: 흰 캔버스(white/zinc-50), 카드 white + `border-zinc-200` + `shadow-sm`, 텍스트 zinc-900/600/500, 강조 1색(indigo/blue/emerald 등 채도 절제). 다크모드 대응은 `dark:` variant로 함께(선택).
- **다크**: 정제된 프로덕트 다크(n8n/Coinbase류) — zinc-950/900 계열 표면, 보더 `white/10`, 텍스트 zinc-50/400, 강조 1~2색. 연극적 발광·스캔라인·그레인 금지.

## 참조 카탈로그 (결정 규칙 — 20-catalog, 복사 금지·링크 참조)
생성 시 아래 정량 카탈로그를 씨앗으로 읽는다. 단 **anti-slop 필터 우선** — 카탈로그 추천값이 본 브리프/[[design-principles]] 금지 항목과 충돌하면 브리프가 이긴다.
- [[charts.catalog]] — 도메인 시각화(§에셋) 선택: 데이터 타입 → 차트 + a11y 등급 + 데이터 볼륨 임계(SVG↔Canvas) + 필수 폴백. **라이브러리 추천 무시, 생성형 SVG 우선**.
- [[colors.catalog]] — 테마 토큰(§테마): AA 보정된 shadcn 18슬롯 팔레트 뱅크. **단일 액센트 원칙 + 틴트 배경은 순백 교체**.
- [[ux-guidelines.catalog]] — a11y/인터랙션 체크리스트(§완성도·§하드제약 재확인용, severity 포함).
- [[motion.catalog]] — 모션(§에셋·인터랙션): 강도 티어·듀레이션·이징 taxonomy. **dash는 dash 열 ✅/△만**(연출·시차·scrub·발광 ❌), 결정론 CSS + `motion-reduce` 게이팅.

## 완성도 기준 (Ridge /dash-rg 에서 검증된 문법 — 전부 적용)
- **앱 셸**: 좌측 사이드바(브랜드 락업 + 워크스페이스 스위처 + 섹션 구분 nav(lucide 아이콘·활성 pill) + 하단 유저) + 상단바(글로벌 검색 ⌘K 버튼 + 주요 액션 버튼 + 알림 + 아바타 메뉴). 모바일은 드로어. 헤더 컨트롤 높이 44px 통일.
- **컴포넌트 시스템**: Card(일관 radius/border/shadow/padding), 정렬 가능한 데이터 테이블(hover 행·상태 배지·아바타 셀·aria-sort), 탭, 세그먼트 컨트롤, 드롭다운/팝오버, 배지, 프로그레스, 스파크라인. 로컬 파일로 분리 구조화.
- **인터랙션 (서비스급 — 최소 4종, §에셋·인터랙션 참조)**: ① 차트 호버 크로스헤어 툴팁(키보드 접근 포함) ② 테이블 실제 정렬/필터 ③ 기간/뷰 토글 ④ 선택→다중 위젯 동기화 ⑤ ⌘K 커맨드 팔레트(여력 시) 중 4개 이상. 전부 `'use client'` 실동작.
- **레이아웃**: 뷰포트 꽉 채움(콘텐츠 유동, 과한 max-w 금지, 초광폭만 완만 cap), 명시적 12-col 그리드(8/4 등), 4/8px 간격 리듬, 그리드 아이템 `min-w-0`(모바일 가로 오버플로 방지), 반응형(KPI 4열은 xl부터 등).
  - **"초광폭"의 임계 — 1920px에서는 캡이 걸리면 안 된다.** 판정은 숫자가 아니라 **결과로 잰다**: **1920px 뷰포트에서 콘텐츠 우단과 뷰포트 사이가 페이지 패딩(≤40px)뿐**이어야 한다. 캡을 둘 거면 셸을 뺀 가용폭보다 커야 안 걸린다 — 사이드바 256 + 좌우 패딩 48을 빼면 1920의 가용폭이 **약 1616**이므로 **캡은 1660 이상**이라야 한다. 그보다 넓은 폭(2560~)에서 완만히 걸리는 것은 허용.
    **왜 결과로 쓰나**: "초광폭만 완만 cap"에 임계가 없어 값 고르기가 매번 추측이 됐고, 2026-08-13 주문 제작에서 **1440 → 1760 → 캡 제거로 두 번 틀렸다**(1440은 1920에서 좌우 112px씩, 1760은 2200부터 벌어졌다). 숫자를 하나 못 박으면 셸 폭이 다른 작품에서 또 어긋난다 — **재는 방법을 적으면 어떤 구조에서도 같은 답이 나온다.**
    **1660은 임계가 아니라 예시다** — 그 셸(사이드바 256 + 패딩 48)에서 나온 값이고, 셸이 다르면 답도 다르다. `/dash/d34`는 사이드바가 240이라 가용폭이 **1680**이었고, 1660으로 고쳤다면 여전히 20px 물렸다. **매번 그 작품의 가용폭을 재서 정한다.**
    **소급 검증**(2026-08-14, 카탈로그 13작품 실측): **12개가 통과**(1920에서 우측 여백 ≤40px), `/dash/d34`만 72px로 미달. 92% 통과라 규칙이 현실과 맞다.
    **해소**(2026-08-14): `/dash/d34` `max-w-[1600px]`→`[1680px]`로 1920에서 32px(패딩만), `/commissioned/hopline`은 캡 제거로 184px→24px. 둘 다 9관문 재통과. **hopline은 위 13작품 스캔 밖이었다** — 스캔을 `/dash/*`로 한정해 `/commissioned/*`의 대시보드를 빠뜨렸고, 그래서 위반이 1건이 아니라 2건이었다. 소급 스캔의 범위가 곧 그 주장의 유효 범위다.
- **타이포**: 페이지제목/섹션/카드제목/본문/캡션/데이터 위계 명확, 숫자 전부 tabular 우측정렬, 레이블 11px uppercase tracking 통일.
- **데이터**: 현실적·결정론적 더미(Math.random/Date.now 금지), 합계 정합(부분합=총합), Intl 포맷.
- **상태 분기 대비**: 정적/Lighthouse 하드게이트는 기본 렌더 뷰만 스캔한다 — 필터·토글로만 도달하는 보조 상태(미배정·우선순위 없음 등) 텍스트도 대비 규칙 동일 적용. 하한은 **표면 톤 조건부**다: 다크 zinc-400 하한 · 라이트는 순백/거의 순백(zinc-50 이하)에서 zinc-500, muted 톤 표면(zinc-100 이상 — 세그먼트·탭 트랙·필)에서 zinc-600. 모든 상태 분기 토큰 점검. (auto-dash-r2/r4 3회 재현 → L3 편입 · auto-login-r1 실측으로 표면 톤 조건 추가, [[curation-criteria]] "Q10 판정")
- **단일 지배 시각화 완성도**: 대표 시각화의 상용 완성도는 인코딩 차원 수가 아니라 at-a-glance 즉시가독에서 온다 — 핵심 값을 상시 텍스트로 병기(hover 전에도 보이게), 산점도류도 예외 아님(값 안 보이면 감점). 아키타입 신규성과 상충 시 브리프+완성도 다수결 우선. (auto-dash-r7/r9/r10 재현 → L3 편입)

## 에셋·인터랙션 (서비스급 절제 유지, 밀도 상향)
- **생성형 SVG/CSS 적극**: 도메인 고유 시각화(오실로스코프·간트·헥스맵류)를 코드 생성형 SVG/CSS(패턴·마스크·그라데이션·블렌드)로 더 풍부하게. 외부 파일 0, 결정론 유지(삼각함수 좌표 소수 2자리).
- **이미지 규율**: 아바타·썸네일 등은 원시 `<img>` 금지 → `next/image` `<Image>`(고정 URL·`width/height` 또는 `fill`·`alt` 필수, `unoptimized` 금지). 비결정 선택(Math.random 인덱싱) 금지.
- **인터랙션 최소 4종**(기존 3종에서 상향): 크로스헤어 툴팁·실제 정렬/필터·기간/뷰 토글·선택→다중 위젯 동기화·라이브 미니 차트 중 4개+. 전부 `'use client'` 실동작 + 결정론(step 카운터·state 구동) + `motion-reduce` 게이팅.
- **"선택→다중 위젯 동기화"의 판정 축은 배선 방식이 아니라 파급 범위다 (2026-08-29 L2 편입 — 3라운드 계보).** 이 인터랙션은 목록에 이름으로 올라 있지만, **어떻게 구현하느냐로는 차별성이 갈리지 않는다.** 세 라운드가 순서대로 다음을 냈다:
  - `r17` — designer 셋이 서로 다른 매크로 골격을 배정받고도 **같은 배선**(단일 `selectedId` 를 Viz/Ledger/Inspector 3컴포넌트에 같은 프롭 이름·같은 순서로 threading)에 독립 수렴했고, 렌즈3 이 그 둘을 *"글리프만 다른 상호치환 가능"* 으로 읽었다
  - `r18` — 승자가 그 threading 대신 **격자 자신의 인코딩 함수 하나**를 재계산하게 해 회피했다
  - `r19` — **그 처방을 문자 그대로 따른 후보(`c`)가 다시 밀렸다.** 단일 빌더(`buildDashboardView`)로 헤드라인·차트·통계·테이블을 전부 재계산했는데, 렌즈3 은 *"선택→전면 재계산"* 이라는 점에서 **표준 master-detail 과 구조적으로 동일**하다고 판정했다

  **그래서 축은 "재인코딩 빌더를 쓰는가"가 아니라 "선택의 파급을 하나로 뭉치는가, 갈래로 나누는가"다.** `r19` 승자는 둘로 나눴다 — (a) 행 헤더 클릭 = **핀**: KPI 요약만 부분 재계산, 원장 테이블은 **의도적으로 비연동**(주석에 명시) (b) 막대 호버/포커스 = **비영속 인스펙터**: 상태를 전혀 바꾸지 않는 ephemeral 툴팁.
  > 이 조항은 [[questions-queue]] Q46(브리프 문구가 형제 threading 을 요구하는가)이 물은 이분법을 **해소한다** — 둘 중 어느 쪽도 축이 아니었다. `r20` 에서 렌즈1 이 같은 지점에 감점하지 않아 그 충돌은 **재현되지 않았다.**
- **금지 유지**: 연극적 발광·스캔라인·그레인·글로시 장식은 여전히 금지(서비스급). 모션은 정보·전환에 기여할 때만 — 의미없는 데코는 감점.

## 추가 학습 (라운드 3 피드백)

### 레이아웃 아키타입 다양화 (필수)
"좌 사이드바 + KPI 4장 가로줄 + 8/4 차트+사이드 + 풀폭 테이블"은 하나의 아키타입일 뿐이다. 같은 세대 안에서 구조가 겹치면 실패. 서비스급을 유지하되 구조를 다양화하라:
- **마스터-디테일**: 좌측 목록 레일(항목 리스트) + 우측 상세 (Linear/Superhuman식)
- **3-페인 마켓**: 좌 워치리스트 레일 + 중앙 대형 차트 + 우 상세/피드 (트레이딩 터미널식)
- **피드 중심**: 중앙 실행/활동 스트림 + 양옆 보조 패널
- **캘린더/보드 중심**: 대형 캘린더·칸반이 화면 주인공
- KPI도 4카드 가로줄만이 아니라 히어로 숫자+보조 지표, 인라인 스탯 등 변주.

**금지는 발견된 버킷 목록이 아니라 "라운드 안에서 2회 반복"이다 (2026-08-19 L2 편입).** 위 목록에 없는 골격도 같은 라운드에서 두 후보가 쓰면 그 라운드는 사실상 2파전이 된다. GENERATE 프롬프트에 **직전 라운드들의 매크로 버킷 목록을 금지 축으로 명시**하고, **배정 직후 세 안을 서로 대조**한다.
`r10` 에서 히어로+단일시각화 버킷이 재수렴했고(a/c — 온콜 링 vs 헬스×ARR 산점도), `r12` 에서 **다른 버킷**이 독립적으로 재수렴했다(b/c — 고정폭 좌 레일 420-460px + flex-1 우 페인 + 2-옵션 세그먼트 토글, 히어로 부재). 구체 버킷은 달랐고 결함 클래스는 같다 — *GENERATE 단계에서 매크로 골격이 사전 체크 없이 재수렴한다*([[curation-criteria]] "재현 판정은 결함 클래스로 한다").

> **다만 버킷 이름으로 막는 것만으로는 부족하다.** 이후 세 라운드가 **버킷을 잘 갈랐는데도 그 아래에서 수렴**했다 — `auto-native-r1`(아키타입을 다르게 배정 → **외곽 실루엣** 일치) · `auto-native-r9`(화면유형·질문을 다르게 배정 → **인터랙션 문법** 일치: 필드+병렬인코딩+인스펙터+커밋) · `auto-landing-r11`(형태 가족·질문을 다르게 배정 → **산식** 일치: 불일치 열거 → 달러 합산). 층위가 매번 한 칸씩 내려갔고, 배정 단계 점검을 어디까지 내릴지는 미결이다([[questions-queue]] Q14).

### 그리드 크래프트 룰 (스크린샷 검수에서 잡힌 실결함 — 재발 금지)
- **테이블은 카드 안에 수납**: 데스크톱 기준 카드 폭 안에 모든 열이 들어가야 함. 마지막 열(상태 배지)이 잘리거나 카드 내 가로 스크롤바가 보이면 실패. min-w는 정말 필요한 만큼만.
- **날짜/수치 열 줄바꿈 금지**: `whitespace-nowrap` — "7월 15일"이 두 줄로 꺾이면 실패.
- **차트는 실제 렌더를 눈으로 확인**: 간트/타임라인 막대가 안 그려지는 채로 제출 금지. Playwright/puppeteer 스크린샷으로 막대·라인이 실제 보이는지 검증.
- **행 높이·카드 높이 균형**: 나란한 카드의 콘텐츠 양 차이가 크면 긴 쪽은 max-height+내부 스크롤 or "더 보기", 짧은 쪽은 여백이 뜨지 않게 배치 재조정.
- **말줄임 최소화**: 제목이 "...로 절반쯤 잘리면 폭 배분이 잘못된 것. 2줄 clamp나 열 폭 재배분으로 해결.
- **sr-only는 클리핑 컨테이너 안에서 포지션 앵커 필수**: `position:absolute` 기반 sr-only(Tailwind `sr-only`)가 `overflow-x-auto` 래퍼 안 — 가로 스크롤 테이블 자체 또는 그 `<td>` 셀 내부 — 에 있을 때, 자기 자신이나 가장 가까운 감싸는 요소에 `position:relative` 앵커가 없으면 containing block이 클리핑 컨테이너를 건너뛰어 상위 비포지션 조상까지 거슬러 올라간다. 그 결과 스크롤되지 않은(scrollLeft=0) 원래 레이아웃 좌표로 페인트되어 `document.scrollWidth`를 오염시키고, **모바일 좁은 폭(390px)에서만** page-overflow가 터진다. 해법은 클리핑 경계 안쪽 가장 가까운 요소에 `relative`를 추가해 로컬 컨테이닝 블록을 만드는 것. 랜딩 루프도 동일 적용([[design-principles]] §접근성/견고성에서 이 규칙을 참조). (auto-dash-r5 sr-only `<table>` 자체 / auto-dash-r11 `<td>` 안 sr-only `<span>` — 서로 다른 트리거로 2라운드 독립 재현 + `dash-sweep.mjs` page-overflow 체크로 기계 검증 → L2 편입)

### 그리드 검증 룰 v2 (라운드 4 피드백 — 단일 폭 검증 금지)
- **1440px 한 폭에서만 검증 금지.** 사용자 환경은 클래식 스크롤바(뷰포트 유효폭 -15px)·임의 창 폭이다. 1280/1366/1440/1600/1920 전 구간에서 카드 수납을 확인하고, **여유폭 ≥16px** 없이 "딱 맞음"(1px 마진)은 실패로 간주.
- **데스크톱 테이블은 가로 스크롤바 금지** — min-w 강제 대신 `table-fixed`+% 열 배분으로 유동화. 배지/라벨이 길어 안 들어가면 축약 라벨을 설계한다("WITHIN"→"PASS" 등). 로컬 가로 스크롤은 모바일 전용.
- **멀티 페인 레이아웃은 레일 고정폭 + 메인 flex-1 min-w-0** — 메인이 레일보다 좁아지는 비율 붕괴 금지. 히어로 숫자는 반응형 클램프+수납 안전망.
- **스크롤 페이드/힌트 오버레이는 실제 스크롤 가능할 때만 표시**(스크롤 위치 기반) — 항상 떠 있는 그라데이션 띠는 얼룩으로 보임.
- **이중 스크롤바 노출 주의** — 내부 스크롤 영역은 thin 스크롤바 + 페이지 스크롤과 겹쳐 보이지 않게 셸 설계.
- **넓은 `overflow-x-auto` 컨테이너를 한 페이지에 두 개 두지 마라 (2026-08-29 L2 편입).** 각각은 정상 클리핑되는데도(자기 `scrollWidth > clientWidth` 는 그 스크롤러에겐 정상이다) **둘이 공존하면 좁은 폭에서 `document.documentElement.scrollWidth` 가 뷰포트를 넘어 샌다** — 즉 `sweep` 관문이 보는 값이 오염된다. `auto-dash-r20/a` 가 한 후보 안에서 **A/B 토글로 격리**했다: 지배 시각화 격자(자체 `overflow-x-auto`, ~320px 박스 안 ~740px 콘텐츠)와 세그먼트 테이블(`min-w` + `overflow-x-auto`)이 **따로 있을 땐 각각 정상**이고 **함께 있을 때만** 샜다. 근본 원인은 미특정이다 — 그래서 규칙은 "왜"가 아니라 **"두 개를 두지 마라"** 로 적는다.
  **피하는 법이 이미 있다**: 테이블은 위 조항대로 `table-fixed` + % 열 배분으로 스크롤러를 아예 없앤다. 보드/칸반형 지배 레이아웃은 **가로 스크롤러 자체가 불필요하다** — `auto-dash-r21/a` 가 N열을 `grid-cols-1 sm:grid-cols-2 xl:grid-cols-N` 로 펼치고 각 열에 `max-height` + 자기 `overflow-y-auto` 를 줘 가로 스크롤러를 **0개**로 만들었다. 두 라운드가 결함과 회피를 각각 냈다.
