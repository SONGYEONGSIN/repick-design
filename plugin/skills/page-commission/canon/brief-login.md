# 타입 프로파일 — `login` (로그인 · 가입)

> 전 타입 공통 규칙은 [[page-brief-core]]. 이 문서는 로그인/가입 페이지 고유 기준만 정의한다.
> 대시보드 기준([[dash-brief-v3]])을 여기에 적용하지 말 것 — 아래 §0 참조.

## 0. 대시보드 기준이 성립하지 않는 지점 (중요)

| dash-brief-v3 요구 | 로그인에서 |
|---|---|
| 앱 셸(사이드바 + 탑바) | **금지** — 인증 전 화면에 앱 내비게이션이 있으면 거짓말이다 |
| 정렬 가능한 데이터 테이블 | 해당 없음 |
| 단일 지배 시각화 | 해당 없음 |
| 인터랙션 최소 4종 | **최소 2종으로 완화** — 폼 하나짜리 화면에 4종을 넣으면 억지 장치가 된다 |
| ⌘K 커맨드 팔레트 | 해당 없음 |

## 1. 페이지 구조 (필수 요소)

1. **브랜드 락업** — 워드마크 + 한 줄 포지셔닝(선택)
2. **인증 폼** — 실제 `<form>`. 이메일/비밀번호 또는 매직링크 중 하나를 주 경로로 확정
3. **보조 경로** — 소셜 프로바이더 버튼(2~3개) 또는 SSO, 시각적으로 주 경로와 구분
4. **부가 링크** — 비밀번호 찾기 · 가입/로그인 전환
5. **법적 고지** — 약관/개인정보 링크 (작게, 하지만 존재해야 함)

## 2. 폼 품질 (이 타입의 핵심 판정 기준)

- `<label>`이 모든 입력에 **연결**돼야 한다(placeholder를 라벨 대용으로 쓰지 말 것)
- `autocomplete` 속성 정확히(`email` · `current-password` · `new-password`)
- 검증 실패는 **인라인 메시지 + `aria-invalid` + `aria-describedby`**로 전달. 색만으로 표시 금지
- 비밀번호 표시 토글은 `aria-pressed`를 가진 버튼이어야 하고, 토글 후에도 포커스를 잃지 않아야 한다
- 제출 중 상태(로딩)를 시각·스크린리더 양쪽에 알린다(`aria-busy` 또는 라이브 영역)
- **실제 인증 로직 금지** — 결정론적 더미 응답만. 성공/실패 상태는 state로 시연

## 3. 레이아웃 아키타입 (라운드 내 중복 금지)

- **센터드 카드** — 화면 중앙 폼 카드, 배경은 절제된 단색/미세 패턴
- **스플릿** — 좌 비주얼(제품샷·추상 그래픽) + 우 폼, 또는 반대
- **풀블리드 배경** — 배경 이미지/그라데이션 위 유리·카드 폼
- **미니멀 무장식** — 장식 0, 타이포와 여백만으로 구성

## 4. 인터랙션 (최소 2종)

폼 유효성 실시간 반영 · 비밀번호 표시 토글 · 로그인/가입 모드 전환 · 소셜 프로바이더 hover/focus 상태 · 매직링크 전송 후 상태 전환 중 **2개 이상**. 전부 `'use client'` 실동작 + 결정론 + `motion-reduce` 게이팅.

## 5. 금지

- 캡차 흉내(체크박스형 포함) — 접근성 위험이 크고 시연 가치가 없다
- 앱 셸·사이드바·대시보드 위젯
- 스크롤 연출 — 이 타입은 **한 화면에서 끝나야 한다**(스크롤이 필요하면 폼이 과설계된 것)
- 소셜 프로바이더 로고를 이모지·CSS 도형으로 대체(lucide 아이콘 또는 절제된 인라인 SVG)

## 6. judge 렌즈

| 렌즈 | 기준 |
|---|---|
