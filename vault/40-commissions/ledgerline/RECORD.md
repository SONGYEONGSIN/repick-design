## 1. 입력과 사전 검토

사용자가 Dribbble 핀테크 대시보드 목업(Sequence, 2400×1800)을 주고 *"해당 스타일에 디자인 구현 가능한지 확인해줘"*를 물었다. **만들기 전에 제약과 대조해 세 갈래를 제시했다** — 이 검토가 이번 주문의 성격을 결정했다.

기술적으로는 전부 구현 가능했다(발산 막대·잔액 밴드·계좌 카드·활동 테이블·신용카드 비주얼 → 전부 생성형 SVG). 걸린 것은 셋이다:

1. **골격이 정본에서 이름 붙여 금지된 것** — `dash-brief-v3`가 *"**좌 사이드바 + KPI 4장 가로줄 + 8/4 차트+사이드 + 풀폭 테이블**은 하나의 아키타입일 뿐이다. 같은 세대 안에서 구조가 겹치면 실패"*라고 적었는데, 레퍼런스가 정확히 이 구성이다
2. **액센트 emerald가 이미 있다** — emerald 2 · teal 3
3. **dashboard가 이미 12작품**으로 카탈로그 최다 포화 타입이다

제시한 세 갈래: ㉮ 골격을 바꿔 만든다 · ㉯ 그대로 만들되 미등재 · ㉰ 다른 타입으로 재해석. **사용자가 ㉮를 택했고 `dashboard` 유지를 지정했다.**

## 3. 골격 결정 — 이 주문의 본체

**배정: 피드 중심.** 중앙에 돈의 이동 스트림이 화면 주인공으로 서고 양옆이 해석 패널이다. **KPI 카드 가로줄도, 사이드바 내비게이션도 쓰지 않는다.**

기존 dashboard 12작품이 소진한 골격을 전부 목록으로 넘겨 회피시켰다 — 필터→전위젯 동기화(d29·d30) · 크로스헤어(d31) · 자산선택 동기화(d32) · 칸반(d33) · 히어로+벤토(d34) · 트리맵(d35) · 퍼널(d36) · 생키(d37) · 레이디얼 다이얼(d38) · 역할×권한 매트릭스(d39) · 캘린더 히트맵(d40).

**골격과 증명이 같은 방향을 본다** — 핵심 증명이 "돈이 어디서 와서 어디로 빠졌나"이므로 흐름이 축이어야 한다.

## 5. 게이트 — 1차 통과, 1-fix 불요

```
route OK · types 0 · static 0 · lint 0 · weights 3종(렌더 실측)
sweep 전 폭 오버플로 0 · console 결함 0 · a11y 100 · perf 73
샷 16장(4폭 × 4스크롤), blank 0
```

**직전 주문(`hopline`)이 3관문 실패였던 것과 대비된다.** 그 라운드에서 얻은 학습 셋을 브리프에 직접 박은 결과다:

| 학습 | 결과 |
|---|---|
| `fontFamily`를 상수로 빼지 마라 (`hopline` 27건) | **상수 사용 0건** — 전부 리터럴 |
| `sr-only`를 클리핑 컨테이너에 두지 마라 (`hopline` 248px 오버플로) | designer가 **`overflow-x-auto`를 한 곳도 쓰지 않아** 트리거 자체를 제거 |
| `<th>`·`<strong>`에도 웨이트 명시 | 스트림을 테이블이 아닌 그룹 리스트로 짜 **UA 기본 bold가 계측될 지점 자체를 없앰** |

### Q19가 3회 재현되지 않았다

`hopline`에서 *"프롬프트 경고만으로는 안 막힌다"*(가설 ③ 반증)가 관측됐는데, 이번엔 **같은 경고 + 실패 사례 인용**(*"직전 주문에서 이걸로 27건이 걸렸다. 지역 변수든 모듈 상수든 예외 없다"*)으로 막혔다.

**경고에 실패 사례를 붙이면 통한다는 1회 관측**이다. 다만 이것이 Q19를 닫지는 않는다 — 자율 라운드는 사람이 프롬프트를 안 쓰므로 이 방법이 닿지 않는다. 가설 ②(정본 명문화)의 필요성은 그대로다.

## 6. 한/영 토글 — 실행으로 확인

| 상태 | 한글 문자수 | `div[lang]` |
|---|---|---|
| 기본 | **0** | `en` |
| KO 클릭 | 808 | `ko` |
| EN 복귀 | **0** | `en` |

**혼용 0**이고 양방향으로 작동한다. 첫 측정에서 "lang이 안 바뀐다"고 읽혔는데, 내 셀렉터가 `[lang]`으로 **root `<html lang="en">`을 먼저 잡은** 착오였다(`hopline`에서는 `div[lang]`으로 지정했었다).

## 7. designer가 정한 것 (5분류)

### ① 이름
- 계좌 3종 `Operating ····4417` / `Payroll ····2038` / `Reserve ····7761`
- 거래처 13곳 전원 가공 법인명(Northgate Timber · Milbrook Interiors · Ashgrove Dental Group · Fairmont Clinics · Stackline Supply · Harbor Freight Logistics · Riverbend Property · Cloudreach Ops · Gridpoint Analytics · Pinecrest Media · Northline Market · Metro Power and Water · Cutwell Machinery)
- **실존 인물명·이메일 0건** — 급여를 개인이 아니라 **"Salary batch"라는 배치 단위**로만 표현했다. `auto-dash-r3/a` delta가 경고한 사고를 구조로 피한 것이다

### ② 숫자·조건
- 통화 **USD** — *"₩는 mono에 글리프가 없고 디스플레이 활자가 mono라 배제"*. `Intl` 없이 수기 콤마·소수 2자리(하이드레이션 로케일 드리프트 회피)
- 앵커 날짜 **2026-07-31을 day 0으로 고정**하고 날짜는 월길이 테이블로 산술 계산 — `new Date` 없음
- 금액은 전부 **센트 정수**(부동소수 오차 차단)
- 거래 **39건**(운영 25·급여 8·예비비 7). **잔액은 마감잔액에서 역산해 자동 정합**
- 버킷 분할 7D=1일×7 / 30D=3일×10 / 90D=10일×9
- 직전 기간 비교치는 계좌×기간 **18개 상수로 별도 고정** — 90일 이전 데이터가 없어 파생 불가

### ③ 카피
- 한/영 전 문자열 이중 사전(UI 40여 · 분류 16 · 수단 5 · 상태 3 · 거래처·적요 39×2)
- 토글 라벨을 **"EN / KO"**로 — *"'한국어'라고 쓰면 영문 화면에 한글이 노출돼 혼용 금지에 걸린다"*
- 한국어 날짜를 `7.31` / `2026.7.31` **숫자형**으로 정해 디스플레이 mono를 두 언어에서 동일하게 걸 수 있게 했다
- 금액 뒤 조사를 **"만큼"**으로 회피 — "이/가"는 숫자 읽기에 따라 갈린다

### ④ 구조·미학
- 레일 비율 lg 4/8 → xl 3/6/3(우 레일은 lg에서 하단 3열로 접힘, 모바일은 **스트림 우선**)
- 상단이 카드가 아니라 **한 문장** — *"지난 30일 동안 운영 계좌에 5개 출처에서 …만큼 들어오고, 6개 항목으로 …만큼 나갔습니다"*
- 히어로 숫자 3개(입금·출금·순이동)를 카드가 아니라 문장 하단의 **`dl` 한 줄**로. 각 값에 델타와 비교 기준 금액이 항상 붙는다
- 발산 막대는 입금 `zinc-800`(위)·출금 `rose-500`(아래). **rose는 액티브 컨트롤과 출금 계열에만** 쓰는 단일 액센트
- 계좌 카드는 SVG 그라디언트+플로우 라인(원격 이미지 0)

### ⑤ 접근성·기술
- 차트 SVG는 `aria-hidden` + **버킷별 입출금을 읽는 `sr-only` 목록** 병행(클리핑 컨테이너 밖, `relative` 앵커)
- **페이지 전체에 `overflow-x-auto`를 한 곳도 쓰지 않음** — 390px sr-only 오버플로 트리거를 제거
- 방향은 색이 아니라 **부호(+/-) + 아이콘 + 기준선 위/아래 위치**, 상태는 **배지 텍스트 + 아이콘**으로 이중 인코딩
- 헤더·기간·언어·계좌·필터 컨트롤 **각각 `h-11`(44px)** — `auto-dash-r4/c` delta 준수
- 카드 섹션에 `bg-zinc-900` 명시 — *"Lighthouse는 배경을 조상에서 계산하므로 SVG 배경만 두면 흰 글씨가 대비 실패로 잡힌다"*
- 포커스는 `focus-visible:ring-2 ring-rose-600`(`outline-none` 미사용)

## 9. designer가 보고한 브리프 구멍 1건

> **언어 토글 자체의 라벨링은 "한 화면에 두 언어 금지"와 원리적으로 충돌한다** — 토글은 대상 언어를 알려야 누를 수 있다. ISO 코드 "EN/KO"로 우회했으나 **이 케이스는 정본에 규칙이 없다.**

정확한 지적이다. `hopline`은 `KO 한국어` / `EN 영어`로 **양쪽 라벨을 병기**해 영문 화면에 한글이 노출됐다 — 같은 규칙의 반대 해석이다. **두 주문이 같은 구멍을 서로 다르게 메웠다.**

주문 제작은 정본을 못 바꾸므로 별건으로 남긴다. 재현 2회이므로 질문 큐 후보다.
