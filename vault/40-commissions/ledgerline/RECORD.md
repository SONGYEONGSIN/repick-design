## 1. 무엇을 잘못했나 (이 기록의 본체)

사용자가 Dribbble 핀테크 대시보드 목업(Sequence)을 주고 *"해당 스타일에 디자인 구현 가능한지 확인해줘"*를 물었다. 나는 **만들기 전에 세 갈래를 제시**했고 ㉮(골격 변경)를 권했다. 근거는 둘이었다:

1. *"레퍼런스 골격이 `dash-brief-v3`에서 이름 들어 경계된 것"*
2. *"dashboard가 이미 12작품으로 카탈로그 최다 포화"*

**둘 다 이 주문에 적용되지 않는 규칙이었다.**

### 근거 ①의 원문

> `dash-brief-v3:51` — "좌 사이드바 + KPI 4장 가로줄 + 8/4 차트+사이드 + 풀폭 테이블"은 하나의 아키타입일 뿐이다. **같은 세대 안에서** 구조가 겹치면 실패.

**"같은 세대 안에서"** — 자율 라운드가 후보 3개를 낼 때 서로 겹치지 말라는 **다양성 규칙**이지, 그 레이아웃을 만들지 말라는 금지가 아니다. 같은 문서 위쪽은 정반대를 말한다:

> `dash-brief-v3:26` — **앱 셸**: 좌측 사이드바(브랜드 락업 + 워크스페이스 스위처 + 섹션 nav + 하단 유저) + 상단바(글로벌 검색 ⌘K + 주요 액션 + 알림 + 아바타)
> `dash-brief-v3:29` — 명시적 12-col 그리드(**8/4 등**) … KPI 4열은 xl부터

**정본의 완성도 기준이 요구하는 것이 바로 그 골격이다.** 레퍼런스는 회피 대상이 아니라 기준선이었고 내가 뒤집어 읽었다.

### 근거 ②

`page-commission:22` — *"갤러리 등재는 사용자가 명시적으로 요청할 때만. **등재하면** 갤러리·큐·다양성 집계에 들어가므로 기본은 미등재다."*

ledgerline은 미등재다. **다양성 제약이 애초에 걸리지 않았다.** 루프 내부 규칙을 사용자 주문에 적용해 원하는 레이아웃에서 멀어지게 만든 것이다.

### 사용자 지적

배포 후 사용자가 `/dash/d30`을 예로 들며 *"나는 아래 대시보드 형태로 구현하기를 원했던 건데"*라고 짚었다. 1차 판은 셸 없는 전폭 1단 에디토리얼 리포트였다 — 같은 데이터를 다루지만 **장르가 달랐다.** d30은 매일 여는 업무 화면이고 1차 판은 한 번 읽는 문서다.

**교훈**: 주문 제작에서 정본 조항을 인용해 사용자를 설득할 때는 **그 조항의 적용 범위를 먼저 확인한다.** 루프 내부 규칙(세대 내 다양성·카탈로그 포화)은 주문에 걸리지 않는다.

## 3. 최종 골격 (재제작 — d30 계열)

- **좌 사이드바** `w-64` sticky — 브랜드 락업 + 계좌 스위처 3종(radiogroup, 이름·종류·last4·잔액) + 2섹션 nav(활성 pill + `aria-current`) + 하단 유저. 모바일은 드로어
- **상단바** sticky, 컨트롤 전부 44px — 검색(Ctrl K 팔레트 실동작) + 기간 세그먼트 + **언어 세그먼트** + 알림 + 아바타. 390px에서 기간·언어가 둘째 줄로 접힘
- **KPI 4장** — Money in · Money out · Net movement · Available balance. 값 + 델타 칩 + 비교 기준 문구
- **8/4 그리드** — 좌 8칸 일별 입출금 발산 차트(기준선 위 입금 rose·아래 출금 zinc), 우 4칸 출처 분해 + `Leaving next`
- **풀폭 거래 테이블** — `table-fixed` + 브레이크포인트별 % 열 배분, 정렬 5열(`aria-sort`), 상태 배지

축은 1차와 동일: **light · rose 단일 · `--font-display-mono`**.

## 4. 게이트 — 9관문 통과 (1-fix 2회)

```
route OK · types 0 · static 0 · lint 0 · weights 3종(렌더 실측)
sweep 전 폭 오버플로 0 · console 결함 0 · a11y 100 · perf 78
샷 16장(4폭 × 4스크롤), blank 0
```

1차 게이트에서 `lint` 1건(`react-hooks/set-state-in-effect` — 팔레트가 열릴 때 effect 안에서 `setQuery("")`). designer가 조건부 렌더로 구조를 뒤집어 해소했는데, **호출부를 절반만 고쳐** `TS2322`가 새로 났다(`CommandPalette`에서 `open` prop을 지웠는데 `LedgerlineApp:258`이 계속 넘김). 오케스트레이터가 호출부를 조건부 렌더로 마저 고쳐 통과.

> **타입 게이트가 없었으면 팔레트가 항상 떠 있었을 것이다.** `if (!open) return null`이 제거된 채 무조건 렌더되고 있었고, 이건 `lint`·`static`·`sweep` 어디에도 안 걸린다. 2026-08-11에 `types` 관문을 넣은 결정이 여기서 값을 했다.

## 7. designer가 정한 것

### ① 이름
1차와 동일 — 계좌 `Operating ····4417` / `Payroll ····2038` / `Reserve ····7761`, 거래처 13곳 전원 가공 법인명, **실존 인물명 0건**(급여는 배치 단위). 재제작에서 추가된 것: 유저 `Maren Okafor / Finance lead`, 알림 3건 — **기존 거래 데이터와 사실관계를 맞췄다**(파인크레스트 확인 요청 · 청구서 2288 정산 대기).

### ② 숫자·조건
**`data.ts`를 한 줄도 고치지 않았다** — 39건 거래·3계좌·잔액 역산·`BASELINE` 직전기간·이중언어 사전·집계 함수·포맷터 전부 재사용. 새로 정한 것 둘:
- **KPI 4번(잔액) 칩을 델타%가 아니라 예정 출금액으로** — *"잔액은 시점 값이라 기간 대비 %가 의미를 갖지 않는다."* 대신 `SCHEDULED` 합계가 계좌 전환에 반응한다
- **순이동 칩을 % 대신 절대 변화액으로** — *"직전 순이동이 음수일 때 백분율 부호가 거짓말을 한다."* 1차 판에 없던 판단이다

### ③ 카피
셸 전용 문자열(nav·알림·표 헤더)만 `ui.tsx`에 이중언어로 신규. 토글 라벨은 **`EN`/`KO` ISO 코드 + `aria-label`에 언어 전체 이름**을 병기했다.

> 이 조합이 [[questions-queue]] Q23(언어 토글 라벨링이 혼용 금지와 충돌)의 **가설 (다)에 해당하는 실물**이다 — 화면에는 언어 중립 코드, 보조기술에는 전체 이름. `hopline`(양쪽 라벨 병기 → 영문 화면에 한글 노출)과 1차 ledgerline(코드만 → 언어 이름이 어디에도 없음)의 결함을 둘 다 피한다. **다만 `aria-label`이 현재 언어를 따라 바뀌어 자동화 셀렉터가 깨진다**(§6) — Q23에 이 실측을 붙일 값어치가 있다.

### ④ 구조·미학 / ⑤ 접근성·기술
차트를 SVG가 아니라 **HTML 바 + 실제 `<button>`**으로 구현(*"키보드 포커스가 공짜로 따라온다"*). 상태 배지에 amber/emerald를 쓰지 않고 확인 필요 건만 rose — **rose 단일 액센트 유지**. 방향은 부호 + 화살표 아이콘 + 기준선 위/아래 위치로 삼중 인코딩.
