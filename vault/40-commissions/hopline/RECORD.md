## 1. 입력 — Dribbble 목업

사용자가 링크 분석 대시보드 목업 URL을 주고 *"해당 이미지 주소 기반으로 페이지 작업 가능한가"*를 물었다. 4320×11292 PNG를 받아 축소해 읽었고, 6구획 구조(판독 밴드 · 이상탐지 카드 · 오디언스 · 유입 생키 · 캠페인 · 링크 표)를 확인했다.

**추상화 수준을 먼저 합의했다** — 사용자가 **"구조·기법만"**을 택했다. Dribbble 샷은 다른 디자이너의 저작물이고, 이 레포의 카탈로그는 *"Linear·Stripe와 나란히 비교되는"* 오리지널이라 픽셀 재현은 성격이 안 맞는다. 이 레포에는 이미 `vault/10-references/`에 참조 문서 관례가 있고 `design-evolve`가 *"참고 URL/캡처 이미지 기반"*을 지원한다.

**가져온 기법 넷**:
1. 이상탐지 카드에 **처방을 붙인다** — 숫자·조건·처방이 한 카드 안에
2. 히트맵에 **결론 문장 병기** — 그리드만 두지 않는다
3. 흐름을 **두 축으로** — 소스에서 링크로 가는 기여를 한 그림에
4. 숫자마다 **델타와 해석**

**따르지 않은 것**: 색·간격·인상. 레퍼런스는 보라 계열인데 카탈로그에 `violet-hex 7 · violet 2`로 최다다.

## 3. 타입 계약 (프로파일 A + 도출한 판정 기준)

프로파일 `dash-brief-v3`가 인터랙션 **4종 이상**·**스크롤 연출 금지**를 강제한다. 여기에 핵심 증명에서 판정 기준을 **도출해 제안·승인**받았다:

> **모든 지표에 "그래서 뭘 하라"가 붙어 있어야 하고, 처방은 지표에서 파생돼야 한다.** 이상탐지 카드가 별도 섹션으로 떠 있고 아래 차트와 무관하면 그건 배너지 처방이 아니다.

**구성안도 생성 전에 승인**받았다(§2 신설분). 레퍼런스의 6구획을 두되 **할 일 섹션을 오디언스보다 위로** 올렸다 — 핵심 증명이 "뭘 고치나"이기 때문이다. 레퍼런스는 이상탐지가 중간에 있다.

## 4. 축 결정 — 레퍼런스에서 의도적으로 뺐다

| 축 | 값 | 근거 |
|---|---|---|
| 테마 | `light` | 레퍼런스와 같음. light 20/dark 15로 편중이 크지 않다 |
| 액센트 | **`orange`** | 카탈로그 1건(그것도 dark)이라 `light+orange`는 미사용. **다양성만이 근거가 아니다** — 핵심 증명이 "뭘 고치나"라 주의·수정 신호로 의미가 맞는다 |
| 활자 | **`--font-display-mono`** | 2건으로 희소하고 URL·코드 도메인과 정합 |

기존 조합 충돌 확인: `dark+orange`(Kestrel) · `light+rose`(Tessera) · `dark+cyan+mono`(Bollard) → **`light+orange+mono`는 신규**.

## 5. 게이트

```

sweep 전 폭 오버플로 0 · console 결함 0 · a11y 100 · perf 78
샷 16장(4폭 × 4스크롤), blank 0
```

**1차에서 3관문이 실패했고 1-fix로 전부 해소했다.**

| 관문 | 실패 | 원인 |
|---|---|---|
| `static` | 27건 | `no-unlisted-font` — `MONO` 상수 |
| `lint` | 1건 | `charts.tsx:241` 렌더 후 `offset` 재할당 |

### static 27건 — Q19가 실증됐다

designer가 `const MONO = "var(--font-display-mono)"`로 빼고 27곳에서 썼다. 정적 검사는 `fontFamily:` 바로 뒤 문자열만 보므로 **런타임에 정확한 상수도 미지의 폰트로 읽힌다.**

**브리프에 "상수로 빼지 마라"를 명시했는데도 걸렸다.** 규칙이 반직관적이라 지시만으로는 안 막힌다는 증거이고, 이것이 [[questions-queue]] Q19가 열려 있는 이유다. designer 스스로도 *"이 부분은 게이트 실행으로 확인 필요"*라고 표시했다.

### sweep — 오케스트레이터가 원인을 잘못 지목했다

내가 히트맵(12구간 × 28px 셀)을 유력 후보로 지목했는데 **틀렸다.** designer가 계산으로 배제했다 — 히트맵은 `min-w-[520px]`가 `overflow-x-auto` 안에 있고 그 안에 `sr-only`가 없어 문서 폭을 밀지 못한다.

진짜 원인은 `page-brief-core` §2가 경고한 **sr-only 앵커** 재현이었다 — 링크 테이블(640px 로컬 스크롤) 안의 `position:absolute` `sr-only`가 클리핑 컨테이너를 건너뛴 좌표로 페인트됐다. **좌표까지 맞췄다**: 델타 열 오른쪽 끝 620 + 페이지 패딩 16 + 카드 보더 1 + 폭 1 = **638 = 390 + 248**.

조치도 근거가 명확했다 — `relative` 앵커 대신 **스크롤러 안에서 절대배치 자체를 제거**했다. 이유: *"앵커는 Tailwind 유틸리티 출력 순서에 의존해 `sr-only`의 `position:absolute`를 이기는 방식이라 결정론적이지 않다."* 색 단독 의미 전달 금지는 유지된다(델타는 부호 + 화살표 + 색 3중이고 스크린리더가 "plus 18.4 percent"로 부호를 읽는다).

## 10. 갤러리 등재 — 정본 §1 충돌과 해소 (2026-08-12)

사용자가 등재를 요청했고, 스킬이 요구하는 대로 **조용히 등재하지 않고 충돌을 알렸다.**

`page-brief-repo` §1은 카탈로그 작품에 **영문 전용**을 강제하는데 이 페이지는 한/영 토글이고 **기본이 `ko`**였다. 등재 전 카탈로그 40작품은 전부 영문이다(샘플 4작품 한글 0건).

**§1이 스스로 근거를 밝힌다** — *"글로벌 벤치마크 정합… 이 근거가 없는 맥락에는 이 규칙이 적용되지 않는다."* 미등재 상태에서는 근거가 없어 한국어가 허용됐고, 갤러리에 들어가는 순간 근거가 생긴다.

사용자에게 셋을 제시했다: ① 기본을 EN으로 ② 한국어 제거 ③ 그대로 등재하고 정본에 예외 단서. **①을 택했다.**

```
const [lang, setLang] = useState<Lang>("en");   // "ko" → "en"
```

한 줄이다. **기능은 안 죽는다** — 한국어는 토글로 남고 인터랙션 6종이 유지되며 한 화면 혼용은 여전히 0이다. 실행으로 확인했다:

| 상태 | 한글 문자수 | `lang` | 첫 문장 |
|---|---|---|---|
| 기본 | **0** | `en` | `Skip to what needs fixing` |
| KO 클릭 | 936 | `ko` | `고칠 것으로 건너뛰기` |

**정본은 고치지 않았다.** ③을 택했다면 §1에 예외 단서를 달아야 했는데, 그건 주문 제작이 판정을 안 거친 산출물로 정본을 바꾸는 것이라 스킬 불변식에 걸린다.
