## 1. 인터뷰 결과

| 항목 | 사용자 답 |
|---|---|
| 도착 후 행동 | 플랜을 비교해 고르고 **가입한다** → 공개 가격표 |
| 도메인 | 매장 POS 단말. 기기 40만~120만원대 · 구독 월 2만~9만원대. 규모 축은 매장 수·단말 수 |
| 핵심 증명 | **지금 당장 얼마를 내야 하는가** (초기 비용) |
| 읽는 사람 | 처음 보는 사람, 평가 중. 아직 고객이 아니다 |
| 분량 | 한 화면 완결 |

`paywall`(프로파일 있음)과 갈리는 지점이 §1-1 첫 질문 하나로 판별됐다 — "막힌 기존 고객"이 아니라 "아직 고객이 아닌 사람"이다.

## 2. 타입 계약 (프로파일이 없어 그 자리에서 세운 것)

**필수 요소**
1. 조달 방식 선택기 (구매 / 분할 / 임대)
2. 오늘 내는 돈 — 선택에 따라 재계산되는 초기 비용
3. 매달 내는 돈 — 초기 비용과 **분리 표기**
4. 규모 입력 — 매장 수 또는 단말 수
5. 포함 범위 — 플랜 간 차이
6. 결정 유도 — 가입 또는 상담

**핵심 판정 기준**

> "오늘 내는 돈"과 "매달 내는 돈"이 **항상 분리된 채 동시에** 보여야 하고, 조달 방식·규모 조작이 **둘 다** 재계산해야 한다.

두 값과 플랜 추천이 **단일 리프트된 계산 상태**에서 나와야 한다. 각자 계산하면 기본값에서만 우연히 맞고 조작 즉시 어긋난다 — `auto-paywall-r2/c`가 정확히 이 결함으로 탈락했다.

**인터랙션 최소 2종** (조달 전환 · 규모 조절) · **스크롤 연출 금지** · **인접 타입과의 차이**: `paywall`은 "현재 플랜"이 표시되지만 이쪽은 없다. "무엇이 언제 멈췄나" 자리가 "오늘 얼마"가 된다.

## 4. designer가 정한 것 (사용자가 말하지 않아 designer가 채운 자리)

원 보고는 34항목. 아래는 `page-commission` 스킬(`.claude/skills/page-commission/SKILL.md`) §5의 5분류로 묶은 것이다.

### ① 이름
- **회사** `Tillmark` (법인 "Tillmark Systems", 금융사 "Tillmark Capital") — POS 도메인 어휘(till = 금전등록기 서랍). **사용자에게 묻지 않았다** — 이 누락이 스킬 수정의 직접 계기가 됐다
- **플랜 3종** `Counter` / `Chain` / `Franchise` — 규모 서사(한 대 → 여러 점포 → 가맹)
- **단말 3종** `T1 Palm` / `T2 Counter` / `T3 Lane`

### ② 숫자·조건
- **구독 과금 단위**: 단말당·월. 매장당으로 하면 "단말 수" 입력이 매달 내는 돈에 영향을 못 줘 필수 요소 4가 반쪽이 된다
- **구독가** 29,000 / 59,000 / 89,000 (지정 대역 하한·중간·상한)
- **기기가** 420,000 / 790,000 / 1,180,000 (지정 대역 하한·중간·상한)
- **분할** 20% 선납 · 24개월 · 총 6% 수수료. 오늘 내는 돈이 0이 되지 않게 선납을 뒀다 — 0원은 버그처럼 읽힌다
- **임대** 36개월 · 보증금 없음. **분할보다 비싸게** 잡아 세 방식이 진짜 트레이드오프가 되게 했다
- **설치비** 매장당 120,000원, 세 방식 **모두**에 부과. 규모 입력 "매장 수"가 오늘 내는 돈을 움직이는 유일한 항이다
- **규모 범위** 매장 1–12(기본 3) · 매장당 단말 1–6(기본 2). 상한을 곱해도 최대 금액이 11자를 넘지 않게 — 390px 칼럼(≈142px) 오버플로 역산
- **추천 임계값** 1매장&단말≤3 → Counter · 매장≤6 → Chain · 그 외 → Franchise. 기본값이 중간 티어에 떨어져 양방향 조작 시 티어가 실제로 바뀐다

### ③ 카피
- **h1** "Two numbers, not a quote." — 핵심 증명을 헤드라인이 주장하고, 동시에 경쟁사 관행("문의하세요")과의 차별 축을 선언
- **회사 한 줄 소개** "Point of sale for counters, lanes and handhelds"
- **통화** 원화 `₩`. 지정 대역이 원화 전제라 USD로 바꾸면 계약이 깨진다. [[page-brief-core]] §1은 **카피 언어**를 영문으로 강제할 뿐 통화는 규정하지 않는다
- **푸터 법적 문구** 금융사 명칭·수수료·소유권·VAT 표기. 연도는 하드코딩(`new Date()` 금지)

### ④ 구조·미학
- **전체 골격**: 가로 밴드 2단 — 위 판독행(오늘·매달·결정) / 아래 조작행(조달·규모·플랜). `/paywall`의 세로 스플릿을 복제하지 않으려면 축 자체를 돌려야 했고, 단말기(위 디스플레이·아래 키패드) 은유가 도메인에서 나왔다
- **플랜을 고르게 하지 않고 규모에서 파생**시켰다. 계약이 "플랜 추천이 단일 계산에서 나와야 한다"고 했으므로 플랜은 선택 축이 아니라 결과다
- **두 금액을 390px에서도 2열 유지**. "항상 분리된 채 **동시에**"가 요구라 세로 스택은 계약 위반. 금액 크기를 `text-xl → sm:text-3xl`로 낮춰 대응
- **플랜 비교를 표가 아니라 누적형 사다리**로. `auto-careers-r2`의 `table-fixed` 함정을 회피가 아니라 **설계로** 제거했다 — 어떤 폭에서도 표가 아니다
- **조달 선택기에 각 방식의 Today/Monthly를 상시 표기**. 선택 전에 트레이드오프가 표 없이 보인다. 이 숫자들도 같은 `quote()`가 계산한다
- **이미지 0장** (SVG 삽화 포함). 한 화면 예산에 자리가 없고, 이 페이지에서 설득력을 갖는 시각 요소는 숫자 자체다
- **다크 · `amber-400` 단색 · `--font-display-mono`** — 다양성 제안 수용. amber는 카탈로그에서 사실상 미사용이었고 POS 도메인(영수증·금전·단말 표시등)과 맞는다

### ⑤ 접근성·기술
- **라이브 리전**: 개별 금액이 아니라 "Configured" 문장 하나에 `role="status"`, 두 금액을 `sr-only`로 덧붙임. 숫자 4개가 각자 떠들면 스테퍼를 누를 때마다 낭독이 겹친다
- **스킵 링크** `#configure` — `/paywall`의 `#plan` 선례
- **`<fieldset>` 테두리**: 테두리 있는 `<div>`가 테두리 없는 `<fieldset>`을 감싸게. `legend`가 상단 보더 안쪽에 그려져 패널 간 불일치가 생긴다
- **`settledMonthly` 필드 삭제** — 죽은 줄이라서가 아니라 **살아 있는 값의 중복 사본**이라서다. 같은 값이 이미 각주로 렌더된다("Falls to ₩354,000 in month 25"). 되살리면 값마다 독립 계산 경로가 생기는데, 그건 이 페이지가 피하려고 존재하는 형태다
- **파일 분할 5개** (page / client / data / readout-row / config-row) — `/paywall`과 같은 결

## 5. 계약 이탈 — 사용자 인수

**"한 화면 완결"이 390px에서는 세로 스크롤로 완화됐다.** 필수 요소 6개를 390×844에 본문 16px·터치 타깃을 지키며 넣을 방법이 없다는 designer 판단이다. 스크롤 **연동 연출은 없고** 첫 화면에 핵심 증명(두 금액 + 추천 플랜 + CTA)은 완결된다.

사용자가 계약의 "한 화면 완결"을 **데스크톱 기준으로 수정해 인수**했다.

## 6. 이 주문이 스킬에 남긴 것

첫 실행이라 스킬의 구멍이 여럿 드러났고 전부 반영됐다.

| 발견 | 반영 |
|---|---|
| designer가 **보고 직전에 3회 연속 중단**, 1회차는 `page.tsx`가 통째로 없었다 | §3 완료 확인 — "파일 존재는 완료가 아니다" |
| `gate.mjs`는 **컴파일 여부를 안 본다** — 타입 에러가 있어도 라우트가 200을 응답했다 | §4 tsc·eslint 선행 |
| 질문 5문이 전부 **레포 정본 용어**였다 | §1-2 평이한 말 전환 |
| 회사명이 복합 질문에 묶여 **실행 단계에서 떨어져 나갔다** | §1-2 회사명 별도 질문 |
| 계약 항목을 **실제로는 제안해 확인받았는데 본문은 "묻는다"**로 되어 있었다 | §1-3 도출·제안 전환 |
| 사용자가 **전체 골격을 스크린샷에서 처음 봤다** | §2 구성안 + 제작에서 중요하게 볼 것 |
| 보고 34항목이 **평평하게** 와 회사명이 묻혔다 | §5 5분류 인수 |
| 스크린샷이 `/tmp`에 있어 **휘발성**이었다 | §5 이 폴더에 커밋 |
