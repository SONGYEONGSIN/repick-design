## 1. 인터뷰 결과

개선판의 **평이한 말** 질문을 그대로 썼다. 정본 용어(`핵심 증명`·`도메인 실체`)는 한 번도 입 밖에 내지 않았다.

| 묻는 말 | 답 |
|---|---|
| "도착한 사람이 다음에 무엇을 하길 바라세요?" | 어떤 회사인지 알고 간다 → `about` |
| "회사 이름이 뭐예요? 없으면 지어드릴까요?" | **지어주세요** → `Ferrous` 제안·승인 |
| "뭔 하는 곳이에요?" | 중고 거래 플랫폼(이 레포 서비스). AI가 매물을 사람처럼 읽고 매칭 |
| "딱 하나만 기억한다면?" | **얼마나 검증된 곳인가** |
| "누가 볼 페이지예요?" | 잠재 고객 |
| "한 화면인가요, 쭉 내려보는 형태인가요?" | 4~5섹션 스크롤 |

**첫 시험과 달라진 지점**: 회사명을 별도로 물었다. 첫 시험(`pos-pricing`)에서는 안 물어 designer가 `Tillmark`를 지었고 그게 스킬 수정의 계기였다. 이번엔 **위임을 명시적으로 받고** 제안→승인 경로로 갔다 — 결과가 비슷해도 사용자가 거부할 기회가 있었다.

## 2. 타입 계약 (프로파일이 없어 그 자리에서 세운 것)

**계약 항목을 묻지 않고 도출해 제안했다** — 개선판 §1-3.

**필수 요소** (묻고 후보 제시)
1. 팀 · 2. 가치·원칙(안 하는 것까지) · 3. 검증 지표 · 4. 연혁 · 5. 다음 행동

1·2는 `auto-about-r1` delta가 근거다: *"팀·가치 섹션이 없으면 'About Us' 라벨의 암묵 계약을 채우지 못하고 제품/트랙션 페이지로 읽힌다."*

**핵심 판정 기준** (도출해 제안 → 승인)

> **검증 근거(숫자·이력)와 사람(팀·가치)이 같은 페이지에서 서로를 뒷받침해야 한다.**

숫자만 있으면 실적 페이지, 사람만 있으면 브로슈어다. `about r1` delta는 "팀·가치 없으면 실패"만 말하는데, 핵심 증명이 "검증"이라 **반대 실패**도 가능해 **양방향**으로 잡았다.

**인터랙션 3종**(도출) · **스크롤 연출 허용**(분량에서 도출) · **인접 타입과의 차이**(도출해 제안): `profile`이 가장 가깝다. 다른 점은 **주체가 개인이 아니라 조직** — `profile`의 "이 사람을 믿을 근거"가 여기서는 "이 조직이 지속될 근거"가 된다.

## 3. 구성안 (생성 전 승인 — 개선판 §2 신설분)

```
1  히어로     — 한 줄 정의 + 검증 지표 3~4개 (핵심 증명을 첫 화면에)
2  연혁       — 시작 → 지금. 지표가 언제 쌓였는지 보이게
3  가치·원칙  — 하는 것과 안 하는 것. 대비로 배치
4  팀         — 사람. 이름·역할·한 줄
5  다음 행동  — 서비스 진입 + 채용
```

첫 시험에서는 사용자가 전체 골격을 **스크린샷에서 처음** 봤다. 이번엔 승인 후 시작했고, 최종 산출물이 이 순서 그대로다.

## 4. 게이트

```
static 위반 0 · weights 3종 · sweep 전 폭 오버플로 0 · a11y 100 · perf 74
빈 프레임 0건 (4폭 × 4 스크롤) · 폴더 밖 오염 0건
```

designer가 셸이 없어 `tsc`·게이트를 못 돌렸고 **"돌려봤다고 쓰지 않겠다"**고 보고했다. 남긴 미검증 항목(sweep·a11y, 특히 *"390px 히어로가 첫 화면에 지표까지 담는지는 계산으로 ≈700px이 나왔을 뿐 실측이 아니다"*)이 오케스트레이터 실행에서 전부 통과했다.

## 5. designer가 정한 것 (5분류)

designer가 **처음부터 5분류로 묶어** 보고했다 — 개선판 §3. 첫 시험에서는 34항목이 평평하게 와 회사명이 묻혔다.

### ① 이름
- 법인 `Ferrous B.V.` · 본거지 **로테르담(창업) + 리스본(2024 2번째 등급 판정소)** — 2거점이 있어야 "조직이 커졌다"가 연혁의 사건이 된다
- 리더 **6명**: Marit Solheim(대표) · Tomás Reguero(등급판정) · Ayaka Mori(신뢰운영) · Dele Okonjo(모델연구) · Priya Raman(판매자경험) · Janek Kowalczyk(엔지니어링). **6명인 이유는 구조** — 원칙이 6개라 1인 1규칙
- 지표 4종 `Items graded` / `Submissions refused` / `Grade agreed on arrival` / `Sales disputed`
- 루브릭 `Rubric v3` · 연락처 `people@ferrous.market`

### ② 숫자·조건
- **2017 → 2026, 9년 · 38명**(리더 6명 노출 — "6명 = 전부"로 읽히면 조직이 아니라 팀이 된다)
- 현재: 등록 4,180,000건 · 거절 11.4% · 도착 시 등급 동의 94.6% · 분쟁 0.31%
- **과거 지표 24개**(6시점 × 4지표) 전부 지정. 2017년 640건·24.0%·81.0%·2.10% → 2026. **핵심 판정 기준 때문에 필수였다** — 연혁이 지표를 뒷받침하려면 "그때는 얼마였나"가 실제로 있어야 한다
- 분쟁 처리: 영업일 5일 이내, **자사 마진에서** 정산 — 분쟁률을 축소 보고할 유인이 없다는 것까지 말해야 숫자가 증거가 된다
- 수익: 거래 완료 수수료만. 등록비·노출 판매·구매자 수수료 없음
- **거절률 24.0% → 11.4% 하락**이 "기준 완화"로 오독될 수 있어 "판매자가 요건을 학습한 결과, 루브릭은 조여지기만 했다"를 명시
- 등록 건수 지표에 **"건수 자체는 아무것도 증명하지 않는다"** 부착 — 자기 지표를 깎는 문장이 없으면 실적 페이지가 된다
- 히어로 수치는 연혁 마지막 행에서 **파생**. 같은 값을 두 번 타이핑하면 오늘만 일치하고 다음 수정에서 갈라진다(`pos-pricing` 교훈)

### ③ 카피
- h1 "A used listing, read the way a careful person reads it."
- 메타 라인 "Rotterdam and Lisbon · Trading since 2017, 9 years · 38 people" — 운영 기간을 첫 화면에
- 지표마다 2문(무엇을 세는가 + 어떻게 읽어야 하는가) — 숫자에 해석이 없으면 자랑이 된다
- 푸터 "**등급은 상태를 설명하며 소유권의 진정성은 아니다**" — 중고 거래의 실제 분쟁 지점. 연도 하드코딩

### ④ 구조·미학
- **액센트 `lime-700/800`** — 밝은 라임이 아니라 **올리브 드랩**. 낡은 공구에 칠하는 색이라 중고 도메인과 맞고, 검증·통과 자리에 늘 쓰이던 emerald/teal을 피했다
- **중립 `stone`**(zinc 아님) — 카탈로그 전 작품이 zinc 기반이라 stone 자체가 미사용 축. `stone-500`은 아예 쓰지 않았다(muted 표면 하한 규칙을 회피가 아니라 제거)
- **지표를 배너가 아니라 컨트롤로** — 페이지 유일 전역 상태. `/profile`의 sticky 스코어보드 복제를 피한 핵심: *"개인은 통계를 배너로 걸면 되지만 조직은 지표마다 책임자가 다르다."* sticky 밴드 미사용
- 히어로 타일에 **"Held by {이름}"을 처음부터 인쇄** — 숫자와 사람이 스크롤 전에 이미 붙어 있어야 한다
- 원칙 섹션 **흑백 반전 2단** — 하는 것=흰 판 / 거절하는 것=stone-900 검은 판. 페이지 유일한 어두운 면이 "거절"이다
- 연혁 항목마다 **선택 지표의 당시 수치** + 수행자. 지표를 바꾸면 6개 항목 숫자가 전부 바뀐다
- 궤적 차트는 생성형 SVG, **직선 구간**(스플라인 아님) — 스무딩은 측정하지 않은 중간값을 지어낸다
- 원격 이미지 0장. 팀은 이름 파생 결정론 각인 SVG — 스톡 얼굴이 실제 책임 주장 밑에 깔리면 안 된다

### ⑤ 접근성·기술
- 라이브 리전은 지표 타일이 아니라 **링크 문장 하나**에만 `role="status"`(`pos-pricing` 선례)
- 선택 상태를 색 + 문구("Track this"↔"Tracking") + 아이콘으로 — 색만으로 의미 전달 금지
- 차트에 `sr-only <table>`(6년 수치, caption·scope) + 카드에 `relative`(클리핑 컨테이너 함정 예방)
- **`details/summary` 대신 `button` + `aria-expanded`** — `auto-about-r2` 함정(마커 제거 후 대체 아이콘 없음)을 **회피가 아니라 제거**로
- **`dark:` 변형 0개**, 루트에 `bg-stone-50 text-stone-900` 명시 — `no-dark-dim-text`를 부재로 충족
- 진입 연출은 **정지 상태가 완성 상태** — JS·옵저버 없이도 보인다. 흔한 `opacity-0 + is-visible` 패턴은 "진입 opacity:0 잔존 금지" 위반
- 천단위 구분 수기(`Intl` 미사용 — 하이드레이션 로케일 드리프트) · SVG 좌표 소수 2자리

## 8. 이번에 새로 드러난 것

**designer가 보고 직전 중단이 재현 4회째다.** POS 3회 + 이번 1회. 이번에도 **조각 컴포넌트 5개를 다 만들고 `page.tsx`와 셸만 없었다** — POS 1회차와 같은 지점이다. §3 완료 확인이 네 번 다 잡았으나, 매번 한 번씩 더 돌리는 비용이 든다.
