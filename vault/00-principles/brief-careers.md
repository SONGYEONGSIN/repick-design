# 타입 프로파일 — `careers` (채용 페이지)

> 전 타입 공통 규칙은 [[page-brief-core]]. 이 문서는 채용 페이지 고유 기준만 정의한다.
> 초안 출처: `auto-careers-r1`·`r2`·`r3` 세 라운드의 판정(2026-08-06~08-08). 이 타입은 **읽는 사람이 자기가 여기 맞는지 판단하고 지원까지 가는** 화면이다 — [[brief-catalog]]가 물건을 좁히게 한다면, 이쪽은 **사람이 자기를 좁힌다**.

## 0. 인접 타입과의 관계

| 인접 타입 | 채용에서 다른 점 |
|---|---|
| [[brief-catalog]] 필터→결과 목록 | 골격은 같으나 **결과가 0건이면 안 된다** — 카탈로그는 "없음"이 정상 응답이지만 채용에서 빈 목록은 회사가 안 뽑는다는 뜻이 된다 |
| `about` (회사 소개) | 컬처·가치를 다루는 구간이 겹친다. 채용은 그것이 **공고에 종속**돼야 한다 — 컬처만 있고 공고가 없으면 about의 재탕이다 |
| [[brief-profile]] 신뢰 통계 상시노출 | 그 자리를 **오픈 롤 인벤토리**가 차지한다 — §2 |

## 1. 페이지 구조 (필수 요소)

1. **오픈 롤 인벤토리** — 실제 공고 목록. §2의 하드 기준 대상
2. **좁히는 수단** — 팀·지역·고용형태 중 최소 하나의 축. 필터·검색·탭 무엇이든
3. **역할 상세** — 책무·자격요건. 드로어·마스터디테일·인라인 디스클로저 중 택일
4. **일하는 방식** — 컬처·원칙·프로세스. 공고에 붙어 있어야 한다(§0)
5. **조건** — 보상·베네핏·근무지. §2의 보상 축 규정 대상
6. **지원 경로** — 각 공고에서 도달 가능해야 한다

## 2. 이 타입의 핵심 판정 기준

- **오픈 롤 상시노출 (하드)** — 부서·카테고리 접기 UI를 쓰더라도 **최소 하나의 클릭 불필요 경로로 실제 공고 제목이 보여야** 한다. 전 그룹 기본 접힘은 위반이다.
  근거: `auto-careers-r1`에서 렌즈2가 c(Northlane)를 부서 그룹 5개 전원 `expanded[slug]=false` 때문에 최하위로 판정했고, 이후 **r2·r3 여섯 후보 전원이 자발적으로 준수**해 세 라운드 동안 이 축에서 결함이 재발하지 않았다.
  > 재현의 성격에 주의: [[brief-profile]] §2와 같은 유형이다 — **"위반이 재발해서"가 아니라 "패턴이 유지돼서"** 정착했다. 위반 카운터가 오르지 않으므로 자동 승격 경로로는 L1에 머문다. 이 절은 그 관측을 사람이 읽고 계약으로 고정한 것이다.

- **보상은 축과 계산 방식을 먼저 정한다** — 보상을 실으면 **① 입력 축이 무엇인지**(연차 / 부서 / 지역 / 레벨) **② 조회인지 산술인지**(고정 밴드 룩업 vs 입력값으로 계산) 둘 다 페이지에서 읽혀야 한다. 축 없이 숫자만 두면 근거 없는 주장이 되고, 산술인데 근거를 안 보이면 검증 불가한 계산기가 된다.
  근거: 브리프가 이를 규정하지 않아 세 라운드에서 구현이 흩어졌다 — `r1/c` 정적 보상 밴드 · `r2/b` 레벨 range 슬라이더 · `r3/b` 부서×연차 2축 룩업 테이블 · `r3/c` 연차×팀·지역 2축 실산술. 형태가 달라도 좋으나 **비교할 기준이 없어** 렌즈가 매번 다른 잣대를 들었다. 보상을 **싣지 않는 것도 유효한 선택**이다(`r1/a`·`r3/a`가 그랬고 둘 다 승자다) — 다만 그때는 §1-5를 근무지·베네핏으로 채운다.

- **공고 수와 구체성이 함께 가야 한다** — 공고가 적으면 목록 UI가 과잉이 되고, 많은데 카피가 뭉뚱그려지면 필터가 무의미해진다.
  근거: `auto-careers-r1` 렌즈2가 승자 a의 카피 구체성을 근거로 들었다 — 12개 역할 각각이 실제 업무를 특정하는 문장을 갖고 있었다.

> **미종결 관찰(L1, 정본 아님)**: `careers-deltas-provisional.jsonl`에 3건이 열려 있다 — 4열 이상 `table-fixed`의 390px 크로우딩, 오피스축 탭리스트+2차 시각화 결합의 우위, 그리고 위 오픈롤 계약. 전부 재현 1회라 **판정 기준으로 쓰지 않는다.** 다음 라운드가 반증할 몫이다.

## 3. 레이아웃 아키타입 (라운드 내 중복 금지)

r1~r3이 소진한 여섯 형태 — 새 라운드는 이 목록 **밖**에서 시작한다:

- **서사 셸 + 칩필터 리스트 + 포커스트랩 드로어** (r1/a)
- **라이브 콤보박스 검색 + 정렬 가능 베네핏 테이블** (r1/b)
- **FAQ 아코디언 + 부서별 접기 그룹** (r1/c)
- **정렬 가능 시맨틱 롤 테이블 + 탭리스트 프로세스** (r2/a)
- **체크박스 다면필터 + 카드 인라인 디스클로저 + 레벨 슬라이더** (r2/b)
- **오피스·지역 탭리스트 주축 + 탭 종속 데이터 시각화** (r3/a)

## 4. 인터랙션 (최소 3종)

팀·지역 필터 · 검색 · 역할 선택 → 상세 · 보상 축 조작 · 지역/오피스 전환 중 **3개 이상**. 전부 `'use client'` 실동작 + 결정론 + `motion-reduce` 게이팅.

## 5. 스크롤 연동 연출

[[brief-catalog]] §5와 동일한 제약으로 허용. §2의 오픈 롤 상시노출을 스크롤 연출로 대체하려는 시도는 금지다.
