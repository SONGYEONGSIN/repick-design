# SaaS 대시보드 — 브리프 v3 (서비스급 · 사용자 피드백 반영)

**목표: 실제 상용 SaaS(Mercury, Monarch, Asana, n8n, Calendly, Coinbase, Cycle 수준)의 프로덕트급 대시보드.**
제품·브랜드는 자유 발명하되, 디자인은 "아트 컨셉/세계관 연출"이 아니라 **매일 쓰는 상용 서비스의 정제된 완성도**다.

## 사용자 피드백 (v2 세대 전원 탈락 — 원인 3가지, 반드시 교정)

1. **가짜 라이트 금지**: 크림·페이퍼·세피아 배경(#F4EFE6류) + "지면/서식/카탈로그" 연출은 라이트 테마가 아니다. **진짜 라이트 = 순백 기반** — `bg-white` / `zinc-50` 캔버스, `zinc-100~200` 헤어라인 보더, 미세한 섀도. Mercury·Asana·Calendly의 라이트를 떠올려라.
2. **세계관 연출 → 프로덕트 정제로**: 레지스트레이션 마크·재단선·타이틀블록·스탬프·베젤 같은 스큐어모픽 연출 금지. 완성도는 **컴포넌트 시스템의 정밀함**(일관된 radius/border/shadow/spacing, 정돈된 테이블, 정확한 정렬)에서 나온다.
3. **폰트 통일 (꼼꼼히)**: 페이지 전체에 **Pretendard(전역 font-sans) 단일** + 숫자/코드/ID에만 `tabular-nums`(필요시 Geist Mono는 코드·해시 등 진짜 코드성 데이터만). **세리프·디스플레이·장식 폰트 일절 금지. next/font 추가 import 금지.** 통화 ₩는 Pretendard tabular-nums로(모노에 ₩ 글리프 없음 — 크래프트 노트).

## 테마 (배정된 것)
- **라이트**: 흰 캔버스(white/zinc-50), 카드 white + `border-zinc-200` + `shadow-sm`, 텍스트 zinc-900/600/500, 강조 1색(indigo/blue/emerald 등 채도 절제). 다크모드 대응은 `dark:` variant로 함께(선택).
- **다크**: 정제된 프로덕트 다크(n8n/Coinbase류) — zinc-950/900 계열 표면, 보더 `white/10`, 텍스트 zinc-50/400, 강조 1~2색. 연극적 발광·스캔라인·그레인 금지.

## 참조 카탈로그 (결정 규칙 — 20-catalog, 복사 금지·링크 참조)
생성 시 아래 정량 카탈로그를 씨앗으로 읽는다. 단 **anti-slop 필터 우선** — 카탈로그 추천값이 본 브리프/[[design-principles]] 금지 항목과 충돌하면 브리프가 이긴다.
- [[charts.catalog]] — 도메인 시각화(§에셋) 선택: 데이터 타입 → 차트 + a11y 등급 + 데이터 볼륨 임계(SVG↔Canvas) + 필수 폴백. **라이브러리 추천 무시, 생성형 SVG 우선**.
- [[colors.catalog]] — 테마 토큰(§테마): AA 보정된 shadcn 18슬롯 팔레트 뱅크. **단일 액센트 원칙 + 틴트 배경은 순백 교체**.
- [[ux-guidelines.catalog]] — a11y/인터랙션 체크리스트(§완성도·§하드제약 재확인용, severity 포함).
- [[motion.catalog]] — 모션(§에셋·인터랙션): 강도 티어·듀레이션·이징 taxonomy. **dash는 dash 열 ✅/△만**(연출·시차·scrub·발광 ❌), 결정론 CSS + `motion-reduce` 게이팅.

## 완성도 기준 (Ridge /dash-rg 에서 검증된 문법 — 전부 적용)
- **앱 셸**: 좌측 사이드바(브랜드 락업 + 워크스페이스 스위처 + 섹션 구분 nav(lucide 아이콘·활성 pill) + 하단 유저) + 상단바(글로벌 검색 ⌘K 버튼 + 주요 액션 버튼 + 알림 + 아바타 메뉴). 모바일은 드로어. 헤더 컨트롤 높이 44px 통일.
- **컴포넌트 시스템**: Card(일관 radius/border/shadow/padding), 정렬 가능한 데이터 테이블(hover 행·상태 배지·아바타 셀·aria-sort), 탭, 세그먼트 컨트롤, 드롭다운/팝오버, 배지, 프로그레스, 스파크라인. 로컬 파일로 분리 구조화.
- **인터랙션 (서비스급 — 최소 4종, §에셋·인터랙션 참조)**: ① 차트 호버 크로스헤어 툴팁(키보드 접근 포함) ② 테이블 실제 정렬/필터 ③ 기간/뷰 토글 ④ 선택→다중 위젯 동기화 ⑤ ⌘K 커맨드 팔레트(여력 시) 중 4개 이상. 전부 `'use client'` 실동작.
- **레이아웃**: 뷰포트 꽉 채움(콘텐츠 유동, 과한 max-w 금지, 초광폭만 완만 cap), 명시적 12-col 그리드(8/4 등), 4/8px 간격 리듬, 그리드 아이템 `min-w-0`(모바일 가로 오버플로 방지), 반응형(KPI 4열은 xl부터 등).
- **타이포**: 페이지제목/섹션/카드제목/본문/캡션/데이터 위계 명확, 숫자 전부 tabular 우측정렬, 레이블 11px uppercase tracking 통일.
- **데이터**: 현실적·결정론적 더미(Math.random/Date.now 금지), 합계 정합(부분합=총합), Intl 포맷.
- **상태 분기 대비**: 정적/Lighthouse 하드게이트는 기본 렌더 뷰만 스캔한다 — 필터·토글로만 도달하는 보조 상태(미배정·우선순위 없음 등) 텍스트도 대비 규칙(다크 보조텍스트 zinc-400 미만·라이트 zinc-500 미만 금지) 동일 적용. 모든 상태 분기 토큰 점검. (auto-dash-r2/r4 3회 재현 → L3 편입)
- **단일 지배 시각화 완성도**: 대표 시각화의 상용 완성도는 인코딩 차원 수가 아니라 at-a-glance 즉시가독에서 온다 — 핵심 값을 상시 텍스트로 병기(hover 전에도 보이게), 산점도류도 예외 아님(값 안 보이면 감점). 아키타입 신규성과 상충 시 브리프+완성도 다수결 우선. (auto-dash-r7/r9/r10 재현 → L3 편입)

## 에셋·인터랙션 (서비스급 절제 유지, 밀도 상향)
- **생성형 SVG/CSS 적극**: 도메인 고유 시각화(오실로스코프·간트·헥스맵류)를 코드 생성형 SVG/CSS(패턴·마스크·그라데이션·블렌드)로 더 풍부하게. 외부 파일 0, 결정론 유지(삼각함수 좌표 소수 2자리).
- **이미지 규율**: 아바타·썸네일 등은 원시 `<img>` 금지 → `next/image` `<Image>`(고정 URL·`width/height` 또는 `fill`·`alt` 필수, `unoptimized` 금지). 비결정 선택(Math.random 인덱싱) 금지.
- **인터랙션 최소 4종**(기존 3종에서 상향): 크로스헤어 툴팁·실제 정렬/필터·기간/뷰 토글·선택→다중 위젯 동기화·라이브 미니 차트 중 4개+. 전부 `'use client'` 실동작 + 결정론(step 카운터·state 구동) + `motion-reduce` 게이팅.
- **금지 유지**: 연극적 발광·스캔라인·그레인·글로시 장식은 여전히 금지(서비스급). 모션은 정보·전환에 기여할 때만 — 의미없는 데코는 감점.

## 하드 제약
- **카피 언어: 영문 전용** — 모든 UI 텍스트·헤딩·브랜드·라벨·더미 데이터는 영어. 한글·혼합 금지(글로벌 SaaS 벤치마크 정합). 한 페이지 내 한/영 혼용은 결함.
- Next.js 16 App Router, Tailwind v4, TS. 배정 경로 page.tsx(+client 컴포넌트 분리), default export.
- 접근성: 단일 h1, 헤딩 스킵 금지, 시맨틱 테이블(caption/scope), 포커스 가시(outline-none 단독 금지), 대비 AA, 색+텍스트 병행, 키보드, reduced-motion(CSS 미디어쿼리 게이팅, 진입 opacity:0 잔존 금지).
- `cd app && npx next build` 통과. 자기 폴더만 작업.
- lucide-react 아이콘 전면 사용(이모지·CSS 도형 금지). 아바타 필요시 실존 Unsplash ID 소량.
- SVG 삼각함수 좌표 소수 2자리 반올림(하이드레이션).

## 추가 학습 (라운드 3 피드백)

### 레이아웃 아키타입 다양화 (필수)
"좌 사이드바 + KPI 4장 가로줄 + 8/4 차트+사이드 + 풀폭 테이블"은 하나의 아키타입일 뿐이다. 같은 세대 안에서 구조가 겹치면 실패. 서비스급을 유지하되 구조를 다양화하라:
- **마스터-디테일**: 좌측 목록 레일(항목 리스트) + 우측 상세 (Linear/Superhuman식)
- **3-페인 마켓**: 좌 워치리스트 레일 + 중앙 대형 차트 + 우 상세/피드 (트레이딩 터미널식)
- **피드 중심**: 중앙 실행/활동 스트림 + 양옆 보조 패널
- **캘린더/보드 중심**: 대형 캘린더·칸반이 화면 주인공
- KPI도 4카드 가로줄만이 아니라 히어로 숫자+보조 지표, 인라인 스탯 등 변주.

### 그리드 크래프트 룰 (스크린샷 검수에서 잡힌 실결함 — 재발 금지)
- **테이블은 카드 안에 수납**: 데스크톱 기준 카드 폭 안에 모든 열이 들어가야 함. 마지막 열(상태 배지)이 잘리거나 카드 내 가로 스크롤바가 보이면 실패. min-w는 정말 필요한 만큼만.
- **날짜/수치 열 줄바꿈 금지**: `whitespace-nowrap` — "7월 15일"이 두 줄로 꺾이면 실패.
- **차트는 실제 렌더를 눈으로 확인**: 간트/타임라인 막대가 안 그려지는 채로 제출 금지. Playwright/puppeteer 스크린샷으로 막대·라인이 실제 보이는지 검증.
- **행 높이·카드 높이 균형**: 나란한 카드의 콘텐츠 양 차이가 크면 긴 쪽은 max-height+내부 스크롤 or "더 보기", 짧은 쪽은 여백이 뜨지 않게 배치 재조정.
- **말줄임 최소화**: 제목이 "...로 절반쯤 잘리면 폭 배분이 잘못된 것. 2줄 clamp나 열 폭 재배분으로 해결.

### 그리드 검증 룰 v2 (라운드 4 피드백 — 단일 폭 검증 금지)
- **1440px 한 폭에서만 검증 금지.** 사용자 환경은 클래식 스크롤바(뷰포트 유효폭 -15px)·임의 창 폭이다. 1280/1366/1440/1600/1920 전 구간에서 카드 수납을 확인하고, **여유폭 ≥16px** 없이 "딱 맞음"(1px 마진)은 실패로 간주.
- **데스크톱 테이블은 가로 스크롤바 금지** — min-w 강제 대신 `table-fixed`+% 열 배분으로 유동화. 배지/라벨이 길어 안 들어가면 축약 라벨을 설계한다("WITHIN"→"PASS" 등). 로컬 가로 스크롤은 모바일 전용.
- **멀티 페인 레이아웃은 레일 고정폭 + 메인 flex-1 min-w-0** — 메인이 레일보다 좁아지는 비율 붕괴 금지. 히어로 숫자는 반응형 클램프+수납 안전망.
- **스크롤 페이드/힌트 오버레이는 실제 스크롤 가능할 때만 표시**(스크롤 위치 기반) — 항상 떠 있는 그라데이션 띠는 얼룩으로 보임.
- **이중 스크롤바 노출 주의** — 내부 스크롤 영역은 thin 스크롤바 + 페이지 스크롤과 겹쳐 보이지 않게 셸 설계.
