# Candidate a — r33

**Concept:** A central hub holding the live AI match score, orbited by five criteria whose literal distance from the hub (not a bar, not an arc) encodes their current weight — move one weight slider and the other four orbits renormalize against a fixed 100-point budget, with the resulting score and leading criterion carried through the value section into the closing CTA's own sentence and button label.

## 브리프에 없던 것

- **Which 5 criteria, and their default weights/scores**: brief named "e.g. Style match, Size fit, Budget fit, Condition grade, Seller trust" as an example, so I used exactly those five. Default weights (Style 24 / Size 20 / Budget 18 / Condition 22 / Trust 16, summing to 100) and the featured listing's per-criterion scores (94/89/81/96/99) are both arbitrary but chosen so the default composite rounds to a clean 92 and the default leading criterion (Style) isn't the same as the highest base score, so moving the sliders visibly changes which orbit is "best" rather than always confirming the same one. Lives in `orbit-math.ts`/`data.ts`.
- **Control shape and renormalization rule**: brief allowed slider/dial/stepper; I used five native `<input type="range">` sliders (step 5, clamped 10–60 each) because they're natively keyboard-operable with zero extra a11y work. The zero-sum rule: moving slider *i* to value *v* sets weight_i = v, and the remaining `100 - v` is split across the other four **in proportion to their own default shares** (not their current values), using the largest-remainder method so the five integers always sum to exactly 100 — deterministic and reproducible from `(activeIndex, activeValue)` alone, no feedback loops between sliders.
- **Radius mapping**: linear interpolation from weight∈[10,60] to radius∈[176,86] SVG user-units (higher weight → smaller radius). Node size also scales 6–16 user-units with weight as a redundant (non-required) visual cue. The whole orbit visualization is `aria-hidden` — every number it shows is independently stated by the accessible hub text and the five range inputs' labels/aria-labels, so hiding the decorative SVG costs no information.
- **Motion gating without JS media-query checks**: rather than inline `style.transition` (which would be unbeatable by a CSS `prefers-reduced-motion` override, since inline styles always win over stylesheet rules), the orbit's radius/position/color transitions live in CSS classes in a scoped `<style>` block, overridden to `transition: none` inside `@media (prefers-reduced-motion: reduce)`. This is a user-triggered drag response, not an autoplay loop, but it's gated anyway to satisfy the rule literally.
- **The "real derived value" for the Value 3-split**: composite score (live) and a "catalog clears" count — `round(312 × (score/100)^2.2)` — are both pure functions of the live score, computed in `orbit-math.ts`, not a static lookup table. The third column is the live ranked list of all five criteria by current weight, i.e. the same ordering the orbit rings are drawing. I deliberately did **not** let the slider state change the featured listing's actual before/after price — a listing's real price shouldn't visibly move because a visitor reweighted trust vs. style, so only the *score and framing* around it are live, keeping the "never claim an unperformed side effect" rule intact.
- **Accent hue — orange family, computed** (base `#FF6A33`, tint `#FFA177`, fill `#C8431F`, all against bg/ink `#0B0B0F`):
  - `accent` (`#FF6A33`) — large text/icons/borders/bars at rest: vs white **2.85:1**, vs dark ink **6.89:1**. Reserved for large text (hub score border, icons) and non-text strokes; never small body text, by rule, even though it would technically clear 4.5 against the dark bg — kept to the brief's letter.
  - `accent-tint` (`#FFA177`) — small text/icons/focus rings: vs white **1.98:1**, vs dark ink **9.93:1**. This is what every small accent-colored label, the "N%-led" hub caption and the focus outline actually use.
  - `accent-fill` (`#C8431F`) — solid button/badge fill paired with **white** text per the fill rule: vs white **4.91:1** (clears AA for the button labels and match-% badge at 12–15px), vs dark ink **4.00:1** (clears the 3:1 non-text/UI-component floor against the page background it sits on). Chose a visibly deeper/redder shade than the base specifically so white text on it would clear 4.5 — the base `#FF6A33` only gives white text 2.85:1, which fails.
  - Deliberately not amber (too yellow, over-represented), not teal (not orange), not lime (used last round, also not orange) — picked a true red-orange so it reads unmistakably different from the catalog's amber family at a glance.
- **Line-length arithmetic (0.44em, no `ch`)**: body paragraphs sit at `max-w-[480px]`–`[500px]` against 16–17px type: 500 ÷ (0.44 × 16) ≈ 71 chars/line; 480 ÷ (0.44 × 17) ≈ 64 chars/line. Both under the 75-char ceiling, near the ~70 target.
- **Exactly 3 rendered weights**: `font-normal` (400, Tailwind preflight default on body copy), `font-semibold` (600, labels/badges/CTA text), `font-extrabold` (800, all headline/display and the hub/stat numbers). No `font-medium`/`font-bold`/`font-light` anywhere in the route; SVG `<text>` (orbit node labels) is exempt per the brief and isn't counted.

## SSR / hydration-gating check

`Reveal.tsx` gates `whileInView`/`initial={{opacity:0}}` on `useMounted()` (a `useSyncExternalStore` returning `false` on the server), used on every section except the Hero — the Hero (headline, CTA, orbit, featured-listing proof) has no reveal wrapper at all and is fully visible, fully interactive, and fully accurate (real score, real grade, real verified badge, real before/after price) on first paint with zero scroll. Verified with `npx tsc --noEmit` (0 errors in the folder) and `npx eslint` on the folder (0 errors/warnings). The orbit's own radius/position CSS transitions are reduced-motion-gated via a stylesheet `@media` rule rather than inline styles, specifically because inline `style.transition` cannot be overridden by any later CSS rule regardless of specificity or media query.
