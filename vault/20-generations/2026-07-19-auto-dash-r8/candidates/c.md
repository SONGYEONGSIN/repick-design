**Canopy — Org & Capacity Intelligence** (`/dash-evolve/r8/c`). People-ops SaaS dashboard for team-capacity planning. The dominant, screen-owning visualization is a top-down branching org tree for a fictional customer "Solace Systems": company root → 4 division nodes → team leaves (asymmetric depth — Engineering and Go-to-Market branch into sub-teams, Product & Design and Operations & People terminate at division level), rendered as deterministic HTML node-cards over an SVG connector layer (smooth cubic-bezier parent→child paths, all coordinates precomputed from a leaf-order layout algorithm and rounded to 2 decimals). Headcount subtotals are derived bottom-up so parent totals always equal the sum of children (company = 143, verified in rendered output); utilization is a headcount-weighted average, not hand-typed. The canvas scales via SVG viewBox + percentage-positioned nodes (same technique as the existing `r6/a/DagCanvas`), so its authored width (872px) sits safely under real desktop card width at every tested breakpoint — confirmed with an actual `dash-sweep.mjs` Playwright run against the live route: `{"pass":true,"failures":[]}` across 1280–1920px (± 16px slack) and 390px mobile, zero page- or container-overflow.

Interactions (5, all `'use client'`, keyboard-operable, `motion-reduce`-gated): (1) **selection sync** — clicking/keyboard-selecting a tree node highlights its ancestor connector path, opens a slide-over detail drawer (breadcrumb nav, utilization sparkline, direct-reports list), and highlights the matching Roster table row; the table and ⌘K palette can also drive the same selection; (2) **real table sort + filter** — Roster table with `aria-sort` columns and a status segmented-control filter (Healthy/At-Risk/Overloaded); (3) **view/metric toggle** — segmented control switches every node's color+bar encoding between "가동률" (utilization, status-tone bars) and "헤드카운트" (headcount, teal-intensity bars normalized per tree level), so both dimensions stay legible at a glance without hover, per the at-a-glance-over-cleverness lesson; (4) **⌘K command palette** searching teams/leads; (5) **hover + keyboard-focus tooltip** on tree nodes (not just mouse), plus roving-tabindex arrow-key tree navigation (Up=parent, Down=first child, Left/Right=siblings, Enter/Space=select).

Font: global Pretendard (`font-sans`) only, no `next/font` import, no serif/display fonts; all counts/percentages use `tabular-nums` + `Intl.NumberFormat`. Light = white/zinc-50 canvas with `zinc-200` hairlines and `shadow-sm`; dark = zinc-950/900 with `white/10` borders; caption text is `zinc-500`/`zinc-400` paired correctly per surface in every state (default, filtered, hovered) — verified by source grep, no bare `zinc-400`-on-light or `zinc-500`-on-dark. Roster table is `table-fixed` + `colgroup` % columns with `min-w-[760px] lg:min-w-0` (mobile-only horizontal scroll); the `sr-only` table caption is on `<caption>`, never on `<table>` itself. Header controls (⌘K trigger, icon buttons, primary action, workspace switcher) are each individually `h-11`. Current-user persona is fictional (Whitney Solano, whitney.solano@solacesystems.io) — no session/environment data leaked. Avatars use fixed, hand-picked real Unsplash photo IDs via `next/image` (no `unoptimized`, explicit width/height, alt text).

Structurally distinct from the exclusion list: no master-detail persistent 2-column split (the detail panel is a transient slide-over that opens only on selection), no 8/4 chart+sidebar KPI-row layout (metrics are inline stat chips folded into the tree card's own header, not a separate KPI card row), no DAG/lanes, no radial/orbit, no treemap, no kanban/calendar/feed/spreadsheet/leaderboard/heatmap shapes — a strict parent-child branching hierarchy tree is the sole screen-owning archetype.
