# a — Halyard Media Kit

**컨셉 1줄**: 자산 목록을 "무엇을 받을 수 있나"가 아니라 **"이 배경 위에 놓아도 되는가"**로 재편한 명세표 — 표면을 바꾸면 각 자산의 승인/불승인과 대체 지시가 즉시 판정된다.

## 이 타입을 무엇으로 정의했나 (`media-kit`)

`about`은 우리를 **읽게** 하고, `media-kit`은 남이 우리를 **정확히 재현하게** 한다. 그래서 이 타입의 1급 콘텐츠는 자산 자체가 아니라 **자산에 붙은 조건**(포맷·최소 크기·여백·허용 배경)과 **오용 사례**다. 다운로드 링크 한 줄이 아니라 **명세표**이고, 성공 기준은 "예뻤나"가 아니라 **"기자가 이걸 보고도 틀리게 쓸 수 있나"**다.

- 페이지 구조: 헤더(아카이브 메타 4항) → 표면 프리뷰 무대 → 자산 매니페스트 표(6종·5열) → 색(표면 5 + 잉크 전용 1) → 활자 3면 → **오용 6종** → 연락
- 자산은 전부 **생성형 SVG**로 직접 그렸다(포스트 2개 + 뒤로 지나가는 할리어드 선 + 매듭). 원격 이미지도 `next/image` 대상 파일도 없다 — 이 타입에서는 그게 자연스러운 해법이다

## 조작 어휘 — 배경 전환 (배정 준수)

조작은 항목을 켜고 끄지 않는다. **자산이 표시되는 맥락**만 바꾼다.

1. **표면 스와치 5종** (Paper White / Mist Grey / Haze Blue / Signal Blue / Ink Black) — 무대 배경이 바뀌고 잉크·액센트가 표면에 맞춰 반전된다
2. **매니페스트 행에서 자산 선택** — 표의 자산 이름이 곧 무대 로더. 토글이 아니라 단일 선택(`aria-current`)
3. **배율 1x / 2x / 4x** — 확대 시 **여백 가이드(파선 프레임)가 자동으로 나타나** 배율이 스펙을 드러낸다. 슬라이더 아님(3단 버튼)
4. **색 섹션 칩 → 무대 채택** — 색을 추상적으로 승인하지 않고 항상 특정 자산 밑에 깔아본다

## 3렌즈 — 핵심 증명은 조작 없이 읽힌다

기본 상태(Primary lockup × Paper White × 1x)에서 이미: 매니페스트 표 6행이 포맷·최소 크기·**허용 배경 칩**·용도를 전부 노출하고, 오용 6종이 그림과 규칙으로 정지 상태로 서 있다. 조작은 판정을 **확인**시키지 증명을 **대체**하지 않는다.

## 브리프에 없던 것

① **"승인 배경"이 데이터가 되면 조작이 검증 장치가 된다.** 브리프는 배경 전환을 *미리보기* 어휘로 줬지만, 자산마다 `approved: SurfaceId[]`를 두는 순간 배경 전환은 미리보기를 넘어 **판정기**가 된다 — App icon을 Signal Blue에 놓으면 "Not cleared" + 대체 지시(심볼을 써라)가 나온다. 조작이 장식이 아니라 **규칙의 실행**이 되는 경로. 다른 타입에도 이식 가능: 조작 축을 데이터의 제약 축과 일치시켜라.

② **확대 배율이 스펙을 드러내는 자리로 쓰인다.** 배율을 단순 돋보기로 쓰면 인터랙션 수만 채운다. 2x 이상에서 여백 가이드를 자동으로 띄우면 "clear space = 1 post width"라는 **표 안의 죽은 문자열이 눈에 보이는 치수**가 된다. 파생 표시(자동)라 토글 금지 규칙도 건드리지 않는다.

③ **금지 사례에 빨강을 쓰지 않는 편이 더 명세서답다.** 오용 카드에 red/rose를 쓰면 즉시 경고 UI의 클리셰로 떨어지고, 색만으로 의미를 전달할 위험도 생긴다. `Ban` 아이콘 + "Don't" 라벨 + **위반을 실제로 그린 SVG**만으로 충분했고, 오히려 브랜드 시트의 톤과 맞았다. 금지 표현의 기본값은 색이 아니라 **그림**이다.

## 남은 질문

- 매니페스트 표의 "Cleared surfaces" 칩과 무대의 판정이 같은 사실을 두 번 말한다 — 중복인가, 필요한 이중화인가(표는 훑고 무대는 확인한다)
- 실제 zip 파일이 없는 상태에서 다운로드 어포던스를 뺀 판단 — `media-kit` 프로파일이 생기면 "파일 없는 자산 명세"의 표준 처리를 정해야 한다
