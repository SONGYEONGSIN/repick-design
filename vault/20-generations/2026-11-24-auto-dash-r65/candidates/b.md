# Candidate b — Harborwatch

Harborwatch is a trust & safety review console for a marketplace/social platform ("Northbridge Marketplace"), built as a genuinely feed-centric layout: a full-height central stream of flagged listings/posts/messages is the page's only "character," flanked by a 280px left panel (queue health: a hero "pending today" count, SLA-breach count, avg time-to-decision, and a category distribution bar chart) and a 320px right panel (reviewer leaderboard). There is no master-detail split — clicking a feed card only expands that card's own disclosure for extra detail (flag reasons, SLA target), never a separate pane, and every decision (Approve / Remove / Escalate) happens inline in the action row and mutates the feed and the left panel's live counts in place. Five interactions are wired: the inline triage actions, a severity segmented filter on the feed, a sortable `aria-sort` reviewer table (Decisions/Accuracy), a hover-and-focus-reachable inspector under the category chart that prints exact counts/percentages as text, and a bonus ⌘K command palette. Theme is a pure white/zinc-50 canvas with zinc-100/200 hairlines, a single `orange-700` accent hand-checked for AA on every text/fill use (white-on-orange-700 ≈5.2:1, orange-700-on-white ≈5.2:1), Pretendard throughout, and `--font-display-mono` reserved strictly for the "HARBORWATCH" wordmark and the hero pending-count stat.

## 브리프에 없던 것

- **① Content preview without photos.** The brief asked for "content preview" per item but didn't require real images. **②** I used an icon tile (listing/post/message glyph) plus the title + snippet text as the preview, no images at all. **③** This removes an entire class of risk (aspect ratio, `alt` text, remote hosting, `next/image` config) while still reading clearly as "a piece of flagged content," and keeps every item deterministic and self-contained.
- **① Severity color coding under a single-accent constraint.** The brief mandates one orange accent family, but severity usually reads via red/amber/green in most moderation tools. **②** I differentiated severity by *intensity* instead of hue — Critical is solid orange-700, High is a light orange-100/800 tint, Medium/Low drop to neutral zinc — never introducing a second hue. **③** This keeps the single-accent rule intact while still giving reviewers an at-a-glance severity scan.
- **① What the primary topbar action should be.** The shared shell requires a "primary action" button but the brief is silent on what it does for this domain. **②** I invented "New detection rule" — a small dialog to pick a flag category and an auto-assigned severity, which confirms what it created. **③** It's a plausible, domain-appropriate control for a T&S console (vs. a generic "Add" button) and gave me a second genuinely-wired modal beyond the required interactions.
- **① How to visually demote resolved items without the opacity/contrast trap.** The brief's own pitfall list flags `opacity-70` on "resolved/dimmed" feed items as a repeated contrast failure. **②** Instead of dimming, resolved items move into a "Resolved this session" sub-list with a solid `zinc-50` background and full-strength text color, plus a solid result badge (Approved/Removed/Escalated) replacing the action row. **③** This sidesteps the contrast-through-opacity failure mode entirely while still making resolved items read as visually "settled" versus the active queue above them.
