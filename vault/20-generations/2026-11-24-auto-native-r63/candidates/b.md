# Candidate b — Request Data Export

A privacy/account-settings screen that lists three fixed data categories (47 orders, 212 messages, 18 listings, all derived once in `data.ts` and reused by both the per-row count and the rolled-up intro sentence) plus a functional "What's included in the file" disclosure, and one inline "Request export" button — no bottom band of any kind, since there is no blocked/incomplete state to gate. Tapping the button is a one-way `ScreenState` transition ("ready" → "requested") that swaps the entire scrollable content for a terminal confirmation (reference number, fixed timestamp, delivery email) with no cancel and no way back. The confirmation's container is the only `accessibilityLiveRegion="polite"` in the tree, and only its headline sentence carries `accessibilityRole="alert"`, so the swap announces itself exactly once to screen readers. This follows the brief's sanctioned "no band, one global button, terminal full-content-swap" shape in the abstract, but uses entirely fresh naming, data, and layout from this domain.
