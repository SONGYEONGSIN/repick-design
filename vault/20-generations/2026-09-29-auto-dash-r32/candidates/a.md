# auto-dash-r32/a — Tripwire

**한 줄 컨셉**: repick 트러스트&세이프티 팀을 위한 사기/분쟁 감시 콘솔 — 10개 신호를 카드 하나가 아니라 "월(wall)"로 늘어놓고, 클릭한 카드가 그 자리에서 2칸으로 확장되며 전체 이력·근본원인·케이스를 드러내는 스몰-멀티플 라인+이상치 마커 대시보드.

- 아키타입: 스몰-멀티플 월(그리드 자체가 지배 시각화, 별도 레일/인스펙터 페인 없음) — 이 카탈로그 최초의 "많은 소형 패널이 곧 메인 이벤트"인 구성, r27의 KPI-4타일+8/4분할과도, r29c/r31a의 3페인 마켓과도 다른 셸.
- 테마: light(zinc-50/white + hairline) · 액센트: rose · 디스플레이 활자: `--font-display-grotesk`(h1 한 곳에만, font-semibold 600으로 고정)
- 인터랙션 6종: ① 크로스헤어 툴팁(마우스 hover + Tab 포커스 후 ←/→로 스크럽, 각 패널 로컬 `cursor` state) ② 실제 정렬 테이블(핀된 패널 내부 케이스 테이블, aria-sort) ③ 기간 토글(7/30/90d, 월 전체에 적용) ④ 핀→멀티위젯 동기화(클릭 시 그리드 안에서 2칸으로 인라인 확장, 전체 90일 이력+근본원인 브레이크다운+케이스 테이블 노출) ⑤ 카테고리 필터(핀과 무관한 두 번째 독립 축 — 필터가 핀을 절대 건드리지 않음) ⑥ ⌘K 커맨드팔레트(신호 검색→핀)
- 셀렉션 분리: `pinnedId`는 부모(client.tsx)의 영속 state, 크로스헤어 `cursor`는 각 `SignalPanel` 내부에만 존재하는 로컬 state — 두 값은 어떤 컴포넌트에서도 이름/타입을 공유하지 않으므로 r17→r19 계보의 "3곳 이상에 동일 prop으로 꿰인 selectedId" 패턴 자체가 성립하지 않음. 카테고리 필터는 핀에 필터를 되먹임하지 않고(핀된 신호는 필터에 안 걸려도 항상 보이도록 예외 처리), 핀도 필터를 리셋하지 않는 진짜 독립 축.
- 액센트 대비(WCAG 상대휘도 공식 직접 계산, 미추정):
  - rose-600(#E11D48) on white(#FFFFFF) = **4.70:1** (버튼의 흰 글자, 큰 UI/마커에 사용)
  - rose-600 on zinc-50(#FAFAFA) = **4.50:1** (경계선상이라 이 조합은 작은 텍스트에 안 씀 — 채움/버튼/배지 점만 용도 한정)
  - rose-700(#BE123C) on white = **6.29:1**, on zinc-50 = **6.03:1** (활성 내비 라벨·강조 숫자 등 작은 액센트 텍스트는 전부 700 사용)
  - rose-700 on rose-50(#FFF1F2, 배지 배경) = **5.73:1**

## 브리프에 없던 것

1. **"elevated" 판정 기준을 재정의했다.** 처음엔 `isCurrentlyElevated`를 "가장 최근 1일 값이 threshold 이상"으로 구현했는데, 스파이크를 종형(bell) 곡선으로 만들다 보니 90일차(가장 최근일)엔 모든 신호가 이미 감쇠해 있어 10개 전부 `false`가 나왔다 — 사기 감시 콘솔인데 헤더가 항상 "0 of 10 elevated"를 보여주는 건 서사적으로 이상하고, 기본 30일 윈도우에 보이는 다이아몬드 마커들과도 모순됐다. 브리프는 "elevated"의 정확한 정의를 안 줬으므로, 트레일링 30일 중 한 번이라도 threshold를 넘었는지로 바꿨다(고정 30일 — 화면의 기간 토글과는 별개라 토글을 바꿔도 배지가 깜빡이지 않는다). 결과: 4/10 신호가 elevated로, 기본 30일 뷰에서 실제로 다이아몬드가 보이는 신호들과 정확히 일치한다.
2. **핀된 카드가 "필터에 안 걸려도 항상 보이게" 만들었다.** 브리프는 카테고리 필터와 핀의 관계를 안 정했다. 처음엔 단순히 `categoryFilter==='all' || category===filter`로만 걸렀는데, 그러면 사용자가 필터를 바꾼 순간 지금 핀 중인 신호가 그리드에서 통째로 사라져 "영속 디테일 뷰"가 조용히 고아가 되는 문제가 생겼다. `|| s.id===pinnedId`를 추가해 핀된 패널은 필터와 무관하게 항상 그리드에 남도록 했다 — 두 축의 "독립성"을 지키되 사용자 경험상 핀이 먼저 깨지는 쪽을 택하지 않았다.
3. **케이스 개수·상태 분포 공식을 두 번 튜닝했다.** 처음 공식(`round(anomalyDays/6)`)은 이상 신호 6개가 전부 케이스 1개씩만 갖게 나와 정렬 인터랙션을 시연하기엔 행이 너무 적었고, 상태 사이클(`escalated,investigating,open`)이 우연히 age 순서와 정확히 같은 rank로 겹쳐서 "Status로 정렬"해도 화면이 안 바뀌는 문제가 있었다. `ceil(anomalyDays/3)`로 케이스 수를 늘리고(기본 핀 신호는 3건), 상태 사이클을 `investigating,escalated,open,escalated`로 재배열해 age 정렬과 status 정렬이 실제로 다른 순서를 만들도록 고쳤다 — 정렬 버튼이 클릭할 때마다 "진짜로" 재정렬되는지 직접 숫자를 계산해서 검증했다(`node -e`로 시드 공식 재현).
4. **JSX 속성 문자열 안의 HTML 엔티티 버그.** `placeholder="…&hellip;"`처럼 일반 문자열 속성에 `&hellip;`를 쓰면 JSX는 그걸 디코드하지 않고 리터럴 텍스트 `&hellip;`로 렌더링한다(엔티티 디코딩은 JSX children에서만 동작). 커맨드팔레트의 placeholder에서 이 실수를 했다가 잡아서 실제 말줄임표 문자(`…`)로 바꿨다. 같은 이유로 단위 문자열을 여러 파일에서 `formatValue(...)+signal.unit`로 그냥 이어붙이면 "2.17per 1k listings"처럼 공백 없이 붙는 걸 발견해 `formatWithUnit` 헬퍼(퍼센트는 공백 없이, 그 외 단위는 공백 삽입)를 새로 만들어 aria-label과 본문 텍스트에 일괄 적용했다.

## 불확실한 부분
- 차트의 얇은 회색 추세선(zinc-400, `#a1a1aa`)은 흰 배경 대비 3:1 그래픽 대비 기준을 정확히 만족하는지 계산하지 않았다 — 이상치는 다이아몬드(rose-600, 4.70:1 이상)와 텍스트 배지로 이미 색 비의존적으로 전달되므로 선 자체는 보조적이라고 판단했지만, 엄격한 자동 대비 검사기가 SVG `stroke`까지 스캔한다면 지적될 수 있다.
- 커맨드팔레트에 포커스 트랩(Tab이 모달 밖으로 못 나가게)은 구현하지 않았다 — 참고한 기존 카탈로그(`r29/c`)의 CommandPalette도 같은 수준(autofocus + Escape)이라 관행을 따랐다.
