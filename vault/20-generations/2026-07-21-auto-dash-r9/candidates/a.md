# r9 · candidate a — Redline (SLO & Error-Budget Console)

**Redline**은 SRE/플랫폼 팀을 위한 상용급 SLO·오류예산 모니터링 콘솔로, 배정된 **게이지/다이얼 콕핏 클러스터** 아키타입을 자동차 계기판 문법 그대로 구현했다: 화면을 지배하는 시각화는 산점도·트리·지도·바 차트가 아니라 대형 SVG 반원형(270°→260° 스윕) 게이지 5개의 비대칭 클러스터로, 왼쪽에 큰 히어로 게이지(Uptime SLO, 300px급)가 있고 오른쪽에 2×2로 배열된 중형 게이지 4개(Error Budget Burn, P99 Latency, Request Volume, Error Rate)가 붙는다. 각 게이지는 (1) 바깥쪽 얇은 "레드라인" 림 — good/warn/bad 3구간을 항상 색으로 표시(브랜드명 "Redline"이 문자 그대로 위험 구간 표시 문법), (2) 안쪽 굵은 아크가 현재 값까지 채워지는 진행 표시(fill-progress), (3) 중심 허브에서 뻗는 니들, (4) SLO 타깃 눈금선으로 구성되며, 좌표는 `polarPoint(cx,cy,r,angleDeg)` 극좌표 함수로 산출하고 전부 소수 2자리 반올림(하이드레이션 안전)했다. 게이지는 산점도(#18 오빗)처럼 점을 원 위에 배치하는 것도, 트리맵(#19)처럼 중첩 사각형도 아닌 "아크 채움 + 니들이 단일 값을 인코딩"하는 계기판 형식이며, 균일한 타일 그리드(#10 모니터링 타일월)와도 다르게 히어로 1개 + 보조 4개의 비균일 크기·비대칭 배치를 명시적으로 커밋했다.

**인터랙션 5종(브리프 최소 4종 상회, 전부 `'use client'` 결정론 + `motion-reduce` 게이팅)**: ① 게이지 호버/키보드 포커스 시 크로스헤어형 툴팁(`role="tooltip"`, 정밀 수치·존 상태·타깃 비교, Tab으로 포커스 가능·Escape로 닫힘) ② 인시던트 테이블 실제 다중 컬럼 정렬(`aria-sort`, Sev/Incident/Service/Started/Duration/Status) + 심각도 세그먼트 필터(All/SEV1-4) ③ 서비스 스코프(All+4개 서비스)·관측 기간(1H/24H/7D/30D) 두 종류의 세그먼트 토글 — 스코프 변경 시 게이지 클러스터·테이블·상세 패널이 동시 재계산 ④ 선택→다중 위젯 동기화: 서비스 pill 선택은 게이지+테이블 필터+디테일 패널 초기 선택을 동시에 갱신하고, 테이블 행 클릭은 우측 디테일 패널(요약·근본원인·서비스별 12틱 오류예산 스파크라인)을 갱신 ⑤ ⌘K 커맨드 팔레트로 서비스/인시던트 검색 후 선택 시 스코프+테이블+디테일 3중 동기화(Playwright로 실측 검증: "Payments CPU saturation alert" 선택 → scope=payments-svc, 테이블 3건으로 필터, 디테일 패널 제목 일치 확인).

**타이포/폰트**: 전역 `font-sans`(Pretendard) 단일, `next/font` 추가 import 없음, 세리프·디스플레이 폰트 없음. 숫자·ID·게이지 판독값 전부 `tabular-nums` + `Intl.NumberFormat`(우ptime은 99.99% 이상일 때만 소수 3자리로 전환하는 등 SLO 관례 반영).

**구조적 차이(제외 목록 22종 대비)**: 마스터-디테일(#9)처럼 좌측 전체 리스트 레일이 화면을 지배하지 않도록 서비스 선택을 가벼운 세그먼트 pill 행으로 축소하고, 화면 주인공은 어디까지나 상단 풀폭 게이지 클러스터 카드 — 그 아래 8/4 테이블+디테일은 "지지" 역할에 머문다. 트레이딩 터미널(#12)의 워치리스트+차트+상세 3열 레이아웃과도 다르게 좌측 고정 레일이 없다. BI 캔버스(#11)식 다위젯 대시보드도 아니고, 히트맵(#17)·펀넬(#20)·DAG(#15)·오빗(#18)·트리맵(#19) 어느 것과도 기하가 겹치지 않는다.

**품질/규정 확인**: `npx tsc --noEmit` 클린, 라우트 스코프 eslint 클린(0 error/0 warning). Playwright로 1280/1440/1920px 전 구간 문서·테이블 `scrollWidth`=`clientWidth`(오버플로 0px) 확인 — 1280px에서 초기 컬럼 배분(9/33/16/15/12/15%)이 SEV1 배지·"Investigating" 상태 배지에서 4~5px씩 클리핑되는 것을 실측으로 발견해 11/26/17/16/13/17%로 재배분 후 재검증 통과(그리드 크래프트 룰 실측 준수 사례). sr-only 서비스별 예산 추이 표는 `<table>`에 직접이 아니라 감싸는 `<div className="sr-only">` 안에 배치(과거 하이드레이션·오버플로 결함 재발 방지 델타 반영). 헤더 컨트롤(⌘K 트리거·모바일 메뉴·Export 버튼·알림/아바타 메뉴·모두 개별 `h-11`=44px). 대비 토큰은 라이트 표면 `zinc-500`+, 다크 표면 `zinc-400`+를 스코프·심각도 필터 등 모든 상태에서 일관 적용(Card/Badge/EyebrowLabel 등 공용 `tokens.ts` 상수 재사용으로 드리프트 방지). `CURRENT_USER`는 세션 컨텍스트와 무관한 가상 인물(Jordan Ellis, Site Reliability Lead, `jordan.ellis@redlinehq.io`, Unsplash 아바타)이며 실제 운영자 이메일과 무관함을 직접 대조 확인. 라우트는 `http://localhost:3100/dash-evolve/r9/a`에서 HTTP 200 확인(개발 서버 컴파일 후). 전역 `next build`는 이 샌드박스가 Google Fonts(`fonts.gstatic.com`) 네트워크 접근이 차단되어 다른 라우트가 쓰는 폰트들(Fraunces·Gaegu·Space Grotesk 등, 본 후보와 무관) 때문에 실패 — 본 후보는 전역 폰트 외 추가 폰트 import가 없음을 소스로 확인했다.
