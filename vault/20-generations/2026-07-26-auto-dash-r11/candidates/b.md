# Candidate B — Amberline (Revenue & P&L Bridge Cockpit)

**Product**: Amberline — a fictional finance-ops SaaS for subscription/SaaS businesses. Route: `/dash-evolve/r11/b`.

**Archetype**: Revenue / P&L Bridge Cockpit (assigned macro skeleton: hero number + single dominant chart). Inside the mandatory app shell (left sidebar with brand lockup/workspace switcher/nav/user, top bar with ⌘K search trigger + "New scenario" primary action + notifications + avatar menu, mobile drawer), a hero zone shows a large "Ending ARR" (or "Ending Seats") figure with an inline sparkline and three inline supporting stats (Net retention, Gross attrition, New business) — not a 4-card KPI row. Below it, the screen-owning visualization is a hand-authored SVG **revenue bridge / waterfall chart**: Starting ARR → New Business → Expansion → Reactivation → Contraction → Churn → Ending ARR (7 bars), with dashed running-total connectors between bars, a truncated-baseline "break mark" (⁄⁄) on the two total bars so period-over-period deltas stay legible, and — per the critical learned principle — **every bar shows its own signed value + directional icon as always-visible text**, never hover-only. Below the chart: a sortable/filterable per-segment driver table (Enterprise/Mid-Market/SMB/Self-serve × 5 delta steps, avatar cell, status-signal badge) whose four segment rows always sum exactly to that driver's bridge-bar value, plus a detail rail for the selected bar (top contributing accounts, segment lead).

**Interactions implemented (5, all `'use client'`, real state, no `Math.random`/`Date.now`)**:
1. **Bar selection** (click or keyboard) — selecting a bar updates a shared `selectedKey` that drives the detail rail (top contributing accounts + segment lead, computed via a deterministic proportional split that sums exactly to the bar's value) and highlights the matching rows in the driver table.
2. **Period toggle** (Monthly / Quarterly) — a real segmented control that swaps to a fully separate, hand-computed dataset (different start/end values, deltas, and driver splits), recomputing every bar height, running total, and hero stat. The two periods are chained on one real fiscal timeline (Jan 1 → Q1+Q2 quarterly bridge → Jun 30 → July monthly bridge → Jul 31) so the numbers agree at the seam.
3. **Metric toggle** (ARR $ / Seats #) — recomputes bar heights and all labels against a second reconciled dataset (seat-based bridge), demonstrating the chart isn't hardcoded to one unit.
4. **Table sort + filter** — clickable column headers with real `aria-sort` (ascending/descending/none, 3-state), plus a "Driver" filter dropdown; filtering to one driver reveals a subtotal footer row that reconciles exactly against that driver's bridge-bar value.
5. **Keyboard roving crosshair** — Left/Right (Home/End) arrow keys move focus across the 7 bars (single tab stop, roving `tabIndex`), and a `role="status" aria-live="polite"` readout above the chart always announces the focused/selected bar's value and running total — satisfying the keyboard-accessible crosshair requirement without a mouse-only hover tooltip.

A ⌘K command palette (Topbar trigger + global shortcut) additionally searches bridge bars and segments, jumping to the matching bar on select (reuses interaction 1).

**Typography/font**: Single global `font-sans` (Pretendard, inherited from the app's root layout — no additional `next/font` imports), `tabular-nums` on all currency/count/percentage figures. Copy is English-only throughout.

**Theme**: Banking/Finance palette from colors.catalog — light default is pure white/zinc-50 canvas, white cards, zinc-200 hairline borders; single UI accent = premium gold (`#A16207` family, on-accent white) used only for emphasis (primary button, active nav pill, focus rings, hero sparkline). `dark:` variants use zinc-950/900 surfaces with white/10 borders. The bridge's increase/decrease/total colors (emerald/rose/navy) are a separate data-encoding palette, not the UI accent, and are always paired with an arrow/equals icon and text — never color alone. Caption/secondary text never drops below zinc-500 (light) / zinc-400 (dark) in any state, including the mostly-"Contained"/"Steady" filtered table views.

**Data determinism**: every dollar figure is hand-computed so each bridge's start + deltas sum exactly to its end (verified in code comments), each driver's 4-segment split sums exactly to its bridge-bar magnitude via an exact-reconciliation split helper (round all but the last segment, last absorbs the remainder), and account-level contributions in the detail rail sum exactly to the selected driver's total.

**Avatars**: `next/image` for the current user (Lena Marchetti, Finance Operations Lead — fictional persona/email, not real session data) in the sidebar and topbar, plus 4 distinct segment-lead owners shown in the driver table's avatar cells and the detail rail, using the remaining real Unsplash IDs from the approved list (`1500648767791-00dcc994a43e`, `1505740420928-5e560c06d30e`, `1515372039744-b8f02a3ae446`, `1531123897727-8f129e1688ce`), all with explicit width/height and descriptive alt text.

**Duplicate-avoidance**: the dominant visualization is a waterfall/bridge chart (not a line/area/bar-race/map/board/feed/tree/graph/spreadsheet/gauge/calendar/leaderboard/heatmap/Sankey/scatter), a chart type not yet used as a dominant viz in this evolution series, rendered as hand-authored SVG+HTML overlay (no chart library). As the only candidate assigned the "hero number + single dominant chart" macro skeleton this round, the domain (finance-ops P&L bridge) and encoding (signed floating/anchor bars with truncated-baseline break marks) are original within that skeleton.
