# auto-profile-r1 / c — "Signal & Noise" (creator: Priya Anand, on Ridgeline)

**Product/brand/trigger**: `profile` has no dedicated brief yet, so this candidate was generated from `page-brief-core` alone per its "타입 프로파일 목록" note — its delta becomes the profile-type profile's draft. Domain: a public creator page on **Ridgeline**, a fictional analytics/newsletter SaaS in the tone of `pw1` "Fathomline". The page belongs to **Priya Anand**, a product-analytics educator who publishes **Signal & Noise**, a paid weekly newsletter — the blend of Substack writer page, Patreon supporter page, and course-instructor profile the brief asked for: reach stats, a post feed with a member-only lock, and three membership tiers.

**Macro structure**: a single vertical editorial column (`max-w-5xl mx-auto`, no sidebar, no dashboard grid) split into four server/client sections composed from a thin server `page.tsx`:
1. `identity-panel.tsx` (client) — hero (gradient-mark avatar with initials, name as the page's one `h1`, verified badge, handle, bio, topic tags, Follow/Email/Website/Feed actions) directly followed, in the same component, by a **permanently-rendered** reach `<dl>` (Subscribers · Paid members · Posts published · Avg. open rate) so the credibility numbers are on screen at load, never behind a tab — the assignment's explicit anti-pattern to avoid.
2. `posts-feed.tsx` (client) — an access-level filter (All / Free / Members only) over 6 seeded posts, each with a date, read time, topic tag, a `Lock`-icon "Members only" indicator on gated posts, and a per-post expand toggle.
3. `membership-tiers.tsx` (client) — a Monthly/Annual billing toggle above three tier cards (Free / Reader / Insider), the middle tier marked "Most popular".
4. `site-footer.tsx` (server) — newsletter name, platform credit, email + RSS.

This is deliberately *not* a dashboard-shaped grid or a marketing landing scroll: it reads top-to-bottom like a person's page, with the stat cluster living inside the hero section itself rather than as a separate "analytics tab" — the structural choice the brief flagged as the thing past rounds lost on.

**Interactions implemented** (4, all information-bearing):
1. **Follow toggle** (`identity-panel.tsx`) — `UserPlus`/`UserCheck`, `aria-pressed`, moves the `Subscribers` stat in the reach `<dl>` by exactly one (18,420 → 18,421) and announces the new total via a `role="status" aria-live="polite"` region.
2. **Posts access filter** (`posts-feed.tsx`) — a 3-way `aria-pressed` segmented group (All / Free / Members only) filters the visible list and updates an `aria-live="polite"` "Showing N of 6 posts" line.
3. **Per-post expand/collapse** (`posts-feed.tsx`) — "Read preview" / "Show less", `aria-expanded` + `aria-controls`, reveals the post's full excerpt paragraph in place.
4. **Billing-period toggle** (`membership-tiers.tsx`) — Monthly/Annual, `aria-pressed`, recomputes the displayed price on all three tier cards simultaneously (Reader $8 → $6/mo, Insider $20 → $15/mo, both a flat 25% off) and swaps the "Billed monthly" caption for "Billed $72/yr" / "Billed $180/yr".

**Palette**: fixed **dark** theme (not a `dark:` media-query variant — the whole route is hardcoded `bg-zinc-950`/`zinc-900` surfaces), single **cyan** accent (`cyan-400` primary, `cyan-300` for badge/label text). Checked by hand since Lighthouse wasn't runnable in this sandbox (see Confirmed): `cyan-400` (#22d3ee) on `zinc-950` (#09090b) ≈ **11.0:1**; on `zinc-900` (#18181b) ≈ **9.8:1**. Body/secondary text floor is `zinc-400` (#a1a1aa) everywhere (`zinc-500`/`600` never used, confirmed by grep) — `zinc-400` on `zinc-950` ≈ **7.8:1**, on `zinc-900` ≈ **6.9:1**, both well clear of the 4.5:1 AA floor and the brief's dark-mode zinc-400 minimum. No photographic imagery is used at all — the avatar is a CSS-gradient initials mark, not a raster image — so `next/image`/aspect-ratio/CLS risk is eliminated by construction rather than mitigated; every icon is `lucide-react`.

**Font**: body stays on `--font-sans` (Pretendard); headings/prices/tier names use `--font-display-wide` (Archivo Display) via inline `style={{ fontFamily: "var(--font-display-wide)" }}`, matching the existing convention in `catalog-client.tsx` / `product-client.tsx` / `scene/tokens.ts` rather than a Tailwind arbitrary-value class. Exactly 3 weight classes route-wide — `font-normal`, `font-medium`, `font-semibold` — confirmed via `node scripts/gate.mjs`'s `countFontWeights` against every file in the route.

**Files**: `app/src/app/profile-evolve/r1/c/page.tsx`, `identity-panel.tsx`, `posts-feed.tsx`, `membership-tiers.tsx`, `site-footer.tsx`, `data.ts`.

**Confirmed**: `cd app && npx next build` passes cleanly (TypeScript clean, route prerenders as static). `node scripts/dash-static-check.mjs app/src/app/profile-evolve/r1/c/*.tsx` returns `[]` — zero violations (no raw `<img>`, no `Math.random`/`Date.now`/bare `new Date()`, no emoji, no unlisted font family, no `dark:text-*-500/600`, no `next/font` import, no `font-serif`). The one `<dl>` (reach stat cluster) follows the documented fix exactly: `dl > div > (dt, dd)`, icon inside `dt` only. Single `h1` (creator name); heading order is h1 → h2 ("Latest posts") → h3 (post titles) → h2 ("Membership") → h3 (tier names), no skips. Every interactive element carries `focus-visible:ring-2 focus-visible:ring-cyan-400 focus-visible:ring-offset-2 focus-visible:ring-offset-zinc-950`. One accessibility bug was caught and fixed during self-review before finalizing: the Email/Website/Feed icon buttons initially hid their label via `hidden sm:inline`, which removes the accessible name entirely below the `sm` breakpoint (a real link-name failure under Lighthouse's mobile preset); switched to `sr-only sm:not-sr-only` so the name stays in the accessibility tree at every width while the visual label still collapses to icon-only on mobile. **Not independently confirmed**: the Playwright browser needed for `dash-sweep`/Lighthouse could not be installed in this sandbox (`cdn.playwright.dev` is blocked by the outbound proxy policy here), so the 1280/1366/1440/1600/1920/390 overflow sweep and the Lighthouse a11y ≥95 gate were reviewed by hand (single `max-w-5xl mx-auto px-5 sm:px-8` column throughout, `flex-wrap`/`min-w-0` on every row and grid that carries variable-length text, 20px mobile side padding) rather than machine-verified — flagging this explicitly rather than claiming a run that didn't happen.
