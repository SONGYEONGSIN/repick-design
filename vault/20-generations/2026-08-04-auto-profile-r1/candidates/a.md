# auto-profile-r1 / a — "Circuitloom Restorations"

**Product/brand/trigger**: Circuitloom Restorations (@circuitloom), a certified-refurbished reseller of audio gear, mechanical keyboards, cameras and optics on the marketplace — the persona a buyer lands on after clicking a seller's name from a listing. No dedicated `profile` type profile exists yet in the vault, so this candidate was generated from `page-brief-core` alone, per its own instruction that the delta it produces becomes the type's seed profile.

**Macro structure**: not a dashboard-with-tabs and not a landing scroll — a **public reputation storefront**. Top to bottom: (1) a full-bleed generated gradient cover banner, (2) an identity header with a generated avatar mark, verified badge, bio, location/join-date/response-time meta row, and Follow/View-listings actions; (3) a flat trust-badge row (four pills, icon-inside-each, no `<dl>` anywhere on the page — the known icon+term+description nesting trap is avoided by construction, not by careful nesting); (4) a **permanently visible** reputation stat cluster (rating average, review count, ship-on-time %, items sold) in its own bordered section, mounted outside the tab component entirely; (5) a semantic **performance-vs-marketplace-average table** (`caption` + `scope="col"`/`scope="row"`, `table-fixed` + % widths, no sort since it's a static comparison) — an extra always-on trust surface beyond the required stat cluster; (6) a keyboard-operable ARIA tablist switching between Listings and Reviews, both panels kept mounted in the DOM (`hidden` attribute toggles visibility) rather than swapped by a ternary, specifically so every tab's `aria-controls` id always resolves to a real element and the inactive panel's heading is excluded from the accessibility tree via `hidden` rather than by not existing. Product photography is replaced throughout by deterministic per-slug generated SVG art tiles (gradient + category icon) instead of a random stock-photo host — same rationale this codebase's `catalog/brand-tile.tsx` already documents (picsum.photos put moss on a CRM card), and it also removes all image-load/CLS risk from the aspect-ratio containers.

**Interactions implemented** (5, all information-bearing):
1. Follow/Unfollow toggle (`aria-pressed`) in the header — flips button style and increments the visible follower count in real time.
2. Listings/Reviews tablist — full roving-tabindex keyboard support (ArrowLeft/Right, Home/End) per the WAI-ARIA tabs pattern, `aria-selected`/`aria-controls` wired to real, always-mounted panels.
3. Condition-grade filter chips (All / Like New / Excellent / Good / Fair) in the Listings panel — filters the grid and updates a live "Showing N of 9" count.
4. Listings sort select (Recommended / Price low–high / Price high–low / Most watched) — reorders the grid.
5. Reviews sort select (Most recent / Highest rated / Most helpful) + "Show more reviews" button — reorders and progressively reveals the review list (4 → 8), backed by a fixed rating-breakdown bar chart that stays visible regardless of sort.

**Palette / AA contrast math** (rose accent on a fixed zinc-900/950 product-dark surface, not `dark:`-conditional — computed via WCAG relative luminance, `#09090b`/`#18181b` bases):
- `zinc-400` body/secondary text: 7.76:1 on zinc-950, 6.91:1 on zinc-900 — used as the dark floor everywhere secondary text appears (avoided `zinc-500`, which measured only 4.12:1 / 3.67:1 on those same surfaces and would have failed AA despite not matching the `dark:text-*-500` static-rule regex, since this page uses plain — not `dark:`-prefixed — classes).
- `rose-300`/`rose-400` accent text: 9.37–10.52:1 on zinc-900/950 — safe for badge/link/price-accent roles.
- Primary "Follow" button fill: `rose-600` background with white text = **4.70:1** (passes AA); `rose-500` was measured first and rejected at 3.67:1 — same fill-darkened-one-step pattern the `auto-paywall-r2/a` candidate used for `amber-700` over `amber-600`.
- `zinc-100` on `zinc-800` (selected tab pill) and `zinc-300` on `zinc-800`/`zinc-900` (chips, table headers) both clear 10:1+.

**Font**: `--font-display-grotesk` on the `h1` and the large reviews-panel rating figure only; every other heading and all body copy stays on the default `--font-sans`. Exactly 3 weight classes route-wide — `font-normal` (3 uses: bio copy, table caption, table row headers), `font-medium` (25 uses: labels, buttons, badges, table column headers), `font-semibold` (7 uses: h1, stat numbers, listing prices) — verified by grep across every file in the route.

**Files**: `app/src/app/profile-evolve/r1/a/page.tsx`, `profile-client.tsx`, `listings-panel.tsx`, `reviews-panel.tsx`, `rating-stars.tsx`, `seller-mark.tsx`, `listing-art.tsx`, `visual-hash.ts`, `data.ts`.

**Confirmed**: `cd app && npx tsc --noEmit` and `npx eslint src/app/profile-evolve/r1/a` both pass clean; the route renders 200 with the expected structure (single `h1`, heading sequence h1→h2→h2→h2→h3 with no skips, one `role="tablist"` + two `role="tab"` + two `role="tabpanel"`, one real `<table>` with `caption`/`scope`). Ran this repo's own `checkSource` static rule-set (the same regexes `gate.mjs --target web` uses) against every file in the route by hand — 0 violations: no raw `<img>`, no `unoptimized`, no `Math.random`/`Date.now`/`new Date()`, no emoji, no `next/font` import, no `font-serif`, no unlisted font family, no `dark:text-{zinc,neutral,gray,slate,stone}-{500,600}`. No `<dl>` anywhere on the page (trust badges and the reputation stat cluster both use `<ul>`, sidestepping the documented icon+term+description nesting trap by construction). `focus-visible:outline-2` rings (never bare `outline-none`) on every interactive element. Grid items (listing cards, stat tiles) all carry `min-w-0`. The comparison table is `table-fixed` with `%`-width columns, so it never needs a desktop horizontal scrollbar. Could not run the Playwright-driven sweep/Lighthouse gate locally in this sandbox (browser binaries blocked from downloading), so width behavior at 1280/1366/1440/1600/1920/390 was verified by structural reasoning instead — no fixed-pixel widths or `whitespace-nowrap` anywhere in the route, only `%`-based table columns and a `max-w-6xl` content wrapper with responsive `px-4`/`sm:px-6`/`lg:px-8` gutters.
