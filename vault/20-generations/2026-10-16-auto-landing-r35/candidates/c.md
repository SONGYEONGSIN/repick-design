# r35/c — Seller Payout Simulator (reassigned reproduction)

**One-line concept:** Three stepper counters (Electronics / Fashion / Home) drive a live seller-payout calculator — the hero's live estimate, an itemized breakdown table and a category-mix stacked bar all recompute from the same state on every click, with the final total threaded through to the closing CTA's own button label.

This candidate is a **reassigned, fixed reproduction** of `auto-landing-r34/c` ("Seller Payout Simulator"), per `vault/00-principles/reassign-queue.md` entry **#12**. r34/c was not dropped for its form — the queue entry says explicitly "`## Hero proof-card note`·`## 브리프에 없던 것` 보고까지 전부 완결돼 있었고, 유일한 결함은 위 하드게이트 두 건이다" ("...the only defect was the two hard-gate failures above") — it was dropped for two fixable rule violations: a lint violation (`react-hooks/set-state-in-effect`) and an unresolved `sweep` `page-overflow` at 390px that survived one prior fix attempt. This candidate keeps the device, the audience framing, and the general copy voice, and targets only the two named failures plus a light-theme/sky-accent reassignment (this round's theme diversification constraint) and a pass over the newer brief constraints the original predates.

## 정제 조치 — 재배정 수정

**① lint `react-hooks/set-state-in-effect` (queue-cited at `Reveal.tsx:29`, `useEffect(() => setMounted(true))`).**
The r34/c source available to read in this repo is already *post*-1-fix (the queue entry records that the lint half of the 1-fix attempt succeeded; only the sweep half re-failed). Its `Reveal.tsx`/`useMounted.ts` already use the correct pattern, so there was nothing left to change here — I carried it over verbatim into `r35/c/useMounted.ts` and `r35/c/Reveal.tsx`:
```ts
// useMounted.ts
export function useMounted(): boolean {
  return useSyncExternalStore(subscribe, getClientSnapshot, getServerSnapshot);
}
```
No `useEffect` anywhere in this candidate sets state. `Reveal.tsx` gates `whileInView`/`initial={{opacity:0}}` on `useMounted()` (not `useReducedMotion()` alone), and the hero itself (`Hero.tsx`) is not wrapped in `Reveal` at all — its headline/subhead/CTA/proof-cards render their final visible state on first paint, removing even the possibility of a mount-gating risk there.

**② sweep `page-overflow` at 390px (queue-cited root cause: a Chromium quirk where a wide descendant inside an `overflow-x-auto`/`hidden` wrapper still inflates `document.documentElement.scrollWidth`, even though the wrapper's own local scroll is correct).**
r34/c's `ProductPreview.tsx` had:
```tsx
<div className="mt-4 overflow-x-auto">
  <table className="w-full min-w-[480px] border-collapse text-left">
```
I removed this pattern entirely rather than containing it — the queue's "more repo-convention-aligned" alternative — in `r35/c/ProductPreview.tsx`:
```tsx
<div className="mt-4 min-w-0">
  <table className="w-full table-fixed border-collapse text-left">
    <colgroup>
      <col style={{ width: "27%" }} /><col style={{ width: "9%" }} /><col style={{ width: "19%" }} />
      <col style={{ width: "16%" }} /><col style={{ width: "19%" }} /><col style={{ width: "10%" }} />
    </colgroup>
```
with `truncate` added to every `<th>`/`<td>` as an independent per-cell guarantee (`overflow:hidden; text-overflow:ellipsis; white-space:nowrap` applied directly on the fixed-width cell box itself, not on a separate ancestor wrapper — this is not the same "nested overflow ancestor" shape the Chromium quirk needs, since there is no longer a genuinely-wider-than-its-box descendant at all). `table-fixed` + `<colgroup>` percentages mean the table's rendered width is capped at its container's width by the CSS table layout algorithm regardless of cell content — cells wrap or truncate instead of forcing the table wider — so there is no wide descendant left for the quirk to act on.
As a belt-and-suspenders measure (since the brief names it as the directly-verified fix and it costs nothing to add), I also kept `[contain:layout]` on the wrapping `<section id="calculator" className="... [contain:layout] ...">` — the section that wraps both the grid item and the table, per the queue's instruction to apply it to the *wrapping* element, not the scroll wrapper itself.
I traced the ancestor chain by hand before submitting: `section#calculator[contain:layout] > div.mx-auto.max-w-[1280px] > div.grid > Reveal(div.min-w-0) > div.min-w-0.rounded-2xl > div.mt-4.min-w-0 > table.table-fixed`. Every ancestor up to the section is `min-w-0` or unconstrained, the table itself cannot exceed 100% of that chain by construction (`table-fixed`), and every leaf cell additionally clips its own content (`truncate`). At a reasoned 390px trace: viewport 390 → page gutter `px-4` (−32) → card padding `p-5` (−40, mobile) ≈ 318px available for the table; `table-fixed` pins the table to exactly that width no matter what six columns of currency text and a 28px icon button ask for. `document.documentElement.scrollWidth === document.documentElement.clientWidth` holds because nothing in this chain is permitted to paint wider than its own fixed-width box: the table can't (table-fixed), and no cell's content can (`truncate` on every data cell, and the one potentially-wide child — the former text+icon "Math" button — was redesigned to an icon-only 28×28px button so it never approached its 10%-column (~32px) budget in the first place; see `브리프에 없던 것` below).

## 브리프에 없던 것

- **Sky accent contrast math, recomputed for the light-theme flip.** (a) Fill/border/bar shade ACCENT = `#0EA5E9` (sky-500): vs white 2.77:1 (fails AA — never used as text on this page), vs this route's ink `#0B0B0F` 7.09:1 (clears AA at any size — this is the pair that matters for (c)). (b) Small-text/icon/focus-ring tint derivative = `#0369A1` (sky-700): vs white 5.94:1, clearing the 4.5:1 small-text floor with real headroom and the 3:1 non-text focus-indicator floor by a wide margin — used identically for eyebrows, captions, icons, the focus outline, and the deepest stacked-bar segment, so there is exactly one accent-on-light number to keep safe rather than several. I explicitly re-checked and rejected carrying over the dark-theme original's `sky-300` for this role: it is 11.78:1 against dark ink (great there) but only 1.67:1 against white — a theme flip can't just swap backgrounds and keep the same hexes doing the same jobs. (c) Text-on-fill: every solid accent button (hero CTA, closing CTA) uses dark-ink text (`text-[#0B0B0F]`) on the `bg-sky-500` fill, not white — 7.09:1, the same pair as (a) read the other direction. White-on-accent would be 2.77:1 and fails outright at any size, so ink was the only option, and it clears AA regardless of the button text's size (it's `text-base font-bold` anyway, comfortably "large text", but the pair would hold even if it weren't).
- **Body line-length arithmetic**, using `container-px ÷ (0.44 × font-px)`, not `ch`: Hero subhead (`maxWidth: 505px`, `text-base`→`sm:text-lg`) = 505/(0.44×16) ≈ 71.7 chars at the mobile size (within the 75 ceiling) and 505/(0.44×18) ≈ 63.8 at `sm:`+ (comfortably under target, since the larger glyph advance shortens the line). `SectionIntro`'s default `bodyWidthPx=500` at `text-base` ≈ 500/7.04 ≈ 71.0 chars. `ClosingCTA`'s paragraph (`505px`, `text-base`) ≈ 71.7 chars, same figure as the hero by design (same voice, same width). `SocialProof` quotes (`420px`, `text-sm`/14px) ≈ 420/(0.44×14) ≈ 68.2 chars — under target with margin, appropriate for a shorter testimonial card. All four sit at or under the 75-char hard ceiling; none relies on `ch`.
- **Banned-template and brief-gap pass over the original copy** (the original predates several of these constraints, so this is new work, not carried over): the `ValueSection` heading "Three numbers, none of them a sales pitch" matched the banned "a 'Three ___ ...' three-pillar heading" skeleton verbatim in shape — rewritten to "The arithmetic behind listing here, laid out plainly." `SELLER_STATS` in `data.ts` paired a dollar-total-paid figure with a payout-speed figure ("$3.1M paid out... / 2 days average time"), which is the same *shape* as the explicitly banned "$-paid-to-sellers + time-to-payout" stat pair even though the exact numbers/unit differed from the banned example's "72 hrs" — replaced with two stats about the calculator itself ("48,000+ listings priced through this exact calculator" / "$41 average gap between a seller's first guess and the number on screen"), which is also a better thematic fit for a device-first candidate. The original `ClosingCTA` button read "List your {itemWord} now" — visible text carried the plural/singular noun but never the actual live number, so the state didn't survive into the CTA's own label as the brief requires; changed to "List {totalItems} {itemWord} on repick", reading `computeBreakdown(counts)` fresh every render exactly like the summary sentence above it.
- **Math-disclosure button redesigned icon-only, for two independent reasons found during the self-verification pass, not called out in the brief.** The original's "Math ⌄" text+icon button has no explicit padding, giving it roughly a 16–18px hit height — under the WCAG 2.5.8 / axe `target-size` 24×24px floor — and at a `table-fixed` 10%-of-318px (~32px) column budget at 390px, a text+icon button is also tight enough to risk its own visual overflow past the cell's fixed-width box (the same failure class as the hard-gate bug, just one DOM level deeper, inside a `<td>` instead of inside the table). Both are solved the same way: the button is now icon-only (`ChevronDown` in a `h-7 w-7` / 28×28px box, well past the target-size floor and comfortably inside the column budget) with a full `aria-label` ("Show/Hide the math for Electronics") carrying the accessible name — since there's no visible text at all, there's no `label-content-name-mismatch` risk either.
- **Stacked-bar segment distinguishability**, since the three sky shades used for the three bar segments don't all individually clear 3:1 against the page's white background (sky-500 is 2.77:1, sky-300 is 1.67:1; only sky-700 clears it at 5.94:1): every segment boundary carries an explicit 2px white divider (`border-r-2 border-white`) and the track itself has a `border border-zinc-200` outline, so segments stay visually distinguishable from each other and from the page by shape/edge, not by relying on color contrast against the background alone — and the legend directly below pairs every swatch with its category name and percentage as running text, so color is never the only signal regardless.
- **Dropped the `width`-animation on the stacked bar's segments.** The original animated each segment's `width` via Framer Motion's `animate={{ width: ... }}` on every stepper click. The brief restricts Framer-Motion-animated props to `transform`/`opacity`; `width` is neither, and it's a layout-affecting property on top of that. Segment widths are now set directly via inline `style` with no transition at all — the component no longer needs `"use client"` or any hook. The route's Framer Motion budget is spent entirely on `Reveal`'s scroll-triggered entrance (`opacity` + `y`, i.e. `transform`), which — together with the 3 steppers, the reset button, and the per-row math-disclosure toggle — comfortably clears the "minimum 4 distinct interactions" floor.
- **Added a skip link.** Neither this device's prior attempt nor (as far as I could tell reading it) the rest of this candidate's own first draft had one, and the brief separately hard-fails on a missing `skip-link`. `Header.tsx` now renders a `sr-only focus:not-sr-only` anchor to `#main` as the very first element in the DOM, ahead of the sticky header itself, targeting a `<main id="main">` that wraps every section from the hero onward.
