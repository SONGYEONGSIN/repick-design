# a — "Sorting Yield"

One-line concept: a Sankey-style proportional flow diagram (Pass as-is / Refurbish-then-sell / Declined) with a live "strictness" toggle, rebuilt from the already-judge-eligible `auto-landing-r47/c` "Allocation Flow" concept per reassign-queue #21 — same device, light/rose/`--font-display-wide`, with the band hit-boxes' tap-target bug fixed.

## The fix

`r47/c`'s 1-fix (removing `min-w` on the diagram wrapper, making the `<svg>` fluid via `viewBox` + `width:100%`, and moving labels to fixed-px HTML overlays) solved the original `sweep` `page-overflow` violation, but the band hit-box `<button>`s kept scaling their height with the now-fluid SVG, shrinking to ~9px tall on mobile — a new `target-size` a11y violation.

`AllocationFlow.tsx` fixes this by giving each hit-box its own overlay, decoupled from the ribbon's own rendered thickness:

- `AllocationFlow.tsx:230–251` — the hit-box `<button>` is a *separate* absolutely-positioned element from the visual node (drawn earlier, inside the `<svg>`, lines ~175–205). Its `top`/`height` inline styles still come from the band's own percent geometry (`g.hitBox.centerTopPct` / `g.hitBox.heightPct` from `flow-math.ts`), so a thin band still *looks* thin — but the className adds Tailwind's `min-h-6 min-w-6` (24px floor) plus `-translate-y-1/2`.
- `top` is set to the node's vertical **center** (not its top edge), and the box is recentered with `-translate-y-1/2`, a transform percentage that always resolves against the element's own *final* box — so whichever is larger, the percent height or the 24px floor, the box stays centered on the same point instead of drifting downward when the floor kicks in.
- `flow-math.ts:53–145` computes `hitBox: { leftPct, widthPct, centerTopPct, heightPct }` as geometry completely separate from the visual `nodeY`/`nodeHeight` fields the SVG `<rect>` uses — so a future change to the ribbon's visual thickness can never silently reach into the tap target's minimum size again.

This is the same *decoupling* technique the original 1-fix used for labels (fixed-px HTML, position-only), applied to *size* instead: a fixed CSS floor (`min-h-6`/`min-w-6`) on an absolutely-positioned overlay, recentered via a self-relative transform, rather than resizing the SVG node itself. Because the floor is scoped to one small absolutely-positioned child inside an already-fluid, already-passing-sweep box — not to the diagram wrapper itself — it cannot reintroduce the original `page-overflow` bug: there is no `min-w`/`min-h` on anything that participates in document flow or width calculation.

## What wasn't in the brief (self-decisions)

- **Accent contrast math** (rose, `#E11D48` base / `#BE123C` small-scale tint, both fixed per the reassignment's "keep rose" instruction):
  - `#E11D48` relative luminance L ≈ 0.1735. White text on this fill → (1.05)/(0.1735+0.05) = **4.70:1** (clears 4.5:1 AA at any size). Dark ink `#171717` (L ≈ 0.00858) on this fill → (0.1735+0.05)/(0.00858+0.05) = **3.82:1** (clears only the 3:1 large-text/non-text floor — so ink is never paired with the accent fill below 24px/19px-bold anywhere in this candidate; small accent-colored text instead uses the tint below).
  - `#BE123C` L ≈ 0.1171. On white → (1.05)/(0.1171+0.05) = **6.29:1** (clears 4.5:1 AA with real margin) — used for every small accent-colored label/icon/eyebrow sitting on the page surface (`ACCENT_TINT_TEXT`), never the raw `#E11D48`, per the brief's small-text/icon tint rule.
  - Focus ring: `outline`/`outline-offset` paint the ring on the page surface beside the element, not over a fill, so it's checked against white (L=1): same 4.70:1 as above, clears the 3:1 non-text floor comfortably.
  - Muted text `#525252` (L ≈ 0.0841) on white → 7.83:1; on the panel surface `#F5F3F3` (L ≈ 0.903) → 7.11:1. Both clear 4.5:1 with margin.
- **Body-copy container widths** (0.44em glyph-advance constant, not `ch`, target ~70 chars/line, ceiling 75):
  - Hero subhead: 16px → 0.44×16 = 7.04px/char → `max-w-[500px]` → 500/7.04 ≈ **71.0 chars**.
  - ValueSplit card body: 15px → 6.6px/char → `max-w-[460px]` → 460/6.6 ≈ **69.7 chars**.
  - Testimonial quote: 16px → 7.04px/char → `max-w-[470px]` → 470/7.04 ≈ **66.8 chars**.
  - ClosingCTA lead line: 16px → 7.04px/char → `max-w-[500px]` → 500/7.04 ≈ **71.0 chars**.
- **Headline clamp split**: used `text-[2.5rem] sm:text-[3rem] lg:text-[clamp(3.25rem,2.75rem+2vw,4.5rem)]` instead of one unified `clamp()` across all breakpoints — a fixed, conservative size below `lg` that can't grow with viewport width at all (so it can't overflow at 375px by construction), and a fluid `clamp()` only at `lg+` for the larger desktop scale. This reads the brief's "distinguish `<lg` from `lg`" instruction as two separate rules rather than one curve tuned to satisfy both.
- **Page structure**: kept the flow diagram as the sole hero device (headline/subhead/CTA/diagram, all inside `Hero.tsx`) and `ProductPreview` as a separate section below, matching `r47/c`'s already-judge-eligible structure, rather than forcing product cards to be children of `Hero` per the generic landing-structure guidance — the reassignment brief explicitly asks to preserve this candidate's existing structure, and the device's own live payout/sell-through figures (visible by default, pinned in the hero) already satisfy the "proof visible by default" causal chain that the hero-fold rule is protecting; that chain is traced through to `ValueSplit` and `ClosingCTA`, both of which read the same `strictnessId` through the same `flow-math.ts` functions, never a hardcoded literal.
- **Did not** add extra spacing/overlap guards between adjacent band hit-boxes beyond the individually-floored 24×24 size. At the narrowest mobile width with the most lopsided profile (Standard: Declined = 13/120 ≈ 10.8% share), the floor only grows a hit-box by roughly 7–8px past its natural edge in each direction, against a ~6–7px natural gap to its neighbor at that same scale — a sub-2px potential intrusion into the gap, not a full overlap. The reassignment's own diagnosis (reassign-queue #21) names only the single-dimension height floor as the fix; a separate, differently-diagnosed reassignment (#20, `auto-dash-r55/c`) explicitly flags adjacent-target spacing as its own distinct failure mode for a different device (slope-chart endpoints), which this candidate's device doesn't share the geometry of. Kept the fix scoped to what was asked rather than speculatively hardening against an unreported failure mode.
- **Renamed "Fail-rejected" → "Declined"** and varied the strictness-profile counts/dollar literals from `r47/c`'s exact numbers (still summing to a fixed batch of 120 both profiles, still fully deterministic) so this candidate's content is independently authored rather than a literal re-skin, while keeping the same domain and device concept per the reassignment instructions.
