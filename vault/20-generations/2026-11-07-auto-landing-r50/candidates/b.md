# Candidate B — "Head-to-Head"

Concept: a pairwise listing diff — two independent dropdowns each pick one of six fixed sample listings, and one shared `compare()` function drives a live signed delta table, a 5-axis radar overlay, and the closing CTA from that same pair, so the reachable state space is the full 6-choose-2 (plus same-pick) grid rather than a single lookup or slider.

## Not specified by the brief

- **Accent hex + contrast math.** Picked orange `#C2410C` as the full-opacity "accent" token (fills/borders/large text) and a darker `#B8410A` as "accent-ink" (small text/icons/links/focus rings) — the opposite of the brief's generic "lighten for small text" phrasing, because that phrasing implicitly assumes a dark default theme where lightening increases contrast against a dark bg. On our assigned LIGHT theme, lightening would *reduce* contrast against the white/near-white bg, so I darkened instead to hit 4.5:1+ for small text. Computed by hand (sRGB→linear→relative luminance→ratio):
  - `#C2410C` vs white: **5.18:1** (white text on this fill clears 4.5 AA for small text, per the brief's explicit white-on-fill rule)
  - `#C2410C` vs ink `#171311`: **3.56:1** (large-text/border use only)
  - `#B8410A` vs white: **5.53:1**, vs bg `#FAF9F7`: **5.25:1**, vs surface `#F1EDE8`: **4.74:1** — all clear 4.5 AA, used for small text/icons/links/focus rings
  - Ghost-number color `#BE7249` vs bg `#FAF9F7`: **3.51:1** — clears the large-text (≥24px) floor only; used at 32px/weight 600/tracking +0.12em so it never outsizes or outweighs an adjacent heading (always ≥800-weight, usually larger)
  - Ink `#171311` vs bg `#FAF9F7`: **17.54:1**; muted `#6B6560` vs bg: **5.46:1** (near-white floor); muted-track `#534E49` vs surface `#F1EDE8`: **7.06:1** (tinted-surface floor, used on the selector box and composite-score strip)
- **Body-copy width math.** Used the brief's constant (Pretendard-with-Latin ≈ 0.44em/glyph) instead of `ch`. At 17px body copy: `70 × 0.44 × 17 ≈ 524px` → `max-w-[524px]`. At the 19px hero subhead: `70 × 0.44 × 19 ≈ 586px` → `max-w-[586px]`. Both aim at ~70 chars/line, not flush to 75.
- **Display typeface mapping.** `--font-display-wide` isn't defined in this route — it's a repo-global CSS variable (resolves to "Archivo Display" per `globals.css`, with `var(--font-sans)`/Pretendard fallback). I applied it only to large Latin headline text (h1/h2 in hero, section headers, closing CTA) via inline `style={{ fontFamily: "var(--font-display-wide)" }}`, never to body copy, chips, or the logo wordmark's running text — matching "display face for large Latin headline text only."
- **Exactly 3 rendered weights.** Chose 400 (implicit Tailwind-Preflight/body default — never wrote `font-normal` explicitly, relied on the browser/Preflight default since Preflight normalizes heading font-weight to `inherit` rather than UA-bold), 600 (`font-semibold` — labels, nav, body emphasis, chips, ghost number), 800 (`font-extrabold` — headlines, composite-score callout). Never used `font-medium`/`font-bold`/`font-light`. SVG `<text>` in the radar chart is unstyled (default normal) and excluded from the count per the rules anyway.
- **Dataset: six fixed listings.** The brief said "small fixed deterministic sample set (5–6)." I picked 6, spanning very different price tiers and categories (a $128 sneaker up to a $5,180 watch, one `verified: false` item) specifically so the diff table/radar would show dramatic, legible shape differences rather than near-identical picks, and so the "pending verification" badge state gets exercised at least once.
- **Composite "value score" formula.** Not specified. Built a transparent weighted sum — `match×0.45 + gradeNormalized×0.25 + discount×0.20 + speed×0.10` — all five radar-axis dimensions feed it except "price efficiency" (kept the table's own Price row separate from the composite so the two surfaces aren't just restating the same number twice). Dataset-wide min/max for days-to-sell and price are computed once from all six listings (module-level constants), never from just the two selected listings, specifically so picking the same listing twice can't collapse a normalization range to zero.
- **Tie/identical guard.** When both selectors pick the same listing, every diff row reads "Tied," the radar polygons sit exactly on top of each other, the composite strip reads "Dead heat — 0.0 pts apart," a dedicated inline note above the table explains why, and the closing CTA switches to a distinct "compared to itself is a wash" sentence — never the generic "X wins by 0.0 pts" phrasing, which would read as a bug.
- **"Biggest swing" reduce guard.** Computed via `Array.reduce` over the 5 radar-axis absolute deltas. Guarded explicitly: if every delta is ≤0.01 (the identical-pick case), the reduce is skipped entirely and `biggestSwing` is `null` rather than defaulting to axis index 0.
- **Radar axis set.** Picked 5 axes (Match, Grade, Discount, Speed, Value/affordability) rather than mirroring the diff table's 5 rows 1:1, because "Price" as an absolute dollar figure doesn't normalize meaningfully onto a shared 0–100 radar without a min/max — so the radar uses "Affordability" (price rank among the 6 listings, cheaper = higher) instead, computed from the same `listing.price` field via the same dataset-wide bounds.
- **Hero fold discipline.** No full-bleed `min-h-screen` hero. Hero cards use a square (not 4:5) aspect ratio, 2×1 badge grid instead of flex-wrap, and a compact currency formatter (`$4.4k` instead of `$4,400`) specifically so the before/after discount badge never gets `truncate`-clipped on the four-figure Hermès bag card used in the hero. Copy was shortened once I hand-estimated the mobile 390px stack (header + eyebrow + headline + subhead + CTA + 2 compact cards) at roughly ~600px, versus a conservative ~650–700px visible viewport.
- **Images.** Hand-picked fixed `images.unsplash.com/photo-<id>` URLs for all 6 listings + 3 testimonial avatars (no randomized endpoints). I can't verify at authoring time that every id still resolves on Unsplash's CDN, so every image container has a fixed `aspect-ratio` + `bg-[#F1EDE8]` fallback and badges are never overlaid on the image, per the brief's own mitigation for this exact risk.
- **Mobile nav accessibility.** Kept the mobile dropdown nav always mounted (not conditionally unmounted) so `aria-controls` always points at a real element, collapsed via `max-h-0 overflow-hidden`, and added `inert` on the closed state so its links drop out of the tab order instead of being invisibly focusable.
- **Fourth interaction type.** Counted: (1) two independent listing selectors + swap button (the core mechanism), (2) per-card "Why this match?" click-to-expand reasoning disclosure (not hover-only), (3) scroll-triggered `framer-motion` reveal sequence (gated on `useReducedMotion`, `initial={false}` when reduced so nothing sticks at `opacity:0`), (4) mobile nav toggle. All four serve conversion/information, none decorative-only.
