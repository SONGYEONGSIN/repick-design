# Features — 창의 후보 d: 라이브 매칭 피드

**컨셉 한 줄**: Features 페이지를 "기능 설명 목록"이 아니라 "지금 이 순간 AI가 일하고 있다는 증거"로 바꾼다 — 2.4초마다 새 이벤트가 위에서 흘러들어오는 실시간 매칭 로그(터미널 스타일 다크 패널)를 히어로의 시각적 주인공으로 세우고, 각 이벤트를 취향 학습/AI 매칭/신뢰 검증/실시간 알림 4개 태그로 색상 구분해 라벨링한 뒤, 아래 기능 상세 섹션에서 "방금 피드에서 본 그 순간"을 하나씩 풀어서 설명하는 구조.

## 왜 이 발상인가
- 기존 Features 패턴(헤드라인+설명+미니 비주얼 나열)은 정적이라 "이게 실제로 돌아가는 건가"를 상상해야 한다. 라이브 피드는 그 상상을 대신 보여준다 — 살아있는 제품 데모를 카피 없이 체감시킨다.
- repick의 핵심 가치("AI가 쉬지 않고 매칭한다")를 문장이 아니라 *현상*으로 증명한다. 방문자가 페이지에 머무는 동안 계속 새 이벤트가 쌓이므로, 스크롤하지 않아도 제품의 생동감이 전달된다.
- 4개 태그(학습/매칭/검증/알림)가 피드와 하단 기능 상세를 잇는 내비게이션 겸 범례 역할을 해서, "우연히 흥미로운 애니메이션"이 아니라 "기능 소개의 구조적 장치"가 된다.

## 구현 요약
- `'use client'` 컴포넌트, `setInterval`(2.4s)로 태그를 순환하며(학습→매칭→검증→알림) 문구 풀에서 무작위 선택해 피드 최상단에 삽입, 최대 6건 유지 후 오래된 항목 제거.
- SSR/hydration 안전을 위해 초기 시드 5건은 고정 문자열("방금 전", "5초 전" 등)이고, 실시간 갱신은 마운트 후 클라이언트에서만 발생 (`Math.random`, `Date` 사용은 전부 `useEffect`/interval 콜백 내부).
- 다크 터미널 카드(트래픽 라이트 도트, LIVE 펄스 인디케이터, 오늘 매칭 건수 카운터, 하단 그라디언트 페이드, 오래된 항목일수록 옅어지는 opacity)로 "라이브니스"를 시각적으로 강화.
- 실시간 피드 아래에 "* 이 피드는 매칭 엔진 동작을 시각화한 데모입니다" 고지 — 실전 배포 시 신뢰를 해치지 않는 정직한 UX 디테일.
- 하단 기능 상세 4블록은 순수 CSS 비주얼(취향 학습=선호도 바 차트, AI 매칭=conic-gradient 매칭률 링, 신뢰 검증=체크리스트, 실시간 알림=핑 링 벨 아이콘)로 외부 이미지 없이 오프라인 렌더.
- 접근성: 피드 리스트는 `aria-label`만 부여하고 `aria-live`는 사용하지 않아 2.4초마다 스크린리더에 스팸 알림이 가지 않도록 함(시각적 데모 성격 존중). `prefers-reduced-motion`에서 피드 입장 애니메이션과 알림 핑 애니메이션 모두 비활성화.
