# Features — 창의 모드 후보 c

## 컨셉: 수동 검색 vs repick 분할 화면

히어로를 좌/우로 가르는 드래그형 비교 슬라이더(`clip-path` 기반, `'use client'`, pointer + 키보드 조작)로 시작한다. 왼쪽 레이어는 "직접 검색" — 지저분한 매물 카드 목록(상태 불명·가격 이상·판매자 미확인 배지), "3시간 12분 경과 · 47개 확인 · 마음에 드는 것 0개". 오른쪽 베이스 레이어는 "repick AI" — 매칭 94% 단일 카드, 인증 배지, "3초 매칭". 헤드라인 자체가 "왼쪽은 3시간, 오른쪽은 3초"로 슬라이더 메타포를 그대로 카피화한다.

그 아래 4개 기능 섹션(취향 학습 / AI 매칭 / 신뢰 검증 / 실시간 알림)은 히어로의 좌우 대조를 각 기능 단위로 반복 증명한다 — "직접 하면" 리스트(✕, amber 톤) vs "repick이 하면" 리스트(✓, emerald 톤). 즉 히어로는 결과의 대조를, 본문은 그 결과를 만드는 메커니즘의 대조를 보여주는 구조.

마무리 CTA는 슬라이더 메타포를 다시 회수 — "슬라이더는 이미 오른쪽을 가리키고 있어요".

## 왜 새로운가
- 기능 소개 페이지의 관습(아이콘 + 3단 카드 그리드)을 버리고, "사용자가 직접 조작해 두 경험의 낙차를 체감"하는 인터랙션을 페이지의 중심 서사로 삼았다.
- 정적 비교표 대신 실제 드래그 가능한 before/after 슬라이더를 순수 CSS `clip-path` + Pointer Events로 구현 — 이미지 없이도 오프라인 렌더 제약을 지키면서 실전 배포 가능한 완성도를 확보.
- 4개 기능 각각이 "왜 왼쪽이 아니라 오른쪽인가"의 근거로 기능하도록 카피를 설계 — 기능 나열이 아니라 대조의 누적.

## 구현 메모
- `SplitCompare`: `useRef` 컨테이너 + `pointerdown/move/up/cancel`으로 드래그, `role="slider"` + 화살표 키보드 조작 지원.
- 색 체계: emerald/teal = repick(해결), amber/neutral = 수동 검색(문제) — 토큰 파일 없는 신규 스캐폴드라 Tailwind 기본 팔레트 직접 사용.
- 컴포넌트명 `Landing` 고정, 단일 h1("왼쪽은 3시간, 오른쪽은 3초"), 반응형 375~1280, 외부 이미지/폰트 CDN 미사용(레이아웃의 Geist 폰트만 사용, 본문은 이모지/유니코드 아이콘).
