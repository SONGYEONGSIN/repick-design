# auto-dash-r2 — JUDGE 판정

라운드: `auto-dash-r2`. 생존 후보 3개(a/b/c, 직전 라운드는 2개) — 3렌즈 judge 병렬(블라인드: 스크린샷 4폭 + 소스 경로만 제공, 생성 순서·컨셉 배정 의도 비공개).

## 후보 요약
- **a — Cadence**: 콘텐츠 발행 스케줄링. 캘린더 중심(대형 월/주 그리드가 화면 주인공) + 우측 큐/스탯 레일.
- **b — Pulse**: 고객지원 SLA 콘솔. 히어로 스코어보드(거대 응답시간 숫자) + 레일 없는 유동 벤토 그리드.
- **c — Relay**: 이메일 캠페인 빌더. 분할 워크벤치(좌 편집 레일 ↔ 우 실시간 미리보기 양방향 동기화).

## 승자 b — Pulse
고객 지원 SLA 운영 콘솔. 4카드 KPI 가로줄 대신 풀폭 히어로 존(거대 응답시간 숫자+크로스헤어 스파크라인)과 레일 없는 12-col 유동 벤토 그리드(대기열/워크로드/에스컬레이션/SLA/자동화/CSAT 카드, 서로 다른 span)로 구성. 카드 클릭→인라인 확장(정렬 가능 테이블), 채널 필터가 히어로 3지표+벤토 카드 동시 동기화, ⌘K 팔레트 포함 5개 실동작 인터랙션. a11y 하드게이트 1차 90(button-name·color-contrast 미달) → `aria-label` 추가 + `text-zinc-500`→`text-zinc-400` 전면 교체로 100/100 통과. sweep 1차부터 pass.

## 패자 기록
- **a — Cadence**: sweep 1차 실패(Sparkline SVG `width`/`height` 미적용 → 고정폭 오버플로) 1회 수정 후 통과, a11y 1차부터 95(하드게이트 통과, 수정 불필요). brief 렌즈에서 캘린더 셀 이벤트 제목 말줄임 결함 지적(재발 금지 항목) — 캘린더-주인공 자체는 archetype 렌즈에서 "진짜 신규"로 인정받았으나 우측 레일 추가로 구조 차별성이 희석됨.
- **c — Relay**: sweep 1차 실패(상태 배지 컬럼 폭 부족 + 모바일 헤더 오버플로) 1회 수정 후 통과, a11y 1차 92(button-name·color-contrast) → 수정 후 100/100. archetype 렌즈 1위(편집↔미리보기 양방향 동기화가 기능적으로 진짜 신규) — brief 렌즈에서 커맨드 팔레트 `outline-none` 단독 사용(포커스 가시 하드 제약 위반) 지적으로 탈락.

## 게이트 사각지대 (배선 결함으로 별도 기록)
- 정적 검사·sweep·Lighthouse 자동 게이트 통과 후에도 judge가 잡은 결함 3건 모두 "화면 렌더 결과를 직접 보거나 코드를 정독해야만" 발견 가능한 종류였다: (1) truncate로 인한 말줄임(레이아웃 여유는 있으나 텍스트 클래스 선택이 문제 — sweep의 오버플로 측정으로는 안 잡힘), (2) `focus:outline-none` 단독 사용(Lighthouse a11y 카테고리가 커버하는 축 밖 — 브리프의 하드 제약이지만 자동화 게이트에 없음), (3) "레일 없음" 아키타입 클레임과 실제 앱 셸 사이드바 존재의 개념적 긴장(자동 게이트로 검증 불가능한 설계 의도 이슈).
- 이번 라운드는 이전 라운드와 달리 sweep 실패가 진짜 결함(고정폭 SVG, 배지 컬럼 폭)이었고 1회 수정으로 전원 회복 — 게이트 자체의 정확도는 양호했다.
