# auto-landing-r28 후보 b — The Funnel (스크리닝 퍼널)

**한 줄 컨셉**: 히어로 안에 실제 매물 증거 카드(매치%·컨디션 등급·인증 배지·할인율)를 그대로 둔 채, 3섹션에서 카메라·시계·스니커즈·가방 4개 카테고리 중 하나를 고르고 "매치 확신도 기준선" 슬라이더를 올리면 제출 → AI 프리스크린 → 컨디션 검증 → 판매자 인증 → 최종 매치, 5단계 퍼널이 실시간으로 좁아지며 그 숫자가 클로징 CTA 헤드라인까지 그대로 인용된다. 히어로에는 buyer/seller 토글을 쓰지 않고 구매자 관점 단일 내러티브로 밀었다.

## 색상 · 대비 실측 (§3)

- Accent = `#3454D1` (코발트 블루). 카탈로그 최다 사용 계열(amber 8·teal 8·violet-hex 7)과 최근 2회 우승작의 정확한 조합(light/blue-hex/grotesk, dark/emerald/wide)을 동시에 피하려고, 파란 계열이지만 디스플레이 서체는 grotesk 대신 `--font-display-mono`로 짝지었다.
  - `#3454D1` vs 흰 배경(`#FFFFFF`) → **6.30:1** — 본문 크기 AA(4.5:1) 통과, 페이지 배경 위 소형 텍스트로 그대로 써도 안전.
  - `#3454D1` vs 어두운 잉크(`#000000`) → **3.34:1** — large-text/non-text 바닥(3:1)만 통과, 소형 다크잉크 텍스트에는 쓰지 않음.
  - accent 채움 위 흰 텍스트 → **6.30:1**(대칭이라 동일) — 칩·버튼의 활성 라벨은 항상 흰색으로 고정.
  - `#3454D1` vs 틴트 패널(`#F4F4F2`) → **5.73:1** — 패널 표면에서도 본문 AA 통과, 별도 라이트 틴트 없이 원색 accent를 텍스트/아이콘 색으로 재사용 가능.
  - 소형 칩 텍스트 전용 진한 파생색 `#28409F`(ACCENT_DEEP) vs 흰 배경 → **9.03:1** — 여유 있게 통과.
  - muted zinc-500 `#71717A` vs 흰 배경 → **4.83:1**(통과) / vs 틴트 패널 `#F4F4F2` → **4.39:1**(AA 미달, 규정대로 실패 확인) → 그래서 패널 위 텍스트는 zinc-600 `#52525B`로 바꿨고, 그 값은 패널 대비 **7.02:1**로 통과.

## 본문 폭 역산 (§4, 0.44em/자, `ch` 금지)

- 17px 본문(섹션 인트로, 클로징 문단) → `70 × 0.44 × 17 = 523.6px` → `max-w-[524px]`. 검산: `524 / (0.44 × 17) ≈ 70.05`자.
- 18px 리드(히어로 서브헤드) → `70 × 0.44 × 18 = 554.4px` → `max-w-[555px]`. 검산: `555 / (0.44 × 18) ≈ 70.08`자.
- 두 값 모두 이 페이지에 실제로 쓰는 두 본문 크기에 맞춰 각각 따로 계산했고, Tailwind 클래스 문자열은 변수 보간 없이 리터럴로 박아 넣어 정적 스캐너가 인식하게 했다(`text-[${var}]` 형태로 쓰면 Tailwind가 클래스를 생성하지 못하는 걸 초안 작성 중 발견해 수정).

## 브리프에 없던 것

**1. 퍼널 데이터 모델 전체 설계**
① 배정은 "깔때기 시각화 — 폭이 넓은 입력에서 단계별로 좁아져 출력까지, 폭이 실제 카운트/퍼센트를 반영하고 실시간 재계산"이라는 형태만 정했고, 카테고리·단계 수·구체적 숫자는 전혀 없었다.
② 카테고리 4개(Cameras/Watches/Sneakers/Bags)마다 submitted(제출량)·preScreenRate·conditionRate·authRate 4개 고정 비율과, threshold 50~99 구간의 보간 제어점(curve) 7개를 직접 만들었다. 예: Cameras는 submitted 8,400 → preScreen 58% → condition 71% → auth 83% → 기본 threshold 80%에서 34% 통과 = 최종 976건(11.6%).
③ 모든 숫자는 `computeFunnel(category, threshold)` 순수 함수 하나로 역산 가능하게 짜서, 히어로의 정적 수치·퍼널 차트·클로징 CTA가 전부 같은 계산 경로를 통과하도록 했다(클로징 CTA가 "라이브 값을 인용해야 한다"는 §5 요구를 코드 구조로 보장).

**2. threshold 보간 방식 (Math.random 금지 대응)**
① "슬라이더를 올리면 실제로 재계산되어야 한다"는 요구는 있었지만, 연속값 threshold(50~99)에 대해 결정론적으로 카운트를 만드는 방법은 정해야 했다.
② 카테고리마다 7개 제어점(threshold, 남는 비율)을 고정 배열로 박아두고 선형보간(`lerpFraction`)하는 순수 함수로 처리했다. 난수·시간 의존 없이 같은 입력은 항상 같은 출력을 낸다.
③ 실제 신뢰도 분포를 갖고 있지 않은 상태에서 "기준을 올릴수록 더 적게 통과한다"는 단조감소 직관을 유지하면서 결정론성 요구(§6, `Math.random`/`Date.now` 금지)를 동시에 만족시키는 가장 단순한 방법이라고 판단했다.

**3. 퍼널 막대의 시각적 최소폭 바닥(`MIN_BAR_PCT = 5`)**
① threshold를 99%까지 올리면 최종 단계 실제 비율이 1~2%까지 떨어져 막대가 사실상 안 보이게 된다 — 브리프에 이런 극단값 처리 지침은 없었다.
② 렌더링 폭에만 5% 바닥을 걸고, 옆에 표시되는 숫자(카운트·퍼센트 텍스트)는 항상 바닥 없는 실제값을 그대로 보여주도록 분리했다. 즉 막대는 "보이게" 유지하되 숫자는 절대 왜곡하지 않는다.
③ 색만으로 정보를 전달하지 말라는 규칙(§6)과도 맞물려 있어서, 막대(장식·aria-hidden)와 텍스트(실제 정보)를 애초에 분리해 이 바닥이 "과장"이 아니라 "가독성 보정"에 그치도록 설계했다.

**4. 틴트 패널 위 muted 텍스트를 위한 두 번째 바디 토큰 세트**
① §3의 "라이트 테마 텍스트 바닥은 표면 톤에 따라 다르다"는 규칙은 서술로만 있었고, 이 페이지에서 실제로 흰 배경 섹션과 틴트 패널(`#F4F4F2`) 섹션이 섞여 있어 어디에 어떤 톤을 쓸지는 구현하면서 정해야 했다.
② `BODY`/`BODY_LG`(zinc-500, 흰 배경·흰 카드용)와 `BODY_PANEL`/`BODY_LG_PANEL`(zinc-600, 틴트 패널용) 두 세트로 나눴다. Product preview·Value·Closing CTA 섹션은 `#F4F4F2` 배경이라 `_PANEL` 계열을, Hero는 흰 배경이라 기본 계열을 쓴다. 매물 카드(`listing-card.tsx`)는 항상 `bg-white` 카드 위라 어느 섹션에 있든 zinc-500을 그대로 썼다.
③ 초안에서는 패널 섹션에도 기본 zinc-500을 그대로 썼다가 실측(4.39:1, AA 미달)하고 나서야 발견해 수정했다 — 표면 톤을 명시적으로 추적하지 않으면 놓치기 쉬운 실패라 토큰을 아예 두 벌로 분리해 재발을 막았다.

**5. 히어로 내러티브 형태 (buyer/seller 토글 회피)**
① §5의 "최근 두 라운드가 buyer/seller 토글 + 비슷한 클로징 문구로 수렴했다"는 경고는 있었지만, 대안 내러티브 구조는 직접 설계해야 했다.
② 히어로를 토글 없이 "대부분의 매물은 당신에게 도달하지 못한다"는 단일 구매자 관점 문장으로 고정하고, 카테고리·threshold 조작은 3섹션(퍼널)에만 배치했다. 소셜프루프의 테스트모니얼에는 판매자 목소리도 섞었지만, 이건 히어로의 인터랙션 메커니즘이 아니라 순수 카피이므로 경고 대상이 아니라고 판단했다.
③ 퍼널 자체가 "무엇이 통과하는지"를 보여주는 구조라, 별도 관점 토글 없이도 시각화 고유의 조작(카테고리·슬라이더)만으로 내러티브가 완결된다고 봤다.

**6. 활자 웨이트 정확히 3종 확정**
① "정확히 3종" 제약은 있었지만 어떤 굵기 3개를 쓸지는 자유였다.
② 400(본문 기본값, 별도 클래스 없이 브라우저 기본)/600(`font-semibold`: 라벨·칩·버튼·소제목)/800(`font-extrabold`: h1/h2/큰 통계 숫자)으로 고정하고, medium(500)·bold(700)·black(900)은 모든 파일에서 쓰지 않았다. 완성 후 `font-(thin|extralight|light|normal|medium|bold|black)` 정규식으로 전체 파일을 훑어 실제로 없는지 확인했다.
③ 디스플레이 서체(`--font-display-mono`)는 h1, 로고 워드마크, 푸터 워드마크, 통계 숫자, 퍼널의 "Final match rate" 큰 숫자처럼 스케일 대비가 큰 자리에만 인라인 스타일로 적용하고 본문·라벨·칩은 `--font-sans`(Pretendard) 기본값 그대로 뒀다.

**7. 히어로의 정적 수치 vs 클로징의 라이브 수치 구분**
① §5는 "클로징 CTA가 조작으로 만든 라이브 값을 인용해야 한다"고만 했고, 히어로에도 숫자를 넣을지·어떻게 넣을지는 정해야 했다.
② 히어로 하단의 "976 of 8,400 camera listings..." 문장은 `computeFunnel(DEFAULT_CATEGORY, DEFAULT_THRESHOLD)`를 빌드 타임에 한 번 계산해 박아 넣은 값이라 페이지 상태와 무관하게 고정이고(카테고리/threshold를 아직 아무도 안 건드린 시점의 "오늘의 기본값"이라는 성격), 클로징 CTA의 숫자는 `useState`로 끌어올린 `category`/`threshold`에서 매번 `useMemo`로 재계산되는 `result`를 직접 참조한다.
③ 같은 계산 함수를 쓰기 때문에 두 숫자가 "다른 소스"처럼 보이지 않으면서도, 요구사항이 명시한 "클로징만 라이브를 인용"이라는 구분은 분명히 유지했다.
