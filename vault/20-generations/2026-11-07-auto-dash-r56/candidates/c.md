Nodewatch — an SRE service-dependency map for repick's platform team: a hand-laid-out tiered node-link graph of 14 services, with a right-side detail panel that computes blast radius via live BFS over the edge list, and a full sortable/filterable adjacency-list table as the mandatory accessible fallback.

## Not specified by the brief

- **Exact indigo accent + contrast math.** Chose `indigo-600` (`#4F46E5`) as the single accent. Luminance L=0.11713; against white (L=1) the ratio is (1+0.05)/(0.11713+0.05) = **6.28:1** — passes for both "indigo text/icon on white" and "white text on indigo-600 button" (same pair of luminances, so the ratio is symmetric either direction). Status colors (separate channel from the accent, always paired with an icon + text label, never color-only): `emerald-700 #047857` → 5.48:1 on white; `amber-700 #B45309` → 5.02:1 on white; `red-700 #B91C1C` → 6.47:1 on white. All comfortably clear the 4.5:1 body-text floor. Muted text follows the surface-conditional floor: `zinc-500` only on white/`zinc-50` (4.83:1, right at the floor but passing), `zinc-600` on any `zinc-100`+ surface (7.7:1+, used in the segmented-control track and icon chips).

- **The actual service topology.** The brief named example services but not a real graph. Invented 14 services across 4 hand-laid tiers (edge → core services → support services → data stores) with 20 directed "depends on" edges, chosen so the graph is a real DAG (no cycles) and so at least one non-healthy node (`search-cluster`, degraded) has a non-obvious, multi-hop blast radius (4 services) — specifically to prove the BFS is doing real traversal rather than reading a hardcoded number: the "down" node (`notification-queue`) actually has a *smaller* blast radius (2) than the degraded `search-cluster` (4), because `search-cluster` backs `search-index`, which both `api-gateway` and `match-engine` call. The "View top risk" topbar action jumps to whichever non-healthy node that computation ranks highest — it's `search-cluster`, not the outage, and that's the point.

- **Graph layout technique.** Interpreted "hand-computed (x, y), no physics" as: node positions are percentages of a fixed 1180×980 design-grid rendered through an SVG `viewBox` with `preserveAspectRatio="none"`, so the whole diagram scales uniformly with its card's width without a second coordinate system. Edge endpoints are trimmed back from each node's raw center by `radius + gap` along the normalized direction vector (real trig: `Math.sqrt`, unit vectors), then rounded to 2 decimals, so arrowheads land cleanly on the node ring at any scale.

- **Mobile strategy for a graph that can't shrink to 390px.** The table becomes the *default* view below 640px (checked once via `matchMedia` in a mount effect, never used to decide SSR markup, so there's no hydration mismatch — the first paint is always "graph" and the swap happens client-side post-mount). The graph remains reachable via the Graph/Table toggle at any width, inside its own `overflow-x-auto` card with a `min-width` floor and a visible "scroll horizontally" hint on narrow screens, so it never silently clips or illegibly shrinks.

- **Which selections should and shouldn't share state.** Per the fan-out doctrine, graph-node selection (drives the right-rail detail panel, and is also what the command palette / "View top risk" / detail-panel dependency chips all write into) is one independent state; the adjacency table's row-expand accordion is a second, fully separate piece of state. Expanding a table row never clears the graph's selection and vice versa — clicking a dependency chip in the detail panel re-selects *within* the same graph-selection channel (that's navigation, not a new independent axis).

- **KPI tile set.** Brief's example list ("total services, degraded count, incidents today") plus "healthy" as a fourth, all four computed from the same `computeKpis()` reducer over `SERVICES` that the graph and table also render from — no hand-typed aggregate anywhere.

- **The "other nav sections" problem.** Sidebar ships five real items (Overview / Dependency map / Incidents / Deploys / Settings), each wired at both the desktop `<aside>` and the mobile drawer. Only Overview and Dependency map render the actual map experience (same content, since an ops "overview" *is* this map); Incidents/Deploys/Settings swap the main content for an honest "not wired up in this preview" placeholder rather than faking three more pages — the click still visibly changes the page, satisfying the wiring requirement without pretending the scope is bigger than it is.

- **Graph label width vs. the longest service name.** At the diagram's narrowest legible width, "notification-queue" doesn't fit two clean lines inside the 64px label box the way every other name does. Rather than let it mid-word-ellipsis-truncate (explicitly banned) or force an ugly three-line mid-word break, the *graph's own label only* displays "notif-queue"; the accessible name (`aria-label` on the node button), the detail panel, the command palette and the fallback table all keep the real `notification-queue` — so no information is actually lost, it's a display-only abbreviation in the one place genuinely too narrow for the full identifier.
