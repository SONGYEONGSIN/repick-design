# DECISION — auto-blog-r2

타깃: `blog` (신규 · 프로파일 부재 2라운드째 — [[page-brief-core]] §"타입 프로파일 목록" 규정대로 코어만으로 생성. `blog-deltas-provisional.jsonl`의 r1 델타(picsum 등 무작위 이미지 호스트 회피)를 GENERATE 사전 지침으로 명시 전달했다.)

큐 선정: 미충족 큐(`profile,blog,about,careers,contact,developers,integration,media-kit`)에서 이번 실행 중 이미 생성한 `profile`(1라운드 목표)을 제외하고 다음 항목인 `blog`을 뽑았다 — 스킬의 "연속 라운드는 순차로, 큐를 따라 내려간다" 규칙대로다.

다양성 축 사전 배정: 최근 5라운드(profile-r2·blog-r1·profile-r1·native-r1·paywall-r2) `variety`로 계산한 banList가 `face: ["wide"]`를 강제 회피로 산출했다(최근 3라운드 윈도우에서 2회 사용). 3후보에 서로 다른 축 배정: a=light/rose/grotesk · b=dark/emerald/mono · c=light/blue/(추가 디스플레이 폰트 없음, Pretendard 단독).

**모바일 nav 위험 사전 차단**: `auto-blog-r1`에서 3후보 전원이 모바일 nav를 대체 경로 없이 숨겼던 결함(질문 큐 Q16, target: blog)을 GENERATE 프롬프트에 명시해 이번 라운드는 3후보 전원에게 실제 접근 가능한 모바일 nav 구현을 요구했다.

## 후보
- **a — "Continuum"**: 시스템 엔지니어링 연구/교육 블로그. 시리즈 탭(`role="tablist"`)이 활성 시리즈를 넘버드 스테퍼(진행률 인디케이터+prev/next+읽음 표시)로 렌더링하고, 별도의 태그 필터링 독립 에세이 리스트가 아래에 이어진다. r1 3종(히어로+그리드/사이드바+리스트/월별 타임라인) 어디에도 없던 "시퀀스 소속 축 + 진행률 스테퍼" 조합.
- **b — "Baseline"**: 벤치마크 저널 블로그. KPI `dl` 통계 행 + Feed/Compare 뷰 토글 — Feed는 인라인 베이스라인-대-결과 바 차트가 있는 카드, Compare는 `aria-sort`가 실동작하는 시맨틱 `<table>`(효과크기/표본수/날짜 정렬)로 동일 필터 데이터셋을 재현한다.
- **c — "Keelson"**: 개발자 인프라 회사의 릴리스노트/체인지로그 블로그. sticky 좌측 "버전으로 이동" 인덱스(스크롤스파이 동기화) + 균일 카드형 세로 릴리스 스파인.

## 하드게이트
게이트 실행: `CHROME_PATH=/opt/pw-browsers/chromium PW_CHROMIUM_PATH=/opt/pw-browsers/chromium PW_NO_SANDBOX=1 node scripts/gate.mjs --target web --routes /blog-evolve/r2/<v>`. 전 후보 1차부터 전 항목 통과(static 위반 0 · weights 3종 · sweep 오버플로 0 · a11y a=95/b=100/c=100 · perf 기록만). a의 a11y 95는 하드게이트 임계(95)에 정확히 걸쳐 있으나 통과. 1-fix 루프 불요. 상세: SCORES.md.

스크린샷: 후보별 16장(4폭×4스크롤 지점), blank 판정 전원 통과(48/48).

## JUDGE 패널 (3렌즈, 블라인드 — 컨셉 문서 비공개, 스크린샷+소스만 전달)

### 렌즈1 — page-brief-core 준수 + 견고성 (모바일 nav 접근성 이번 라운드 가중 검사)
1위 b · 2위 c(근소) · 3위 a. **모바일 nav 결함은 이번 라운드 3후보 전원이 해소** — a는 `role="dialog" aria-modal="true"` 패널(포커스 이동+Escape+스크롤락), b는 인라인 `hidden` 토글 nav, c는 조건부 마운트 nav. 전원 390px 전 스크롤 깊이에서 도달 가능 확인, 이 결함으로는 순위가 갈리지 않았다. b는 이번 라운드 유일하게 완전히 동작하는 시맨틱 데이터 테이블(`caption`+`scope`+실동작 `aria-sort`)을 갖춰 브리프의 명시 체크리스트 항목을 유일하게 완수. **a — 실질 결함(하드게이트 미검출)**: `role="dialog" aria-modal="true"`를 선언했으나 실제 포커스 트랩이 없어 패널 마지막 링크에서 Tab하면 초점이 뒤의(시각적으로만 흐려진) 메인 콘텐츠로 계속 이동하고, "Primary" `aria-label` 랜드마크가 중첩 중복됨 — a11y=95(임계 근접)와 정합.

### 렌즈2 — 상용 완성도
1위 b · 2위 a · 3위 c. b: 카드마다 실측값을 인코딩하는 베이스라인-대-결과 바 차트(장식이 아닌 정보), Compare 테이블의 정렬·행별 방법론 펼치기까지 전부 상태 일관(`TOTAL_REPORTS`/`TOTAL_AUTHORS`가 소스 배열에서 파생, 드리프트 불가) — 이번 라운드 유일하게 생성형 자산이 정보를 온전히 전달. a: 시리즈 진행률(읽음 카운트·에세이 필터 카운트) 전부 파생값으로 일관되나, 커버 아트가 40-48px 소형 장식 스월이라 정보 전달력이 b 대비 얇음. c: 스크롤스파이(`IntersectionObserver`) 등 인터랙션 엔지니어링은 3후보 중 가장 정교하나(필터 제거 시 활성 인덱스 안전 폴백까지 구현), 릴리스 카드 커버 아트가 카드마다 동일 구성(색상만 변주)이라 반복될수록 순수 장식으로 읽히고, 390px에서 카드당 풀폭 16:9로 확대돼 가장 큰 화면 면적을 가장 적은 정보량에 씀 — "블로그"보다 SaaS 릴리스노트/제품 페이지에 가까운 장르 이질감도 감점 사유.

### 렌즈3 — 아키타입 차별성
1위 a · 2위 b · 3위 c. a: "시퀀스 소속을 축으로 삼고 그 축을 스테퍼/진행률로 렌더링"하는 조합은 r1 3종에도, 이번 라운드 b/c에도 전례가 없다 — blog-native(장문 연재·튜토리얼의 실제 관용구)로 판정(고신뢰). b: Feed/Compare 이중 뷰 자체는 신규 조합이나, KPI `dl` 통계 타일+`aria-sort` 데이터 테이블+신뢰도 배지 어휘가 [[dash-brief-v3]] 대시보드 프로파일의 어휘를 블로그 크롬 위에 얹은 것으로 읽혀 **이식**으로 판정(중신뢰) — blog에는 구조적으로 새로우나 어휘 자체는 빌려온 것. c: 좌측 고정 인덱스+세로 스파인 골격이 r1/b(카테고리 레일+리스트)의 재적용이자 r1/c(사이드바+타임라인)와도 겹치는 데다, "Product/Pricing/Start free trial" 내비+CTA가 블로그보다 SaaS 랜딩/제품 크롬에 가까워 3후보 중 가장 이식 판정에 가깝다(고신뢰).

## 집계
1위 표: b 2표(렌즈1·렌즈2) · a 1표(렌즈3) → **다수결 성립**, tie-break 불요. `auto-profile-r2`와 동형의 패턴 — 완성도(렌즈2)와 준수(렌즈1)가 수렴한 후보가 승자가 됐고, 렌즈3만 반대(가장 독자적인 후보를 1위에 둠)였다. 렌즈1이 지적한 a의 결함(불완전 포커스 트랩)은 승자(b)가 아닌 비승자 후보의 결함이므로 §3-1 정제 조치 대상이 아니다 — 아래 "비승자 결함 기록"에만 남긴다.

## 승자 — b (Baseline)

## 정제 조치 (§3-1)
불요 — 승자 b는 3렌즈 전원에게서 규칙 위반이나 하드게이트 미검출 결함을 지적받지 않았다(렌즈1이 "본질적으로 흠 없음"으로 명시). 하드게이트도 1차 전 항목 통과.

## 기권
없음 — 3렌즈 전원 정상 응답.

## 참고 — Q16 관측 갱신 (모바일 nav 공통 결함의 루프 유입 경로, 아래 §정제 게이트에서 반영)
`auto-blog-r1`에서 3후보 전원에게 있던 모바일 nav 결함이, 이번 라운드는 GENERATE 프롬프트에 **명시적으로 위험을 적어 전달**하자 3후보 전원이 해소했다 — 즉 "질문 큐에 기록된 관측"이 다음 라운드 설계자 지침에 직접 반영되면 재현을 막을 수 있음을 실증했다. 다만 이는 오케스트레이터(사람 또는 이 세션)가 수동으로 프롬프트에 적어 넣은 개입이지, 루프 자체가 과거 라운드의 "공통(비차별) 결함" 기록을 다음 라운드 GENERATE에 **자동으로** 흘려보내는 구조는 아직 없다. Q16의 핵심 질문("공통 결함에 루프로 들어올 자동 경로를 줘야 하는가")은 이번 라운드로 완전히 답해지지 않는다 — 오히려 "수동 개입이 통한다"는 것만 보여준다.

## 참고 — 비승자 결함 기록 (다음 라운드 방지용, 델타 미승격)
- a의 `role="dialog" aria-modal="true"` 모바일 패널이 실제 포커스 트랩 없이 모달 시맨틱만 선언한 패턴(탭 포커스가 흐려진 배경으로 계속 이동)은 이번 라운드 델타로 올리지 않았으나, 하드게이트가 못 잡는 결함 클래스로 재현 시 delta 편입 검토.
