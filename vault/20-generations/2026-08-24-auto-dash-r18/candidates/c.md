# r18-c — Trellis

**한 줄 컨셉** — Trellis(Northsail Labs 워크스페이스), SaaS 사용자 리텐션 분석 콘솔. 페이지의 주인공은 행=코호트 시작 월 / 열=가입 후 경과 개월인 **12×12 코호트 잔존 삼각행렬**(오른쪽 두 열 = 행 주변합 `규모`·`최종 잔존`, `<tfoot>` = 열 주변합 `가중 평균` + 평균 곡선 SVG)이고, 그 아래 얇은 보조 행 하나(세그먼트 요약 + 관측 기준)만 둔다. 적용 인터랙션 5종 — ① 셀 hover/focus 크로스헤어 리드아웃(행·열 머리글 동시 점등 + 방향키 격자 이동, 로빙 tabindex) ② 실제 정렬·필터(코호트 행 순서 `aria-sort` 토글 · 세그먼트 칩 5종 · 세그먼트 표 4열 `aria-sort` 정렬) ③ 지표 토글(계정/좌석/매출 잔존 3-옵션 세그먼트 컨트롤) ④ **기준 행 고정(pin-as-baseline)** — 코호트를 핀하면 격자 전체 인코딩이 절대 잔존율(순차 오렌지 램프)에서 기준 대비 델타 pt(발산형 warm/cool 램프)로 전환되고 행·열 주변합과 곡선 도메인까지 함께 바뀐다 ⑤ ⌘K 커맨드 팔레트(23개 명령: 지표·세그먼트·기준 코호트·정렬).

**핵심 증명의 코드 구조** — `baselineId`의 소비자는 `buildEncoding()` **하나**뿐이고, 돌아온 `GridEncoding` 객체만 격자가 읽는다. `selectedId`를 Viz/Ledger/Inspector 세 컴포넌트에 같은 프롭으로 threading 하는 배선은 없다 — 세그먼트 요약 카드와 관측 기준 카드는 핀의 존재 자체를 모른다. 핀은 위젯 세 개를 동기화시키는 장치가 아니라 **격자 자신의 인코딩 함수를 교체하는 장치**다.

**파일**
- `app/src/app/dash-evolve/r18/c/page.tsx` — 서버 컴포넌트 + `metadata`
- `cohort-data.ts` — 결정론적 데이터셋(정수 해시 PRNG). 세그먼트 규모를 합쳐 코호트 규모를 만들고, 좌석 = 계정 × 기본석 × 확장, 매출 = 좌석 × 좌석 단가로 파생시켜 셀·행합·열합이 산술적으로 어긋날 수 없게 했다
- `encoding.ts` — `buildEncoding()`(절대/델타 두 인코딩, 램프, 주변합, 곡선 도메인)
- `RetentionClient.tsx` / `AppFrame.tsx` / `CohortMatrix.tsx` / `CohortStack.tsx` / `SegmentPanel.tsx` / `CommandPalette.tsx` / `ui.tsx`

## 브리프에 없던 것

### 1. 셀에 인쇄할 잉크 색
- **정해야 했던 것**: 강도에 따라 셀 글자색을 분기할지, 한 색으로 갈지.
- **정한 값**: 절대 램프·발산 램프 양쪽 모두 `#18181B`(zinc-900) 단일 잉크. 분기 없음.
- **이유**: 램프 **전 단계**의 대비를 먼저 계산했다. 순차 램프 최악 `#F97316` 6.32:1, 발산 램프 최악 `#FB923C` 7.82:1 / `#94A3B8` 6.91:1. 한 단계 더 진한 orange-700은 3.42:1, slate-500은 3.72:1로 AA를 못 넘어 램프 상한에서 잘라냈다. 발산형은 양 끝이 다 진해지므로 "밝은 쪽 흰 글자·어두운 쪽 검은 글자" 분기가 가장 위험한 선택이고, 한 색이 전 구간을 넘도록 램프 자체를 설계하는 편이 유일하게 안전하다.

### 2. 램프 상한을 잔존율 100%가 아니라 75%에 둔 것
- **정해야 했던 것**: 절대 램프의 최상단 임계값.
- **정한 값**: `75% 이상`을 최고 단계로 두고, 그 단계의 색을 orange-500에서 멈췄다.
- **이유**: M0은 정의상 항상 100%라 최상단 색이 반드시 쓰인다. 상한 색을 더 진하게 잡으면 12개 행 전부의 첫 칸이 AA 경계에 걸리는 셀이 된다. 색 단계를 하나 잃는 대신 대비 마진을 6.32:1로 확보했다.

### 3. 델타 램프의 두 번째 극(polarity)
- **정해야 했던 것**: 액센트가 orange 1색인데 발산형 램프의 반대편 색.
- **정한 값**: 양(+)은 orange 계열, 음(−)은 slate 계열(중립 냉색), 중앙(±0.5pt 이내)은 순백.
- **이유**: 두 번째 유채색을 도입하면 1-액센트 규칙을 깬다. 온·냉 대비는 액센트를 하나로 유지하면서도 방향성을 즉시 읽히게 한다. 또한 부호(`+`/`−`)를 셀에 직접 인쇄하므로 색이 유일한 신호가 되는 구간이 없다.

### 4. 390px 대응 방식
- **정해야 했던 것**: 12열 격자를 좁은 폭에서 어떻게 다룰지(가로 스크롤 vs 레이아웃 교체).
- **정한 값**: `xl`(1280px) 미만에서는 표를 렌더하지 않고 **코호트별 스택 카드 + 월 칩 그리드**(390px 4열 → sm 6열 → md 12열)로 교체. 가로 스크롤은 어디에도 없다.
- **이유**: `table-fixed` + % 열 폭은 데스크톱 가로 스크롤은 피하지만, 390px에서 열 폭이 숫자 고유폭 아래로 압축되면 글자가 옆 열로 번지면서도 `scrollWidth`는 늘지 않아 sweep이 못 잡는다. 동시에 가로 스크롤 컨테이너를 쓰면 그 안의 `sr-only`가 `scrollWidth`를 오염시키는 별도 함정이 열린다. 두 함정을 다 없애는 유일한 방법이 레이아웃 교체였다. 모바일 칩은 비인터랙티브로 만들어 `target-size`(24×24) 논쟁 자체를 없앴고, 핀 버튼만 44px로 남겼다.

### 5. 격자를 SVG가 아니라 시맨틱 `<table>`로 만든 것
- **정해야 했던 것**: 삼각행렬의 구현 매체.
- **정한 값**: `<table class="table-fixed">` + `<caption>` + `scope="col"/"row"` + `aria-sort`, 셀은 `<td>` 안의 `<button>`.
- **이유**: 주변합이 `<tfoot>`와 오른쪽 두 열로 자연스럽게 표현되고, 포커스 표시·정렬 시맨틱·행/열 머리글 연결이 전부 공짜로 따라온다. SVG였다면 셀마다 포커스 가시성을 손으로 만들어야 했다.

### 6. 셀 포커스 링의 색
- **정해야 했던 것**: 전역 포커스 색(orange-600)을 오렌지 셀 위에서도 쓸지.
- **정한 값**: 격자 셀만 `focus-visible:outline-zinc-900` + `focus-visible:z-10`, 나머지 전부 orange-600.
- **이유**: 오렌지 셀 위의 오렌지 링은 거의 안 보인다. `ring-offset-*`(v4에서 투명하게 칠해짐)과 `outline-none` 선행(스스로 취소됨) 두 관용구는 전 코드베이스에서 사용하지 않았다.

### 7. 셀 클릭의 동작
- **정해야 했던 것**: 셀 버튼에 `onClick`을 줄지, 순수 리드아웃으로 둘지.
- **정한 값**: 셀 클릭도 그 행을 기준선으로 토글한다. 리드아웃 바에 이 규칙을 상시 문장으로 적어두었다.
- **이유**: 포커스 가능한 요소가 아무 동작도 안 하면 키보드 사용자에게 죽은 정지점이 된다. 격자 전체를 핀 표면으로 만들면 이 라운드의 핵심 문법이 어디서든 발동한다.

### 8. 지표 토글을 2안이 아니라 3안으로 한 것
- **정해야 했던 것**: 지표 세그먼트 컨트롤의 옵션 수.
- **정한 값**: 계정 / 좌석 / 매출 잔존 3안.
- **이유**: 2-옵션 세그먼트 토글은 직전 라운드에서 금지된 매크로 버킷의 구성요소다. 동시에 좌석·매출을 계정에서 파생시키면 세 곡선이 서로 다른 모양을 갖게 되어(계정 M11 ≈ 29%, 좌석 ≈ 63%, 매출 ≈ 70%) 토글이 장식이 아니라 실제 발견을 만든다.

### 9. 정렬을 "행 순서 뒤집기"로 한정한 것
- **정해야 했던 것**: 코호트 행을 규모·최종 잔존으로도 정렬할지.
- **정한 값**: 코호트 열은 시간순 오름/내림만, `aria-sort`는 그 축에 붙였다. 임의 정렬은 세그먼트 요약 표(4열)에서 제공한다.
- **이유**: 규모순으로 섞으면 행마다 길이가 제각각인 계단이 되어 삼각형이라는 형태 정보가 파괴된다. 삼각 형상이 이 작품을 카탈로그의 두 히트맵과 구분하는 지점이므로 그것을 지켰다.

### 10. 평균 곡선을 원이 아니라 스템+캡으로 그린 것
- **정해야 했던 것**: `<tfoot>`의 `colSpan=12` SVG를 어떻게 열 폭에 정렬시킬지.
- **정한 값**: `viewBox="0 0 120 46"` + `preserveAspectRatio="none"`, x = 오프셋×10+5, 마커는 원 대신 세로 스템 + 짧은 가로 캡, 선은 `vectorEffect="non-scaling-stroke"`.
- **이유**: 비균등 스케일에서 `<circle>`은 타원으로 찌그러진다. 세로선은 형태가 보존되고, 좌표를 소수 2자리로 반올림해 SSR/CSR이 정확히 일치한다.

### 11. 디스플레이 활자를 쓸 두 자리
- **정해야 했던 것**: `--font-display-grotesk`를 어디에 쓸지(한국어 UI라 대형 라틴 텍스트가 드묾).
- **정한 값**: 사이드바 워드마크 `Trellis`(19px), 그리고 격자 카드 헤더의 인코딩 모드 배지 `ABSOLUTE`/`DELTA`(15px, tracking 0.16em). h1과 본문은 전부 Pretendard.
- **이유**: 배정된 규칙은 "라틴 대형 텍스트에만"이다. 모드 배지는 핀 상태에 따라 바뀌는 유일한 라틴 대형 텍스트라, 디스플레이 페이스가 장식이 아니라 상태 신호를 맡는다.

### 12. 초광폭 캡 부재
- **정해야 했던 것**: `max-w` 캡을 둘지 말지.
- **정한 값**: 캡 없음. `main`은 `px-4 sm:px-6`(1920에서 우측 여백 24px)만 갖는다.
- **이유**: 셸(사이드바 256 + 좌우 패딩 48)을 뺀 1920의 가용폭이 약 1616이라, 규정상 캡을 둔다면 1660 이상이어야 한다 — 그 값은 어떤 뷰포트에서도 발동하지 않는 죽은 규칙이므로 아예 두지 않았다. 격자는 폭이 넓어질수록 셀이 커져 가독이 좋아지므로 캡의 이득도 없다.

### 13. ⌘K 버튼 라벨의 숨김 방식
- **정해야 했던 것**: 좁은 폭에서 검색 버튼 라벨을 어떻게 감출지.
- **정한 값**: `sr-only sm:not-sr-only` (그리고 `aria-label`은 쓰지 않음).
- **이유**: `hidden sm:inline`은 `display:none`이라 그 아래 폭에서 접근 이름이 0이 된다. `aria-label`로 덮으면 보이는 라벨과 접근 이름이 어긋나 `label-content-name-mismatch` 위험이 생긴다. 콘솔의 모든 아이콘 버튼도 같은 이유로 `aria-label` 대신 `sr-only` 텍스트로 이름을 만든다.

### 14. 더미 인명·도메인
- **정해야 했던 것**: 사용자·워크스페이스·이메일 값.
- **정한 값**: 서지우(애널리틱스 리드) / `sj@northsail.io` / Northsail Labs · Kestrel Data. 전부 가공.
- **이유**: 세션 컨텍스트에 보이는 실제 이메일·이름을 데이터에 옮겨 적지 않는다.

### 15. 관측 시각 문자열
- **정해야 했던 것**: "갱신 시각"을 어떻게 만들지.
- **정한 값**: 상수 문자열 `2025-10-02 09:14 KST`.
- **이유**: `new Date()`(무인자)·`Date.now()`는 하드페일이고, 하이드레이션 불일치의 고전적 원인이기도 하다. 데이터 관측 창(2024-10 – 2025-09)과 정합하는 고정 값으로 박았다.
