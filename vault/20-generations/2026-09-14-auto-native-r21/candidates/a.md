# Candidate a — Live Auction Bid: countdown + bid ladder + proxy-ceiling stepper

A single-item timed-auction screen — countdown clock, current-highest-bid readout, a scrollable bid ladder (bidder/amount/time), a bid-increment stepper with a destructive-confirm placement step, and an optional proxy "max auto-bid" ceiling that explains how it will auto-raise the user's bid.

## 브리프에 없던 것
- Countdown format ("H:MM:SS", e.g. "2:14:37"): brief said only "a countdown timer to auction close" with no format. Chose a single large tabular-nums string rather than three separate labeled fields (hours/min/sec boxes), for visual weight/restraint consistent with the "service-grade, no theatrical decoration" DNA rule.
- Deterministic "ticking" mechanism: brief requires no `Date.now`/`new Date`, but also implies a live countdown. Invented a pattern where a `setInterval` only increments a local counter (`tickCount`), and the displayed remaining time is `INITIAL_REMAINING_MS - tickCount*1000` — so the value is a pure function of state, not wall-clock, and the initial render (what a one-shot screenshot/gate sees) is exactly the fixed constant. This wasn't specified anywhere; I inferred it as the intersection of "must look live" and "must be deterministic."
- Bid ladder ordering & "leading" marker: brief says "list/ladder of recent bids" with no order specified. Chose most-recent-first (common leaderboard/chat convention) and added an explicit "▲ Leading" text chip on the top row (not just a border color) to satisfy the "never convey state by color alone" rule, since the top-of-ladder position + accent border alone would have been color/position only.
- Placing a bid = destructive-confirm two-step, not one-tap: brief didn't specify confirmation UX for the bid button. GENERATION.md §3 explicitly names "destructive-action confirmation → band becomes Cancel/Confirm row" as a valid form when a control commits money; I applied that pattern here since a bid is an irreversible monetary commitment, and wrote entirely new style keys/copy for it per the explicit instruction not to reuse band key names.
- Can't bid against yourself: brief didn't say whether the current highest bidder can re-bid. I disabled the Place Bid control (with a labeled reason, "You're Leading") whenever the user is already the highest bidder, since raising your own leading bid has no purpose in an English-auction model — an invented business rule, not stated in brief.
- Bid increment size, starting price, stepper ceiling (₩10,000 step, ₩150,000 start, stepper capped 20 increments above the current minimum): brief gave no numbers. Picked a plausible resale-camera price scale and a generous-but-bounded stepper cap purely as a UI safety rail (not a stated business rule).
- Auto-bid ceiling defaults/step/cap (₩320,000 default, ₩10,000 step, ₩800,000 cap): invented entirely; brief only said "optional max auto-bid setting... up to a ceiling."
- Auto-bid mechanism depth: rather than simulating live third-party counter-bids in real time (which would require either randomness or a scripted "opponent" event outside the brief's scope), I implemented auto-bid as a configured, explained setting ("Armed. Repick bids the minimum needed... stops at ₩X") plus an immediate ceiling bump on your own confirmed bid if your ceiling was set below your new bid. Full live proxy-vs-proxy simulation was judged out of scope for a static/deterministic screen.
- Item domain (camera, seller name, bidder names): all invented placeholder content since brief gave no specific item.
- Single live region placement: brief's §4 example explicitly names "you are currently winning/outbid" as the canonical live-region case for this screen type, so I put the one required live region there (not on the bid-bar confirm copy, to avoid two simultaneous live regions) — a direct decision, not really invented, but worth noting since it meant the destructive-confirm copy is deliberately NOT a live-announced alert.
- Type scale: reused the reference screen's rough scale (11/12/13/14/15/16/18/20/22/24/36) rather than inventing a new one, to stay consistent with the catalog's existing modular-scale convention.
