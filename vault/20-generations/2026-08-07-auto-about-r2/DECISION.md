# DECISION — auto-about-r2

타깃: `about` (2라운드째 · 프로파일 부재 지속 — [[page-brief-core]] §"타입 프로파일 목록" 규정대로 코어만으로 생성. 승격은 `/dash-falsify apply`에서만 일어나므로 `auto-about-r1`이 아직 `works.ts` 카탈로그에 없어 `about`이 이번 실행에서도 미채움 큐 선두로 다시 뽑혔다.)

**§0 타깃 선택 재실행 결과**: `IS_NATIVE_DAY` 체크(`new Date().getUTCDay()===1`) → 오늘(2026-08-07)은 금요일(5), native 고정 라운드 아님. 미채움 큐 조회(`works.ts` `PAGE_TYPES` vs `category:` 존재 여부) → `about`이 선두로 재선정. 라운드 번호 조회(`auto-ledger.jsonl`에서 `auto-about-r*` 최대값+1) → 2. Run id `auto-about-r2`.

**프로세스 이탈 고지 (중요)**: 이 세션 환경에는 SKILL §2·§4가 지시하는 3개 독립 designer 서브에이전트, 3개 독립 judge 서브에이전트를 병렬 기동할 도구(Agent/Task 계열)가 제공되지 않았다 — `ToolSearch`로 배포 도구 목록을 확인했으나 해당 계열 도구가 없었다. 이 라운드는 다음과 같이 대체 수행했다:
- **GENERATE**: 이 세션이 3개의 명확히 분기된 아키타입 지정(매크로 셸·인터랙션 메커니즘·색상/활자·중복 회피 목록을 사전에 서면으로 확정)을 스스로에게 부여해 순차 작성. designer 간 "비동기 완료 대기" 문제는 발생하지 않는다(순차 작성이므로 각 파일 작성 직후 상태가 곧 최종 상태).
- **JUDGE**: 이 세션이 3렌즈 각각의 판정 기준을 독립 순서로 적용(코드 재검토 + 48프레임 스크린샷 재검토를 렌즈 단위로 순차 수행). 완전한 프로세스 격리·블라인드는 아니므로, 판정 근거는 아래에 코드/스크린샷 구체 인용으로 남겨 사후 검증 가능하게 했다.
- 하드게이트·스크린샷 캡처·소스 해시 동결은 SKILL이 지시하는 스크립트를 그대로, 지시된 환경 변수로 실행했다 — 이 부분은 이탈 없음.

1위 b · 2위 a · 3위 c.

**b**: "네이티브 range 슬라이더가 고정 연도 레코드를 선택"이라는 입력×출력 조합은 about-r1의 세 형태(서사+타임라인/디렉토리+필터/다이어그램+스텝)에도, 이번 라운드의 a·c에도, 카탈로그 전체 26작품에도 없는 신규 메커니즘이다. 알파벳 점프 내비 + 행별 details라는 "사람 인덱스" 형태도 about-r1/b의 "칩필터+검색→그리드 재계산" 디렉토리와 입력(연속 스크럽 vs 이산 칩/검색)·출력(고정 레코드 스위칭 vs 실시간 재계산 그리드) 양 축에서 다르다.

**a**: sticky 세그먼트 통계 레일 + org-pod 디스클로저 + 화살표키 탭리스트 조합도 카탈로그·about-r1·이번 라운드 c와 겹치지 않는 신규 조합. 다만 "클릭하면 하위 항목이 펼쳐지는 목록"이라는 pod 디스클로저 자체의 부품 수준 메커니즘은 about-r1/a의 마일스톤 확장, about-r1/c의 모바일 폴백 아코디언과 동일 계열의 상용 위젯이라 "조립은 신규, 부품은 상용"(about-r1 DECISION이 c에 붙인 것과 같은 평가축).

**c — 가장 낮은 신규성**: 재생/정지 토글이 붙은 자동 진행 위젯이라는 개념 자체가 **같은 타입의 직전 라운드**(`auto-about-r1/c`의 "접근성 있는 재생/정지 파트너 로고 마퀴")와 겹친다. 콘텐츠 도메인(로고 연속 스크롤 vs 컬처 필러 카드 이산 전환)과 진행 메커니즘(연속 마퀴 vs 이산 슬라이드 advance)은 다르지만, "재생/정지 컨트롤이 붙은 자동 진행 요소"라는 상위 개념은 about 타입 자체 역사에서 이미 한 번 쓰였다 — 완전히 새로운 조합이라 보기 어렵다. 지역/직군 이중 select 필터도 개별 위젯으로는(네이티브 select) 카탈로그에서 이미 흔히 쓰이는 부품이라 조합 자체의 신규성이 a·b보다 낮다.

## 집계
1위 표: a 1(렌즈1) · b 1(렌즈3) · c 1(렌즈2) — **3파전 완전 동률**. `auto-about-r1`과 정확히 같은 패턴이 재현됐다(그때도 렌즈1=a, 렌즈2=b, 렌즈3=c로 완전 동률). [[curation-criteria]] "3파전 동률 tie-break 예외"와 "차별성↔완성도 상충 시 판정 방향"을 순서대로 적용한다.

**1단계 — 차별성↔완성도 상충 확인**: 아키타입 렌즈(렌즈3) 1위인 b가, 완성도를 재는 두 렌즈(렌즈1=브리프, 렌즈2=상용완성도) **양쪽 모두에서 동시에 최하위**다 — 그리고 그 사유가 추상적 취향이 아니라 렌즈1·렌즈2가 독립적으로 지적한 같은 구체적 결함(바이오 확장 표시 부재로 인한 콘텐츠 발견성 붕괴)이다. "완성도 다수결" 원칙에 따라 b를 우승 후보에서 제외한다.

**2단계 — 남은 a·c 사이의 동률**: "3파전 tie-break 예외"의 기본 규칙(브리프 렌즈 우선 유지, 단 아키타입 렌즈가 그 후보를 최하위로 명시했으면 제외)을 적용. 아키타입 렌즈(렌즈3)는 a를 **2위**로 판정했다(최하위 아님 — c가 렌즈3 최하위). 제외 조건 불성립. 따라서 기본값인 **브리프 렌즈(렌즈1) 1위 = a**가 승자로 확정된다.

## 승자 — a (Cordwell)
렌즈1 무결함 1위 + 렌즈2 무결함 2위(1위 c와 결함 유무 차이는 없고 콘텐츠 폭에서만 밀림) + 렌즈3 2위(최하위 아님, tie-break 제외 조건 미성립) — 세 렌즈 중 어느 것도 a를 최하위로 두지 않은 유일한 후보(`auto-about-r1`과 동일 구조: 그때도 승자 a가 세 렌즈 중 유일하게 무-최하위 후보였다).

## 정제 조치 (§3-1)
없음. 렌즈1이 지적한 `zinc-500`→`zinc-400` 대비 교정은 GENERATE 단계(코드 작성 중 자체 대비 계산 검증)에서 이미 완료된 상태로 게이트·판정을 받았다 — 판정 후 수정이 아니다. 판정본 그대로 승격.

## 기권
없음 — 3렌즈 전원 정상 응답(이 세션이 순차 수행).

## 참고 — 비승자 결함 기록 (다음 라운드·정본 후보용)
- **b — details 확장 표시 누락(재현 1회, L1 · Q8 판정 계열)**: `<summary>`에 `list-none`을 쓰면서 대체 시각 신호(쉐브론·플러스 아이콘)를 넣지 않으면 실제로는 상시-노출이 아닌 콘텐츠(바이오)가 발견되지 않는다. 같은 라운드 같은 후보의 다른 컴포넌트(`values-accordion.tsx`)는 정확히 이 문제를 아이콘으로 해결해, 한 라우트 안에서도 컴포넌트 간 일관성이 깨질 수 있음을 보여준다. 향후 규칙 후보: "`list-none`이 적용된 `<summary>`는 형제 요소로 확장 상태 아이콘을 반드시 동반한다" — 정적 검사로 잡기 어려운 시각적 완결성 규칙이라 judge 프롬프트 체크리스트 후보.
- **c — 재생/정지 위젯의 타입 내 재현(렌즈3 기록)**: `auto-about-r1/c`(로고 마퀴)와 `auto-about-r2/c`(컬처 필러 캐러셀)가 콘텐츠 도메인은 다르지만 "재생/정지 컨트롤이 붙은 자동 진행 요소"라는 상위 개념을 공유 — 같은 타입 내 재현 1회. 다음 about 라운드에서 세 번째로 재현되면 "About 타입은 재생/정지 자동진행 위젯을 매크로 차별화 축으로 인정하지 않는다"는 타입 특화 규칙 후보로 questions-queue 상정 검토.
- **about 타입 People 콘텐츠 계약 재확인(재현 2회째, r1→r2)**: `auto-about-r1`의 delta(People·Values 상시노출 요구)가 이번 라운드 3후보 전원에게 정확히 반영돼 재현 없이 방지됐다 — 델타가 실제로 다음 세대 브리프 역할을 한다는 실증. L1→L2 승격 근거로 아래 LEARN 참조.

## 지식 정제 게이트
`about-deltas-provisional.jsonl`이 이제 2건(r1·r2) — 클러스터링: r1 델타("People·Values 상시노출 계약")와 r2 델타("details 확장 표시 동반 의무")는 서로 다른 대상(섹션 존재 여부 vs 위젯 완결성)이라 충돌 없음, 병합 대상 아님.

**레벨 재책정**: r1 델타는 이번 라운드에서 **재현되지 않고 오히려 방지됐다** — 3후보 전원이 People·Values를 상시-노출로 설계해 지킨 결과다. curation-criteria의 L2 기준("2개 라운드 이상 재현")은 "위반이 2회 재현"을 뜻하지, "방지가 2회 재현"을 뜻하지 않는다 — 위반이 없으면 재현 카운트가 오르지 않는 구조이므로 이 델타는 L1에 머문다(단, "설계 단계에서 반영돼 위반이 발생하지 않았다"는 사실 자체는 델타가 실제로 유효했다는 방증이라 DECISION에 기록해 둔다 — 위 "참고" 참조). r2 신규 델타는 최초 관찰이라 L1 유지.

**질문 강제 생성**: 신규 질문 없음. c의 재생/정지 위젯 타입-내 재현(1회)은 questions-queue 승격 기준(충돌쌍 또는 meta-기준 정당화 불가)에 아직 못 미친다 — 세 번째 재현 시 재검토.
