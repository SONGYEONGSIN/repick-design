# Candidate C — Meshline (service-topology graph)

**One-line concept:** Meshline is a light, rose-accented service-reliability console for a fictional commerce platform, built around a hand-built, deterministically-laid-out SVG node-link dependency graph of 20 microservices and 32 calls between them — every node always prints its own error rate and throughput, edges encode health with both color and dash/thickness, and a click-to-pin node axis (a summary-strip stat) runs independently from a click-to-pin edge axis (a graph-card "traced dependency" readout), with fully ephemeral hover/focus tooltips layered on top of both.

## Implementation summary

- **Domain:** a service-dependency map for an observability/DevOps product (`api-gateway`, `auth-service`, `payments-service`, `fraud-service`, `primary-db`, etc.), not resale-ops/ARR/ticket-triage, and not previously used in this round.
- **Layout determinism:** `computeLayout(groupBy)` in `data.ts` buckets the 20 fixed `NODES` by `tier` or `domain` into fixed-order columns, then places each node at `PAD + column*colWidth` / `PAD + row*rowPitch` (rounded to 2 decimals) — no runtime force simulation, no trig. Toggling the "By tier / By domain" segmented control recomputes this synchronously and re-renders the same `<svg viewBox>` at a new fixed size (via `aspect-ratio` on the wrapper, so it stays fluid at every breakpoint with no horizontal scroll).
- **Edges:** each of the 32 calls gets a status derived from the worse of its two endpoints' health (never hand-duplicated), a stroke width from a sqrt-scaled `weightRps` (derived as `min(fromRps, toRps) * 0.35`, never hardcoded), and a quadratic-bezier curve whose control point is a fixed perpendicular offset keyed off the edge's index — deterministic, and it keeps the ~10 edges converging on `primary-db` from stacking exactly on top of one another.
- **Always-visible values (the catalog's documented graph failure mode):** every node prints its short name, current error-rate percentage (large, status-colored, `tabular-nums`), and throughput (`req/s`) directly on the node face in the default render — nothing is gated behind hover. Hover/focus adds p99 latency, saturation %, on-call owner, and a one-line incident note in a `role="tooltip"` panel positioned by percentage of the fixed viewBox (no DOM measurement, no hydration risk).
- **Pin vs. hover, on two different widget clusters:** clicking a node toggles a persistent `pinnedNodeId` that drives *only* the summary strip's "Focused service" card; clicking an edge toggles a separate persistent `pinnedEdgeId` that drives *only* a "Traced dependency" readout inside the graph card's own header — a different cluster from the summary strip. Hovering/focusing any node or edge sets fully separate, un-persisted `hoveredNodeId`/`hoveredEdgeId` state that clears on mouse-leave or blur and is guarded so it never renders on top of an already-pinned element's styling.
- **Keyboard-real graph:** every node and edge is an SVG `<g role="button" tabIndex={0}>` (not just an outline trick) — the pinned/hovered/connected states are driven by the same `onFocus`/`onBlur` handlers that also handle `onMouseEnter`/`onMouseLeave`, so a keyboard `Tab` genuinely changes a visible `fill`/`stroke` (rose ring or rose-tinted fill), independent of whether the browser also paints a CSS `:focus-visible` outline.
- **`label-content-name-mismatch` hardening:** each node's `aria-label` is built by joining the exact same formatter calls (`formatPercent`, `formatRps`) used by its visible `<text>` children, in the same order, and the JSX inserts literal `{" "}` text nodes between those `<text>` elements (SVG never paints character data outside `<text>`/`<tspan>`, so this is invisible) so the group's real `textContent` is guaranteed to appear verbatim as a prefix of the accessible name in both the pinned and unpinned states.
- **Accessible fallbacks:** a visible, sortable/filterable `NodeTable` below the graph (caption, `scope`, `aria-sort`, `table-fixed` + percentage `<colgroup>`, mobile-only horizontal scroll via `min-w` on the `<table>` element only) covers every node's own metrics; a separate screen-reader-only `AdjacencyTable` (sr-only on the wrapping `<div>`, never on the `<table>` itself) covers the edges — the relationship data the SVG conveys only visually.
- **Contrast pass:** `STATUS_META.text` was moved from `-600` to `-700` shades (emerald/amber/rose) after checking that `amber-600`/`emerald-600` fall below 4.5:1 on white at normal text sizes; every secondary caption sitting on a `bg-zinc-50` panel (workspace switcher, "Focused service", "Traced dependency", search trigger) was bumped from `zinc-500` to `zinc-600` to clear the tinted-surface minimum.
- All data is fixed literals or values reduced from them (`TOTALS`, edge `status`/`weightRps`/`strokeWidth`) — no `Math.random`, no `Date.now()`/bare `new Date()`. No `Intl.NumberFormat({ notation: "compact" })`; `formatCompact` divides/rounds by hand.
- Fictional personas only: Denise Okafor, Marcus Lindqvist, Priya Nair, Sana Al-Rashid, Tomas Vidal, Elin Novak (on-call leads) — no real names or emails from session context.

**Composition:** sidebar (Meshline lockup + workspace switcher + 6-item nav + user footer) + topbar (⌘K search trigger, Export snapshot, notifications, avatar menu, 44px controls) + page header (eyebrow, h1 "Service topology", tier/domain toggle, Export CSV) + summary strip (6 derived KPIs + Focused-service pin card) + graph card (legend, traced-dependency pin card, the dominant SVG graph, sr-only adjacency table) + sortable/filterable services table.

**Interactions (5):** (1) hover/focus tooltip on nodes and edges, keyboard-reachable, changing a real SVG fill/stroke on focus; (2) sortable + status-filterable services table; (3) "By tier / By domain" toggle recomputing fixed node positions; (4) persistent node-pin → summary-strip stat, independently persistent edge-pin → graph-card "traced dependency" readout, both distinct from ephemeral hover; (5) ⌘K command palette to search/jump to a service, which pins it and smooth-scrolls it into view (respecting `prefers-reduced-motion`).

**Theme/accent/type:** light (white/zinc-50 canvas, zinc-200 hairlines), rose brand/interactive accent; edge health uses its own independent emerald/amber/rose semantic scale (color + dash pattern + thickness, never color alone). `--font-display-wide` on the h1 and the sidebar brand lockup only. Exactly 3 rendered weights: 400, 500 (`font-medium`), 600 (`font-semibold`) — SVG `<text>` is excluded from that count per the brief.

## What wasn't in the brief

- The brief's "Interactions" list mentions a "live mini-chart" as a general (non-mandatory-for-this-candidate) bonus; I left it out entirely rather than bolting on an unrelated sparkline, since the graph itself is already the dominant, data-dense visualization and a second chart risked competing with it.
- I added a `Crosshair` "Focus" action button to every table row (in addition to clicking the node itself) so the table can drive the same node-pin axis without becoming a second, competing selection surface — it's an action, not a click-to-expand detail pane, and it doesn't change the table's shape.
- I went further than the brief's literal ask on SVG accessible-name safety: rather than trusting that a nicely-worded `aria-label` would satisfy `label-content-name-mismatch` against a multi-`<text>` composite button, I made the DOM `textContent` and the `aria-label` provably share a common prefix by construction (shared formatter calls + explicit `{" "}` separators), since I could not run the actual gate to verify empirically.
- I darkened `STATUS_META.text` from Tailwind's default `-600` semantic shades to `-700` (and bumped several `zinc-500` captions to `zinc-600`) after hand-computing WCAG contrast ratios, since the brief's contrast rules are stated as minimums and I had no way to run the automated checker myself.
