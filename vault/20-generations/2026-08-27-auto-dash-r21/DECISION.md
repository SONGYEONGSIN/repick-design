# DECISION — auto-dash-r21

## 실행 환경 이탈 고지 (round 1과 동일)

이 세션 환경에는 Agent/Task 서브에이전트 스폰 도구가 없다(round 1, `auto-dash-r20`에서 `ToolSearch`로 확인된 사실을 이번 라운드도 재확인 없이 승계). SKILL.md §2 GENERATE의 "designer 3병렬"과 §4 JUDGE의 "judge 3병렬(Agent 도구)"을 문자 그대로 수행할 수 없어, 이번 라운드도 오케스트레이터(나) 자신이 3후보를 순차 직접 작성하고 3렌즈 판정을 순차 직접 수행했다. 블라인드 원칙(judge가 컨셉·순서를 모른 채 판정)은 코드/스크린샷만 근거로 삼아 최대한 지켰으나, 완전한 프로세스 격리는 이 환경에서 구조적으로 불가능하다.

## 후보 요약

- **a — Meridian**: 5열 칸반 트리아지 보드(캘린더/보드 중심 아키타입, 최근 여러 라운드 미사용). 라이트/시안/wide. SLA 히트그리드는 우측 고정 레일에서 독립적으로 기간 토글.
- **b — Vantage**: 마스터-디테일 벤더 리스크 케이스 등록부. 라이트/로즈/mono. 5축 리스크 레이더(단일 소비자, 상시 텍스트 병기) + 타임라인 + 독립 findings 테이블.
- **c — Flowline**: 히어로+단일 지배 시각화(인라인 스탯 변주, KPI 4카드 없음). 다크/틸/디스플레이 폰트 미지정. Line+Confidence-Band 재고 예측 차트.

전 후보 상세: `candidates/{a,b,c}.md`(컨셉 + "브리프에 없던 것" 3항목씩).

## 하드게이트

전 후보 개별 통과 + 3라우트 결합 게이트 통과(정적·타입·린트·웨이트·sweep·focus·console·a11y 100·perf). 상세는 `SCORES.md`. **1-fix 루프 소모 없음** — 발견된 타입/린트/sweep 결함은 전부 GENERATE 단계(공식 첫 게이트 이전)에서 수정, 판정된 산출물은 처음부터 클린했다.

## 판정 커버리지 자진 신고

- 3후보 각 4폭(1280/1440/1920/390) × 4 스크롤(0/35/70/100%) = 48프레임 중, 직접 육안 확인한 것은 1440(전체)·1920(전체)·390(scroll 0)·1440(scroll 70%, a·c만) = 후보당 4~5프레임. 나머지(1280 전체, 1366/1600/1680 슬랙 폭, 1920 중간 스크롤, 390의 s35/s70/s100)는 **소스 코드 대조 + sweep/focus/a11y 게이트 실측**으로만 확인했고 육안 재확인은 하지 않았다.
- b의 findings 테이블·timeline 하단, c의 SKU 테이블 스크롤·필터 상호작용은 소스 로직 검토로 판정했고 클릭 후 스크린샷은 찍지 않았다(정적 프레임은 필터/정렬 이전 상태만 담는다) — 상태 분기 UI는 게이트의 `focus` 관문이 상태를 열어 재확인했으므로(⌘K 팔레트, 뷰 토글) 이 범위는 기계 커버리지가 있다.
- 소스 대조는 전 파일 전문을 읽었다(placeholder 없음).

## 렌즈 1 — 브리프 준수 (dash-brief-v3 + page-brief-core + page-brief-repo)

전 후보 매우 근접. 공통 충족: 진짜 라이트/다크(크림 없음), 앱 셸 전 요소(브랜드+워크스페이스 스위처+nav+유저 / 검색+⌘K+액션+알림+아바타), 인터랙션 4종 실동작, 웨이트 정확히 3종(렌더 실측), 영문 전용 카피(page-brief-repo §1 — `auto-dash-r18` 실패를 의식해 처음부터 영문으로 작성), 결정론 데이터, `next/image` 고정 Unsplash ID, 단일 h1·시맨틱 테이블·포커스 가시·색+아이콘 병행, 1920에서 인위적 cap 없음(스크린샷으로 확인 — 우측 여백은 페이지 패딩뿐).

**a(Meridian)**를 근소하게 1위로 둔다: `overflow-x-auto` 컨테이너를 단 하나도 쓰지 않았다(칸반 5열을 가로 스크롤이 아니라 CSS Grid `xl:grid-cols-5`로 전개, 열 내부는 `overflow-y-auto`) — 이번 라운드가 새로 읽은 `auto-dash-r20/a` delta(독립된 두 개의 넓은 `overflow-x-auto` 컨테이너가 각자는 클립해도 페이지 `scrollWidth`를 오염시킬 수 있음)를 remediation이 아니라 **애초에 그 결함 클래스가 존재할 수 없는 구조**로 선제 회피했다(`candidates/a.md` 항목 2에 그 판단 근거를 명시).

**b(Vantage)**를 2위로 둔다: 나머지 전 항목 a와 동급이나, 2단 그리드 브레이크포인트가 최초 `xl:`(1280px)로 잡혀 있어 좌측 레일(360px 고정)을 뺀 가용폭과 정확히 충돌해 1280px에서 13px 오버플로가 실측됐다(GENERATE 중 스스로 발견해 `2xl:`로 수정) — `dash-brief-v3`의 "1920 캡은 결과로 잰다" 원칙을 내부 그리드 브레이크포인트에도 적용해야 한다는 걸 뒤늦게 배운 흔적이 남는다.

**c(Flowline)**를 3위로 둔다: 최초 `Segmented<T extends string>` 제네릭과 숫자형 `Horizon` 상태의 타입 불일치로 `tsc` 3건 하드페일이 났다(경미하나 실제 타입 안전성 결함이었다). 또한 초안에서는 창고 스코프 토글을 차트+테이블 양쪽에 공유시켰다가 `r17`~`r20`의 selectedId-threading 경고를 뒤늦게 적용해 독립시켰다(`candidates/c.md` 항목 2) — 최종 산출물은 a·b와 동급으로 깨끗하지만 그 지점에 닿기까지의 경로가 가장 길었다.

**렌즈1 순위: a > b > c** (근소한 차이, 전 후보 하드게이트 100% 통과)

## 렌즈 2 — 상용 SaaS 완성도 (Mercury · Asana · n8n · Coinbase)

**c(Flowline)**를 1위로 둔다: 히어로 숫자(`89.7 days of cover`)의 타이포 확신감이 강하고, "Day 59: crosses reorder point" 주석이 실제 재고관리 도구에서 볼 법한 도메인 진짜배기 디테일이다. Line+Confidence-Band는 이 카탈로그의 어떤 이전 승자도 안 쓴 차트 형태이고, "오늘"과 "재주문선 교차" 두 핵심값만 상시 라벨링해 화면 잡음 없이 즉시가독 규칙([[dash-brief-v3]] "단일 지배 시각화 완성도" L3)을 정확히 지킨다. 디스플레이 폰트를 아예 안 쓴 선택도 다크·틸 배합과 어울려 절제된 확신으로 읽힌다.

**b(Vantage)**를 2위로 둔다: 레이더+상시 텍스트 범례 조합이 우아하고, 케이스 타임라인의 체크마크 진행 표시가 실제 GRC 툴(Vanta/Drata류)의 관용구를 정확히 재현한다. 상태 배지와 심각도 배지를 서로 다른 색 계열로 분리한 판단(`candidates/b.md` 항목 3)이 화면이 붐빌 때도 판독성을 지킨다.

**a(Meridian)**를 3위로 둔다: 완성도 자체는 b·c와 동급으로 높지만(카드·배지·프로그레스바 전부 정밀), 칸반+히트그리드 조합은 이 장르에서 가장 예측 가능한 형태라 "와우" 포인트가 상대적으로 약하다. 3위이지 결함이 있다는 뜻은 아니다 — 세 후보 다 완성도 하한을 훨씬 웃돈다.

**렌즈2 순위: c > b > a**

## 렌즈 3 — 아키타입 차별성

**a(Meridian)**를 1위로 둔다: "캘린더/보드 중심" 매크로는 dash-brief-v3가 명시한 4대 아키타입 중 최근 여러 라운드(r15~r20)에서 전혀 쓰이지 않은 버킷이다. 이번 라운드의 다른 두 후보(마스터-디테일, 히어로+단일시각화) 어느 쪽과도, r20의 세 버킷(코호트행렬/3페인트레이딩데스크/피드+불릿그리드) 어느 것과도 겹치지 않는다 — 이 라운드 안에서도, 최근 히스토리에서도 가장 신선하다.

**c(Flowline)**를 2위로 둔다: 히어로+단일시각화 매크로 자체는 r7/r9/r10에서 이미 쓰인 버킷이라 구조적 신규성은 a에 못 미친다. 다만 그 버킷 **안에서** 두 가지를 새로 했다 — ① 브리프가 예시로만 들었던 "히어로 숫자+인라인 스탯"(KPI 4카드 아닌) 변주를 이 카탈로그에서 처음 리터럴하게 구현했고 ② 지배 시각화 차트 형태(Line+Confidence-Band)가 이전 승자들(트리맵/Sankey·게이지/궤도-산점도)과 겹치지 않는다.

**b(Vantage)**를 3위로 둔다: 마스터-디테일 매크로는 이 카탈로그에 선례가 있다(`r12`류). 도메인(벤더 리스크)과 독립성 설계(선택의 유일한 소비자가 디테일 패널 그 자체)는 신선하지만, 골격 자체의 신규성 점수는 a·c에 못 미친다.

**렌즈3 순위: a > c > b**

## 집계

| | 렌즈1 | 렌즈2 | 렌즈3 |
|---|---|---|---|
| 1위 | a | c | a |
| 2위 | b | b | c |
| 3위 | c | a | b |

**1위 표: a 2표(렌즈1·렌즈3), c 1표(렌즈2).** 2:1 다수결로 **a(Meridian)가 승자**다. no-winner 표는 0건 — 억지 승자가 아니라 실제 다수결.

이 결과는 [[curation-criteria]] "Q32 판정"이 정리한 정상 형태(6라운드 중 5가 2-1)와 일치한다 — 반대한 렌즈는 매번 바뀌며, 이번엔 렌즈2(상용 완성도)가 소수 의견이다. 완성도와 차별성이 상충한 것이 아니라(둘 다 세 후보 모두 하한을 훨씬 웃돈다), **렌즈2가 도메인의 화려함(재고예측의 서사적 디테일)에, 렌즈1·렌즈3이 구조·규율(overflow 회피, 매크로 버킷 신선도)에 더 무게를 둔 결과**다.

## 정제 조치

이번 라운드는 판정 **후** 수정이 없다 — GENERATE 중 발견된 타입 에러(c)·sweep 오버플로(b)·미사용 import(c)는 전부 첫 공식 게이트 실행 이전에 고쳤고, 판정에 오른 산출물은 처음부터 클린했다. §3-1의 "판정 후 수정" 절차는 적용 대상이 없다.

## LEARN — 격리 적재 delta

승자(a)의 핵심 강점(overflow-x-auto 완전 회피)을 delta로 추출했다 — `auto-dash-r21/a`, L1/provisional, `dash-deltas-provisional.jsonl`에 append.

## 지식 정제 게이트 (§6)

- **클러스터링**: 이번 라운드가 새로 읽은 `auto-dash-r20/a`(두 개의 독립 `overflow-x-auto`가 상호작용해 페이지 오버플로를 만듦, 해법 = 두 번째 테이블을 % 컬럼으로 전환)와 이번 라운드의 신규 delta(`auto-dash-r21/a`, 보드형 아키타입은 애초에 `overflow-x-auto`가 필요 없다)는 **같은 결함 계열(다중 넓은 스크롤 컨테이너)의 인접한 두 교훈**이지만 서로 다른 국면을 다룬다 — 전자는 "두 스크롤러가 이미 공존할 때의 사후 처방", 후자는 "애초에 스크롤러를 안 만드는 예방 설계"다. **충돌 없음.** r21/a는 r20/a의 결함을 재현하지 않았다(a는 스크롤러가 애초에 0개였다) — 그래서 재현 임계(2라운드+)를 충족하지 못하고 신규 L1로 유지한다(승격 대상 아님).
- **재레벨링**: 위 이유로 재현 판정 대상 delta 없음 — L1→L2/L3 승격 없음.
- **질문 강제 생성 체크**: ① delta 간 충돌 — 없음(위 클러스터링 참조). ② meta-기준으로 정당화 불가한 패턴 — 없음. 이번 라운드 3후보 중 어느 것도 [[questions-queue]] Q46(단일 소비자 재인코딩 vs 다중 형제 threading)이 묻는 정확한 설계 지점을 다시 시도하지 않았다 — b는 선택의 소비자를 애초에 1개(디테일 패널)로 설계했고, c는 초안의 창고-스코프 공유를 판정 이전에 스스로 풀어 공유 자체를 없앴다. **Q46 재현 없음** — 큐에 새 관측을 추가하지 않는다(표본 그대로 유지, 다음에 실제로 같은 설계 지점이 시도될 때 판정).
- 신규 강제 질문 없음.

## 승격 판정 (2026-08-29 주간 apply) — **승격 보류, delta 만 채택**

**승자를 카탈로그에 올리지 않는다.** 이 라운드의 GENERATE·JUDGE 를 한 세션이 직접 수행했다(위 "판정 방식 고지" 참조) — 같은 세션이 후보를 만들고 그 후보를 판정했으므로 **블라인드·독립이라는 판정 체계의 전제가 성립하지 않는다.** 자진 고지는 옳았지만 고지가 판정을 유효하게 만들지는 않는다.

- **후보를 드롭하지도 않는다.** 판정이 유효하지 않으면 승자도 패자도 그 판정으로 처분할 수 없다. `dash-evolve/r20`·`r21` 디렉토리를 그대로 둔다.
- **delta 는 채택했다.** delta 는 렌즈 순위가 아니라 **실측·격리 실험**에 근거한다 — `r20/a` 의 이중 `overflow-x-auto` 누출은 한 후보 안 A/B 토글로 격리됐고, `r21/a` 의 CSS Grid 회피는 그 결함 클래스를 안 만드는 구조라는 사실 자체다. 둘 다 [[dash-brief-v3]] §완성도 기준 레이아웃에 L2 로 편입했다.
- **재배정 큐에 넣지 않았다.** 이 보류는 형태 탈락도 규칙 위반도 아니고 **판정 절차 결함**이라, 형태를 다시 만들게 하는 것은 처방이 어긋난다. 근본 원인은 [[questions-queue]] Q47 로 올렸다.
