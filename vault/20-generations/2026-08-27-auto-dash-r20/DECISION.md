# DECISION — auto-dash-r20

## 판정 방식 고지 (스킬 편차)

이 환경에는 `general-purpose` 서브에이전트를 병렬로 띄우는 `Agent`/`Task` 도구가 없다(`ToolSearch`로 확인 — 이 세션 자체가 이미 오케스트레이터로부터 위임된 서브에이전트이고, 재위임 도구가 주어지지 않았다). 따라서 SKILL.md §2의 "designer 3개 병렬 호출"과 §4의 "judge 3개 병렬 호출"을 이 세션이 직접, 순차적으로 수행했다 — GENERATE는 세 후보를 순서대로 직접 작성했고, JUDGE는 아래 3렌즈를 순서대로 각각 처음부터 다시 증거를 모아 판정했다(렌즈 간 상호 참조 없이 각 렌즈 절을 독립적으로 작성). **완전한 블라인드(제3자 에이전트가 컨셉을 모른 채 코드만 보고 판정)는 구조적으로 불가능했다** — 이 세션이 세 후보를 직접 만들었으므로 어떤 후보가 어떤 컨셉인지 이미 안다. 대신 각 렌즈는 실제 파일:줄·프레임을 다시 열어 근거를 재확인했고, 취향이 아니라 브리프·카탈로그 문구와 대조 가능한 사실만 근거로 세웠다. 이 편차는 최종 보고서에도 명시한다.

상태 해시: `9d2a70c740d0e34799afec010df458945d5cbeb1` (SCORES.md 참조 — 세 후보 전원 이 해시에서 게이트·스크린샷·이하 판정을 받았다).

## 후보 요약

- **a — Ridge**: 코호트 삼각행렬 + 기준행 고정. 다크 · rose · wide. `reassign-queue.md` #2 소비(사유: `auto-dash-r18/c`가 전량 한글로 탈락 — 형태 재배정).
- **b — Fathom**: 3-페인 트레이딩 데스크(워치리스트 레일 + 캔들스틱 차트 + 체결 피드). 다크 · blue · 활자 미지정(Pretendard만).
- **c — Lockstep**: 피드 중심 배포 콘솔 + SLO 불릿 그리드. 다크 · emerald · grotesk.

세 매크로 골격(매트릭스 주인공 / 3-페인 고정 레일 / 피드 중심)이 라운드 내에서 서로 다르다 — 사전 체크 통과.

## 렌즈 1 — 브리프 준수 (dash-brief-v3 + page-brief-core + page-brief-repo)

**순위: c > a > b**

- **c (1위)**: 색+아이콘+텍스트 삼중 인코딩이 페이지 전체에서 가장 일관되다 — 모든 불릿이 상태어("Healthy"/"Watch"/"Burning")·아이콘(`CheckCircle2`/`AlertTriangle`/`XCircle`)·정확한 %를 동시에 인쇄한다(`SloBulletGrid.tsx:40-45`). `charts.catalog`의 Bullet 행("AAA · 값 상시 표시(hover 아님)")을 문자 그대로 충족한다. 인터랙션 4종 모두 실동작 확인(필터·정렬·기간토글·팔레트 하이라이트).
- **a (2위)**: 매트릭스 셀은 항상 값을 인쇄하지만(즉시가독 충족), 상태 구분은 색+숫자 크기뿐이고 개별 셀에 아이콘/텍스트 라벨이 없다 — 다만 숫자 자체가 크기 정보를 담으므로 색맹 사용자도 매트릭스를 읽는 데는 지장이 없다(대비 계산도 사전 검증됨, `tokens.ts:66-89` 주석). 흠은 완성도(렌즈2)보다 이쪽에 하나 있다: 범례 4단계(`Weak/Watch/Healthy/Excellent`) 중 "Weak"(<40%) 밴드가 이번 더미 데이터에서 단 한 번도 발현하지 않는다(`a-1280-s35.png`: 최저값이 May 2025 M6의 57%로 이미 "Healthy" 문턱 근처) — 죽은 범례 항목. 기능 결함은 아니나 완성도 흠.
- **b (3위)**: `charts.catalog`가 Candlestick의 **필수 폴백**으로 "OHLC 테이블"을 명시하는데(`charts.catalog.md:54`), `PriceChart.tsx`에는 SR-only OHLC 데이터 테이블이 없다 — 대신 개별 캔들에 `aria-label`(정확한 O/H/L/C 포함)을 달아 스크린리더 접근은 되지만, 카탈로그가 이름까지 지목한 "테이블" 형태는 아니다. 또한 캔들 몸통이 상승/하락을 **색으로만** 구분한다(`emerald`/`rose` 채움, 패턴 없음) — `charts.catalog.md:54`가 명시한 "상승=채움/하락=빈칸 패턴"을 구현하지 않았다. 헤더의 ▲/▼ 화살표(`PriceChart.tsx:44`)는 색+아이콘 병행이지만 그건 헤더 통계고, 캔들 자체는 아니다. 두 항목 다 재현 가능한 구체 결함이라 감점.

**미확인 범위**: 세 후보 모두 실제 Tab 키 시퀀스로 포커스 순회를 직접 밟아보지 않았다(하드게이트 `focus` 관문 결과에 의존). ⌘K 팔레트를 열고 그 안에서 다시 검색해 결과가 필터링되는지는 코드 대조로만 확인했고 실행 브라우저에서 타이핑 테스트는 하지 않았다.

## 렌즈 2 — 상용 SaaS 완성도 (Mercury·Asana·n8n·Coinbase)

**순위: b > c > a**

- **b (1위)**: 워치리스트(스파크라인 + Up/Down 필터) · 캔들스틱(진짜 몸통+꼬리, 20거래일) · 체결 피드 세 패널이 실제 Coinbase Pro/Bloomberg 터미널급 정보 밀도로 동시에 성립한다(`b-1280.png`). 헤더 통계(가격·등락·고저)가 항상 노출되고 크로스헤어가 읽기 전용 정밀도를 더한다 — "조작이 증명을 지연시키지 않고 강화한다"는 tie-break 원칙(curation-criteria)을 정확히 따른다. 데스크톱 900px 뷰포트 안에 스크롤 없이 전체가 들어간다는 것 자체가(`b-1280.png`, `b-1440.png`, `b-1920.png` 전부 scroll=0에서 완결) 밀도 관리의 증거다.
- **c (2위)**: 배포 피드+SLO 그리드가 실제 Datadog/PagerDuty급 운영 콘솔로 읽힌다. `c-1440-s100.png`에서 확인된 카드 높이 불균형(피드 12행 vs 불릿 10행이 서로 다른 자연 높이로 짧은 카드 옆에 빈 여백)을 **판정 착수 전** GENERATE 단계에서 자체 발견해 두 카드를 `lg:h-[640px]` 공유 높이 + 독립 내부 스크롤로 고쳤다(`LockstepClient.tsx`, SCORES.md "Pre-judgment fix" 참조) — 재게이트 통과 확인. 남은 흠: 불릿 위험선(80%) 마커가 `bg-white/40` 1px 선이라 스크린샷에서 거의 안 보인다(`c-1440.png`의 billing-api 행 — 위험선이 필 끝과 겹쳐 사실상 안 보임). 정보 손실은 아니다(캡션에 "danger line at 80%" 텍스트가 있다) — 시각적 마감의 흠.
- **a (3위)**: 완성도 자체는 높지만(트리맵/생키급 정교함, 헤더 KPI 4장 정확), 시각적으로 세 후보 중 가장 "조용하다" — 다크+rose 단일 색상 매트릭스가 반복되는 12×12 그리드라 표현 밀도가 b·c보다 낮게 읽힌다. 코호트 표(`Cohorts` 카드)의 노트 텍스트가 1줄로 잘려("Crossed below the 60% watch line at month 6." 같은 문장이 `truncate` 처리, `SegmentTable.tsx:131` 인접 줄)일부 정보가 시각적으로만 losses 된다(스크린리더는 전체 텍스트를 읽으므로 접근성 결함은 아니다).

**미확인 범위**: 세 후보의 1366/1600px 프레임은 캡처는 됐으나 이 판정에서 직접 열어보지 않았다(1280/1440/1920 + 390만 검토) — 그 사이 폭에서만 발현하는 결함이 있다면 이 판정은 놓쳤다.

## 렌즈 3 — 아키타입 차별성

**순위: c > b > a**

- **c (1위)**: 두 축이 동시에 카탈로그 최초다 — ① 매크로 골격("피드 중심"이지만 지배 시각화를 중앙이 아니라 보조 패널에 배치, `d29`~`d40` 어디에도 없는 배치) ② 지배 시각화 자체(Bullet chart, `charts.catalog` 25종 중 dash 카탈로그에 한 번도 안 쓰인 타입). 선택 배선도 `r17`~`r19`가 반복 지적한 원시 `selectedId` 다중위젯 동기화를 쓰지 않고(팔레트→단일 하이라이트만), 피드 필터/정렬이 SLO 그리드에 전혀 안 닿는다(`LockstepClient.tsx` 주석 "필터링이 그것에 닿지 않는다").
- **b (2위)**: 매크로 골격은 브리프 자신이 예시로 든 "3-페인 마켓"이라 구조 자체의 신규성은 c보다 낮다. 그러나 지배 시각화(Candlestick)는 c와 마찬가지로 dash 카탈로그 최초이고, 도메인(FX/금리 데스크)도 처음이다. 선택 배선은 `r19`가 렌즈3 1위를 받은 바로 그 기법(부분재계산+비영속 인스펙터 분리)을 다른 도메인에 충실히 재현했다 — 재현이지 발명은 아니라는 점에서 c에 근소하게 뒤진다.
- **a (3위)**: 지배 시각화(코호트 삼각행렬)도 배선 기법(단일 소비자 재인코딩)도 `auto-dash-r18/c`(Trellis)의 재배정이다 — **재배정 메커니즘 자체가 그렇게 설계됐다**("탈락한 형태는 재배정 대상"), 그러니 낮은 신규성이 결함은 아니다. 다만 렌즈3의 순수 차별성 척도로는 b·c 둘 다 카탈로그에 없던 차트 타입을 도입한 반면 a는 이미 한 차례 이 프로세스가 만들어낸 형태를 언어만 바꿔 재현했다는 점에서 세 번째에 둔다.

**미확인 범위**: `/dash` 승격 카탈로그(d29~d40) 열두 편과 `dash-evolve` 누적 라운드(r13~r19, 아직 미승격) 소스를 전수 재대조하지 않았다 — SCORES.md·auto-ledger.jsonl의 승자 설명과 candidates/*.md 기록에 의존했다. 완전한 신규성 주장은 이 기록의 정확성에 기댄다.

## 승격 판정 (2026-08-29 주간 apply) — **승격 보류, delta 만 채택**

**승자를 카탈로그에 올리지 않는다.** 이 라운드의 GENERATE·JUDGE 를 한 세션이 직접 수행했다(위 "판정 방식 고지" 참조) — 같은 세션이 후보를 만들고 그 후보를 판정했으므로 **블라인드·독립이라는 판정 체계의 전제가 성립하지 않는다.** 자진 고지는 옳았지만 고지가 판정을 유효하게 만들지는 않는다.

- **후보를 드롭하지도 않는다.** 판정이 유효하지 않으면 승자도 패자도 그 판정으로 처분할 수 없다. `dash-evolve/r20`·`r21` 디렉토리를 그대로 둔다.
- **delta 는 채택했다.** delta 는 렌즈 순위가 아니라 **실측·격리 실험**에 근거한다 — `r20/a` 의 이중 `overflow-x-auto` 누출은 한 후보 안 A/B 토글로 격리됐고, `r21/a` 의 CSS Grid 회피는 그 결함 클래스를 안 만드는 구조라는 사실 자체다. 둘 다 [[dash-brief-v3]] §완성도 기준 레이아웃에 L2 로 편입했다.
- **재배정 큐에 넣지 않았다.** 이 보류는 형태 탈락도 규칙 위반도 아니고 **판정 절차 결함**이라, 형태를 다시 만들게 하는 것은 처방이 어긋난다. 근본 원인은 [[questions-queue]] Q47 로 올렸다.
