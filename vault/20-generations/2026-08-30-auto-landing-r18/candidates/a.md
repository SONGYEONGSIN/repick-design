# r18/a — Grading Timeline

한 줄 컨셉: 히어로 안의 5단계(Received→Inspected→Graded→Verified→Listed) 그레이딩 파이프라인 슬라이더를 스크럽하면 실제 카메라 한 대의 증거 다이어그램·결함 마커·인증 체크리스트·신뢰도/매칭/가격이 즉시 재계산되고, 그 state가 가치 3분할 섹션의 미니 스텝 컨트롤과 마무리 CTA 헤드라인까지 그대로 이어진다. 레스트 상태는 "Graded"(3/5)로 이미 가격·등급 증거가 노출된 중간 지점이다.

## 브리프에 없던 것

**1. 제품 도메인 및 대표 상품**
① 무엇을 정해야 했나 — "실제 증거가 붙은 실제 상품"이 구체적으로 무엇인지(브리프는 등급/인증/할인율 어휘만 규정).
② 무엇으로 정했나 — Canon AE-1 Program 35mm SLR 카메라(REPICK-CAM-0482)를 히어로의 고정 주인공으로, 프리뷰 섹션에는 이 카메라 포함 4종(가구 2, 액세서리 1)을 배치.
③ 왜 — "사진 증거"라는 컨셉이 카메라라는 상품 자체와 은유적으로 겹쳐서(초점·플로우) 파이프라인 서사를 가장 직접적으로 설명할 수 있음. repick-design 저장소명과 정합되는 "Repick" 브랜드 유지.

**2. accent 색상 계열 (hex 및 대비 계산 — 필수 기록)**
① 무엇을 정해야 했나 — violet/indigo 회피 + 라이트 테마 채택 시 선택한 색이 배경·잉크 양쪽에 대해 실제로 통과하는지.
② 무엇으로 정했나 — 베이스 accent `#B8791A`(브라스/앰버, 채움·보더·큰 텍스트용), 파생 딥틴트 `#8F5D12`(작은 텍스트/아이콘/포커스링용). 직접 계산한 상대휘도·대비:
   - `#B8791A` 자체: L=0.2397. bg(`#FAFAF8`, L=0.9549) 대비 = **3.47:1**(24px 이상/굵은 텍스트·필/보더는 통과, 작은 텍스트는 미달) · ink(`#111114`, L=0.0056) 대비 = **5.21:1**(작은 텍스트도 통과) · 순백 대비 = **3.63:1**.
   - 딥틴트 `#8F5D12`: L=0.1372. bg 대비 = **5.37:1**(작은 텍스트/아이콘/포커스링 통과) · 순백 대비 = **5.61:1** · ink 대비 = 3.37:1(참고용, 사용 안 함).
   - 채움 버튼 텍스트 규칙: `#B8791A` 채움 위에는 흰색이 아니라 **어두운 잉크**(`#111114`)를 사용 — 흰색은 채움 대비 3.63:1로 작은 텍스트 기준(4.5:1) 미달이지만 잉크는 5.21:1로 통과하기 때문. 이는 정본이 "드문 경우"로 언급한 "잉크가 독자적으로 4.5:1을 충족"하는 케이스에 정확히 해당.
③ 왜 — "등급/인증 도장(seal)"이라는 은유에 금속성 브라스 계열이 자연스럽게 맞고, 최근 라운드가 오렌지 계열(r17/a)을 이미 썼다는 점을 감안해 같은 웜톤이라도 채도를 낮춘 브라스/골드 쪽으로 이동시켜 차별화.

**3. 라이트 vs 다크 테마**
① 무엇을 정해야 했나 — "최근 라운드가 다크로 쏠렸으니 라이트를 고려하라"는 권고를 실제로 채택할지.
② 무엇으로 정했나 — 라이트 테마로 완전히 커밋(`bg #FAFAF8`, `ink #111114`, `muted #6B6B72`). 다크 모드 분기(`@media prefers-color-scheme: dark`, `[data-theme="dark"]`)는 의도적으로 생략 — 정본이 "단일 룩에 확정하는 디자인은 다크 블록을 생략해도 되지만 배경·색은 명시적으로 칠해야 한다"고 허용한 예외를 사용.
③ 왜 — 편집적/증빙 서류(inspection record) 느낌은 밝은 종이 질감의 라이트 테마가 "감사 가능한 문서"라는 개념과 더 잘 맞는다고 판단; 다크는 이미 카탈로그 다수를 차지해 구조적 차별화 여지도 라이트 쪽이 큼.

**4. 디스플레이 활자**
① 무엇을 정해야 했나 — candidate a에 배정된 `--font-display-wide`(Archivo Display)를 어디까지 적용할지.
② 무엇으로 정했나 — h1과 각 섹션 h2에만 적용(font-extrabold, letter-spacing -0.02em). 카드 제목(h3)·배지·칩·본문은 전부 Pretendard 유지.
③ 왜 — 브리프가 "large latin display text only (headlines 등)"로 명시적으로 범위를 좁혔으므로, 그 경계를 그대로 지킴 — 배지/칩까지 확장하면 사실상 두 번째 룩이 생겨 위계가 흐려짐.

**5. 폰트 웨이트 배정 (정확히 3종)**
① 무엇을 정해야 했나 — 400/600/800 중 어디에 무엇을 배정할지.
② 무엇으로 정했나 — 400(본문, 명시 클래스 없이 상속)/600(`font-semibold`: 라벨·배지·칩·카드 제목·CTA)/800(`font-extrabold`: h1·h2·큰 통계 숫자·가격). `font-normal`은 단 한 곳(파이프라인 스텝 버튼의 비활성 라벨)에만 명시적으로 사용.
③ 왜 — grep으로 실측 확인(`font-normal`/`font-semibold`/`font-extrabold` 세 클래스만 존재) — 4번째 웨이트가 프리플라이트나 `<strong>`/기본 버튼 스타일로 새어 들어오지 않도록 굵기가 필요한 곳은 전부 span에 명시적 클래스를 부여.

**6. 본문 문단 폭 계산 (`ch` 단위 금지, 0.44em 상수)**
① 무엇을 정해야 했나 — 65~75자 상한(목표 70자)을 만족하는 실제 px 컨테이너 폭.
② 무엇으로 정했나 — 히어로 서브헤드는 `max-w-[480px]` + `text-base`(16px): 480 ÷ (0.44×16) = 480 ÷ 7.04 ≈ **68.2자**. 다른 본문 문단(가치 3분할 설명, 카드 바디 텍스트 등)은 그보다 좁은 320~480px 컨테이너를 사용해 항상 68자 이하로 유지.
③ 왜 — 68자는 70자 목표에 가까우면서 75자 상한에 5자 이상 여유를 둬, 반응형으로 폰트가 살짝 커져도(그럴 일은 없지만) 안전 마진 확보.

**7. 그레이딩 파이프라인 단계 수·라벨·데이터**
① 무엇을 정해야 했나 — 브리프 예시("e.g. Received → Inspected → Graded → Verified → Listed")를 그대로 쓸지, 단계별로 무엇이 바뀌는지 구체적 수치를 어떻게 정할지.
② 무엇으로 정했나 — 브리프 예시 5단계를 그대로 채택하고, 단계마다 결정론적 고정 데이터셋 구성: 신뢰도 42→61→78→92→96, 매칭 구매자 3→7→14→21→24, 인증 체크 0/4→1/4→2/4→4/4→4/4, 가격은 Graded 단계부터 $186(원가 $310 대비 -40%)로 고정.
③ 왜 — 단계가 진행될수록 모든 지표가 단조 증가하도록 설계해 "스크럽 = 신뢰가 쌓이는 서사"를 숫자로 직접 체감시킴; 임의 값이지만 40% 할인이라는 라운드 숫자가 나오도록 가격을 역산(310×0.6=186)해 계산이 맞는지 검증 가능하게 함.

**8. 증거 다이어그램의 접근성 취급**
① 무엇을 정해야 했나 — "실제 증거(사진)"를 next/image 사진으로 할지 생성형으로 할지, SVG 안에 텍스트를 넣을지.
② 무엇으로 정했나 — 카메라를 단색 도형(사각형+원, 블루프린트 선화 아님)으로 구성한 인라인 SVG를 만들고 `aria-hidden`+`role="presentation"` 처리, `<text>` 노드는 전혀 넣지 않음. 같은 정보(결함 위치 설명)는 SVG 옆 실제 `<ul>` 텍스트 목록으로 중복 제공.
③ 왜 — line-art/블루프린트 장식 금지 조항을 피하려 채움 도형만 사용; SVG 텍스트를 아예 배제하면 "`aria-hidden`은 대비 검사 면제가 아니다"라는 조항이 걸릴 여지 자체가 없어짐. 실제 카메라 사진(next/image)은 사용하지 않았는데, 가상 상품에 정확히 맞는 고정 Unsplash 사진 ID를 검증 없이 고르는 위험(브리프가 명시적으로 경고)을 피하기 위함 — 상품 프리뷰 카드도 같은 이유로 전부 생성형 아이콘 타일.

**9. 포커스 링 구현**
① 무엇을 정해야 했나 — Tailwind v4에서 실제로 페인트되는 포커스 표시 패턴.
② 무엇으로 정했나 — `outline-none focus-visible:ring-2 focus-visible:ring-[#8F5D12] focus-visible:border-[#8F5D12]` 하나의 상수(`FOCUS_RING`)로 통일, `ring-offset-*`는 어디에도 사용하지 않음.
③ 왜 — 브리프가 명시한 두 가지 죽은 관용구(ring+ring-offset 조합, outline-none과 focus-visible:outline 조합)를 모두 피하고 box-shadow 기반 ring만 사용; 보더가 있는 요소는 보더 색 전환도 같이 일어나 이중 안전장치.

**10. 소셜프루프 수치**
① 무엇을 정해야 했나 — 실데이터 없는 상태의 신뢰 지표.
② 무엇으로 정했나 — "14,300+ 그레이딩 완료 / 4.9 / 5 평점 / 40% 평균 트레이드인 대비 초과 지급".
③ 왜 — near-monochrome·과장 없는 보이스에 맞춰 huge-round-number를 피하고, 40%는 히어로의 discountPercent와 같은 숫자를 재사용해 "이 40%가 어디서 나왔는지" 시스템 전체에서 일관되게 만듦(임의 숫자 남발 방지).

## 인터랙션 목록 (최소 4종 확인)

1. **히어로 타임라인 스크럽** — `<input type="range">`(스크럽) + 5개 스텝 버튼(클릭 점프), 둘 다 같은 `stage` state를 갱신. 이동 시 헤드라인·타임스탬프·증거 다이어그램의 결함 마커·설명 리스트·신뢰도/체크/매칭 수·가격 배지가 전부 즉시 재계산됨. 레스트 상태는 index 2(Graded)로 이미 가격·등급이 노출된 중간 지점.
2. **스크롤 트리거** — `Reveal`(framer-motion `whileInView`, viewport `once:true`)이 프로덕트 프리뷰/가치 3분할/소셜프루프/클로징 각 섹션에 적용. `useReducedMotion()`이 true면 `Reveal`이 애니메이션 없는 순수 `div`를 렌더링해 opacity:0 잔존 없음.
3. **프로덕트 프리뷰 카테고리 필터** — All/Photography/Furniture/Accessories 칩, `aria-pressed` + 색상(딥틴트)과 함께 별도 라벨 텍스트로 상태 구분(색 단독 아님), 4개 카드를 실시간 필터링.
4. **클로징 CTA 이메일 폼** — 정규식 검증(`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`) 후 성공 상태로 전환, `aria-invalid`/`aria-describedby`로 에러 연결, 네트워크 호출 없이 결정론적 로컬 상태만 사용.
+보강 5. **가치 3분할 미니 스텝 컨트롤** — 히어로와 동일한 `stage` state를 공유하는 5개 필 버튼이 섹션 안에 다시 노출되어, 여기서 조작해도 3개 카드(구매자/판매자/매칭엔진 관점)의 통계가 즉시 재계산됨 — "조작=체감 가치"를 값 3분할 섹션 자체에서 반복.
+보강 6. **소셜프루프 증언 캐러셀** — 이전/다음 버튼 + `role="tablist"` 점 인디케이터, `AnimatePresence`로 전환(reduced-motion 시 정적 blockquote로 대체).

## 상태 연속성 확인 (히어로 → 하단까지)

`client.tsx`가 `stage` state를 최상위에서 소유하고 `Hero`, `ValueSplit`, `ClosingCta` 세 컴포넌트에 그대로 내려보냄 — 히어로에서 스크럽한 결과가 가치 3분할의 미니 컨트롤에도, 마무리 CTA의 헤드라인·매칭 수·가격 언급에도 동일하게 반영됨. 히어로 이후 "라이브 상태가 죽는" 문제를 프로젝트 히스토리상의 문서화된 결함으로 인지하고 의도적으로 피한 구조.

## 폰트 웨이트 실측 확인

`grep -E "font-(thin|extralight|light|normal|medium|semibold|bold|extrabold|black)"` 결과 `font-normal`(1곳)/`font-semibold`/`font-extrabold` 세 종류만 검출. `font-medium`·`font-bold`·`font-light` 등 미사용.
