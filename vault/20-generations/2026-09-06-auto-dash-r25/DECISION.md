## 하드게이트 — b 탈락 (판정 미진입)
3후보 전원이 최초 게이트에서 `sweep` 실패, 원인이 전부 **같은 근본 오해**였다: `table-fixed` + `<colgroup>` 퍼센트 배분을 쓰면서 안전장치(`min-w`)를 개별 `<td>`/`<th>`에만 걸었는데, `table-fixed` 레이아웃 알고리즘은 첫 행 이후 셀의 `min-width`를 완전히 무시한다 — 그래서 세 후보 모두 "안전장치가 있다고 착각한 채 사실상 무방비"였다.
- **a(Parity)**: 390px에서 셀 겹침 50건 + target-size 1건 → 1-fix(테이블 자체에 `min-w-[900px]` 부여 + 작은 정렬버튼에 `min-h-6`) → 전 항목 통과.
- **b(Payline)**: 390px 셀 겹침 3건 + 1264px `table-overflow` 1px 2건 → 1-fix(테이블에 `min-w-[480px]`+래퍼 `min-w-0`)로 셀 겹침은 해소했으나 **1264px table-overflow 1px가 재실패** → 스킬 §3 "재실패 시 탈락, 사유 무관" 규칙에 따라 판정 진입 못함. 형태 자체(히어로 넘버+인라인 통계, 브리프가 명시적으로 권장하는 저활용 변주)는 규칙 위반 없이 살아 있었다면 유효했을 것이나, 게이트 재실패는 형태 판정이 아니라 그대로 적용된다.
- **c(Portage)**: 1264px(60px)·1280px(44px) table-overflow — 정반대 증상(모바일 겹침이 아니라 데스크톱 강제 스크롤, "데스크톱 테이블 가로 스크롤 금지" 규칙 위반). 원인은 전폭 섹션의 실가용폭(1264→900px·1280→916px)이 설계자 자체 계산 최소합(900px)+안전마진(960px)보다 좁았던 것 → 1-fix(`min-w-[960px]`를 `max-lg:min-w-[960px]`로 전환 — 데스크톱은 %열 배분만으로 유동, 모바일만 최소폭 안전장치 유지) → 전 항목 통과.

생존 2후보(a·c)로 판정 진행.

## 후보 요약
- **a — Parity**: 재고 실사 대사(reconciliation) 콘솔. 26행 밀집 데이터그리드가 페이지 주인공. 행 Pin(영속, `PinnedTray` 단일 형제만 전체 갱신·그리드는 경미한 하이라이트만) + SKU 호버(완전 비영속 스캔트레일 팝오버)로 파급 분기, 필터에서 벗어난 pin은 "out of sync" 배너로 UI 노출.
- **c — Portage**: 픽업 물류 디스패치 콘솔. 방사형 허브-스포크 SVG 맵(리터럴 지도 아님, 자체 캡션 명시)이 주 시각화, 활성 큐 레일 + 상세 패널 + 존부하 패널 + 트렌드차트 + 매니페스트 테이블 5개 워킹패널. Pin(영속, 맵+레일+상세패널 3형제 갱신·ZoneLoadPanel은 명시적 배제) + 마커 호버(완전 비영속 인스펙터).

## 판정
- **렌즈1(브리프/DNA 준수)**: a 1위. 결정 요인 둘 — ① a의 파급 분기가 형제 1개만 전체 갱신하는 더 좁고 깨끗한 구조(브리프가 경계하는 "균일 threading"에서 더 멀다) vs c는 3형제(맵·레일·상세패널)가 pin에 반응해 "표준 master-detail과 상호치환 가능"이라는 규칙이 경계하는 형태에 더 가깝다(단 ZoneLoadPanel 명시 배제로 완화). ② c의 주 시각화(방사형 맵)가 기본 레이어에서 호버 없이는 ETA·정류장수 등 수치가 전혀 안 보여 "단일 지배 시각화는 상시 텍스트 병기" 원칙을 a보다 더 크게 어김(위 KPI 4장은 별개 위젯).
- **렌즈2(상용 완성도)**: c 1위. a보다 워킹패널 수가 많고(6개 vs 3개) 인터랙션이 더 넓으며(6종 vs 5종, 맵 레이어 토글이 렌더 콘텐츠 자체를 바꿈), 테이블 크래프트도 스파크라인 열까지 갖춰 a와 동급 이상. a는 단일 워크플로우 화면으로는 탄탄하나 상용 벤치마크(Mercury·Coinbase급 멀티패널) 대비 상대적으로 얇다.
- **렌즈3(아키타입 차별성)**: c 1위. 방사형 허브-스포크 맵은 카탈로그에 전례 없는 시각화 형태(테이블·차트·캘린더·칸반 어디에도 없음)인 반면 a의 대시보드 뼈대(히어로 KPI카드→트레이→전폭 테이블)는 브리프가 명시적으로 경계하는 "기본값 폴백" 형태의 완만한 변주에 가깝다고 판정. 단 파급분기 실행 자체는 a가 더 정확하다고 인정(3형제 threading보다 1형제+명시배제가 규칙 문언에 더 가깝다).
