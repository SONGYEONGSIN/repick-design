# auto-landing-r15 후보 b — Swipe Deck Comparator

**한 줄 컨셉**: 8개 인근 매물을 손가락으로 Keep/Pass 스와이프하는 카드 덱이 태그 기반 취향 프로필을 실시간으로 쌓고, 그 프로필이 곧바로 같은 8개 매물의 랭크·match%를 다시 계산해 아래 그리드에서 눈앞에 재배열한다.

## 브리프에 없던 것

**① 액센트 색상 — teal `#0F766E`** ★ — ② 흰 배경(`#FAFAF7`) 위 흰 텍스트-온-필 대비 **5.475:1**(칩·버튼의 11px 흰 텍스트가 4.5:1 기준 통과), 어두운 잉크(`#111114`) 온 액센트는 **3.59:1**(∴ 채움 위 소형 텍스트 금지, 대형/굵은 텍스트·보더 전용 규칙 그대로 적용). 액센트 자체가 흰 배경 위에서 직접 텍스트로 쓰일 때도 **5.475:1**이라 별도 "밝은 틴트"가 필요 없었다 — 브리프의 틴트 공식은 어두운 배경을 전제하는데, 라이트 테마에서는 반대로 같은 색이 이미 충분히 어두워 소형 텍스트 기준을 자체로 만족했다. **직접 계산.** 바이올렛(`#6E56CF` 계열, 카탈로그 최다 8/49)과 블루(오늘 `auto-landing-r14`가 사용) 둘 다 회피.

**② 라이트 테마 선택** — ② `bg #FAFAF7` / 카드 `#FFFFFF` / 잉크 `#111114` / 캡션용 뮤트 `#6B6B76`(대비 **5.26:1**) / 본문용 진한 그레이 `#3F3F46`(대비 **9.99:1**, 계산 후 캡션보다 진하게 잡음) / 고스트 숫자 `#7A7A85`(대비 **4.06:1**, 대형 볼드 3:1 기준을 여유 있게 통과). ③ 최근 3라운드(r11/r12/r14)가 전부 다크로 수렴해 다양성 리인 명시 — 스와이프 덱이라는 촉각적 제스처 인터랙션에 종이 카드/실물 셀렉트 느낌을 주려면 밝은 표면이 카드 그림자·깊이감을 더 잘 살린다고 판단. **임의(다양성 대응).**

**③ 본문 폭 (0.44em, `ch` 미사용)** — ② `chars = width / (0.44 × font-size)`, 목표 70자. 히어로 리드 18px → `70 × 0.44 × 18 = 554.4` → `max-w-[554px]`. 섹션 본문 16px → `70 × 0.44 × 16 = 492.8` → `max-w-[493px]`(70.0자). 3-way 카드 본문 15px는 카드 실폭(`max-w-[440px]`)이 유효 상한 → `440 / (0.44×15) = 66.7자`. 랭크 카드의 12px 리즌 텍스트는 그리드 컬럼 폭(~280px)이 실효 제한 → `280/(0.44×12) = 53자`. **직접 계산, 전부 `ch` 미사용.**

**④ 스와이프 덱 데이터 구조** — ② 6개 스타일 태그(`oversized/tailored/minimal/workwear/denim/leather`) × 8개 고정 매물 목록(`LISTINGS`, 스와이프 순서 = 배열 순서, 셔플 없음). `history: {itemId,dir}[]` 한 배열만 상태로 두고 `deckIndex = history.length`(파생, 별도 state 없음)로 정합성을 강제. `profile`은 `history`의 순수 리듀스, `match% = clamp(base + Σ profile[tag]×3, 5, 99)`, 랭크는 `match desc, tie→원래 인덱스 asc`로 완전 결정론. 덱과 "당신을 위한 랭크" 그리드가 **동일한 8개 매물**을 공유하도록 설계 — "조작이 곧 가치"를 별도 프리뷰 이미지 없이, 같은 카탈로그가 눈앞에서 재배열되는 것으로 직접 증명. ③ 브리프가 "실제로 표시되는 증거를 재계산"하라고 요구했는데, 별개의 프리뷰 세트를 새로 만들면 그 연결이 눈에 안 보일 위험이 있었다. **조항 도출.**

**⑤ 스와이프 임계값** — ② `DRAG_PX_THRESHOLD=120px`, `DRAG_VELOCITY_THRESHOLD=600px/s`(둘 중 하나만 넘어도 커밋 — 표준 tinder-swipe 휴리스틱), `EXIT_DISTANCE=560px`, `EXIT_DURATION=0.16s`, 스냅백은 reduced-motion 시 `duration:0`, 아닐 때 `spring(stiffness:380, damping:30)`. 버튼 클릭도 동일한 `commitFly()` 경로를 타도록 nonce 기반 `trigger` prop으로 연결해 **드래그와 키보드 접근 버튼이 완전히 같은 결과**를 내게 함. ③ "결정론적 임계값, 랜덤 없음" 요구를 만족하면서 드래그·버튼 두 입력 경로가 다른 결과를 내지 않도록. **임의(표준값 채택) + 조항 도출(버튼-드래그 경로 통합).**

**⑥ Undo 상태 모델** — ② `deckIndex`를 별도 state로 두지 않고 `history.length`로 파생시켜, Undo(`history.slice(0,-1)`)가 인덱스·프로필·표시 매물을 자동으로 정합되게 되돌림. ③ 별도 `deckIndex` state를 뒀다면 undo 때 두 state를 함께 굴려야 해서 불일치 버그 표면적이 늘어난다. **조항 도출(단일 진실원.)**

**⑦ 디스플레이 활자 — `--font-display-mono`** — ② JetBrains Mono Display, h1/h2/큰 스탯/랭크 고스트 숫자에만 적용, 본문·카드 타이틀은 Pretendard 유지. ③ 브리프가 이번 라운드엔 grotesk(카탈로그 최다 9종) 대신 mono를 권장 — 스와이프로 "계산되는 프로필"이라는 데이터적 성격과도 결이 맞아 그대로 채택. **가이드 그대로 채택.**

## 웨이트·구조 감사

정확히 3종(400/600/800) — `font-medium`·`font-bold`·`<strong>`·`<b>`·`<table>`·`<th>` 0회. 단일 `h1`, `h2`→`h3` 순서 유지(초안에서 히어로 안 카드 타이틀을 `h3`로 뒀다가 `h1` 다음 `h2` 없이 등장해 레벨 스킵이 발생 — 발견 후 `p`로 교정). `aria-live` 정확히 1개(덱 옆 프로필 요약 문장, 색+아이콘+텍스트 병행). `outline-none` 미사용, 포커스는 전 인터랙티브 요소에 `outline-2 outline-offset-2 outline-[#0F766E]`. Math.random/Date.now/무인자 `new Date()` 0회 — 랭크 타이브레이크는 고정 배열 인덱스로.

## 인터랙션 5종

①드래그 스와이프 + 키보드 접근 Pass/Keep 버튼(동일 커밋 경로) ②Undo(마지막 스와이프 되돌리기) ③스크롤 진입 리빌(`whileInView`, 진입 0.22s, reduced-motion 시 즉시) ④랭크 카드 hover 리프트 ⑤프로필 바·랭크 그리드·클로징 CTA 문장이 전부 `history` 상태의 순수 함수로 실시간 재계산.

이미지 8종은 저장소에 이미 검증된(`v7`/`v10`/`v12`/`landing-client` 등에서 재사용 중인) Unsplash 고정 URL만 사용 — 이번 세션에서 `images.unsplash.com`으로 직접 curl 검증이 프록시에 막혀, 레포 내 기존 사용 이력으로 실재를 대신 확인했다.
