# auto-landing-r15 후보 a — Negotiation Transcript (AI 구매 에이전트 대화)

**한 줄 컨셉**: 방문자가 자신의 상한가(ceiling)와 협상 스타일만 정하면, **AI 구매 에이전트가 판매자와 실제로 주고받는 채팅 트랜스크립트**가 매 라운드 재계산되어 타임스탬프와 함께 쌓이고, 끝에 정착가(SETTLED) 또는 결렬(NO DEAL) 카드로 수렴한다 — 차트·게이지·테이블이 아니라 순수하게 텍스트/말풍선으로 증거를 나른다.

## 형태

- 말풍선 2종(에이전트/판매자) + 타임스탬프 + 정착가 카드. 슬라이더/다이얼/테이블 없음.
- `negotiate(listing, target, style)` 순수 함수가 앵커(anchor)→라운드별 오퍼→정착가를 전부 결정론적으로 계산 (`app/src/app/landing-evolve/r15/a/data.ts`). `Math.random`, `Date.now`, 인자 없는 `new Date()` 전무 — 타임스탬프는 고정 문자열 테이블(`TIME_TABLE`)에서 인덱스로 가져온다.
- 핵심 논증: 에이전트는 **상한가까지는 가지만 공정가(fair value)에서 멈춘다** — 상한을 올려도 정착가가 그 이상으로 따라 올라가지 않는 것이 "감정적으로 협상하지 않는다"는 주장의 직접 증거.

## 인터랙션 5종 이상

| 조작 | 갱신면 |
|---|---|
| 매물 탭 3택 (히어로 + 상품 프리뷰 카드) | 카테고리·글리프 패널·proof 칩 4종·asking price·앵커/공정가/바닥가 전체 재계산 · 트랜스크립트 전량 교체 · 정착/결렬 카드 · 3-way 카드 값 · 클로징 CTA 문구 |
| 상한가 스테퍼 (−/+ 버튼 + 숫자 입력, 히어로와 §3 두 곳에 동일 상태 배선) | 정착가 유무(딜/노딜) 분기 · 트랜스크립트 전 메시지의 오퍼 숫자 · 헤드룸 % · 3-way 카드 02/03 · 클로징 CTA |
| 협상 스타일 토글 (Patient/Fast close) | 라운드 수(3↔2) · 메시지 톤 · 오퍼 곡선 · 정착가/결렬 여부까지 바뀔 수 있음 |

| 상품 프리뷰 카드 "Negotiate this" 클릭 | 활성 매물 전환 + `#negotiation` 앵커 스크롤 |

**초기 상태**: 3개 매물 전부 기본 상한가가 공정가보다 높게 설정되어 있어 첫 렌더부터 이미 딜이 성립한 트랜스크립트가 보인다 (Meridian A7: $990 정착, ask $1,180 대비 −16%, retail $2,400 대비 −59%). 상한을 바닥가 아래로 내리면(NO DEAL 카드) 결렬 상태도 직접 확인 가능 — 이 상태 역시 기본 톤(흰색/회색 텍스트)만 쓰므로 AA를 그대로 통과한다(별도 대비 계산 불필요, 상태 전환마다 새 색을 쓰지 않았다).

## 브리프에 없던 것

**① 3항 협상 모델 — anchor → fair-capped settle → floor 결렬** ★ — ② `naturalSettle = round5(clamp(fair*0.96, floor, ask))`, 최종 정착가 `= clamp(min(naturalSettle, target), floor, ask)`; `target < floor`면 별도 결렬 분기(에이전트는 상한까지, 판매자는 바닥까지 각각 수렴하지만 만나지 않음). 라운드별 오퍼는 `anchor/ask`에서 정착가까지 `style.fractions`(patient: `[0.4,0.7,1.0]`, fast: `[0.55,1.0]`)로 선형 보간. ③ "상한을 올려도 에이전트가 상한까지 다 안 쓴다"는 게 이 페이지의 핵심 주장인데, 단순 보간(정착가=상한)으로 짜면 상한을 계속 올릴 때 정착가가 무한정 따라 올라가 주장이 성립하지 않는다. `naturalSettle`을 상한과 별개의 상수로 분리해서, 상한이 공정가보다 넉넉하면 정착가는 공정가 근처에 멈추고, 상한이 빠듯하면 상한 자체가 정착가가 되는 두 갈래를 모두 만들었다. **임의 (수치·공식 자체는 브리프에 없음)**

**② 결렬(NO DEAL) 상태를 별도 색 없이 설계** ★ — ② 결렬 카드도 딜 카드와 동일하게 흰색/뮤트 회색 텍스트만 사용, 점선 테두리(`border-dashed border-white/25`)로만 구분 — 새 hue를 쓰지 않음. ③ 브리프의 "인터랙션으로만 도달 가능한 상태도 AA를 통과해야 한다"는 요구를 만족시키는 가장 안전한 방법은애초에 그 상태에 새 색을 안 쓰는 것이었다. accent(에메랄드)는 오직 "딜 성사" 의미로만 예약해서, 결렬 상태가 accent를 오염시키지 않게 했다. **임의**

**③ 액센트 — emerald, 직접 계산** — ② 채움/보더/대형 텍스트용 베이스 `#047857`, 소형 텍스트·아이콘·포커스링용 틴트 `#6EE7B7`. **계산**: `#047857` 위 흰 텍스트 상대휘도 대비 **5.48:1**(본문 AA 통과) / 다크 잉크(`#0B0B0F`) 대비 **3.58:1**(대형 텍스트 3:1만 통과, 본문 4.5:1 미달 — r10에서 실증된 패턴과 일치). `#6EE7B7` 대 배경 `#0B0B0F` **12.89:1**(소형 텍스트·포커스링 여유 충분). ③ violet·blue 회피 조항 + "협상 성사 = 초록"이라는 보편적 색채 관습이 정직성 주제와 맞아, 계열은 emerald로 정하고 실제 sRGB→선형 변환으로 두 대비를 손계산해 로그로 남겼다. **임의 + 직접 계산**

**④ 디스플레이 서체 — `--font-display-mono`** — ② h1, 정착가 숫자, 스탯 카드 값, 인용부호, 섹션 인덱스 넘버에만 적용, 본문/한국어 없음(영문 카피). ③ 오늘 라운드는 `grotesk`·`wide` 과다사용 회피 조항이 `mono`를 우선하라고 명시했고, 마침 "협상 로그/타임스탬프 트랜스크립트"라는 소재 자체가 모노스페이스 활자의 터미널·장부 톤과 실제로 맞아떨어져 선택 이유가 이중으로 성립했다. **임의 (조항 준수 + 소재 적합성)**

**⑤ 본문 폭 — `ch` 미사용, 0.44em 역산** — ② 히어로 서브헤드 `520px @17px → 520/(0.44×17)=69.5자`; 섹션 인트로 `488px @16px → 488/(0.44×16)=69.3자`; 카드/인용 본문 `440px @15px → 440/(0.44×15)=66.7자`. 전부 70자 근처, 75자 상한에 16px+ 여유. ③ 브리프가 명시한 상수를 그대로 적용, `ch` 단위는 어디서도 쓰지 않았다. **브리프 값 적용, 임의 아님**

**⑥ 매물 3종 — 생성형 "사진" 패널** — ② 실제 이미지 없이 그라디언트 배경 + 대형 글리프(`A7`/`C14`/`BT`) 카드로 대체(`next/image` 미사용, 외부 이미지 0). 매치%·등급·인증·할인 배지는 패널 **아래** 별도 행에 배치(오버레이 금지 규칙 준수). ③ 브리프가 "이 아키타입은 사진이 없어도 된다"고 명시했고, 협상 트랜스크립트가 페이지의 실제 증거이므로 사진 대신 생성형 마크로 카드 정체성만 주고 시선을 대화로 모았다. **임의**
