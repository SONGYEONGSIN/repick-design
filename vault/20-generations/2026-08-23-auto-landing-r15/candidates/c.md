# auto-landing-r15 후보 c — Live Bid/Auction Ticker Board

**한 줄 컨셉**: 방문자가 카테고리 필터·정렬·목표가(target price) 슬라이더를 조작하면 5개 매물의 실시간 오퍼/워처/가격인하 티커 로우가 즉시 재정렬·재계산되고, 목표가 이내로 들어온 매물에는 accent 하이라이트가 두 개의 행 기반 표면(리스팅 스트립 + 활동 피드) 모두에서 동시에 붙는다 — 차트·게이지·사진 없이 순수 로우 + 타임스탬프 + 수치 델타(▲▼)만으로 유동성과 긴급성을 증명한다.

## 형태

- 히어로 오른쪽 패널이 두 개의 로우 기반 표면으로 구성: (1) **리스팅 스트립** — 5개 매물을 매치%·등급·인증·before/after 할인까지 첫 폴드에서 바로 노출(스크롤 불필요), (2) **활동 피드** — 시간·매물명·이벤트종류(OFFER/MARKDOWN/WATCH)·델타(▲▼)를 20개 로우로 나열, `max-h-[300px] overflow-y-auto`로 내부 스크롤.
- `TICKER_EVENTS`(`data.ts`)는 20개 이벤트, 오름차순 **리터럴** 타임스탬프(`"14:02:03"`, `"14:44:33"` 등)로 고정된 배열. `Date.now()` / `Math.random()` / 인자 없는 `new Date()` 전무 — grep으로 확인, 매칭 없음.
- "살아있다"는 인상은 2.4초 고정 인터벌로 피드 로우 하나씩을 순서대로(배열 인덱스 mod, 결정론) 펄스 하이라이트하는 것으로만 낸다 — 콘텐츠·수치는 전혀 바뀌지 않고 `opacity`만 움직이므로 `aria-live` 스팸이 없다. `prefers-reduced-motion`이면 `setInterval` 자체를 시작하지 않아 완전히 정지(고정 상태).
- 사진 0장 — `next/image` 미사용, 외부 이미지 0건. 순수 타이포/숫자 티커 보드로만 구성(브리프가 "이 아키타입은 사진이 거의 필요 없다"고 명시한 것을 그대로 따름).

## 브리프에 없던 것

**① 액센트 — 딥 앰버 `#B45309` / 틴트 `#F3B457`, 직접 계산** — ② sRGB→선형 변환으로 손계산: `#B45309`(채움/보더/≥24px 텍스트) 대 배경 `#0B0B0F` **3.91:1**(대형 텍스트 3:1만 통과, 본문 4.5:1 미달 — 정본 패턴과 일치). 그 채움 위 흰 텍스트 **5.02:1**(소형 텍스트 AA 통과), 다크 잉크(`#0B0B0F`) **3.91:1**(대형/굵게만 허용, 실제로 "TARGET PRICE" 숫자 22px bold에만 다크 잉크 사용하고 그 위의 9px 라벨은 흰색으로 분리 배치). 틴트 `#F3B457` 대 배경 **10.74:1**(소형 텍스트·아이콘·포커스링·델타 글리프 전부 이걸로). ③ violet·blue 회피 조항 + 오늘 라운드 후보 a가 이미 emerald를 썼음을 확인 → hue 자체는 겹치지 않는 앰버를 선택. 순수 대비 계산으로 처음 시도한 밝은 앰버(`#F5A623`, 배경 대비 9.69:1)는 흰 텍스트 대비가 **2.03:1**로 완전히 실패해서(채움 자체가 너무 밝아 흰 글자가 안 보임) 폐기하고, 정본 보라색과 유사한 밝기대(배경 대비 3.5~4:1)로 되돌려 `#B45309`를 골랐다 — "accent는 자유지만 밝기(luminance)가 정본과 크게 다르면 흰/다크 잉크 선택 규칙 자체가 뒤집힌다"는 것을 실측으로 확인. **임의 + 직접 계산**

**② 델타 색상 — 방향 대신 accent 단일색 + 글리프** — ② 모든 이벤트 델타(오퍼/마크다운/워처 증가)는 방향 무관하게 동일한 틴트 `#F3B457` + `▲`/`▼` 글리프 + weight로만 구분, green/red 이원색 없음. ③ 브리프가 "ad-hoc green/red 금지, accent+글리프+weight"를 명시적으로 지정 — 색이 방향을 나르지 않고 글리프가 나르므로 색+텍스트/아이콘 병행 규칙도 자동 충족. **브리프 명시 규칙 그대로 적용**

**③ 디스플레이 서체 — `--font-display-mono`** — ② h1, 가격/시간/스탯 등 tabular-nums 숫자 전부, 섹션 인덱스 넘버, 인용부호에 적용. 본문·한국어 없음. ③ 브리프가 이번 라운드는 mono를 우선하라고 명시했고, 후보 a가 이미 같은 서체를 골랐음을 뒤늦게 확인했지만 "티커 로우의 숫자 밀도"라는 이 아키타입 고유의 소재 적합성이 mono를 재확인시켰다 — 결정 번복하지 않음(액센트 hue는 이미 분화되어 있어 서체까지 바꿀 근거는 약하다고 판단). **임의 (조항 준수 + 소재 적합성, sibling 중복은 인지하되 유지)**

**④ 본문 폭 — `ch` 미사용, 0.44em 역산** — ② 히어로 서브헤드/클로징 서브헤드 `520px @17px → 520/(0.44×17)=69.5자`; 섹션 인트로 `488px @16px → 488/(0.44×16)=69.3자`; 카드/인용 본문 `440px @15px → 440/(0.44×15)=66.7자`. 전부 70자 근처, 75자 상한에 5~8자 여유. ③ 브리프가 명시한 상수를 그대로 역산, `ch` 단위는 파일 전체에서 미사용(grep 확인). **브리프 값 적용, 계산만 임의**

**⑤ 티커 데이터 구조 & 결정론 확보 방식** — ② `TICKER_EVENTS: TickerEvent[]`를 오름차순 `ts`(리터럴 `"HH:MM:SS"` 문자열) 고정 배열로 선언하고, 화면 표시는 `feedFor()`가 이 배열을 필터링 후 `.reverse()`만 해서 최신순으로 뒤집는다 — 실행마다 다시 정렬/셔플하지 않으므로 완전히 결정론적. "살아있는" 티는 `pulseTick % feed.length`로 순회하는 시각 하이라이트 하나로만 낸다(콘텐츠 변경 없음, `aria-live` 미부착). ③ 브리프가 "고정·사전 스크립트된 배열, 실행 시점 시계에서 계산 금지"를 아키타입 핵심 제약으로 명시 — 처음 설계 단계에서부터 "watchers 카운트가 이벤트마다 정확히 +1씩 증가해야 하는가"를 고민했으나, 그건 브리프가 요구한 게 아니라 내가 스스로 부과하려던 사실성 검증이었고 완벽한 산술 일치는 오히려 각 리스팅에 이벤트 4개씩(드랍 1 + 오퍼 1~2 + 워처 1~2)을 배정하고 **각 리스팅의 마지막 워처 이벤트 값만** `listing.watchers`와 일치시키는 것으로 충분히 신뢰감 있게 절충했다. **임의 (구조는 브리프 제약을 만족시키기 위한 설계, 세부 숫자는 임의)**

**⑥ 목표가(target price) 메커닉 — 예산 슬라이더 + 이중 표면 하이라이트** — ② `<input type="range" min={50} max={2500} step={10}>` 하나의 상태(`target`)를 리스팅 스트립·활동 피드·3-way "Within budget" 카드·클로징 CTA 요약까지 전부 공유. "IN BUDGET"은 accent 채움 + 흰 텍스트 배지(색+텍스트 병행)로만 표시, 색 단독 의존 없음. 기본값 700은 "3/5가 이미 예산 안"이라는 눈에 보이는 초기 증명을 만들도록 역산해서 고른 값. ③ 브리프의 "방문자가 필터/정렬하거나 목표가를 설정해 어떤 로우가 범위 안인지 보는" 것이 정확히 이 아키타입에 요구된 인터랙션이라, 슬라이더 하나로 마켓플레이스의 "예산 알림" 개념과 직결시켰다. **임의**

**⑦ HTML 목록 시맨틱 — `<ul>/<li>` 대신 `role="list"/"listitem"` div** — ② `AnimatePresence`로 필터/정렬 변경 시 리스트 로우를 진입/퇴장 애니메이션시켜야 했는데, `motion.div`가 `<li>`를 감싸면 `<ul>` 직속 자식이 `<li>`가 아니게 되어 유효하지 않은 HTML이 된다(스크린리더가 목록 구조를 못 읽을 위험). 세 곳(리스팅 스트립·활동 피드·상품 카드 그리드) 전부 `<ul>`을 `role="list"` div로, `<li>`를 `role="listitem"` div로 바꿔 애니메이션 래퍼 자체가 목록 항목이 되도록 재구성. ③ 브리프의 "div 그리드를 쓰더라도 진짜 row/heading 구조를 유지하라"는 요구를 실제로 지키려면 motion 래퍼와 목록 항목이 같은 엘리먼트여야 했다. **임의 (a11y 사고 과정에서 발견, 최초 초안은 무효 HTML이었음 — 자체 리뷰로 수정)**
