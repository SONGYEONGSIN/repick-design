# Candidate b — Dockwise

Dockwise is a warehouse fulfillment-ops console: the Overview page leads with a hero "inventory value on hand" number plus three inline secondary stats (fill rate with a sparkline, avg dwell time, units received) under a 7D/30D/QTD window toggle, paired with one dominant horizontal ranked-and-stacked bar chart ("Inventory value by zone") as the page's main attraction, a pinned-zone detail card, and a tabbed replenishment-queue / recent-receipts panel below. Interactions: hover/focus tooltip on each bar row (ephemeral, keyboard-reachable), click-to-pin a zone (updates only the pinned-zone card — chart and table are untouched), the 7D/30D/QTD segmented toggle, real sort (Qty/ETA, `aria-sort`) + status filter on the replenishment table, and a ⌘K command palette. Theme is pure white/zinc-50 light, single accent is true `green-700`/`green-600` (verified ≥4.5:1 for all text use), display type is `--font-display-grotesk` on the wordmark and big number only, everything else stays on Pretendard, and exactly three font weights (400/500/600) are used throughout.

## 브리프에 없던 것

1. **"Crosshair tooltip" on a bar chart, not a line chart.** The brief's phrase assumes a line/candlestick chart. For a ranked-bar list I instead reveal a one-line breakdown (On-hand / Reserved / Backordered in full `$` figures) directly under the hovered-or-focused row, triggered by both `onMouseEnter`/`onFocus`. Chose this over a floating absolute-positioned tooltip because it has zero positioning/z-index risk and is trivially keyboard-reachable (focusing the row shows the same detail a mouse hover would), at the cost of a small layout shift — acceptable since only one row is ever expanded at a time.
2. **Which value gets baked into the bar vs. left to hover.** The brief requires "always-visible" key values but also a "sane fallback" for tiny cells. I made the zone name + total value always-visible text on every row (the two numbers that matter for ranking), and additionally baked the On-hand dollar figure into the green segment when that segment's rendered width is ≥12% of the row's own width — below that (only the smallest zone, Overflow, at ~9.7%) the label is omitted rather than letting text spill past its segment. Reserved/Backordered never get inline labels (always via hover/focus or the pinned-zone card) to avoid three competing text layers on an 8px-tall-ish bar.
3. **Tabs that mount/unmount instead of CSS-hiding.** The brief explicitly flags "never two wide `overflow-x-auto` containers on one page." Replenishment Queue and Recent Receipts each have their own table-in-`overflow-x-auto` wrapper; rendering both and hiding one with CSS would put two such containers in the DOM simultaneously. I render the inactive tab's panel as `null` (ternary, not `hidden`) so only one scrollable table ever exists in the DOM at a time — sacrificing the "keep inactive panel for instant switch" nicety for a structural guarantee against the leaked-scrollWidth bug.
4. **Roving `tabindex` dropped from the Tabs component.** The ARIA tabs authoring pattern suggests `tabIndex={-1}` on inactive tabs with arrow-key re-routing of focus. I didn't implement arrow-key handling, so I left both tab buttons at their native default tabIndex (reachable via sequential Tab) rather than ship the textbook pattern half-finished and strand the second tab outside the tab order.
5. **Invented a third "always-on" progress bar usage.** The completeness bar requires a Progress component but a zone's capacity/utilization wasn't otherwise in the data model. I used it inside the pinned-zone card for "reserved share of value" (reserved ÷ total) — a number that's already in the breakdown as text, so the bar is a redundant-but-legible visual gloss on an existing figure rather than a new unreconciled metric.
