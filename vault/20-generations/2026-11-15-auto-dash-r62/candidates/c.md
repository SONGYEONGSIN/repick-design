# Candidate c — Clearcall

Clearcall is a revenue call-intelligence console for B2B sales teams, built as a master-detail dashboard: a fixed-width call list rail (search, sentiment filter, sort) on the left and a `flex-1` detail pane on the right. The two selection axes are genuinely independent and live on two different widget clusters: (1) clicking a call row sets `pinnedId`, whose only consumer is the header "Spotlight" card — the Coaching Digest body below it never changes, since it always describes the whole team's period, not whichever call was last clicked; (2) hovering or keyboard-focusing a segment of the topic-mix bar inside the Coaching Digest sets an ephemeral `hoveredTopic`, which only drives that bar's own inline inspector and resets on blur/mouse-leave — it never touches `pinnedId` or the Spotlight card. A third, separate toggle (`period`: week/month) swaps the whole digest dataset without touching either selection. Theme is genuinely dark (zinc-950/900 surfaces, white/10 borders, no glow/grain), accent is sky with contrast verified by hand (e.g. sky-400 text on zinc-950 ≈ 9.3:1; bg-sky-400 with zinc-950 text ≈ 9.3:1), and display type is `--font-display-grotesk` for the wordmark and large numerals only — Pretendard everywhere else — with exactly three rendered weights (400/500/600) throughout.

## 브리프에 없던 것
① Decision: what the `period` (week/month) toggle should and should not touch. Decided it only swaps the Coaching Digest's own dataset (headline stats, topic mix, and the leaderboard's "Calls" column) and never the call list rail or the Spotlight card — so it reads as a clearly separate, third axis rather than a hidden coupling with either selection state.

② Decision: how master-detail collapses below `lg`, since the brief only sketches "pushed/stacked nav." Added a local `mobileScreen` state (`"list" | "detail"`) that is inert at `lg` and up (both panes are always shown there via an `lg:block` override) and only decides which full-width screen shows on mobile, with a "Back to calls" button inside the detail pane returning to the list.

③ Decision: which colors are allowed alongside the single sky accent. Kept emerald/rose as domain-standard semantic colors for positive/at-risk status (badges, stat deltas) rather than treating them as a second "accent" — sky stays the only interactive/brand color (primary buttons, focus rings, active nav and segment states, links).

④ Decision: how to size avatars for `next/image` without a dedicated crop/CDN service. Used small fixed square `width`/`height` (16–28px) with `object-cover` on fixed Unsplash photo IDs, rather than adding crop query parameters, so every avatar URL stays a plain `https://images.unsplash.com/photo-<id>` match against the existing `remotePatterns` allow-list in `next.config.ts`.

⑤ Decision: what counts as "realistic reconciling data" for a call-intelligence product with no real backend. Fixed `CALLS.length` at 10 so `REPS[].callsWeek` sums to exactly 10, picked a month total of 42 so `REPS[].callsMonth` sums to exactly 42, and kept every period's `topics[].pct` summing to exactly 100 — so the dashboard's totals check out under inspection instead of merely looking plausible.
