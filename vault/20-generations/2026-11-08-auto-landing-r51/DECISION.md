### Lens 1 (brief/DNA compliance) — ranking: **c > b > a**
All three pass the hard-rule-shaped checks (English-only copy, font whitelist, exactly 3 weights, determinism, hero-fold component boundary, manipulation-survives-to-CTA, badge placement, container-width arithmetic). Ranking decided on finer, citable gaps: **a** has a real violation of `page-brief-core` §3's `tabular-nums` rule — grepped zero instances across the entire file despite the page's core mechanic being live-reranking numerals (scores, percentages) that will visibly jitter in digit width as they update; this is exactly the scenario the rule exists for. **b** has an undisclosed near-verbatim copy overlap with `r34/a` (identical hero headline, near-identical subhead template, near-identical sr-only announcement string) that b's own duplicate-check note never flagged, despite flagging structural differentiation — a gap in the brief's own duplicate-check honesty norm. **c** has no comparable gap: `tabular-nums` present on every live numeral, container-width math verified correct, hero-fold and closing-CTA derivation chains both traced and confirmed live (including zero-value and max-value edge cases), keyboard operability (`role="slider"` + arrow keys + single shared `aria-live`) verified.

### Lens 2 (commercial completeness/polish) — ranking: **b > a > c**
All three hand-traced correct at the default state and at least one additional state, with a genuine single source of truth for every derived number (no candidate has two independent implementations of the same readout that could drift). **b** rated most polished: best accessibility (drag is never the only path — always-visible, always-focusable up/down buttons calling the exact same pure function as drag), richest AI-reasoning tags (5 hand-written narrative lines selected live by current rank leader, vs. a's and c's thinner equivalents), cleanest visual craft ("closest to Linear/Stripe-grade editorial restraint"), best mobile document-order (primary mechanic first on all viewports). **a** close second: clean derivation chain, real collapsible 4th interaction, one minor over-verbose `aria-live` region (wraps the whole card instead of a concise summary). **c** rated 3rd specifically on two concrete, citable gaps: (1) each listing's "AI match reasoning" text is a single fixed string never tied to the live curve/active point (unlike a's and b's genuinely live-selected reasoning tags) — "closer to the static-placeholder-text pattern the brief warns against"; (2) a real mobile document-order defect — the curve editor (the mechanic the hero's proof cards' captions reference) renders AFTER the proof cards in the single-column mobile layout, so a mobile visitor sees a specific budget figure before ever seeing the control that produced it (confirmed in `c-390.png`).

### Lens 3 (archetype differentiation) — ranking: **c > a > b**
Applied the established input×output reduction method (`curation-criteria.md` "Q6 판정") plus the code-surface-reuse doctrine (borrowed from `native/GENERATION.md` §3 for this lens's method, as instructed). **c** rated cleanest: genuinely new (6 independent uncoupled points → dual independent derived reads) pair, verified against both a single-position scrubber (`r49/b`) and a renormalizing-slider composite (`v21`/`r18/c`) as structurally distinct on both counts, zero code-surface overlap with either. **a** also genuinely new (discrete binary-tournament input → derived-weight full-catalog re-rank), verified distinct from the catalog's existing head-to-head duel (`r35/b`, a two-dropdown comparator with static weights, never re-ranks the full catalog) and from the continuous-reweight-slider family — but its own candidate note never checked against `r35/b` at all (this judge's finding, not a verified claim in a's own record). **b** rated a clear reskin: this project's own prior research (`auto-landing-r48`'s research fork, `DECISION.md:24`) had already documented "Priority Ranking Composer" (drag/reorder N criteria → rank-to-weight → re-ranked list) as a **saturated archetype with 4+ prior instances** (`v11`, `v22`, `r25/c`, `r34/a`, `r40/a`) — independently confirmed by reading `v11`, `r34/a`, and `r40/a` in full. b's own claimed distinctions (rank-map vs array data structure, "computed formula" vs "hardcoded table") don't survive scrutiny as *shape* differences — b's own linear-weight formula evaluated at n=4 reproduces `r34/a`'s exact hardcoded `[40,30,20,10]` table. Drawn directly from the winning candidate's own flagged flaw, following this project's established practice of extracting generalizable lessons from a winner's own cited weaknesses (not only from what it did right) — the same pattern as `auto-landing-r49/b`'s delta.
