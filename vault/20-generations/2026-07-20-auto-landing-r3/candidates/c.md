## c — 절약 계산기 히어로

히어로 우측이 이미지 리빌이 아니라 **실사용 가능한 금융형 계산 도구**다 — 좌측은 표준 카피(헤드라인+서브+단일 CTA), 우측은 카테고리 세그먼트(아우터/가방/신발/상의, radiogroup이 아닌 버튼 그룹) + 예산 스텝퍼(±버튼)·슬라이더(결정론적 프리셋 4단계 배열 인덱싱)로 "매장 신품가"와 "repick AI 매칭가"를 초대형 tabular-nums 숫자로 실시간 대조하는 절약 계산기가 채운다. 장식은 0 — 순수 타이포그래피 숫자와 절제된 세그먼트/슬라이더 UI만 사용했다.

**핵심 인터랙션 4종+**
1. 카테고리 세그먼트 전환 → 매장 신품가·repick가·절약액·절약율이 `useMotionValue`+`useSpring`으로 count-up 애니메이션(선언적 값 전환, RAF 직접 사용 없음, tabular-nums).
2. 예산 슬라이더/스테퍼(±버튼 + range track) 조작 → 하단 "AI 매칭 근거" 카드가 선택된 예산 구간의 프리셋 제품(매칭%·컨디션 등급·인증 셀러·실측 근거 3종·before/after 가)으로 즉시 교체.
3. 계산기 카드가 `whileInView`로 뷰포트 최초 진입 시 숫자가 0→값 count-up으로 트리거(1회, `motion-reduce` 시 즉시 최종값 수렴 + 320ms 타임아웃 안전장치로 화면 캡처 시 빈 상태 잔존 방지).
4. CTA 버튼 텍스트에 현재 계산된 절약액이 인라인으로 삽입("이 조건으로 N원 절약하고 매칭받기")되어, 컨트롤을 조작할 때마다 설득 문구 자체가 갱신됨.

**중복 회피**: r2/a는 이미지 두 장(일반 리스팅 vs AI 큐레이션)을 드래그 핸들로 좌우 리빌하는 방식이었다면, 이 후보는 이미지 드래그 자체가 없다 — 조작 대상이 이미지가 아니라 "카테고리·예산이라는 숫자 입력"이고, 결과도 사진이 아니라 "가격·절약액이라는 숫자 출력"이라는 점에서 완전히 다른 감각(Stripe형 가격 계산기)이다. 계기판/게이지/라인아트 장식도 전혀 사용하지 않아 브리프의 블루프린트 감점 조건도 피했다.
