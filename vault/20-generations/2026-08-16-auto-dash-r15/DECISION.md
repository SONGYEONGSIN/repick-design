# DECISION — auto-dash-r15

## 후보
- **a — Nodal**: 서비스 메시 관측 콘솔. 4-tier 레이어드(Sugiyama식) 서비스 의존성 그래프가 지배 시각화, 필수 인접목록 테이블 폴백(Network Graph A11y D등급). 다크 + sky 액센트, `--font-display-wide`.
- **b — Traverse**: 지역 물류 네트워크 콘솔. 12허브×17레인 스키매틱 버블맵이 지배 시각화, 정렬가능 라우트 테이블 폴백(Geographic A11y B등급). 다크 + cyan 액센트, `--font-display-mono`.
- **c — Vela**: 성장실험(A/B) 콘솔. 신뢰구간 밴드 포함 예측 차트(실측 실선 + 예측 파선 + 95% CI 셰이딩)가 지배 시각화(Time-Series Forecast A11y AA등급). 다크 + cyan 액센트, 디스플레이 폰트 미사용(Pretendard only).

셋 모두 갤러리·`auto-dash-r14`에 없는 지배 시각화 계열(그래프/지도/예측밴드) 배정 — GENERATE §매크로-버킷 선제 체크 적용.

## 하드게이트
전원 생존. a·c는 1차 통과. b는 1차 `focus` 게이트 7건 실패(SVG 허브 노드가 상태구동 형제 `<circle>` 링으로만 포커스를 표시해 게이트의 페인트 샘플링 범위(요소 자신+조상+자식) 밖) → 1-fix(요소 자신에 기존 `FOCUS_VISIBLE` 토큰 직접 적용, candidate a와 동일 패턴) → 재게이트 전 항목 통과. 상세: `SCORES.md`.

## JUDGE 패널 (3렌즈 병렬, 블라인드)

### 렌즈1 — 브리프 준수: **b > c > a**
- b 1위: 다크 대비 하한 전 구간 준수, 렌더 실측 3종 웨이트, 브리프 자신의 1920px 캡 예시(사이드바256+패딩48→가용1616→캡≥1660)를 거의 그대로 재현(`console-client.tsx:61` `max-w-[1680px]`), 전용 skip-link(`console-client.tsx:45-53`), 포커스 죽은 코드 0건.
- c 2위: 포커스·sr-only 앵커 등 대부분 정확. 마이너 2건 — 커맨드팔레트 placeholder가 zinc-500(다른 두 후보는 zinc-400), `ExperimentPicker.tsx:53` 카드 제목이 1280px에서 1줄 말줄임(1920px는 2줄 전문 노출) — 둘 다 저심각도.
- a 3위 (탈락 결정적 사유): `topology-table.tsx:86,94` — Table 뷰의 필터 `<input>`이 `outline-none`이고 포커스 표시 클래스(`FOCUS_RING`)는 정작 포커스 불가능한 감싸는 `<div>`에 붙어 있어 그 인풋을 Tab하면 시각 표시가 전혀 없음(자기 `tokens.ts:14-15` 문서 주장과 정면 모순). **게이트 회피 구조**: `topology-client.tsx:31`가 기본 뷰를 `"graph"`로 두어 이 결함이 있는 Table 뷰가 기본 렌더에 없다 — r14 델타(모달 전용 컨트롤은 자동 게이트 Tab-스캔 밖)와 동일 계열의 재현. 부차: `a-1280.png`에서 "SUPPORT SERVICES" 티어 라벨이 "Payments" 노드 칩과 시각적으로 겹침(구조적 오버플로 0, 육안 크로우딩).

### 렌즈2 — 상용 SaaS 완성도: **a > c > b**
- a 1위: 15노드/~20엣지 의존성 그래프, 엣지 굵기/불투명도가 헬스 등급 인코딩, 비정상 엣지는 상시 텍스트 배지(hover 아님), 선택→하이라이트 전파, 마스터-디테일 슬라이드오버(크로스헤어 스파크라인 2개), 결정론 라이브 미니차트(`live-mesh-chart.tsx` 고정 배열, `motion-reduce`는 장식용 ping만 게이팅) — 세 후보 중 지배 자산·인터랙션 밀도 최고.
- c 2위: 6카드 실험 피커(개별 스파크라인)→예측+CI밴드 차트(항상-노출 lift/CI 수치, 키보드 크로스헤어)→변형비교→정렬테이블로 스크롤 서사가 매끈함(`ForecastChart.tsx:121-212`).
- b 3위: 실행 자체는 신중(결정론 베지어 레인 `laneControl`, 촘촘한 a11y 라벨)하나 12노드·희소한 밀도로 세 지배 자산 중 시각적으로 가장 옅고, 자체 카피가 "not a geographic tile map"이라 명시(`b-1440.png`)해 스스로 한계를 인정.

### 렌즈3 — 아키타입 차별성: **c > a > b**
- c 1위: 신뢰구간 예측 밴드는 갤러리·r14 어디에도 없는 유일한 방향 — 실측 유효.
- a 2위: 배정된 그래프 방향을 정석대로 구현.
- b 3위 (핵심 발견): **a와 b가 지배 시각화 차원에서 사실상 같은 아키타입으로 수렴** — 둘 다 고정 좌표 노드 + SVG 선/경로 엣지, 헬스 색 인코딩, 선택→하이라이트 전파, 클릭 시 (통계grid+트렌드차트+인접목록 칩) 구성의 상세 패널까지 인터랙션 모델이 사실상 동일(`a/topology-graph.tsx` vs `b/network-map.tsx`, `a/detail-panel.tsx:69-93` vs `b/hub-detail-panel.tsx:38-88`). b는 "지리적 지도" 배정을 받았으나 좌표가 실제 지리 투영이 아닌 임의 배치 Cartesian(`b/data.ts:34-45`)이라, 배정된 방향(공간/지리적 지도)을 실질적으로 달성하지 못하고 a와 같은 "노드-링크 그래프" 계열로 재수렴했다 — 이번 라운드가 실제로 전달한 신규 방향은 그래프(a)와 예측밴드(c) 둘뿐.

## 집계 — 3파전 완전 동률 → tie-break 정본 적용
1위 표: 렌즈1=b, 렌즈2=a, 렌즈3=c — 세 후보가 정확히 1표씩, 다수결 불성립.

[[curation-criteria]] "주간 반증 판정 기준 ② 3파전 동률 tie-break 예외"(2026-07-25 정본, 타깃 중립)를 그대로 적용한다: **"완전 동률 시 brief 렌즈 우선을 유지하되, archetype 렌즈가 그 후보를 최하위로 명시 판정했으면 동률 우승서 제외하고 나머지 중 brief 1위 재적용."**

1. brief 렌즈(렌즈1) 1위 = **b**.
2. archetype 렌즈(렌즈3)가 b를 최하위(3위)로 명시 판정 — 위 c>a>b 랭킹 확인.
3. → b를 동률 우승 후보에서 제외. 잔여 {a, c}에 brief 렌즈 순위 재적용: 렌즈1 랭킹 `b > c > a`에서 b를 뺀 잔여 순서는 **c > a**.

**→ 승자: c (Vela)**

부가로 렌즈2↔렌즈3 상충 규칙(curation-criteria "차별성↔완성도 상충 시 완성도 다수결")도 참고 대조했다 — 이 규칙은 2-1 분포를 전제하는데 이번은 완전 3-way라 직접 적용 대상은 아니지만, c가 렌즈2에서도 2위(a에만 뒤짐, b보다 우위)라 결과가 상충하지 않는다는 점을 교차 확인했다.

## 정제 조치 (판정 후 수정)
승자 c는 판정 전 결함 0건, 정제 조치 대상 아님. b는 하드게이트 1-fix(포커스)를 거쳤으나 승자가 아니므로 §3-1(판정 후 수정) 대상이 아니라 §3(하드게이트) 정규 1-fix 루프 범위였음을 명시한다.

## LEARN — delta 추출
아키타입 배정이 "지배 시각화 카테고리 이름"(예: "지리적/공간 지도")만 지정하고 그 카테고리를 성립시키는 필수 속성(지리 투영·영역 기반 배치 등 실제 공간성)을 명시하지 않으면, designer가 데이터 볼륨·톤·상세패널 구성만 다른 채 인접 카테고리(노드-링크 그래프)로 조용히 수렴할 수 있다 — a/b 두 candidate가 서로 다른 렌즈 지시(그래프 vs 지도)를 받았음에도 상세 패널 인터랙션 모델까지 사실상 동일하게 수렴한 것이 그 증거(`dash-deltas-provisional.jsonl` append 참조).

## 지식 정제 게이트
`dash-deltas-provisional.jsonl` 전체(33→36건, 본 라운드 신규 3건 포함)를 클러스터링:
- **아직 미승격(provisional, promoted 짝 없음) 항목**: `auto-dash-r3/a`(더미 데이터에 세션 컨텍스트 운영자 정보 유출 위험), `auto-dash-r4/c`(44px는 헤더 컨테이너가 아니라 개별 컨트롤 단위), `auto-dash-r15/b`(본 라운드 LEARN, 아키타입 카테고리 수렴) — 재현 근거 없어 L1 그대로 유지, 조치 없음.
- **재현 확인 → L2 승격 2건**:
  1. `auto-dash-r10/a`(히어로+단일시각화 매크로버킷 재수렴) + `auto-dash-r12/a`(고정레일+세그먼트토글 버킷 재수렴, 서로 다른 구체 버킷) → 결함 클래스가 같음("GENERATE 사전 체크 없이 매크로 골격 재수렴") 확인, `auto-dash-r12/a`를 `supersedes:auto-dash-r10` L2로 append.
  2. `auto-dash-r14/c`("모달 전용 컨트롤은 기본 렌더 Tab-스캔 밖" — 자기 본문이 상태분기대비 패턴의 재현/확장을 주장)의 재현 주장을 검증: 이번 라운드 렌즈1이 후보 a의 Table뷰 필터에서 **트리거만 다른(뷰토글 vs 모달) 동일 결함 클래스**를 독립 발견 → 채택, `auto-dash-r15/a`를 `supersedes:auto-dash-r14` L2로 append. (§6 규칙: 재현 주장은 먼저 검증하고 결론 명시 — 이번엔 채택 결론.)
- **정본 소급 편입 확인**: `auto-dash-r13/a`(hidden-until-breakpoint 접근이름 소실, `sr-only sm:not-sr-only` 해법)는 별도 승격 조치 없이도 이미 실효 — `page-brief-core.md` "좁은 승격 2차 완료(2026-08-16)"가 `button-name`을 하드페일로 승격하며 동일 결함·동일 해법을 문서화했다(오늘 자, 이 라운드 밖의 다른 트랙에서 이미 처리됨). 델타 원줄은 append-only 원칙상 그대로 두고 추가 조치 없음 — 실효는 게이트 자체가 더 강하게 담보한다.
- **질문 큐**: 신규 충돌 쌍·정당화 불가 항목 없음. 다만 `Q31`(상태 분기 대비를 누가 재나)이 이번 L2 승격 2건과 직접 관련돼 "대비"에서 "모달·뷰토글로 조건부 마운트되는 서브트리 일반"으로 범위가 넓어져야 한다는 관측을 `questions-queue.md` Q31에 갱신 append(신규 질문 생성 아님 — 기존 질문의 일반화).

## 판정 커버리지 (자진 신고 종합)
- 렌즈1: 1366/1600px 미실측, 포커스 죽은코드 판정은 소스 정적 추론(실 Tab 스크린샷 아님) — 단 이는 게이트(`focus`) 스크립트가 이미 실제 Tab으로 라이브 측정해 교차검증되므로 낮은 리스크.

- 렌즈3: 갤러리 17종 전문 소스 대신 `works.ts` 한 줄 설명으로 대조(예산 내), 1280/1920 중간폭 프레임 다수 미확인.
- 셋 다 1280/1600px 일부 폭 및 hover 상태(정적 캡처 한계)는 미확인 자진 신고.
