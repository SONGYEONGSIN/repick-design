# r5/b — 옷장 레일 (Wardrobe Rail) 히어로

## 한 줄 컨셉
히어로를 실제 옷장 레일(closet rail)의 물리적 은유로 구성한다 — 상단에 가로로 뻗은 레일 봉과 순수 SVG 옷걸이 훅으로 매물 카드들을 "걸어" 놓고, 사용자가 손끝(포인터 드래그) 또는 화살표 키로 레일을 밀면 정보가 빈약하고 밀집·무채도인 "일반 옷장" 구간(5개)이 지나가고, 간격이 넓고 컬러풀하며 근거 태그가 상시 노출되는 "AI 큐레이션 캡슐" 구간(5개)이 이어진다. 레일을 이동하는 물리적 행위 자체가 "AI가 다시 고르는 중고"라는 핵심 가치명제를 극화한다.

## 경로
- `app/src/app/landing-evolve/r5/b/page.tsx` — 서버 컴포넌트, metadata만 export.
- `app/src/app/landing-evolve/r5/b/ui.tsx` — `'use client'`, Landing 5단(Hero/제품프리뷰/가치3분할/소셜프루프/마무리CTA) 조립.
- `app/src/app/landing-evolve/r5/b/WardrobeRail.tsx` — `'use client'`, 옷장 레일 히어로 위젯 본체(레일 봉 + 옷걸이 훅 SVG + 카드 + 이동 컨트롤 + 활성 항목 스포트라이트 패널).
- `app/src/app/landing-evolve/r5/b/data.ts` — RAIL_ITEMS(일반 5 + 큐레이션 5, 동일 이미지 1:1 대응 없음), CURATED_ITEMS, VALUES, PROOF, AUDIENCE_PROOF + 공유 토큰.

## 핵심 인터랙션 (4종 이상)
1. **레일 드래그 + 스크롤스냅 + 키보드 이동** — `overflow-x-auto` 스크롤 컨테이너(`role="group" aria-roledescription="carousel"`, `tabIndex=0`, `overscrollBehaviorX: contain`)에 포인터 드래그(마우스 전용, `pointerType==="touch"`는 네이티브 터치 스크롤에 위임)로 `scrollLeft`를 직접 조작하고, 드래그 중엔 `snap-none`으로 전환했다가 릴리즈 시 `getBoundingClientRect` 기반으로 가장 가까운 카드를 계산해 `scrollIntoView`로 스냅한다. `ArrowLeft/ArrowRight/Home/End` 키다운 핸들러가 동일한 `selectIndex` 로직을 공유해 완전한 키보드 조작을 보장한다. `Math.random`/`Date.now` 없이 포인터 좌표·`requestAnimationFrame`만으로 결정론적으로 동작.
2. **구간별 점 지도 + 활성 항목 스포트라이트 동기화** — sm 이상에서 24px 히트 영역의 점 10개(일반=무채색, 큐레이션=보라색)를 클릭하면 즉시 해당 카드로 이동하고, 레일 하단의 "지금 보는 행거" 패널이 활성 인덱스에 맞춰 실시간으로 내용을 교체한다. 일반 매물일 땐 "검수 이력 없음" 경고형 카피를, AI 큐레이션 매물일 땐 매칭%·등급·인증·before/after 할인율·태그를 보여줘 조작이 곧바로 대조 가능한 증명 데이터로 이어진다(모바일은 점 10개 대신 진행률 바 + 텍스트로 대체해 24px 타깃 크기와 좁은 뷰포트 폭을 동시에 만족).
3. **제품 프리뷰 정렬 토글 — 순위 재계산** — "매칭 정확도순" / "할인율순" 세그먼트 토글을 누르면 `CURATED_ITEMS` 배열이 즉시 재정렬되고, 각 카드의 "N위" 배지와 그리드상 위치가 `framer-motion layout` 애니메이션으로 재배치된다. 브랜드·가격·매칭%·등급·인증·태그는 정렬 여부와 무관하게 카드 전면에 항상 노출.
4. **소셜프루프 구매자/판매자 토글** — 세그먼트 토글로 "구매자 후기" ↔ "판매자 후기"를 전환하면 인용구와 함께 스탯 밴드 3개 수치(평균 절감률/매칭 소요 vs 평균 판매 완료/누적 거래/재구매율) 전체가 실제로 교체된다.

## "조작=가치체감" 결속 방식
레일을 미는 행위 자체가 "일반 매물 → AI가 재검수한 캡슐"이라는 전환을 물리적으로 체감시키며, 이동할 때마다 스포트라이트 패널의 증명 데이터가 실시간으로 갱신되어 장식이 아니라 핵심 가치 증거 자체가 된다. 정렬 토글과 후기 토글도 각각 순위·통계라는 실제 데이터를 즉시 재계산해 동일 원칙(r3/r4 delta: "조작이 핵심 증명/비교 데이터를 실시간으로 갱신하는가")을 다른 표면 형태로 재현한다.

## 중복 회피 근거
- 이번 라운드에서 명시적으로 금지된 스캐닝 콘솔·채팅 로그·스와이프 카드 덱(Tinder류)·매서너리 피드·비교 표·예산 계산기/슬라이더·드래그 before/after 리빌 중 어느 것도 사용하지 않았다. 카드가 N장이라는 점은 r4/a(스와이프 덱)와 표면상 유사해 보일 수 있으나, r4/a는 카드가 겹쳐 쌓인 스택에서 위 카드 1장만 보이는 상태로 드래그해 옆으로 튕겨 보내는 제스처인 반면, 이번 후보는 카드 10장이 **동시에** 가로로 펼쳐진 물리적 레일이며 드래그는 "튕겨내기"가 아니라 "레일을 미는" 스크롤이다. 또한 좌우 두 구간(일반→큐레이션)이 서로 다른 매물로 채워진 서사적 전환 구조를 갖는다는 점이 r4/a·r4/b 어디에도 없던 신규 장치다.
- r2/a(드래그 before/after 슬라이더)와도 다르다 — 동일 이미지 1장을 좌우로 드래그해 두 상태를 겹쳐 비교하는 것이 아니라, 완전히 다른 매물 10개가 순서대로 배열된 레일을 옆으로 이동하는 구조이며 "이미지 겹침 비교" 자체가 없다.
- 옷걸이 훅은 사진이 아닌 순수 SVG 기하 형태(삼각형 몸체 + 고리)로 구현해 스큐어모피즘을 피했다.

## 접근성/견고성 메모
- 레일 스크롤 컨테이너는 `role="group" aria-roledescription="carousel"` + `aria-label` + `tabIndex=0`(axe `scrollable-region-focusable` 규칙 충족)이며, `aria-live="polite"` 텍스트로 현재 위치·매물 정보를 스크린리더에 안내. 개별 카드 버튼은 `tabIndex=-1`(로빙 없이 컨테이너 레벨 화살표 키로 통합 탐색, r4/a와 동일 패턴)이지만 `aria-label`로 완전한 정보를 제공(터치 스크린리더의 스와이프 탐색에서도 접근 가능).
- 점 지도 버튼은 h-6 w-6(24px) 히트 영역으로 target-size 기준을 충족(r4/a에서 발견된 h-2→h-6 학습을 선제 반영), 모바일에서는 점 10개 대신 진행률 바로 대체해 좁은 뷰포트에서의 클리핑 위험을 원천 차단.
- 헤딩 순서: h1(히어로) → h2(레일 카드 제목·스포트라이트 활성 항목, 레벨 스킵 없음) → h2(제품 프리뷰 섹션) → h3(프리뷰 카드 제목) → h2(가치 3분할/최종 CTA), 모두 레벨 스킵 없이 이어짐.
- 대비: 일반 매물 카드의 메타 텍스트를 `text-white/35`가 아닌 브리프 muted 토큰 `text-[#A1A1AA]`로 작성(사전에 저대비 위험 제거), 활성/비활성 카드 구분은 텍스트 투명도가 아니라 `scale` 트랜스폼으로만 표현해 텍스트 대비가 상태와 무관하게 항상 동일하게 유지되도록 함.
- `motion-reduce`/`useReducedMotion` 게이팅으로 스크롤 스냅 애니메이션·정렬 재배치·진입 시퀀스가 감속모션 시 즉시 최종 상태로 수렴, `Math.random`/`Date.now`/`new Date` 미사용, 이미지 전부 `next/image` + `images.unsplash.com` 고정 URL + alt, 폰트 웨이트 정확히 3종(font-normal/font-semibold/font-extrabold).
- `npx tsc --noEmit`, `npx eslint`(대상 파일) 모두 에러 0건.
