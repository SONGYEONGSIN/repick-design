# r54 / b — Gantry

**Concept.** Gantry is a model-deployment approval console for ML platform teams: a dark, service-grade console (`zinc-950` canvas, `zinc-900` panels, `white/10` hairline borders, single cyan accent) built around a five-column kanban board — Requested → Risk Review → Approved → Canary → Live — as the main content area's clear visual center of gravity, with a compact SVG "Pipeline velocity" bar strip (median hours per stage, headline "58h median to Live · n=31") sitting above it as a secondary, always-legible supporting chart. The standard app shell (left sidebar with workspace switcher, five-item nav, bottom user area; topbar with ⌘K search, a primary "New deployment request" button, notifications and avatar menus) wraps the board; each of the five columns is independently vertically-scrollable (fixed `max-height` + `overflow-y-auto`) and the board reflows to a vertical stack below `lg` so the page never grows a horizontal scrollbar. Four-plus real, `'use client'`-stateful interactions: (1) a keyboard-reachable "Move to…" menu on every card and in the detail panel — the drag-free alternative to drag-and-drop — that actually re-assigns a deployment's stage in state; (2) a live search-plus-risk-chip filter over the 18 deployment cards; (3) the funnel strip's per-bar hover/focus tooltip (sample size, always paired with the permanently-visible hour label); (4) a ⌘K command palette that jumps straight to a deployment's detail panel; (5) a card-click detail modal with an independently-toggleable checklist and a "Watch" bookmark whose state is scoped on its own `Set<string>` (two deployments start pre-watched, unrelated to whatever is currently selected) rather than threaded through the same `selectedId` as everything else. Typography: body stays on `--font-sans` (Pretendard) everywhere; `--font-display-wide` is used only on the sidebar wordmark ("Gantry") and the page's single `<h1>` ("Deployments"); exactly three rendered weights appear anywhere in the route — the unset default (400, body/captions), `font-medium` (500, nav/buttons/pills/card titles), and `font-semibold` (600, h1/h2 headings and the chart's/column's emphasized numbers) — applied directly on leaf elements, with no `<table>`/`<th>`/`<strong>`/`<b>` anywhere to leak a stray UA bold. Versus reference products: it covers roughly Linear/GitHub-Projects-grade board mechanics (stage columns, card move, filtering, detail panel, command palette) plus an n8n-style "pipeline" framing via the velocity strip, but is intentionally narrower than a full platform — no bulk multi-select, no saved views, no audit-log detail screen behind the nav item (those nav items other than Deployments are present as wayfinding but not built out), which is the right scope for one board-first screen rather than a whole console.

## 브리프에 없던 것

- ① 정확한 칸반 단계 구성과 라벨 ② "Requested → Risk Review → Approved → Canary → Live"의 5단계로 확정 ③ 브리프가 예시로 든 "model-deployment approval board" 도메인 자체는 주어졌지만 구체적 단계명·개수는 비어 있었고, 승인 파이프라인을 실제로 걷는 모델이 거치는 현실적 체크포인트(위험 검토 → 승인 → 캐너리 → 전체 배포)로 5개가 과밀하지 않으면서도 "move to…" 메뉴가 의미를 가질 만큼 단계가 충분하도록 결정.
- ② 퍼널/차트가 보여줄 구체적 지표 ② 단계별 "median hours"(4/18/6/30h, 합계 58h)와 트레일링 90일 샘플 수(42→38→35→31→n=31 shipped) ③ "stage-duration funnel strip"이라는 이름만 주어졌고 무엇을 세로축/가로축으로 잴지는 비어 있었음; 결정론적이면서도(고정 리터럴, 산술 합계 검증 가능) 보드의 실제 단계와 1:1로 대응해 차트가 "보드를 설명하는 보조 지표"로 읽히도록, 각 단계 체류시간 + 통과 건수를 선택.
- ③ 브랜드명·도메인 세부사항(워크스페이스, 팀, 모델 이름) ② "Gantry"라는 브랜드명과 Vector Labs/Payments ML/Trust & Safety ML 워크스페이스, 18개의 구체적 모델명(fraud-scoring-v4, chat-router-llm 등) ③ "제품/브랜드 이름을 정하라"는 요구만 있었고 실제 명칭은 비어 있었음; "gantry"(발사대 구조물)가 배포 승인·출시라는 도메인과 시각적으로 맞아떨어지고, 이전 라운드 우승작의 블루/모노 톤과 겹치지 않는 네이밍이라 선택.
- ④ 포커스 복원 패턴의 정확한 구현 방식 ② 커맨드 팔레트와 상세 모달 양쪽 모두에 "wasOpenRef"/"prevOpenCardRef" 전환-추적 ref를 별도로 두고, 마운트 시점에는 아무것도 포커스하지 않도록 구현 ③ 브리프는 "이 패턴을 쓰라"고만 명시했고 두 개의 서로 다른 트리거(팔레트 버튼 vs. 카드별로 다른 트리거 엘리먼트)를 어떻게 함께 다룰지는 비어 있었음; 카드마다 트리거가 다르므로 불리언 하나로는 부족해, 마지막으로 클릭된 트리거 엘리먼트 자체를 ref에 저장하는 방식으로 일반화.
- ⑤ 보드 반응형 붕괴 지점 ② `lg`(1024px) 미만에서는 5열이 세로로 쌓이는 1열 스택으로, `lg` 이상에서는 `flex-1`(최소 180px·최대 360px)로 수평 5열로 분기 ③ "가로 스크롤 금지 + 1280px 이상에서 5열이 맞아야 함"이라는 두 제약만 주어졌고 정확한 브레이크포인트·min/max px는 비어 있었음; 1280px에서 사이드바(240px)+패딩을 뺀 실측 가용폭(≈992px)이 5열×최소폭+gap을 넘는 지점을 계산해 맞춤.
