# auto-native-r11 후보 c — Membership tiers

**한 줄 컨셉**: **손익분기 자(ruler) 화면** — 등급을 나란히 세우는 대신, 월 거래량이라는 **하나의 수직선 위에 각 등급이 이기는 구간을 갈라놓고** 내 위치를 마커로 찍는다. 논증은 "Elite 가 좋다"가 아니라 *"₩3,200,000 에서 Elite 는 ₩122,700, Basic 보다 ₩62,900 아래"* 라는 **내 숫자에 대입된 문장**이고, 골격은 리스트·격자·컴포저·타임라인·비교표 어디에도 속하지 않는 **구간축 + 판정문**이다.

**인터랙션 3종**

| 조작 | 증명 갱신 |
|---|---|
| − / + 거래량 스텝퍼 (56×56, 40만원 단위 16단) | 판정 헤드라인·지불액·절감액, 레일의 승자 밴드 강조와 마커 위치, "Where it flips" 두 문장, 등급 카드 대비 문장, 밴드 상태문이 **동시에** 재계산. **답만 바뀌는 게 아니라 이유(어느 선을 넘었는지, 얼마 남았는지)까지 갱신** |
| 등급 세그먼트 3분할 | 판정은 건드리지 않고 **그 등급의 조건**과 *"내 거래량에서 이 등급은 ₩144,300 — Elite 보다 ₩21,600 위"* 차액 문장을 연다. 추천 등급에 `CHEAPEST` 라벨이 붙어 **색 없이도 승자를 읽는다.** 기본 선택 = 추천 등급이라 열자마자 답이 상시 노출되고, 조작은 답을 지연시키는 게 아니라 **반례를 대보게** 한다 |
| 하단 밴드 (4-상태 기계) | `settled`(현재 등급이 곧 최적 → **버튼 없음, 문장만**) / `reveal`(다른 등급이 더 가볍다 + `Show Elite`) / `adopt`(추천을 보는 중 → `Switch to Elite`) / `override`(추천 아닌 걸 보는 중 → "₩21,600 더 든다" + 양방향 버튼) |

접근성: 밴드 컨테이너 하나에만 `polite`, 그 안 전환 문장에만 `alert`(라이브 리전 1개). 레일은 `accessible` 단일 노드로 묶어 손익분기 두 값과 현재 위치를 문장으로 읽힌다. 상태는 색 + **마커 위치** + **라벨 굵기** + `CHEAPEST` 텍스트로 중복 인코딩.

## 통제 실험 (Q38) — 회피 없음

`money` 스타일(`MembershipTiersScreen.tsx:682-687`): `fontSize:14 / fontWeight:"800" / color: ink2 / fontVariant:["tabular-nums"]`. `data.ts` `formatWon()` 이 `"₩" + 자릿수` 를 **한 문자열로** 반환 — 분리 없음.

**적용 17지점**: `100·105·109·114`(밴드 4상태) · `138·139·140`(판정문 거래량·지불액·절감액) · `147`(다이얼 헤드) · `233·235·240·245`(플립 문장) · `311·315`(보증 한도·월 요금) · `323·329·330`(등급 카드 대비 문장).

> **c 가 짚은 관측 포인트**: 이 셀은 `14/800/ink2` 라 **화면에 큰 숫자가 하나도 없다** — 금액이 전부 문장 안에 박힌 인라인 볼드로만 존재한다. `statValue`(수수료율·정산 주기)를 `14/700/ink` 로 맞춰 옆칸과 크기 단차를 없앴으므로, 남는 아티팩트는 (a) 800 굵기에서 `₩` 글리프와 숫자의 광학 무게 차 (b) `tabular-nums` 적용 시 `₩` 폭이 숫자 폭에 끌려가며 콤마 뒤 간격이 벌어지는지 — 두 지점에서 관찰될 것이다.

## 브리프에 없던 것

**① 등급 3종의 실제 수치** — ② Basic 5.8%/7일/₩300,000/₩0 · Plus 4.2%/3일/₩1,500,000/₩9,900 · Elite 2.9%/익일/₩5,000,000/₩29,900 ③ **손익분기가 스텝 격자와 겹치지 않게**(618,750 / 1,538,462) 고르고, 세 등급이 각각 이기는 구간이 실제로 존재하도록 역산했다. 값이 겹치면 구간축 자체가 무의미해진다. **임의 + 역산**

**② 거래량 축의 범위·간격·기본값** — ② 0~₩6,000,000, 40만원 16단, 기본 index 8(₩3,200,000) ③ 모든 스텝이 세 요율에 곱해 **정수로 떨어지게** 40만을 골랐다(반올림 잡음 0). 기본값은 압도적 승자 지점이 아니라 **이미 두 플립을 지난 지점**으로 두어 "왜 그 등급인가"가 거리로 설명되게 했다. **관행 + 계산 편의**

**③ 사용자의 현재 가입 등급** — ② `basic`(무료) ③ 밴드가 첫 프레임부터 할 일이 있는 상태(`adopt`)로 열려야 상태기계가 관찰 가능하다. **현재 등급이 곧 최적이면 밴드가 처음부터 terminal 이라 심사 대상이 사라진다.** **임의(관찰 가능성 역산)**

**④ 손익분기 계산식과 반올림** — ② `(상위 월요금 − 하위 월요금) / (하위 요율 − 상위 요율)` 을 `Math.round`, 비용은 `Math.round(거래량 × 요율) + 월요금` ③ 부동소수(`0.058−0.042 = 0.016000000000000004`) 때문에 반올림 없이는 618,749.99 가 나온다. 화면의 모든 숫자는 모듈 로드 시 상수에서 결정된다. **관행 + 결정론**

**⑤ 밴드가 "할 일 없음"에 도달했을 때** ★ — ② 문장만 남기고 버튼을 **언마운트**, 컨테이너(라이브 리전)는 유지 ③ "비활성 버튼은 감점, 밴드가 없는 것도 유효"를 절충했다. **컨테이너까지 없애면 라이브 리전이 사라져 이후 거래량 변경 시 알림이 끊긴다** — 리전은 남기고 액션만 비웠다. **정본 해석**

**⑥ 리스트 아닌 반복 렌더에 `.map()` 을 쓸지** — ② 3개 고정 그룹에만 `.map()`, `FlatList` 미사용 ③ "리스트 → FlatList" 조항의 대상은 **스크롤되는 데이터 목록**으로 읽었다. 3칸 세그먼트를 `FlatList` 로 만들면 비례 폭(2:2:12)을 잃어 구간축이 깨진다. 16눈금 설계도 검토했다가 비례 폭 3분할 + 절대배치 마커로 바꿨다. **정본 해석 — judge 판단 지점**

**⑦ 마커 위치 표현** — ② `data.ts` 에 16개 퍼센트 리터럴을 `as const` 로 박고 인덱스 참조 ③ 런타임 계산 문자열은 `DimensionValue` 의 `${number}%` 템플릿 타입에 안 맞아 `tsc` 가 걸릴 수 있다. **리터럴이면 타입도 통과하고 값도 결정론적.** **임의(타입 안전)**

**⑧ 다크 표면 사용 여부** ★ — ② 전면 순백, 다크 블록 0개(`onInk`/`onInkMuted` 미사용) ③ **통제 실험이 금액 색을 `ink2` 로 고정하는데 `ink` 표면 위 `ink2` 는 대비가 무너진다.** 실험 조건을 지키려면 금액이 놓이는 표면이 전부 밝아야 한다. **정본 충돌 회피**
