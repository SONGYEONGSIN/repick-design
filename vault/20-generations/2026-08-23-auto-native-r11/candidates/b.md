# auto-native-r11 후보 b — Shipping method picker

**한 줄 컨셉**: **비용 × 대기시간 산점도가 골격.** 네 발송 방법을 요금(세로) × 도착 시간(가로) 평면에 점으로 찍고, 그 위에 소포 성격 칩(부피·파손·수취인 부재)을 얹었다. 칩을 켜면 점들이 움직이고 어떤 점은 파선으로 죽는다. **세로 리스트 + 라디오는 "제일 싼 것"만 답하지만 평면은 "이 물건에 맞는 것"을 눈으로 답한다** — 저렴×느림 대 비쌈×즉시가 열자마자 좌하/우상 대각으로 보인다.

**인터랙션 4종**

| 조작 | 갱신되는 증명 |
|---|---|
| 프로필 칩 3종 토글 (Oversized / Fragile / Buyer away) | 할증·지연이 각 carrier 에 재적용 → **점 좌표 자체가 재배치**(정규화 재계산)되고, 거절 조건에 걸린 carrier 는 파선 + `no` 로 변한다. 하단 힌트가 몇 개가 배제됐는지 문장으로 말한다 |
| 평면 위 점 탭 (74×46) | 점이 ink 반전 → 밴드가 `Ready to book X · arrives in N days` 로 전환, 합계가 나타난다. **막힌 점을 탭하면 밴드가 거절 사유를 문장으로 말하고** CTA 가 비활성 + 재탭으로 해제(상태기계) |
| 하단 원장 행 탭 | 평면과 **선택 상태 공유**. 평면이 못 담는 보상 한도·거절 사유 전문을 텍스트로 (✓/✕ 형태 + 파선으로 인코딩, 색 아님) |
| Book | `confirmed` → 밴드가 handoff 지시문으로 바뀐다(`Print the label, drop it at any partner counter by 6 pm.`) — 종결 후 다음 행동을 말한다 |

기본값 `bulk:true, fragile:true` — **열자마자 두 개가 이미 배제/할증된 평면**이 보인다. 상시-노출 증명이 있고 조작이 그것을 강화한다.

## 통제 실험 (Q38)

`fontSize:15 / fontWeight:"800" / color: ink2 / fontVariant:["tabular-nums"]` + 같은 `Text` 안 `₩` — **StyleSheet 3곳 정의 → 렌더 5지점, 선택 상태에서 화면에 최소 9개 동시 렌더**(4 dot + 4 row + 1 total).

- `ShippingMethodScreen.tsx:381` `dotFare` → 렌더 `:172` (carrier 4개 동시)
- `:441` `rowFare` → 렌더 `:266` (행 4개 동시)
- `:459` `bandTotal` → 렌더 `:302`

`won()`(`data.ts:150`)이 `"₩" + 숫자`를 **한 문자열로** 반환해 ₩ 와 숫자가 같은 `Text`·같은 `fontVariant` 안에 있다 — 분리하지 않았다. 상태 변형(`dotFarePicked`·`dotFareBlocked`)은 `color` 만 덮어쓰고 size/weight/fontVariant 를 상속시켰다. `rowFareOff`(`:447`)만 의도적으로 `tabular-nums` 를 빼고 `—` 를 렌더 — 숫자가 아닌 자리라 **내부 대조군**으로 남겼다.

## 브리프에 없던 것

**① 소포 프로필 축을 몇 개, 무엇으로** — ② 3개(Oversized / Fragile / Buyer away on weekdays) ③ 브리프가 "부피·파손 위험·수취인 사정"을 나열했으므로 그 셋을 축으로 승격. 개수는 칩 3개가 가로 한 줄에 44pt 높이로 들어가는 상한. **브리프 도출 + 임의**

**② 배제(거절)를 표현할 것인가** ★ — ② 표현한다. `refuses` 맵으로 carrier×profile 거절 사유 문자열을 두고 파선 + `no` 라벨 + 원장 ✕ + 밴드 문장 **4중 인코딩** ③ "색만으로 인코딩 금지"와 "밴드는 왜 불가한지 문장으로 말한다"를 동시에 만족시키려면 배제 상태가 필요했다 — **배제가 없으면 밴드가 말할 불가 사유가 존재하지 않아 상태기계 조항이 공회전한다.** **조항 도출**

**③ 요금 외 제3 변수** — ② 파손 보상 한도(₩50,000~₩2,000,000)를 원장 행 메타에만 ③ 브리프가 "보상 한도가 다르다"고 적었으나 평면은 2축이라 자리가 없다. **평면=2축 / 원장=제3변수**로 분업. **관행(차트+테이블 병치)**

**④ ₩ 포맷터** — ② `data.ts` 에 `won()` 직접 구현, `toLocaleString` 미사용 ③ RN 구버전 Android 의 `toLocaleString` 은 로케일 데이터 부재로 구분자를 안 넣는 편차가 있어 결정론이 깨진다. **결정론 조항을 문자열 레벨까지 밀었다**

**⑤ 산점도 좌표를 절대값 대 정규화** — ② 현재 활성 프로필 기준 min–max 정규화 후 `left/bottom` 퍼센트(8~70%) ③ 절대값이면 same-day(₩12,800)와 freight(₩26,000)가 counter(₩3,200)를 바닥에 뭉갠다. 정규화하면 **칩 토글 시 점들이 서로 순위를 바꾸는 것이 보인다.** **임의(조항 만족 방향)**

**⑥ 마감 밴드를 둘 것인가** — ② 둔다(1개), `band` 컨테이너에 `polite` · `bandLine` 하나에만 `alert` ③ 브리프가 종결 액션 조항을 명시했고 밴드 없이 `alert` 를 둘 자연스러운 자리가 없다. **검증된 조합 그대로**

**⑦ 배경 판매 건의 구체 데이터** — ② Vintage turntable, walnut plinth / Nari K. / Busan / Sold Mar 4 ③ 부피 큼 + 파손 위험 두 프로필이 자연스럽게 켜져 있는 기본 상태를 만들려면 턴테이블 같은 물건이어야 했다 — **기본값이 억지로 안 보이게 하는 역산**

**⑧ 원장을 `FlatList` 대 `View` 나열** — ② `FlatList`(4행뿐이지만) ③ 정본 조항. 다만 평면의 점들은 절대 배치 오버레이라 `.map()` 유지 — **그건 리스트가 아니라 좌표 그리기다**

**⑨ `left`/`bottom` 퍼센트 타입** — ② `(left + "%") as unknown as number` 캐스팅 ③ RN 런타임은 `DimensionValue` 로 퍼센트를 받지만 배열 스타일 병합에서 타입이 좁게 추론되는 경우가 있다. **이 두 프로퍼티에만 적용, 다른 곳엔 단언 없음** — judge 감점 가능 지점으로 자진 표시
