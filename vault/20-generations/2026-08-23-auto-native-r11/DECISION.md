## ★★★ Q38 통제 실험 — 정본 조항이 존재하지 않는 원인을 쫓고 있었다

이 라운드는 `native/GENERATION.md` §1 의 `tabular-nums` + ₩ 조항을 시험하기 위해 배정됐다([[curation-criteria]] "Q38 판정"). 세 후보에 **같은 구성을 다른 크기·굵기로** 지시했다(색은 `ink2` 고정).

### 1단계 — 세 셀 모두 재현

| 후보 | 조건 | 390px 렌더 |
|---|---|---|
| a | `14 / 700 / ink2` | **아티팩트 재현** |
| b | `15 / 800 / ink2` | **아티팩트 재현** |
| c | `14 / 800 / ink2` | **아티팩트 재현** |

`b` 의 `15/800` 은 `r10` 에서 "깨끗했다"고 판정된 조합인데 여기선 터졌다. **크기도 굵기도 변수가 아니다** — Q38 이 좁혀 둔 세 후보 변수 중 둘이 배제됐다.

### 2단계 — DOM 계측

Q38 이 요구한 라이브 DOM 검사를 돌렸다(Expo web 렌더에 Playwright `getComputedStyle`):

```
textDecorationLine: "none"      ← ₩ 를 담은 전 노드
textDecoration:     "none"
fontVariantNumeric: "tabular-nums"
fontFamily:         -apple-system, "system-ui", "Segoe UI", Roboto, …
```

**취소선이 DOM 에 없다.** 즉 이것은 텍스트 장식이 아니라 **글리프**다.

### 3단계 — 결정적 A/B

같은 문자열을 `tabular-nums` 유/무로 나란히 렌더하고 `₩` 와 `W` 를 64px 로 확대했다([shots/AB-tabular-nums.png](./shots/AB-tabular-nums.png)):

| 조건 | 결과 |
|---|---|
| `tabular ON` 14/700 · `₩1,797,615` | 가로선 있음 |
| **`tabular OFF` 14/700 · 같은 문자열** | **가로선 있음 — 동일** |
| `tabular ON` 34/700 | 가로선 있음 |
| **`tabular OFF` 34/700** | **가로선 있음 — 동일** |
| `tabular ON` 14/700 · **₩ 없이 `1,797,615`** | **완전히 깨끗** |

확대한 `₩ W` 가 답이다 — **`₩`(U+20A9)는 원래 W 에 가로획이 그어진 글자**이고, `-apple-system` 스택에서 그 획이 W 좌우로 삐져나온다. 본문 크기에서 옆 숫자와 붙으면 취소선처럼 읽힌다.

### 결론

**`fontVariant: ["tabular-nums"]` 는 이 현상과 아무 관계가 없다.**

정본은 이 조항을 **두 번** 고쳐 썼다 — `r4` 의 *"₩ 를 형제 `Text` 로 분리하라"* → `r6` 의 *"형제 여부가 아니라 **중첩 깊이**가 기준"*. 두 처방 모두 **존재하지 않는 캐스케이드를 막으려던 것**이다. 그래서:

- `r6/a` 가 정본을 그대로 따르고도 실패한 것 — 따를 것이 없었다
- `r6/b` 가 `tabular-nums` 를 안 써서 "회피"한 것 — ₩ 를 안 썼거나 크기가 달랐을 뿐, `tabular-nums` 는 무관했다
- `r10` 이 비중첩에서 재발한 것 — 중첩은 애초에 조건이 아니었다

**네 라운드에 걸친 delta 계보 전체가 유령을 쫓았다.** 두 번 반증된 조항에 세 번째 처방을 쓰는 대신 변수를 통제하기로 한 판단이 정확히 이것을 잡으려던 것이고, **첫 실행에서 잡혔다.**

> **남는 실제 문제**: ₩ 는 본문 크기에서 옆 숫자와 시각적으로 붙어 읽힌다. 이건 렌더링 버그가 아니라 **글자 모양**이므로 "피하는 방법"이 아니라 **선택**이다 — ₩ 와 숫자 사이 간격을 주거나, `KRW` 표기를 쓰거나, 그냥 받아들이거나. §5 delta 로 올린다.

## 왜 c 가 이겼나

**렌즈 2 (완성도)** — 조작 한 번(± 스테퍼)에 **8개 면이 동시 재계산**된다: 추천 티어명 · 수수료 문장 3개 숫자 · 존 트랙 마커 · 존 라벨 굵기 · 하한선·초과분 · `CHEAPEST` 배지 위치 · 절감액 · CTA 라벨. `MembershipTiersScreen.tsx:36` 의 `rankAtVolume(volume)` 이 랭킹 자체를 파생시켜 **숫자가 움직이는 게 아니라 답의 정체가 뒤집힌다.** 768 에서 유일하게 폭을 일했다 — 390 에서 접혀 있던 2×2 스펙 그리드가 드러난다(늘어난 게 아니라 채워졌다).

**렌즈 3 (차별성)** — 세 후보 중 **유일하게 리스트가 답을 못 낸다.** 요금표 3줄을 아무리 잘 나열해도 *"₩1,538,462 위에서는 아무것도 Elite 를 못 넘는다"* 는 안 나온다 — 평면들의 교점을 풀어야 나오는 값이고 실제로 닫힌 형태로 푼다(`data.ts:105-107`). 상시노출도 통과: 슬라이더를 건드리기 전에 `WHERE IT FLIPS` 카드가 값이 채워진 채 떠 있다.

**렌즈 1 (정본)이 a 를 고른 이유** — **밴드가 조항 문구 그대로 일을 한다.** 문장으로 이유를 말하고(`the tax residency form for this quarter is unsigned`), 누르면 `scrollToEnd` 로 **실제 이동 + 도착지 하이라이트**한다(`:82-85`, `:344`) — 세 후보 중 유일하게 "이동"이 구현된 밴드다. 그리고 `role="alert"` 가 released 분기에만 있어 **진행 불가→가능이 뒤집히는 순간에만** 발화한다. c 는 `status` 가 `volume` 을 포함해 재계산돼 **스테퍼를 누를 때마다 alert 가 다시 읽힌다** — 조항이 요구하는 "바뀌는 지점"이 아니다.

## ★ 렌즈 1 이 b 에서 죽은 코드를 찾았다

`ShippingMethodScreen.tsx:297-301`:

```
disabled={!canBook}
onPress={() => {
  if (canBook) setConfirmed(true);
  else if (chosen !== null && chosen.blocked !== null) setPicked(null);
}}
```

`disabled` 가 걸려 있으므로 **`else if` 분기는 절대 실행되지 않는다.** 작성자가 복구 액션을 의도했는데 `disabled` 가 그것을 죽였다 — 즉 "눌리면 다음 미완료 지점으로 이동"이 코드상 존재했다가 무효화된 상태다. 렌즈 1 이 b 를 3위에 놓은 결정적 근거.
