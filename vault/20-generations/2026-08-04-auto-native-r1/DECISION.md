# DECISION — auto-native-r1

타깃: `native` (**루프 최초 native 라운드**). 이전까지 `auto-native-r*` 원장 entry 0건·`native-deltas-provisional.jsonl` 0줄이었다. `native/src`의 기존 3화면(watchlist·match·detail)은 S0~S4c 단계에서 손으로 만든 것이고 자율 라운드 산출물이 아니다.

BRIEF: `native/GENERATION.md`(§1~§8) + `native/src/tokens.ts`. 이 타깃은 프로파일이 아니라 정본이 GENERATION.md 하나다.

## 왜 지금 돌렸나

타깃 선택은 `PAGE_TYPES` 미채움을 우선하는데 `mobile`은 이미 차 있어, native는 전 타입 소진 후에야 1/3 확률로 뽑힌다. 미채움이 10종 남은 시점이라 최소 열흘 뒤에야 처음 실행될 예정이었고, **그 첫 실행이 무인 야간 라운드가 된다**. 게이트 native 분기(Expo Web export → 8091 서브 → tsc/export/render/iframe)와 스킬 native 절차 17군데가 전부 미검증이었으므로, 사람이 보는 앞에서 한 번 통과시키기 위해 수동으로 앞당겼다.

## 후보

기존 3화면이 전부 읽기 전용(리스트 2 + 상세 1)이라, 세 후보를 서로 다른 차별 축에 배정했다.

- **a — List an Item** (`ListingComposer`): 3단계 등록 폼. 컨디션·번들 선택이 요청가와 실수령액을 재계산하고 두 값은 단계 위 고정 카드에 상시 노출. 축 = **쓰기/입력**
- **b — Offer Thread** (`OfferThread`): 시간순 협상 스레드 + 인라인 오퍼 카드. 하단에 "수락 시 실수령액"과 수락/역제안/거절 고정. 축 = **시간에 따른 상태 전이**
- **c — Taste Calibration** (`TasteCalibration`): 단건 판정(Fits me / Not for me)이 추론 취향 프로필을 즉시 다시 씀. 축 = **시스템이 배우는 과정 자체**

## 하드게이트

`node scripts/gate.mjs --target native --screens evolve-r1-{a,b,c}` → **12/12 전원 통과**(후보×4단계). 1-fix 루프 불요. 상세는 SCORES.md.

**사전 스모크 테스트**: 후보 생성 전에 기존 `watchlist` 화면으로 게이트를 먼저 돌려 4/4 통과를 확인했다. 미검증 경로였으므로 후보의 결함과 게이트 자체의 결함을 분리하기 위한 조치다.

## 판정 대상 동결 (오케스트레이션 결함과 그 조치)

최초 게이트(06:46)와 최초 스크린샷(06:47)은 **낡은 상태를 쟀다**. 후보 b의 designer가 파일 생성 뒤에도 편집을 계속해 `OfferThread.tsx`가 06:50에 다시 쓰였다. **파일이 디스크에 나타난 것을 작업 완료로 오인**한 것이 원인이다 — designer 완료 알림을 기다리지 않고 진행했다.

판정 시작 후 렌즈3이 스스로 "후보 파일이 첫 읽기 이후 바뀌었다"고 감지하면서 드러났다. 조치: judge 3개 즉시 중단 → 해시가 20초간 불변임을 확인해 상태 동결 → **전 후보 재게이트 + 전 프레임 재캡처** → 판정 재시작.

**판정 대상 해시**: `38e915e4857ed39b500d4e2c2c8954689af6fb51`. 게이트·스크린샷·judge가 모두 같은 산출물을 봤다는 증거다.

이 결함은 native 고유가 아니다 — 웹 야간 라운드도 같은 구조이고, 무인 실행이라 발생해도 아무도 모른다. 스킬 §2·§3에 반영한다.

## JUDGE 패널 (3렌즈, 블라인드 — X/Y/Z = a/b/c)

### 렌즈1 — DNA 준수 (`GENERATION.md` §1~§7)
**1위 b · 2위 a · 3위 c.**

b는 세 후보 중 **유일하게 §1의 명시 조항 "최상위 래퍼 → `SafeAreaView`"를 지켰다**(`OfferThread.tsx:8`·`:369`). 조항 위반 0건.
a는 `SafeAreaView` 미사용(`ListingComposer.tsx:481` 최상위가 일반 `View`)이나 나머지 §1은 최고 수준 — 인라인 style 0건, 리스트 3종 전부 `FlatList`+`renderItem`. §4 접근성이 가장 넓다(`radio`/`switch`/`radiogroup`/`alert`/`accessibilityLiveRegion`).
c는 a와 동일한 `SafeAreaView` 위반에 더해 §1 "인라인 style 지양"에 걸리는 동적 객체 4건.

**세 후보 공통 통과**: §2 하드코딩 색 0건 · §3 한글 0자·순백 배경·단일 액센트·이모지 0 · §5 결정론 위반 0건 · 순수 텍스트 노드 0건.

### 렌즈2 — 모바일 앱 완성도
**1위 b · 2위 c · 3위 a.**

b는 이 렌즈에서 **열린 🔴이 없는 유일한 후보**. `SafeAreaView` 적용 + 커밋 액션 전부 2탭 confirm(`:472-506`) + 스테퍼 44×44에 `hitSlop 6`·경계 `disabled`. 핀 스트립이 조작 전에 이미 유효 오퍼와 만료 게이지를, 하단 바가 실수령액을 정적 기본값으로 노출한다.
c는 **두 폭 모두에서 아무것도 무너지지 않은 유일한 후보**(`maxWidth: 480` 열). 다만 화면 전체에 스크롤 컨테이너가 없어(`FlatList scrollEnabled={false}`) 667pt급 단말·글자 확대 시 하단 패널이 도달 불가 — 🔴이나 조건부 발현.
a는 배선이 가장 촘촘하나 🔴이 **상시 발현**: Next/Back 바가 홈인디케이터 영역을 침범한다(버튼 하단 y≈828/844, `SafeAreaView` 미사용). 768폭에서 −/+ 스테퍼가 약 606pt 벌어져 한 손 조작이 불가하고, `TextInput`을 가진 유일한 화면인데 `KeyboardAvoidingView`가 없다.

### 렌즈3 — 화면유형 차별성
**1위 c · 2위 b · 3위 a.**

c는 "핀 요약 / 스크롤 / 하단 액션바" 3밴드 실루엣 **밖**에 있는 유일한 후보. 밴드 순서가 역전되고 판정 버튼이 카드 바로 아래 붙으며, 스크롤 컨테이너가 아예 없다. 주 인터랙션 동사가 **판정 + 정확한 되돌리기**로 6개 화면 중 유일하며, `data.ts:334-347`이 현재·직전 fold를 둘 다 계산해 undo가 근사가 아닌 역연산이다. **차별성의 대가**로 화면 밀도가 최저이고 잘림 복구 수단이 없다.
b는 중간 밴드가 진짜 다르다 — 이종 4종 엔트리 + 당사자별 좌우 정렬 + 최신 앵커. 상태 전이가 가장 두껍고 **유일하게 이력이 쌓인다**(`data.ts:201-236`이 엔트리를 append하며 기존 live 오퍼를 superseded로 강등).
a는 매크로 버킷(3스텝 위저드) 자체는 신규이나 **두 겹으로 겹친다**: 외곽 3밴드 실루엣이 b와 동일하고, 각 스텝 본문이 "좌 텍스트 / 우 ₩수치" 균질 행 리스트로 `WatchList.tsx:40-74`의 행 해부와 같은 버킷으로 회귀한다.

**렌즈3이 지목한 후보 간 수렴**: a와 b의 외곽 실루엣(고정 헤더 + 파생 금액 핀 카드 / 스크롤 / 하단 accent 풀폭 액션바)이 동일하다. 서로 다른 아키타입을 배정했는데도 겉 골격이 수렴했고, 구분은 중간 밴드 내용물에서만 발생한다.

## 승자 — b (Offer Thread)

1위 표: **b 2표(렌즈1·렌즈2) · c 1표(렌즈3)** → 다수결 성립, tie-break 불요.

렌즈3이 b를 "외곽 실루엣이 a와 동일"이라 감점했음에도, 렌즈1·2가 지목한 a의 상시 발현 🔴(홈인디케이터 침범)과 c의 스크롤 부재가 준수·완성도 축에서 b를 앞세웠다. [[curation-criteria]] "차별성 ↔ 완성도 상충 시 판정 방향"(완성도 다수결 우선)과 정합하며, 이 패턴이 **네 번째 타깃에서 재현**됐다(catalog·product-detail·paywall에 이어).

## 반증된 judge 관찰 1건

렌즈1이 렌즈 밖 관찰로 "6장 스크린샷 전부에서 `₩` 글리프의 가로획이 뒤 숫자까지 번져 취소선처럼 보인다"고 보고했다. **오케스트레이터가 확대 검증한 결과 반증**: `a-390`의 `₩538,000`을 4배 확대하면 가로획이 W 안에서 끝나고 숫자를 건드리지 않는다. b 스크린샷에서 취소선으로 보인 금액은 렌더 결함이 아니라 `textDecorationLine: "line-through"`(`OfferThread.tsx:543`·`:598`)를 **만료·대체된 오퍼에 의도적으로 적용**한 것이다.

judge 관찰이라도 렌즈 밖 항목은 근거가 약할 수 있다는 사례로 기록한다. (오케스트레이터 본인도 첫 샷 판독에서 같은 오독을 했다.)

## 다양성 축

native는 `tokens.ts`가 배경·액센트를 고정한다(순백 라이트 + 단일 indigo). 웹 타깃의 테마·액센트 금지 축은 **이 타깃에 적용되지 않는다** — 회피할 자유도가 정본에 의해 닫혀 있다. 활자도 RN 기본이라 `catalog-variety.mjs`의 세 축 중 어느 것도 native 후보를 구분하지 못한다. 이 타깃의 차별 축은 **화면유형**이며 렌즈3이 그 역할을 한다.
