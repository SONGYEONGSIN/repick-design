# auto-native-r14 후보 a — Bulk Relist / Inventory Manager

**한 줄 컨셉**: 판매자가 자신의 리스팅 7개를 상시 브라우즈하는 화면에, 체크박스 탭 또는 롱프레스로 진입하는 멀티-셀렉트와 선택이 하나라도 있을 때만 나타나는 컨텍스트 배치 툴바(가격 10% 인하·재게시·내리기)를 얹어, 내리기만 파괴적 확인(인라인 Cancel/Confirm)을 거치고 나머지는 곧장 처리 스피너 → 결과 안내로 화면 안에서 종결한다.

## 브리프에 없던 것

**① 하단 상태기계 밴드 없이, 라이브 리전을 어디에 둘 것인가** — ② 헤더 바로 아래에 화면 수명 내내 마운트돼 있는 얇은 상태줄(`statusRegion`) 하나에 `accessibilityLiveRegion="polite"`를 걸고, 선택모드 진입/해제·배치 액션 결과 세 가지 전환을 전부 이 한 곳의 텍스트로만 흘려보냈다(평시엔 `alert` 롤 없는 힌트 문구, 전환 순간에만 `alert` 롤로 교체) ③ 델타 지시가 "선택 모드일 때만 뜨는 컨텍스트 툴바가 이 화면의 밴드"라고 명시해 하단 툴바 자체는 선택이 있을 때만 마운트되는 조건부 요소라, 거기에 라이브 리전을 걸면 모드 진입 발화(아직 아무것도 선택 안 한 시점)와 모드 해제 발화(툴바가 막 사라지는 시점)를 놓친다. §4의 "최대 1쌍" 제약을 지키면서 두 순간을 모두 커버하려면 화면 수명 내내 살아있는 별도의 얇은 캡션 자리가 필요했다. **논증 정합(제약 하 결정)**

**② "Paused" 탭을 의도적으로 빈 상태에서 시작시켰다** — ② 7개 리스팅 전부 초기 status를 `"active"`로 고정해 Paused 탭이 첫 렌더부터 진짜로 0건이고, ListEmptyComponent가 안내문 + "Go to Active" 같은 실제 액션(가짜 no-op 아님)을 보여준다. 사용자가 멀티셀렉트로 "Take down"을 실행하면 그제서야 Paused 탭이 채워진다 ③ UX 체크리스트의 "빈 상태(리스팅 0개일 때 안내+액션)"를 만족시키려고 인위적으로 별도 필터나 삭제 플로우를 새로 만들지 않고, 이 화면의 핵심 배치 액션("내리기")이 만들어내는 자연스러운 부작용을 빈 상태 증명에 그대로 재사용했다 — 데이터 결정론(§5)과도 충돌 없이 검증 가능. **논증 정합**

**③ "Relist"가 상태를 `active`로도 되돌리는 겸용 액션** — ② `relist` 배치 액션은 조회수/좋아요를 0으로 리셋하고 "Relisted just now" 레이블을 붙이는 동시에 status를 무조건 `"active"`로 세팅한다(이미 active인 항목엔 무해, paused였던 항목은 재활성화) ③ 배정 아키타입이 "재게시"를 활성 리스팅 관리의 한 축으로 명시했는데, 만약 재게시가 상태를 되돌리지 않으면 Paused 탭에서 항목을 빠져나가게 할 유일한 경로가 없어져 Paused 탭이 영구히 늘어나기만 하는 막다른 상태가 된다. 겸용으로 만들어 Active↔Paused 순환 고리를 완성했다. **논증 정합**

**④ 체크박스는 언제나 렌더링(선택모드 아닐 때도), 다만 진입 트리거로만 동작** — ② 모든 행 왼쪽에 항상 아웃라인 원(체크박스)을 그려두고, 선택모드가 아닐 때 그걸 탭하면 즉시 선택모드로 진입 + 해당 항목 선택까지 한 번에 처리한다. 롱프레스도 같은 결과를 낸다 ③ UX 체크리스트 "제스처엔 시각 힌트 동반(선택모드 진입 방법을 아이콘/라벨로 명시)"을 롱프레스라는 비가시적 제스처 하나에만 의존하지 않고, 상시 노출된 아이콘으로도 같은 진입점을 제공해 발견 가능성을 이중화했다. 헤더의 "Select" 텍스트 버튼이 세 번째 진입점. **정본 규칙 직접 적용**

**⑤ 행 자체의 일반 탭(선택모드 아닐 때)은 no-op — 상세/수정 화면으로 안 감** — ② `handleRowPress`에서 선택모드가 아니면 아무 것도 하지 않고, 코드 주석에 "이 폴더 범위에 리스팅 단건 상세/수정 플로우가 없다"고 명시했다 ③ 델타 지시 "no-op Pressable은 아직 없는 하위 플로우의 정당한 자리표시자"를 그대로 적용 — 단, 비활성 룩으로 죽이지 않고 정상 Pressable(눌림 피드백 포함)로 두어 "여기 뭔가 있을 것 같은데 반응이 없다"는 오인보다 "지금은 선택만 가능하다"는 화면의 실제 기능 범위를 정직하게 반영했다. **정본 규칙 직접 적용(델타)**

**⑥ ₩ 표기: 공백 분리(선택지 ①), payout/data.ts·evolve/r12/a와 동일 컨벤션 재사용** — ② `formatWon()`이 `₩ 89,000`처럼 ₩와 숫자 사이에 고정 공백을 넣는 방식을 그대로 가져왔다(새 유틸을 안 만들고 payout 관용구를 그대로 복제) ③ 이미 통제실험(2026-08-24 정정)으로 안전성이 확정된 조합이고, 가격이 이 화면에서도 핵심 증명 중 하나(배치 인하 액션이 실제로 숫자를 바꾼다)라 표기 방식을 이 라운드에서 새로 실험할 이유가 없었다. **정본 컨벤션 재사용**

**⑦ 처리 중 배치 버튼에 진짜 ActivityIndicator 스피너** — ② 텍스트로만 "Processing…"이라 적지 않고 `ActivityIndicator`를 텍스트 옆에 같이 렌더해 툴바 전체를 단일 비활성·busy 행으로 교체했다(`accessibilityState={{disabled:true, busy:true}}`) ③ UX 체크리스트가 "로딩 버튼(배치 액션 처리 중 비활성+스피너)"을 명시적으로 요구했고, payout 화면은 텍스트만으로 처리했지만 이 화면은 최대 7건을 동시에 건드리는 배치 작업이라 시각적 처리 신호를 더 분명히 하는 쪽이 낫다고 판단. **정본 규칙 직접 적용**
