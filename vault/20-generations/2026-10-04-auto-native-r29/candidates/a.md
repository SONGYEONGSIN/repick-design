# r29 · candidate a — Loyalty Points Statement

A read-only record screen for repick's loyalty program: a member opens their statement for a closed period (Sep 1–30, 2026) and sees a hero current-balance figure, a line-item ledger of every earn/redeem/expire/referral event with a running balance per row, and a persistent bottom action bar instead of a blocked-workflow band, since nothing on this screen is pending a decision. The hero balance and every row's running balance are never independently hand-typed — both read off one `computeStatementLedger` fold over the same `STATEMENT_TRANSACTIONS` array in `data.ts`, so the headline number and the arithmetic underneath it cannot drift apart. The bottom bar carries two working actions: "Share Statement" calls React Native's core `Share.share(...)` with a message built from the real current balance and period, and "View Rules" toggles real `useState` state that expands an inline redemption-rules panel further up the scroll content with actual rule text, not a stub.

## 브리프에 없던 것

1. **₩ 기호 vs "KRW" 리터럴 표기** — 브리프가 지적한 대로 ₩ 글리치가 숫자와 붙으면 취소선처럼 보일 위험이 있어, 어떤 방식을 쓸지는 스스로 정해야 했다. 간격을 주는 방법 대신 "KRW 8,210" 처럼 리터럴 문자열을 선택했다. 이유: 글리프 간격 조정은 폰트/플랫폼마다 렌더링이 미묘하게 달라질 수 있어 결정론적이지 않다고 판단했고, "KRW"는 영수증·명세서류 핀테크 UI에서 흔히 쓰이는 표기라 한국 사용자에게도 낯설지 않다(토스·카카오페이 등 일부 정산 화면 관행 참고).
2. **환불/손실 트랜잭션의 색상 톤 구분 기준** — 브리프는 4가지 트랜잭션 타입을 섞으라고만 했고, 각 타입에 어떤 색을 쓸지는 명시하지 않았다. "적립/추천 보너스"는 success(녹색), "만료"는 danger(적색), "적립 매장 크레딧 교환(redeemed-for-store-credit)"은 의도적인 소비이므로 danger가 아닌 중립 ink2 톤을 쓰기로 했다. 이유: 포인트가 줄어든다고 해서 전부 "나쁜 일"은 아니며, 사용자가 직접 선택해 교환한 것과 자동으로 소멸된 것을 같은 경고색으로 묶으면 오인시킬 수 있다고 판단 — 금융 명세서 UI에서 "출금/사용"과 "손실/수수료"를 다른 톤으로 구분하는 일반적 관행을 따랐다.
3. **바텀 액션 바와 인라인 패널의 토글 제어를 하나로 합칠지 여부** — "View Redemption Rules가 실제 인라인 패널을 펼친다"는 요구를 만족시키는 방법이 여러 가지였다(인라인에 자체 토글 버튼을 또 둘 수도 있었음). 토글 컨트롤은 바텀 바에만 두고, 본문에는 패널과 안내 문구만 배치하기로 했다. 이유: 같은 상태를 여는 버튼이 화면 두 곳에 중복되면 스크린리더 사용자에게 동일 기능이 두 번 노출되어 혼란스럽고, "persistent bottom action bar에 실질적 액션 두 개"라는 요구 조건과도 더 깔끔하게 맞아떨어진다고 판단했다.
4. **포인트→원화 환산 비율(1포인트=10원)과 적립 규칙 5개 항목의 구체적 문구** — 브리프는 "실제 규정 텍스트"만 요구했지 비율이나 문구를 주지 않았다. 10원/포인트, 100포인트 단위 교환, 18개월 소멸 등은 국내 이커머스/리워드 프로그램에서 흔한 수치 범위를 참고해 임의로 정했다 — 실제 repick 정책 문서가 없는 상태에서의 플레이스홀더 성격의 결정이다.
