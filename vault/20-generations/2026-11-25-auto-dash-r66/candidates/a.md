Gridwell is a renewable-energy grid-balancing operations console for utility dispatchers watching supply, demand and storage across six balancing regions in real time; it implements the assigned 3-pane market layout as a fixed 300px left region rail, a fluid center pane carrying the dominant chart (a generation-mix stacked area — solar/wind/gas/storage, bottom-to-top in validated dark-surface categorical order — with a dashed neutral demand line overlaid, and the headline generation/demand/net-balance/renewable-share numbers always rendered as text above the chart, never hover-only), and a fixed 380px right pane that holds a pinned-region snapshot card plus a tabbed, filterable, sortable event table. Deliberately splitting the "selection → multi-widget sync" fan-out so it never collapses into master-detail: (1) clicking a region in the left rail sets a `pinnedRegionId` that updates **only** the one snapshot card in the right pane and explicitly never touches the chart or the event table; (2) the chart's crosshair hover/keyboard-arrow inspection is a fully separate, ephemeral `activeIndex` state scoped only to GridChart's own aria-live readout, never written to shared state; (3) the period segmented control (24h/7d/30d) recomputes the chart from an independent daily dataset; (4) the event table has its own tabs (Active/Resolved), a severity filter popover, and a column sort, all independent of the rail and the chart. A ⌘K command palette (bonus 5th interaction) lets you jump to and pin any region from anywhere. Typography discipline: Pretendard for all body/UI/data text (copy is English-only per brief), `--font-display-wide` used exactly once on the "Gridwell" wordmark and nowhere else, all currency/count/percent/time values in `tabular-nums` and right-aligned in tables, 11px uppercase tracked labels for every field label, and exactly three rendered font weights (400/500/600) across the whole route. Against commercial references, the app shell (sidebar + workspace switcher + nav with stub panels + avatar menu + notification popover + primary-action modal that actually creates a toast-confirmed order + 44px header controls) and the local component system (Card/Badge/ProgressBar/SegmentedControl/Tabs/FilterMenu/Sparkline, all built as real files rather than inline soup) aim for Mercury/n8n-grade completeness rather than a single hero screen; the one place it still falls short of a shipped product is that only the chart's time range is genuinely re-fetchable — regions and events are a fixed deterministic fixture set rather than a live-filterable universe.

## 브리프에 없던 것

① What had to be decided: the numeric thresholds that turn a region's supply/demand balance into a status label (Surplus/Balanced/Tight/Deficit).
② What I decided: balance-to-demand ratio bands of ≥10% / ≥-5% / ≥-15% / below that, computed from the same per-region bucket the rest of the page reads.
③ Why: the brief asked for a region status concept (Dedup list mentions "Harborline... persistent badge pin") but never gave bands; I picked round, intuitive numbers rather than anything data-fit, so they're an arbitrary-but-reasonable convention, not a measured threshold.

① What had to be decided: which of the four generation sources gets which of the dataviz skill's validated categorical slots, and in what stack order.
② What I decided: storage = slot 1 (blue, bottom of stack), gas = slot 2 (orange), wind = slot 3 (aqua), solar = slot 4 (yellow), with the demand line kept off the categorical palette entirely (neutral zinc-100/dashed) since it's a reference overlay, not a stacked identity.
③ Why: the dataviz skill's palette.md specifies the validated hue *order* for adjacent-pair stacks but not which real-world series maps to which slot; I picked intuitive associations (yellow→solar, aqua→wind) while keeping the validated adjacency order intact, and kept demand off-palette per the skill's own "text/reference lines use ink, not series color" guidance.

① What had to be decided: how many balancing regions to invent, and their names, geography flavor and generation character.
② What I decided: six US-flavored regions (Pacific Northwest, Desert Southwest, Gulf Coast, Great Lakes, Mountain West, Atlantic Seaboard), each with a distinct dominant fuel mix (wind-heavy, solar-heavy, gas-anchored, balanced, solar+storage, offshore-wind-lagging) so the rail has visible variety instead of six near-identical rows.
③ Why: the brief specified the chart composition and domain but not a region roster; six felt like enough to make the rail and the command palette feel like a real directory without turning the fixture data module into unmanageable hand-authored volume.

① What had to be decided: how "7d" and "30d" chart views should differ structurally from "24h" rather than just being a cosmetic re-label.
② What I decided: a genuinely separate 30-point daily dataset (with its own weekly/weekend demand dip and seasonal drift) rather than re-chunking the 24 hourly points, so the three period views show distinguishable shapes.
③ Why: a prior round's reference pattern (seen in this repo for a different domain) chunked one 24-point array three ways; that produces suspiciously smooth "weekly" and "monthly" curves from only a day of source data, so I built a second generator instead.

① What had to be decided: a concrete, working focus-visible treatment, since the brief named two broken idioms (ring+ring-offset, and self-cancelling outline-none) but didn't hand me a replacement.
② What I decided: a shared `FOCUS_RING` / `FOCUS_RING_INSET` pair in `components/focus.ts` using the plain `outline` utility (which sets `outline-style: solid` explicitly) plus `outline-2` and `outline-offset-2`/`-outline-offset-2`, never combined with `outline-none` anywhere on the page.
③ Why: this was flagged as a hard gate risk with no prescribed fix; I chose the simplest utility that Tailwind v4 is documented to apply unconditionally (`outline`, not `ring`), and centralized it in one file so every interactive element gets the identical, verified treatment.

① What had to be decided: which metrics get a bounded `ProgressBar` versus a plain signed number, given the explicit warning against silently clamping a metric that can exceed 100%.
② What I decided: only naturally-capped metrics (battery state of charge, renewable share of generation) get the progress-bar treatment; balance/reserve-margin, which can legitimately go deeply negative or far over 100% of a target, stay as signed text with a color cue instead.
③ Why: rather than build overflow-indicator UI for a metric the brief didn't ask for, I avoided the pitfall by routing the bar component only to metrics where 0–100% is actually the full possible range.

① What had to be decided: a brand name, wordmark icon, and a named operator persona for the account menu / toast copy, since the brief gave a product name ("Gridwell") but no visual identity or "logged-in user."
② What I decided: a `Zap` glyph in an indigo tile for the wordmark, and "Priya Natarajan, Grid balancing operator" as the signed-in user shown in the sidebar and account menu.
③ Why: arbitrary but deliberately unremarkable choices (a lightning-bolt glyph reads immediately as "energy/grid" without claiming any real company's mark) so the shell doesn't feel like a placeholder.
