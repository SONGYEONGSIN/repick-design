# auto-dash-r4 — JUDGE 판정

생존 후보 3개(a Ridgeline, b Wardline, c Parallax) 전원 하드게이트 통과. 3렌즈 병렬 판정(블라인드 — 스크린샷 4폭 + 소스 경로만 제공, 생성 컨셉/순서 비공개).

## brief 렌즈 (brief v3 전문 대조)

**랭킹: c > b > a**

- **a (Ridgeline)**: 위반 다수 — (1) 명시적 12-col 그리드 전무(전체 flex 기반, `grid-cols-12` 0회). (2) 컴포넌트 체크리스트의 "스파크라인" 전무. (3) 헤더 바 컨테이너는 h-11(44px)이나 개별 버튼(⌘K 트리거·아이콘버튼·New issue)은 h-9(36px) — "헤더 컨트롤 높이 44px 통일" 위반(컨테이너 아닌 개별 컨트롤 기준). (4) "Unassigned"/"No priority" 라벨이 라이트 배경에 `text-zinc-400`(~2.4:1) — 대비 하드게이트 미달이나 기본 뷰에 없어 Lighthouse 자동 스캔이 못 잡음.
- **b (Wardline)**: 타일월에서 "Mobile Gateway — iOS/Android", "Notifications — Email/Push/SMS" 등 유사 접두사 라벨이 truncate로 전부 "Mobile Gatew…"/"Notificati…"로 뭉개져 구분 불가 — 자동 sweep(overflow 없음)은 통과하지만 브리프의 "말줄임 최소화" 의도를 어김. 그 외 12-col 그리드·44px·다크 대비 토큰 전부 준수.
- **c (Parallax)**: 위반 없음(경미하게 아웃라인 레일의 세그먼트 드롭다운만 h-9). 12-col 그리드·스파크라인 포함 전 컴포넌트·44px 전 컨트롤·대비 위반 0건·가장 문자 그대로의 "선택→다중 위젯 동기화"(공유 필터가 7개 위젯 실제 재계산).

## visual 렌즈 (상용 서비스급 스크린샷 심사)

**랭킹: a > b > c**

- **a**: Linear급 완성도 — 리스트/상세 분할, 라벨 배지·탭뉴럴 메타그리드·서브이슈 진행바·연동PR칩·활동피드 전부 정제. 모바일 콘텐츠 우선 축소 깔끔. 가장 "출시 가능"해 보임.
- **b**: 다크모드 실행 우수(기능적 상태색), 카드가 촘촘해 5개 지표+스파크라인이 빽빽. "Notifications — Push/Email/SMS" 반복 네이밍이 보일러플레이트처럼 느껴짐.
- **c**: 카드 리듬·단일 강조색 절제는 양호하나 구성(라인차트+KPI+진행바+도넛) 자체가 셋 중 가장 스톡 템플릿에 가까움. 모바일에서 필터 레일이 리포트 콘텐츠보다 위에 쌓여 스크롤 우선순위 오류.

## archetype 렌즈 (구조 차별성)

**랭킹: b > a > c**

- **a**: 마스터-디테일을 기본 뷰로 완전히 커밋(레일+상세, KPI/차트/카드그리드 전무). Table 토글은 부차 뷰라 감점 미미.
- **b**: 가장 명확한 커밋 — 24개 균일 타일(반응형 1→2→3→4→6열), KPI 카드·상시 상세 패널 없음, 상세는 일시적 드로어. 등록된 아키타입과 겹침 0.
- **c**: `dash/d30`과 직접 대조 시 구조가 거의 동일(히어로차트+KPI 8/4 분할→카드 행→풀폭 테이블, 12-col grid col-span 카드) — "BI 캔버스"의 실질 신규성은 OutlineRail(위젯 점프+공유 필터) 정도. 셋 중 구조적 차별화가 가장 약함.
