# 후보 c — "Negotiation Console"

**한 줄**: 히어로의 톤 슬라이더(polite → assertive)가 판매자에게 보낼 메시지 초안·예상 절감액·수락 확률 세 증거를 동시에 재계산하고, 그 아래 같은 폴드에 4장의 보딩패스형 비교-스트립 매물 카드가 상시 노출된다.

- 배정: 조작 어휘 = **협상 톤 슬라이더** / 매크로 골격 = 히어로+콘솔 → **탭 패널 스위처 → 마퀴 티커 → 비교 테이블** → CTA / 다크 · `--font-display-grotesk`
- 파일: `page.tsx`(서버 셸 · 마감 CTA · 푸터) · `HeroNegotiation.tsx`(클라 히어로 · 슬라이더 · 콘솔) · `ProductStrip.tsx`(서버 · 4카드 비교-스트립) · `ValueTabs.tsx`(클라 · role=tablist 탭) · `TrustMarquee.tsx`(서버 · 순수 CSS 마퀴) · `CompareTable.tsx`(서버 · 시맨틱 테이블) · `data.ts`(결정론 파생 함수 + 상수)

## 인터랙션 (4종 이상)

| # | 조작 | 동시 갱신 증거 |
|---|---|---|
| 1 | 협상 톤 슬라이더(`input[type=range]`, `aria-valuetext`) | ① 초안 메시지 문장 교체(4단계) ② Est. savings($ · %) ③ Accept odds(%) — savings는 오르고 odds는 내려가는 실제 트레이드오프 |
| 2 | 가치제안 탭(`role=tablist/tab/tabpanel`, ArrowLeft/Right/Home/End 키보드) | 패널 헤딩·본문·proof 배지 전환 |
| 3 | 스크롤 리빌(`whileInView`, `once:true`, `useReducedMotion` 게이팅) | 탭 섹션 헤더 진입 |
| 4 | CTA 클릭 시 부드러운 스크롤(`scrollIntoView`, reduced-motion이면 `auto`) | 히어로 CTA → 매물 스트립으로 점프 |
| 5 (보너스) | 매물 카드 hover | `transform`+`border-color`만, 200ms ease-out, `motion-reduce` 게이팅 |

## 브리프에 없던 것

1. **채움 배경 위 글자색(흰색 vs 어두운 잉크)** — ① design-principles §Color Tokens는 "accent 배경 위에는 흰색이 아니라 어두운 잉크"라고 적었다. ② 직접 WCAG 상대휘도를 계산했다: `#6E56CF`(휘도 0.1447)는 화이트-블랙 교차점(휘도 0.1791)보다 어두운 쪽이라 **흰 글자(5.39:1)가 검은/어두운 잉크(3.65:1)보다 실제로 대비가 더 높다** — 버튼 텍스트(14px semibold)는 대형 텍스트 예외에 못 들어가 4.5:1이 필요한데 어두운 잉크는 미달이다. 그래서 CTA/칩 채움에는 기존 카탈로그(v6·v7·v11)와 동일하게 흰 글자를 유지했다. ③ 계산 근거 + 기존 프로덕션 챔피언과의 일관성. **단** 라이트 틴트 `#B6A6F0`(휘도 0.4351, 교차점보다 밝음)를 채움으로 쓰는 경우엔 반대로 어두운 잉크가 맞다고 계산했지만, 이번 산출물엔 틴트를 배경 채움으로 쓴 곳이 없어 실제 적용 사례는 없다.
2. **첫 폴드 완전 무스크롤 vs 실측 타협** — ① "스크롤 없이 4카드"를 마련하려면 히어로 카피+콘솔+4카드 전부가 필요해, 정보 밀도상 812×390 뷰포트에서 완전한 무스크롤은 불가능에 가까웠다(측정: 900px 뷰포트에서도 카드 통계행이 폴드 경계에 걸침). ② 모바일 패딩/줄간격을 데스크톱보다 공격적으로 줄이고(pt-9, 카드 종횡비 16:10으로 축소) "사진+제목까지는 완전히 보이고 통계행만 근소하게 걸치는" 지점까지 좁혔다. ③ design-principles 자체가 "섹션 상하 패딩 최소 96px"을 데스크톱 한정으로 적어 모바일 여지를 열어뒀고, 실제 상용 모바일 랜딩도 히어로+4카드를 완전 무스크롤로 넣는 사례가 드물어 "최대한 타이트하게"를 실용적 해석으로 택했다.
3. **협상 대상 매물과 통화 표기** — ① 브리프는 협상 슬라이더의 대상 매물이 무엇인지, 통화가 무엇인지 특정하지 않았다. ② 매물 스트립 4장과 이름을 공유하지 않는 독립된 "$185 listing"으로 두고(구체적 상품명 없이 일반화), 통화는 `$`로 통일(₩ 유니코드 기호는 이전 라운드에서 이모지 오탐 전례가 있던 `©`와 같은 위험군은 아니지만, 카탈로그 절반이 `$`를 쓰고 있어 일관성을 택함). ③ 방어적 임의 — 특정 매물에 값을 묶으면 "이미 repick이 골라준 할인가"와 "사용자가 판매자와 협상 중인 원가"가 같은 카드 안에서 두 가지 다른 가격 체계로 읽혀 혼동을 줄 수 있다고 판단해 분리했다.
4. **톤 슬라이더 저장액/수락확률의 구체 공식과 기본값** — ① 브리프는 "저장액 또는 수락확률"만 예시로 들었지 실제 숫자·기본 슬라이더 위치는 정하지 않았다. ② `savings = round(18 + v×0.6)`, `likelihood = round(82 - v×0.34)`, 기본값 `v=45`(정확히 중앙값 50이 아닌 임의값으로 "이미 사용 중인" 느낌을 의도) → 기본 상태에서 savings=$45(24%)·odds=67%로 이미 0이 아닌 실측 가능한 값이 보이도록 함(직전 라운드의 "정지 상태 동일값" 결함 회피). ③ 임의(제약 역산) — 두 수치가 서로 반대 방향으로 움직여야 "트레이드오프"라는 서사가 성립하므로 부호를 반대로 설계했다.

## designer 자체 신고 — 검증 상태

`npx tsc --noEmit`, `npx eslint`, `node scripts/dash-static-check.mjs`를 이 폴더 파일에 대해 직접 실행해 전부 통과를 확인했다. Playwright로 1280/1366/1440/1600/1920/390 전 폭에서 `scrollWidth === clientWidth`(가로 오버플로 0건)를 실측했고, 1440px·390px 폴드 스크린샷과 탭 키보드 내비게이션(ArrowRight 이동), 비교 테이블·마퀴 렌더를 육안 확인했다. 샌드박스 프록시가 `images.unsplash.com`·Pretendard CDN을 차단해 콘솔에 리소스 로드 실패가 찍히지만 hydration/런타임 예외는 0건이었고, 별도 네트워크 경로(직접 서버 접속) 스크린샷에서는 이미지가 정상 로드됨을 확인했다. Lighthouse a11y·perf 게이트는 이 세션에서 실행하지 않았다.
