# Candidate C — Consignment Drop-off Scheduling

## Concept

A seller-facing React Native screen that schedules a physical consignment drop-off in two dependent picks driven by a single `FlatList` of partner stores: the list (`native/src/evolve/r22/c/data.ts` → `LOCATIONS`) is sorted nearest-first, and each row shows that store's fixed today-hours window, with stores closed today rendered dashed-border/low-opacity and paired with an explicit "Closed today" tag (not tappable, `disabled` + `accessibilityState`) rather than relying on color alone; picking an open store computes its time-slot grid live by dividing that store's today open-hours window into fixed 30-minute windows and subtracting a fixed set of already-booked start-times (`deriveSlots` in `data.ts` — pure function, no randomness), rendering full slots as struck-through and labeled "Full" and open ones as tappable cells. A bottom status band (`StatusBand.tsx`) implements the blocked-workflow state machine: while no store is picked it states that in a full sentence and, when tapped, scrolls the list to the top and moves accessibility focus to the store-list heading; once a store is picked but no slot is, it names the store and explains a time is still needed, tapping scrolls to the end of the list (where the slot grid lives as the `FlatList`'s footer) and focuses that heading; once both are picked the band itself becomes the "Confirm drop-off" action, and pressing it computes a deterministic confirmation code from the chosen store + slot (`buildConfirmationCode`) and reveals it inline in the band, replacing the CTA with a non-interactive confirmed state. The band's message text carries `accessibilityRole="alert"` inside the screen's one `accessibilityLiveRegion="polite"` container so every blocked→ready transition is announced.

## 브리프에 없던 것

1. ① What day/time to treat as "today" for the open-hours math, since no real clock read is allowed. ② A fixed constant `TODAY: Weekday = "Thursday"` in `data.ts`, used everywhere instead of any `Date` object. ③ Arbitrary choice made purely to satisfy the determinism rule (no argument-less `new Date()`); Thursday was picked so at least two stores could plausibly be "closed today" without every store needing a special case.

2. ① What slot length to derive against. ② Fixed `SLOT_LENGTH_MINUTES = 30` exported from `data.ts` and referenced in the UI copy ("split into 30-minute windows"). ③ The brief suggested "30 minutes" as an example, so I took it as the concrete value rather than inventing a different number.

3. ① How to represent "already booked" slots as an input to the derivation. ② A fixed `BOOKED_SLOTS: Record<locationId, number[]>` map of booked start-minutes per store, subtracted inside `deriveSlots`. ③ Arbitrary but deliberately shaped as a minimal fixture (a plain lookup table) so the derivation is visibly "open-hours ÷ slot length, minus a fixed list" and not disguised randomness.

4. ① How the confirmation code should be generated without `Math.random`/`Date.now`. ② A pure `buildConfirmationCode` function: store-name initials + a weighted char-code checksum of `locationId:slotId`, formatted as `RPK-XXX-####`. ③ Arbitrary invention to keep the "confirmation code" proof-of-computation deterministic and reproducible per pick, consistent with the repo's no-randomness rule.

5. ① Where the slot section should live relative to the virtualized store list, since nested `FlatList`s aren't valid RN. ② Made the slot section the `FlatList`'s `ListFooterComponent` (and the intro copy its `ListHeaderComponent`), so the single `FlatList` stays the one scrollable surface and the "jump to slot section" band action can just call `scrollToEnd`. ③ Followed the RN convention of using header/footer components to avoid nested `VirtualizedList` warnings, rather than an existing screen's layout.

6. ① Exact wording/behavior contract for the bottom band per phase (since the brief forbids literally reusing another screen's hint phrasing/style keys). ② Wrote fresh style keys (`wrap`, `touchable`, `touchableReady`, `touchableDone`, `headline`, `detail`) and fresh copy ("Pick a partner store before this can be confirmed.", "Jumps down to the time grid for this store.", etc.), each hint checked against what the handler literally does (scroll + focus, or compute + reveal code). ③ Arbitrary wording invented to satisfy the "don't copy verbatim" instruction while keeping the same blocked→ready principle.

7. ① How many/which stores to include and their distances/hours, since none were given. ② Seven fixed stores (0.6–4.5 mi) with varied hour patterns (standard, shortened Thursday, evening-only, two closed-today) to exercise sort order, closed-store styling, and slot-count variety. ③ Arbitrary choice sized to be enough for a meaningful `FlatList` and to demonstrate the hours-math branching (full day / short day / closed).
