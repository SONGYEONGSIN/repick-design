# Candidate a — Lotwise

Lotwise is an internal pricing & liquidation desk console for a resale-marketplace ops team (invented client: Harborline Resale Ops). The page is a trading-terminal-style **3-pane market shell**: a fixed-width left **Watchlist rail** (six-lot personal watchlist / all-ten-lots tab, sparkline + price + status per row), a dominant center **candlestick chart pane** (hand-built SVG OHLC chart, daily/weekly period toggle, keyboard-accessible crosshair, embedded readout, and a required OHLC data-table fallback), and a right **desk pane** holding a floor/reserve progress readout + floor-price-adjustment tool, a sortable active-bids table, and a desk-wide activity feed. All ten lots, thirty trading days of candles, bid ladders and the activity feed are generated from a fixed `mulberry32` PRNG seeded per lot id, anchored to business days ending Fri Sep 25 2026 (no `Math.random`/`Date.now`/argument-less `new Date`); status counts on the watchlist header reconcile exactly to the lot total by construction.

**Interactions implemented (5, all real `'use client'` state, deterministic):**
1. **Pin (click, persistent):** clicking a watchlist row sets `pinnedId`, visibly marked with a Pin glyph, and updates exactly two things — the "Pinned lot" summary card above the chart and the right-hand desk pane (floor/reserve readout, floor adjuster, active-bids table). Nothing else on the page reacts.
2. **Hover (ephemeral, separate code path):** hovering/focusing a watchlist row reveals an inline bid-count/floor-price micro-detail via pure CSS `group-hover`/`group-focus-within` — no React state touched, cannot leak into the pin.
3. **Chart crosshair (third, independent mechanism):** a roving-tabindex row of real, per-candle buttons overlays the SVG; mouse hover or Left/Right/Home/End arrow keys move the focused candle and update the embedded OHLC + change readout. It is driven by its own `chartLotId`/`focusIndex` state, entirely separate from the watchlist pin.
4. **Period/view toggle:** a segmented control (Daily / Weekly) re-aggregates the same 30 daily candles into 6 real weekly OHLC candles (open=first, close=last, high=max, low=min) — the chart, its readout, and its data-table fallback all update together.
5. **Sortable bids table + command palette:** the Active Bids table sorts by Amount (`aria-sort`, click-to-toggle) with avatar cells and Leading/Outbid status badges; a ⌘K palette searches all ten lots by code/title/category and pins the selection (reusing the same pin mechanism).

**Typography:** Body copy is Pretendard (`font-sans`) throughout. `var(--font-display-mono)` is the single optional display face, used only for the sidebar wordmark ("Lotwise") and the one large numeric price in the pinned-lot summary card — never body, never Korean. Exactly three rendered weights, audited by grep: `font-normal` (400), `font-medium` (500), `font-semibold` (600) — no `font-bold` anywhere. Uppercase 11px tracked labels (`text-[11px] font-semibold uppercase tracking-wide`) via one shared `SectionLabel` component for every card/table header.

**Theme/accent:** Refined product dark — `bg-zinc-950` canvas, `bg-zinc-900` cards, `border-white/10` hairlines, no glow/scanline/grain. Single accent: indigo (`indigo-600` primary actions, `indigo-300/400` interactive text and crosshair, `indigo-500/15` active-nav and active-tab washes) — contrast-checked (`indigo-600` + white ≈ 6.3:1, `indigo-400` on `zinc-950` ≈ 6.4:1). Candle direction and lot/bid status use a separate semantic set (emerald/amber/teal/rose/zinc), always paired with an icon + text label, never color alone. Secondary text never drops below `zinc-400` on any dark surface, including hover-revealed rows, the empty search-palette state, and closed/all-lots tab views.

**Completeness vs. the Mercury/Coinbase bar:** every topbar control (menu, search trigger, primary "New adjustment" action, notifications, avatar menu) is exactly `h-11` (44px); the primary action is wired to a real behavior (scrolls to and focuses the pinned lot's floor-price input, not a dead button); reconciling deterministic data (max generated price ≈ $6,522, verified by simulation, so no table column was sized against an unverified worst case); single `h1`, seven `h2`s (one per named region), no skip; semantic `<table>` × 2 with `caption`/`scope`/`aria-sort` where sortable; exactly one `overflow-x-auto` on the whole page (the OHLC table, `min-w-[420px]` scoped to below `lg` only, `lg:min-w-0` above it); explicit `focus-visible:outline-2 …outline-indigo-400` with no competing `outline-none`/bare `ring` anywhere.

## 브리프에 없던 것

① 캔들 차트가 보여주는 "selected lot"이 좌측 워치리스트 핀과 같은 상태여야 하는지가 브리프 문구상 모호했음(일반 지침은 "선택된 lot의 가격 이력"이라 했지만, 후보별 지침은 핀 클릭이 "우측 디테일 패널과 요약 카드 하나 — 그 외에는 아무것도" 갱신하지 않는다고 명시). ② 차트를 워치리스트 핀과 완전히 분리된 자체 `chartLotId` 상태로 만들고, 기본값은 "데스크에서 입찰이 가장 활발한 lot"으로 결정론적으로 계산, 차트 헤더의 네이티브 `<select>`로만 바꿀 수 있게 함. ③ 후보별 지침의 "차트의 크로스헤어 호버가 세 번째의, row-pin과 무관한 메커니즘"이라는 문장이 차트=독립 개체라는 신호였고, pin의 팬아웃을 "우측 패널 + 요약 카드 1개, 그 외 없음"으로 좁게 한정한 지시를 문자 그대로 지키기 위함.

① 핀 클릭이 갱신해야 한다는 "요약 카드 1개"를 우측 패널 안에 둘지, 별도 위치에 둘지가 없었음. ② 우측 패널은 입찰 사다리/플로어 조정 도구로 채우고, 요약 카드는 센터 컬럼 상단(차트 바로 위)에 별도로 배치. ③ 지문이 "우측 디테일 패널 AND 요약 카드 하나"를 별개 항목으로 나열한 것을 "우측 패널=하나의 반응 영역, 요약 카드=또 다른 별개의 반응 영역"으로 읽었고, 같은 컬럼 안에 두면 시각적으로 "우측 패널"과 구분이 안 될 것 같아 분리.

① "핀에 반응하지 않는 위젯" 하나를 무엇으로 정할지가 필요했음. ② 데스크 전체 활동 피드(Desk activity)로 정하고, 카드 안에 "이 목록은 무엇을 핀해도 바뀌지 않는다"는 캡션을 명시. ③ 실제 트레이딩 데스크에서 "내가 지금 보는 종목"과 무관하게 항상 보이는 전체 틱 피드가 관례이고, 브리프가 예시로 든 "deliberate non-reactivity"에 정확히 부합.

① lot 가격 단위(센트 포함 여부)와 자릿수가 없었음. ② 센트 없는 정수 달러(예: $6,522)로 결정. ③ B2B 청산/재판매 랏 가격은 실무에서도 정수 단위가 일반적이고, 3-pane 레이아웃에서 OHLC 표 컬럼 폭이 매우 좁아지는 1280px 구간에서 "$12,480.50" 같은 긴 문자열이 셀 안에서 겹치는 것을 원천 차단하기 위한 실측 기반 선택(시뮬레이션으로 전 lot 최대값 $6,522 확인).

① 워치리스트의 "Watching"과 "All lots" 탭이 정확히 어떤 부분집합을 보여줘야 하는지가 없었음. ② 10개 lot 중 6개를 트레이더 개인 워치리스트로 고정하고, 두 번째 탭은 전체 10개를 보여주도록 함. ③ 실제 트레이딩 UI(관심종목 vs 전체 종목)의 표준 관례이며, 탭이 실제로 서로 다른 결정론적 부분집합을 필터링하도록 해 "죽은 컨트롤"이 되지 않게 함.
