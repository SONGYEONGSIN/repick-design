# Candidate b — Auditlane

One-line concept: A master-detail supplier-quality console where pinning a supplier cohort in the left rail swaps a Tukey box plot of its defect-severity distribution (plus a five-number-summary fallback table and a sortable inspection ledger) in the right pane, while a merely-hovered row only ever opens a zero-state "Preview" popover that is local to the rail and never reaches the detail pane.

## 브리프에 없던 것

**Product / domain invention**
① The brief only specifies a B2B SaaS dashboard, a master-detail skeleton, and a box-plot dominant chart — the actual product, its cohorts, and its metric were unspecified.
② Decided: "Auditlane," a supplier-quality inspection console for manufacturing/procurement teams. Left-rail cohorts are six suppliers (Solmark Fabrication, Vireo Components, Northfield Alloys, Corrigan Textiles, Kessler Optics, Tallow Ridge Materials); the box-plotted metric is a 0–100 "defect severity score" per inspection.
③ The catalogue's own suggestion list names "결함 심각도 분포" (defect-severity distribution) as a direct example for this chart type, and a QA console gives every rail row a naturally distinct, non-overlapping sample (one supplier's inspections never mix with another's) — a clean fit for a per-cohort box plot instead of a contrived metric.

**Accent hue + measured contrast**
① Recent rounds used blue/teal/amber; had to pick a fresh family and verify real numbers rather than trust a Tailwind pairing by name.
② Decided: violet, split by role — violet-700 `#6D28D9` on white ≈ **7.10:1** (AAA for normal text; computed via WCAG relative luminance, not assumed) carries all text/icons/focus rings/solid buttons and the box plot's box outline, median line, and crosshair. Violet-50/100 are tint-only surfaces, always paired with violet-700 text. (For reference, the alternate dark-accent shade violet-400 `#A78BFA` against a zinc-950 `#09090B` ground was also computed at ≈7.31:1, but this candidate commits to a single true-light theme end to end, so that pairing isn't used on the page.)
③ Status/risk badges (pass/watch/flagged, steady/elevated/at-risk) deliberately reuse a *separate* emerald/amber/rose set instead of the violet accent, so the accent's meaning ("this is Auditlane, this is interactive/brand") never collides with a semantic status color on the same card.

**1920px width arithmetic (no cap applied)**
① Brief requires computing the cap math or proving no premature cap exists, using this page's own shell measurements rather than a generic number.
② Decided: no `max-w` anywhere on the main content column. Shell = sidebar `w-64` (256px, visible at `lg:block`) + main padding `lg:px-8` (32px each side = 64px total). At 1920px viewport: available content width = 1920 − 256 − 64 = **1600px**, and the page (KPI `dl`, the rail+detail flex row, every card inside it) fills that width via `flex-1`/`w-full` with no competing cap — so the gap from content's right edge to the viewport edge is exactly 32px, the page padding itself, which is ≤ the 40px ceiling.
③ Re-derived the same shell arithmetic at the required intermediate widths to confirm the rail (fixed 320px + 16px gap) never starves the detail pane: 1280px → 960px available → 624px for the detail column; 1366px → 710px; 1440px → 784px; 1600px → 944px. All comfortably exceed the ledger table's 560px `min-w` floor, so no breakpoint is a "just barely fits" case.

**Box-plot AA-required fallback, plus a real Tukey outlier check (not a cosmetic one)**
① The catalogue's own grade for Distribution/Box-Plot requires a standing min/Q1/median/Q3/max table with an outlier-count annotation, and the brief separately requires the chart's key values to be legible without hovering.
② Decided: `computeBoxStats` implements the actual Tukey method (linear-interpolated quartiles, 1.5×IQR fences) over deterministic per-supplier samples, and the five-number summary + IQR + outlier list is printed in a permanent `dl` under the chart, not inside a tooltip. While building this I discovered the fences are genuinely sensitive to how wide a supplier's *baseline* spread is: giving "Northfield Alloys" (the intentionally worst-performing supplier) a wide natural spread made its injected high-severity records sit comfortably inside the 1.5×IQR fence — i.e., a real Tukey box plot correctly refuses to call them statistical outliers, because they're merely the top of an already-wide distribution. "Kessler Optics" instead keeps a narrower baseline with one isolated high value, which the same math does flag (verified by hand for its 7D and 30D windows). The page therefore defaults to Kessler pinned, not Northfield, so the outlier annotation is visibly non-zero on first load.
③ This was the honest result of running real statistics on the data rather than hand-picking which suppliers "should" show outliers — and it produces two legitimately different, useful stories on one page: Northfield reads as *broadly elevated risk* (caught by the "at risk" tier badge, not by outlier count), while Kessler reads as *one isolated incident against an otherwise fine baseline* (caught by the outlier annotation). Faking a guaranteed outlier on the worse supplier would have been the more obvious choice but the statistically wrong one.

**Fluid box plot vs. fixed-size interaction targets (target-size compliance)**
① The chart has to span the full width of its card (it's the page's dominant, viewport-scaling visualization), but Lighthouse's `target-size` audit requires real ≥24×24 CSS-px hit areas — and a value marker placed via an SVG `foreignObject` scales down with the viewBox on a narrow card, same as any other SVG content.
② Decided: the five key markers (min/Q1/median/Q3/max) and each outlier are rendered as real HTML `<button>` elements (fixed `h-7 w-7`, 28px) absolutely positioned by percentage over an `aspect-ratio`-boxed SVG, rather than as `foreignObject` children of the SVG itself. The percentage math is derived from the same `viewBox` units the chart itself uses, so the two layers stay pixel-aligned at any width.
③ A fixed-size chart (like a radar in an earlier round) can safely put its focus targets inside the SVG because the SVG itself never resizes; this chart is intentionally fluid-width per the "viewport-filling, no premature max-w" rule, so its interaction layer had to be decoupled from SVG scaling to keep hit areas legal on a phone-width card.

**Branched selection: pin (persistent) vs. hover (ephemeral, zero external state)**
① The brief calls out that three prior rounds threaded one `selectedId` uniformly and got penalized as "interchangeable with plain master-detail" — the split has to be structural and visible, not just a naming difference.
② Decided: `previewId` lives as `useState` *inside* `SupplierRail` itself and is never lifted to the parent — hovering or focusing a row cannot, by construction, touch `pinnedId` or re-render the detail pane, because the two states don't share a component. It renders a dashed-border "Preview" popover (Eye icon, quick median/IQR/outlier-count glance) that vanishes on `mouseleave`/`blur`. Only a click (or Enter/Space) calls the parent's `onPin`, which is the sole trigger for swapping the entire detail pane — box plot, status-mix panel, and inspection ledger together, which is the accepted "normal master-detail" scope per this round's brief.
③ The visible split: a pinned row carries a permanent solid "Pinned" badge with a filled pin icon; a merely-previewed row never earns that badge, only the transient popover, and the rail's own header caption ("Hover a row to preview · click to pin it open") states the split in plain text so it doesn't rely on a screenshot-reader inferring it from behavior alone.

**Supplier data: deterministic-by-formula instead of hand-typed literals**
① ~150 individual inspection records (severity, duration, inspector, day-offset) across 6 suppliers × 3 reporting windows needed to be both realistic and provably free of `Math.random`/`Date.now`/`new Date()`.
② Decided: a fixed 20-entry numeric lookup table (`NOISE`) stands in for sampling variance; each supplier/period combination is generated by a pure function that indexes into `NOISE` by `(seed + i)`, so the exact same records are produced on every render, every environment, forever — and two isolated numeric overrides per "incident" supplier substitute for the one real data point that needed to look like an actual QA incident rather than formula output. Dates are computed by subtracting `daysAgo` from a fixed anchor tuple `{y:2026,m:9,d:12}` through a hand-rolled month-length table, never touching `Date`.
③ This is stricter than "no literal `Math.random()` call" — it means changing the reporting-window toggle recomputes real statistics from a real (if synthetic) sample every time, so the org-wide KPI totals, the per-supplier tiers, and the box-plot fences are all genuinely derived rather than three sets of hand-matched numbers that happen to agree.

**Post-promotion hard-gate a11y fixes: color-contrast + target-size overlap**
① The promoted candidate scored 93 on a11y (< 95 floor) on two hard-fail audits: `color-contrast` on `SupplierRail.tsx`'s `· N outlier(s)` label (`button > span.min-w-0 > span.mt-1.5 > span.text-rose-600`), and `target-size` on `BoxPlotPanel.tsx`'s quartile-marker buttons (`aria-label="Q3: 41.9"`-style, `h-7 w-7` = 28×28px). Neither was a brief requirement — both were regressions the hard gate caught after promotion.
② color-contrast: the outlier-count label only ever renders inside a pinned row, whose background is `bg-violet-50/60` composited over white — violet-50 `#F5F3FF` at 60% alpha over white resolves to `#F9F8FF`. `text-rose-600` there is Tailwind v4's oklch rose-600 (`oklch(58.6% 0.253 17.585)` ≈ `#ED003F` in sRGB), which measures **4.27:1** against `#F9F8FF` at 11px/normal weight — under the 4.5:1 small-text floor. Changed to `text-rose-700` (`oklch(51.4% 0.222 16.935)` ≈ `#C70036`), which measures **≈5.74:1** on the same `#F9F8FF` (and higher still on the unpinned white/`zinc-50` backgrounds the same span can sit on) — both computed via the standard WCAG relative-luminance formula from the oklch→linear-sRGB conversion, not read off a swatch.
③ target-size: the five quartile buttons (min/Q1/median/Q3/max) all sit on one y (`Y_MID`) and are positioned by their true data value, so a supplier/period with a tight spread (small IQR, few inspections) can put two 28px buttons' centers closer together than 28px apart — Lighthouse measured the worst case at 21.2px of unobscured space on a Q3 target, under the WCAG 2.5.8 24px floor. Rather than resize the visible marks, added a `spreadMinGap` pass that nudges only the invisible hit-target center (`hitX`, kept separate from the true `x` used by the crosshair and the SVG box/whisker/median marks) so adjacent main-marker centers are never closer than `MIN_HIT_GAP = 64` SVG px. That threshold is sized for the narrowest width the panel is ever audited at — Lighthouse's default mobile emulation (360 CSS px viewport) shrinks this card's content to ≈296px (`px-4` main padding + `p-4` card padding subtracted), a ≈0.4625 real-px-per-SVG-px scale, so 64 SVG px ≈ 29.6 real px of guaranteed clear space — a margin over the 24px floor, not a value that just clears it. Outliers keep their raw position (already vertically offset ±14px from the main row to stay clear of it) since they were not the audited failure.
