# Candidate C — Nudge (Survey & Form Builder)

**Product**: Nudge — a fictional B2B survey/form-builder SaaS ("Forms that read the room") for product and growth teams building NPS, onboarding, and feedback flows. Route: `/dash-evolve/r12/c`.

**Archetype**: Split workbench. Inside the mandatory app shell (left sidebar with brand lockup/workspace switcher/nav/user, top bar with ⌘K trigger + "Publish survey" primary action + notifications + avatar menu, mobile drawer), the main content is a two-pane survey editor for one live survey ("Onboarding Pulse Survey", 7 questions: NPS score → reason-for-score → open feedback → discovery channel → setup-ease rating → role → follow-up email). The **left edit rail** lists every question as an accordion row — type icon, label, a "Required" text badge, and an always-visible inline analytics line (`92.5% · -180`) above a compact CSS completion bar (bar color keyed to a good/warn/bad threshold, never color-only since the percentage/drop-off is printed as text). Selecting a row expands an inline settings sub-panel in place: a 4-way question-type segmented picker (short text / multiple choice / rating / NPS), a Required switch, and a read-only conditional-logic branch summary ("If Score 0–6 (Detractor) → skip to Q3"). The **right live-preview pane** renders the selected question exactly as a respondent would see it — progress bar + "Question N of 7", prompt, type-matched answer control, Back/Next — inside a card-shaped frame that resizes via a Mobile/Desktop segmented toggle; a second segmented control swaps the whole pane to a generated **Logic map** (SVG flow diagram: the 7 questions as a straight default chain plus three condition-labelled skip arcs, using the warm orange accent only for those branch edges/labels — always rendered as real `<text>`, never a hover tooltip).

**Interactions implemented (5, all `'use client'`, real state, no `Math.random`/`Date.now`)**:
1. **Selection sync (required)** — clicking a rail row selects it, expands its settings panel, and instantly re-renders the live-preview pane for that exact question; the preview's own Back/Next buttons drive the same shared `selectedIndex` state, so stepping through the preview also moves the rail's highlighted/expanded row.
2. **Device-width toggle** — Mobile/Desktop segmented control resizes the preview frame (`max-w-[380px]` ↔ `max-w-[640px]`) with a `motion-reduce`-gated width transition.
3. **Full keyboard navigation of the rail** — each row header is a real `<button>`; Arrow Up/Down/Home/End move both focus and selection between rows via a synchronous ref-based roving handler (verified: focusing Q3 and pressing Arrow Down moves focus to Q4's button and swaps the preview to Q4's prompt).
4. **⌘K command palette** — global shortcut opens a dialog to jump straight to any question (updates rail selection + preview) or add a new question of a chosen type (appends to the rail with deterministic id/label `New question N` and an honest "Not live yet" analytics state instead of fabricated numbers, since it has no seed funnel data).
5. **Preview / Logic map segmented toggle** — swaps the whole right pane between the live respondent preview and the generated branch diagram, sharing the same selected-question highlight.

Additional real interactivity beyond the minimum: the question-type segmented picker in each settings sub-panel actually changes `q.type` and reflows the live preview's answer control (NPS 0–10 grid ↔ multiple-choice radio list ↔ 5-star rating ↔ textarea) via a `defaultsForType()` helper; the Required switch is a working `role="switch"` toggle that updates both the settings panel and the preview's `*`/`sr-only "(required)"` marker.

**Funnel data reconciles**: entering[1]=2,400 → dropoff 180 → entering[2]=2,220 → dropoff 96 → entering[3]=2,124 → dropoff 240 → entering[4]=1,884 → dropoff 54 → entering[5]=1,830 → dropoff 402 → entering[6]=1,428 → dropoff 88 → entering[7]=1,340 → dropoff 150 → completed 1,190. Sum of drop-offs (1,210) exactly equals 2,400−1,190. Every rate is computed from these fixed integers via `completionRatePct()`, formatted with `Intl.NumberFormat`.

**Typography/font**: Single global `font-sans` (Pretendard, inherited from the root layout — no additional `next/font` imports anywhere in this route). `tabular-nums` on every count/percentage/score/rating. Copy is English-only throughout.

**Theme**: Productivity Tool palette — light default is a pure white/zinc-50 canvas, white cards, zinc-200 hairline borders; primary accent blue-600/blue-400 (`#2563EB` family) drives buttons, focus rings, and selected states; a second warm accent orange-600/orange-300 (`#EA580C` family) is used sparingly and only on the logic-map's conditional-branch edges/labels/chips, always paired with text. `dark:` variants use zinc-950/900 surfaces with white/10 borders. Caption/secondary text never drops below zinc-500 (light) / zinc-400 (dark) in any state, including every question type's placeholder/helper text and the "Not live yet" state for a freshly-added question.

**Commercial-polish reference points**: the rail-plus-live-preview composition and the card-shaped device-frame preview are the same information architecture real Typeform/Tally-tier builders ship — progress bar, required-asterisk convention, Back/Next chrome — rather than an "art concept" reinterpretation of a form. The completion bars and logic-map diagram are Mercury/Asana-style precise, flat, single-accent components (no gradients, no glow, no skeuomorphic device bezel/notch — the preview frame is a plain rounded card, not a fake phone shell), and the app shell (sidebar, ⌘K, notifications, avatar menu, all header controls at literal `h-11`) matches the same shared chrome used across this round's other candidates.

**Duplicate-avoidance**: this is a genuine rail-plus-live-preview split workbench for a form/survey builder — distinct from the round's other two candidates (hero+single-dominant-chart and master-detail skeletons) and from the prior email-campaign split-editor+live-preview candidate (different domain: question/logic/form-flow building, not email composition; no send/audience/deliverability content anywhere). Not a kanban board, spreadsheet grid, map, DAG canvas, or any of the other 32 previously-shipped archetypes.
