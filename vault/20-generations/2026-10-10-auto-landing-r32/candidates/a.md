# Candidate a — r32

**Concept:** A dual-handle price-range slider that recomputes a live box-and-whisker plot of 60 fixed comparable Sneaker sales per condition grade, with the example listing's own price marked on top — the same filtered state then carries into the value section and the closing CTA's own label.

## 브리프에 없던 것

- **Category / brand**: chose "Sneakers" as the resale category and kept the brand as "Repick" (given). Picked something concrete enough to make the box-plot story legible rather than a generic "items."
- **Dataset**: brief said "a fixed pool of comparable sold listings" but not size/shape. I hardcoded 60 sold listings (20 per grade: Like New / Good / Fair) in `data.ts`, prices ascending per grade, domain $40–$420, default slider selection $100–$300. Chosen so the default view already shows a non-trivial, non-empty box for all three grades (15/19/11 items filtered at default) and so "Like New" medians > "Good" > "Fair" (238 > 170 > 138), matching real-world intuition.
- **Box-plot math**: linear-interpolation quantile function (`quantile(sorted, q)`) over the live-filtered, re-sorted subset per grade; `min`/`max` are the array ends, `q1`/`median`/`q3` via `(n-1)*q` interpolation, rounded to whole dollars. Recomputed with `useMemo` on every slider move in both `Hero.tsx` and `ValueSection.tsx`. Empty-filter buckets render "No comps in this range" instead of a collapsed box. Geometry is plain absolutely-positioned `div`s (not SVG) with `left`/`width` as a percentage of the fixed $40–$420 axis, rounded to 2 decimals — this is linear scaling, not trig, so no sin/cos rounding case applies, but I rounded anyway for determinism.
- **Example-listing marker**: kept its screen position pinned to the fixed domain (not the filtered sub-range) so it stays comparable across slider moves; it renders hollow when the current slider range excludes its price, solid when included — a detail the brief didn't ask for but that makes "where you sit" legible when you drag the range away from the example.
- **Where the shared slider state lives**: lifted `minPrice`/`maxPrice` to `LandingPage.tsx` and passed down to `Hero`, `ValueSection`, and `ClosingCta`. Section 3's "assigned control" is the *same* hero slider (not a second control) — Part 2 of the value section and the closing CTA's sentence + button label (`Browse comps $<min>–$<max>`) all read the identical derived numbers, satisfying "derived state must survive to the closing CTA" and "appear in both the summary sentence and the CTA label."
- **Macro skeleton**: asymmetric hero (headline + CTA left, slider/box-plot/proof-card right, inside one Hero component/JSX tree) → rich preview cards with a per-card "Match breakdown" disclosure → 3-part value recap (static spread explainer / live recomputed per-grade stats / live percentile-of-example sentence) → testimonials + stat `dl` → closing CTA card with dynamic-label button + inline price-alert form. No deck/snap sections, no map/wizard/leaderboard shapes.
- **4 interactions**: (1) hero dual-range slider (device), (2) `whileInView` scroll reveals on every section after the hero (mount-gated, see below), (3) per-card "Match breakdown" disclosure toggle in product preview, (4) the price-alert email form in the closing CTA (local state only, no network call, confirmation text echoes the live range).
- **Accent color — sky family, calculated**:
  - Primary token `sky-600` (`#0284c7`): contrast vs white = **4.10:1**, vs zinc-900 ink (`#18181b`) = **4.32:1**. Both clear 3:1 (so fine for icons, the slider fill, chart strokes, and the 2px focus-visible outline), but *not* 4.5:1, so it is never used for small body-size text.
  - Derived darker tint `sky-700` (`#0369a1`) for any actual small accent-colored text (match-% chip text, discount-% text, percentile caption): contrast vs white = **5.94:1** (clears AA at small sizes). Used `sky-800` once (price-alert confirmation on a `sky-50` chip) for extra margin.
  - No accent-filled large background was used for small text, so the "white-on-fill" default rule never had to be invoked — primary buttons are zinc-900/white, accent stays a thin, resting-visible layer (slider fill, box borders, chip text, focus rings), never hidden behind hover-only.
- **State-dependent contrast floor**: audited every text node against its actual surface. Fixed two early drafts that would have failed: a `zinc-400` strikethrough retail-price + axis labels (measured ≈2.56:1 on white, well under the 4.5 floor) — bumped to `zinc-500` (≈4.83:1 on pure white / ≈4.70:1 on `zinc-50`). The one genuinely tinted surface (`bg-zinc-100` box-plot track) uses `zinc-600` for its "No comps" fallback text, not `zinc-500`.
- **Body column arithmetic (0.44em constant, no `ch`)**: target ≈70 chars/line. For the 17px paragraph copy (hero sub, section intros, value blurbs): chars-per-line = container-px ÷ (0.44 × 17) = container-px ÷ 7.48. Solving for 70 chars → container ≈ 523.6px; I used `max-w-[520px]` → 520 ÷ 7.48 ≈ **69.5 chars/line**, under the 75 ceiling.

## SSR / hydration-gating check

Used `whileInView`/`initial={{opacity:0}}` via a shared `Reveal.tsx` wrapper on every section **except** the Hero. `Reveal` gates on `useMounted()` (a `useSyncExternalStore` that returns `false` on the server and `true` only after client mount) — when not yet mounted, `initial`/`whileInView` are both `undefined`, so Framer Motion applies no inline style at all on first paint. Confirmed by curling the built route and grepping the raw SSR HTML for `opacity:0`: zero matches anywhere in the document, hero included (the hero itself never uses a reveal wrapper — everything in it is visible from first paint; its buttons/thumbs only use `whileHover`/`whileTap`-style affordances, which don't touch SSR output at all). Also verified via `tsc --noEmit` (0 errors) and `eslint` on the folder (0 errors/warnings), and a live `next dev` request to `/landing-evolve/r32/a` returned HTTP 200 with the h1/box-plot/proof-card/skip-link all present in the server-rendered markup.
