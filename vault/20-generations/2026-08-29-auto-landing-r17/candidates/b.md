# r17/b — Assay

한 줄 컨셉: 히어로 안에서 4개 검증 카테고리(진품·컨디션·가격공정성·판매자이력) 토글과 6개 매물 선택기를 조작하면, 같은 상태로부터 순차 파이프라인(인테이크→4개 체크→종합 판정) 각 단계의 pass/hold/skipped 상태와 가중 신뢰 점수(0-100)가 실시간 재계산되고, 그 상태가 제품 프리뷰 그리드·가치 3분할·클로징 CTA까지 그대로 이어진다.

## 브리프에 없던 것

**1. 제품 도메인 및 매물 데이터셋**
① 무엇을 정해야 했나 — "매물"이 무엇을 파는 마켓플레이스인지, 카테고리와 개별 매물의 구체적 검증 결과·가격·컨디션 등급 텍스트 (브리프는 순차 검증 파이프라인이라는 메커니즘만 규정).
② 무엇으로 정했나 — 러닝화·시계·카메라·가방·자전거·아우터 6개 카테고리, 각 1개씩 총 6개 고정 매물(`data.ts`의 `LISTINGS`). 매물마다 4개 카테고리별 pass/hold 결과와 사람이 읽는 근거 문장(예: "Bezel insert shows a hairline chip — held for buyer review")을 손으로 채움.
③ 왜 — 리세일 마켓플레이스에서 카테고리마다 검증 근거가 다르게 읽혀야("시계"는 무브먼트 시리얼, "신발"은 아웃솔 마모율) 파이프라인이 진짜로 그 매물을 보고 판정한 것처럼 느껴지고, 6개면 상태 조합(전부 pass / 1개 hold / 다중 hold)이 자연히 섞여 토글 조작 전에도 밋밋하지 않은 화면이 나옴.

**2. accent 색상 계열 (hex 및 대비 계산 — violet 회피)**
① 무엇을 정해야 했나 — violet(카탈로그 최다 8건) 회피 + 계열 선택 시 흰색·어두운 잉크 양쪽 대비 실측 의무.
② 무엇으로 정했나 — Tailwind `amber` 계열 3틴트: `amber-700 #B45309`(버튼/판정 배지 채움), `amber-300 #FCD34D`(오버라인 라벨·소형 아이콘·포커스링), `amber-600 #D97706`(hover). 직접 계산(`L=0.2126R+0.7152G+0.0722B`, sRGB→linear 후):
  - `amber-700` vs 배경(`#0B0B0F`, L≈0.00345) = **3.91:1** — fill/border 3:1 기준은 통과하지만 소형 텍스트(4.5:1)엔 못 씀 → 그 위엔 텍스트를 얹지 않고 채움 자체로만 사용.
  - **흰색 vs `amber-700` 채움 = 5.02:1** — AA 소형 텍스트(4.5:1) 통과. CTA 버튼("Start a verification")과 "Clear" 판정 배지 모두 이 조합만 사용.
  - **어두운 잉크(`zinc-900 #18181B`) vs `amber-700` = 3.53:1** — AA 미달 확인. 그래서 채움 위 텍스트는 예외 없이 흰색으로 통일하고, 다른 곳에서 다크 잉크를 쓰는 코드가 남지 않았는지 grep으로 재확인함.
  - `amber-300` vs 배경(`#0B0B0F`) = **13.6:1** — 소형 텍스트·아이콘·포커스링 기준 압도적 통과, 배경 위 저비중 라벨(카테고리 오버라인, "Validation pipeline" 등)에 전용.
③ 왜 — "감정(assay)"이라는 개념이 금·귀금속 순도 검증의 관용어라, 앰버/브론즈 계열이 인증 스탬프·왁스 실 같은 도메인 연상과 맞고 최근 라운드에서 흔한 teal/violet/emerald와도 겹치지 않음.

**3. 디스플레이 활자**
① 무엇을 정해야 했나 — grotesk(카탈로그 최다 10건, 직전 r16도 사용) 회피 후 wide/mono 중 선택.
② 무엇으로 정했나 — `--font-display-mono`, `style={{ fontFamily: "var(--font-display-mono)" }}`로만 지정, H1·오버라인 라벨·가격/점수 같은 수치·로고 워드마크에 적용.
③ 왜 — 페이지의 핵심 숫자(신뢰 점수 0-100, 할인율 %, 가격, 매치 카운트 "3/4 running")가 전부 tabular 판독을 요구하는데, 모노스페이스가 "계측 리포트"라는 인상을 주고 grotesk보다 이 컨셉에 더 잘 맞음.

**4. 가중 신뢰 점수 공식**
① 무엇을 정해야 했나 — "종합 신뢰 점수가 실시간 재계산"만 요구되고, 구체적 산식(가중치, hold의 감점 폭, 판정 임계값)은 미지정.
② 무엇으로 정했나 — 카테고리별 고정 가중치(진품 4, 컨디션 3, 가격 2, 판매자이력 2), `earned = pass ? weight : weight×0.35`, `score = round(earned / active weight sum × 100)`. 활성 카테고리가 0개면 점수 0. 판정 임계값 `PASS_THRESHOLD = 75` (score≥75 → "Clear", 아니면 "Review", 활성 0개는 무조건 "Review").
③ 왜 — 진품 검증이 가장 무거운 축이어야 "위조품이 가격은 싸고 판매자는 좋아도 전체 점수가 크게 깎인다"는 도메인 직관이 성립하고, hold를 0점이 아닌 0.35 부분점수로 둔 이유는 "리뷰 대기"가 "탈락"과 다르다는 걸 숫자로도 구분하기 위함(완전히 0점이면 hold 하나로 점수가 과도하게 무너져 토글을 꺼도 체감 차이가 안 남).

**5. 카테고리 전체 끄기 방지 규칙**
① 무엇을 정해야 했나 — 4개 토글을 자유롭게 켜고 끌 수 있게 할지, 최소 1개는 항상 켜져 있어야 하는지 브리프에 명시 없음.
② 무엇으로 정했나 — 마지막 남은 활성 토글은 `aria-disabled`로 클릭을 막고(`isLast` 체크, `client.tsx`의 `toggle` 함수도 `anyOn` false면 상태 변경 자체를 거부하는 이중 방어), 툴팁으로 "At least one check must stay on." 안내.
③ 왜 — 전부 꺼진 상태는 파이프라인이 "아무것도 검증 안 함"이 되어 점수·판정이 무의미해지고(`computeScore`가 0을 반환), 그 빈 상태를 보여주는 것보다 "조작이 항상 의미 있는 결과를 낳는다"는 원칙을 지키는 편이 체감 가치 요구에 더 맞음.

**6. 본문 문단 폭 계산 (`ch` 금지, 0.44em 상수)**
① 무엇을 정해야 했나 — 65~75자 상한을 만족하는 실제 컨테이너 px 값. 이전 에이전트가 남긴 값 중 하나가 상한을 초과해 있어 이번 검수에서 직접 발견·수정함.
② 무엇으로 정했나 — `Hero.tsx`의 "Each check carries its own weight…" 캡션을 `max-w-[480px]`→`max-w-[400px]`로 축소(13px 기준: 480÷(0.44×13)=83.9자로 상한 75자 초과 → 400÷(0.44×13)=69.9자로 목표 70자 근접). 나머지 6곳은 검산 결과 이미 63~73자 범위 안이라 그대로 둠(예: Hero 서브헤드 520px@17px=69.5자, ClosingCta 본문 460px@15px=69.7자, ProductPreview 인트로 420px@14px=68.2자).
③ 왜 — Pretendard 영문 혼합 평균 자폭 0.44em 기준으로 직접 계산해야 실제 렌더 줄바꿈과 맞아떨어지고, `ch` 단위는 폰트별 실측 자폭과 어긋나 이 계산 원칙과 충돌하기 때문.

**7. 매물 시각 자산 — 사진 대신 아이콘 패널**
① 무엇을 정해야 했나 — 히어로·제품 프리뷰의 매물 카드에 실제 상품 사진(`next/image`)을 쓸지, 다른 방식을 쓸지.
② 무엇으로 정했나 — 전 매물에 `next/image`를 전혀 쓰지 않고, 카테고리별 lucide 아이콘(Footprints/Watch/Camera/Package/Bike/Shirt) 하나를 고정 비율(`aspect-[4/3]`) 패널 안에 배치. 매치%·등급·인증 배지는 이 패널 아래 별도 행에 둬 사진 위 오버레이 자체가 발생하지 않음.
③ 왜 — 가상의 매물명(예: "Chrono Diver 42")에 정확히 맞는 실제 사진을 무작위 이미지 서비스 없이 조달할 방법이 없고, 원격 이미지 실패 시 레이아웃이 무너지는 리스크(`no-raw-img`/`no-random-image-host` 게이트)를 원천적으로 없애는 결정론적 대안을 택함.

**8. 폰트 웨이트 배정 (정확히 3종)**
① 무엇을 정해야 했나 — 정확히 3종 중 어떤 굵기 값을 쓸지.
② 무엇으로 정했나 — `font-normal`(암묵 400, 스킵 상태 텍스트·점수 단위 "/100")/`font-semibold`(600, 본문 강조·배지·라벨·버튼·스텝 라벨)/`font-extrabold`(800, H1·H2·큰 숫자·워드마크). `font-medium`·`font-bold`·`font-black` 등은 파일 전체에 미사용(grep으로 재확인, `font-(thin|extralight|light|normal|medium|semibold|bold|extrabold|black)` 정규식 매치 결과 `normal`/`semibold`/`extrabold` 세 값만 나옴).
③ 왜 — 세리프 없이 웨이트만으로 3단 위계(보조/본문 강조/헤딩)를 표현하되, 딱 세 값만 써서 위계를 색·크기·자간에 과도하게 의존하지 않으면서도 네 번째 굵기를 끌어올 필요가 없도록 함.

**9. 본문 줄 길이 초과분 발견 및 수정 경위**
① 무엇을 정해야 했나 — 인수인계 검증 과정에서 이전 에이전트가 남긴 값이 체크리스트 상한을 넘는지 실제로 계산해봐야 했음(코드만 봐서는 통과 여부가 육안으로 안 보임).
② 무엇으로 정했나 — 파일 내 `max-w-[\d+px]` 전량을 grep으로 뽑아 옆에 붙은 `text-[\d+px]`와 짝지어 7곳 전부 직접 계산, 1곳(위 6번 항목)만 초과를 발견해 수정.
③ 왜 — 이 체크리스트 항목은 육안 검수로는 놓치기 쉽고, 브리프가 명시한 공식(0.44em, 상한 75자)을 코드베이스의 실제 max-w/text 조합에 하나하나 대입해야만 미달·초과를 확정할 수 있기 때문.

## 인터랙션 목록 (최소 4종 확인)
1. 카테고리 토글 4개(`role="group"`, `aria-pressed`) — 파이프라인 각 스텝의 상태와 종합 신뢰 점수를 실시간 재계산, 마지막 1개는 끄기 방지.
2. 매물 선택기(히어로 캐로셀 6칩 + 제품 프리뷰 카드의 "Inspect" 버튼) — 선택된 매물이 바뀌면 히어로의 파이프라인 디바이스 전체가 그 매물 기준으로 재계산되고, "Inspect" 클릭 시 `#pipeline`으로 스크롤.
3. 스크롤 트리거 — `ProductPreview`/`ValueSplit` 카드가 `framer-motion` `whileInView`(`viewport={{ once: true }}`)로 순차 등장, `useReducedMotion()`으로 게이팅.
4. 히어로 파이프라인 상태 전환 애니메이션 — `AnimatePresence`가 `selectedId`+토글 조합 키로 스텝 리스트/점수 카드를 페이드 전환(reduced-motion 시 `initial`을 `undefined`로 꺼서 opacity:0 잔존 없음).
+보강: 클로징 CTA와 가치 3분할 섹션 모두 같은 `active` state를 인용(패스율, 중앙값, 활성 체크 수)해 조작 상태가 페이지 끝까지 이어짐 — 하드코딩된 정적 숫자 없음(`computeScore`/`median`/`activeCount`를 각 섹션에서 다시 호출).

## 폰트 웨이트 및 기타 실측 확인
- `font-(thin|extralight|light|normal|medium|semibold|bold|extrabold|black)` grep 결과: `font-normal`/`font-semibold`/`font-extrabold` 세 종류만 사용, 세리프 클래스 미사용.
- `outline-none`/`outline-hidden`/`ring-offset` 실사용 없음(설명 주석 1건 제외) — `FOCUS_RING`이 `outline-none` 없이 `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-amber-300`만 추가.
- `<img>`/`unoptimized`/무작위 이미지 서비스/`Math.random`/`Date.now`/무인자 `new Date()`/`ch` 단위 — 전량 미사용(grep 확인).
- 한글·혼합 카피 없음(라운드 산출물 코드 전체 grep 확인).
