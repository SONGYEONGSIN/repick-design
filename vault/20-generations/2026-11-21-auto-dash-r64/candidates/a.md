# Candidate a — Weir

Weir is an API gateway rate-limit and quota console: a two-region master-detail (never three) pairs a sortable, filterable key rail — seven API keys, each with a compact mini-bar of its own intraday request shape — against a detail pane dominated by an hour-of-day × endpoint request-volume heatmap for whichever key is pinned, rendered as a single generative SVG (every cell/label coordinate is a pure function of fixed constants, passed through one `r2()` rounding helper). A Key overview card above the heatmap (requests today, quota remaining, peak hour, endpoints in scope, and a 0–120%-scale quota bar) and the heatmap/table below it all read the exact same per-key hourly request matrix, so nothing on the page is a hand-placed duplicate of a number the drill-down also shows. One key (Checkout, pinned by default) runs at 118% of its daily quota, rendered with an explicit ceiling tick, a hatched overflow segment past it, and an "N.NN× over" label rather than a bar that silently caps at 100%. Five real interactions: rail search + status filter + usage/name sort; a pinned-key selection that updates only the Key overview card and which key's data the heatmap/table render — explicitly never the heatmap's own internal state; a keyboard-reachable (arrow-key roving tabindex) crosshair hover/focus inspector on the SVG heatmap that dims every cell outside the hovered row/column and reports through one shared `aria-live` caption, never a per-cell tooltip; a Heatmap/Table view toggle with a full accessible `table-fixed` + `colgroup` fallback (six 4-hour buckets); and a ⌘K command palette. Light theme only, pure white/zinc-50 surfaces, emerald-700/600 as the single accent, Pretendard for every weight of text on the page, including the "Weir" wordmark itself — no display face anywhere this round.

This is a reassigned form of a prior round's candidate (r63/c) that was eliminated purely on one accessibility bug, never on its design: the heatmap's peak cell rendered a visible `aria-hidden` `<span>{value}</span>` with the raw unformatted number (e.g. "1897"), while the cell button's `aria-label` used the comma-formatted `formatNumber(value)` (e.g. "1,897 requests") — the rendered text was not a literal substring of the accessible name, a hard `label-content-name-mismatch` fail that `aria-hidden` does not exempt. The fix applied here follows the brief's safest route rather than trying to reconcile the two strings: no heatmap cell renders any visible numeric callout at all, peak or otherwise. Every cell is a bare SVG `<rect role="button" aria-label="…">` with color/intensity as its only visible signal; the exact value is exposed solely through that `aria-label` and the one shared `role="status" aria-live="polite"` crosshair caption beneath the grid. Since no cell has a competing visible text node, there is nothing for the accessible name to mismatch against. The peak cell is marked only by staying undimmed during crosshair hover (a non-text visual exemption, same as the prior candidate's logic) — never by a label or a number. The heatmap itself was also rebuilt from a CSS grid of `<button>`s into one generative `<svg>` (deterministic coordinates rounded to 2 decimals via `r2()`) to match this round's domain spec and to make the "no absolutely-positioned per-cell decoration" grid-craft rule structurally impossible to violate — there is nothing to position absolutely inside an SVG's own coordinate space.

## 브리프에 없던 것

**① Brand and domain invention**
① The archetype assignment named the product "Weir" directly (unlike a normal round, where only the domain is assigned and the name is invented), but didn't say whether to keep that exact name or invent a different one for this recreation.
② Kept **Weir** — a small dam that regulates a river's flow, mapping directly onto "rate limiting" — since the task frames this as a faithful recreation of that specific prior candidate, not a fresh invention.
③ Reusing the name keeps the recreation legible as "the same candidate, bug fixed" rather than a new, unrelated design wearing the old structure.

**② How to satisfy "no display font" for a wordmark that previously had one**
① The prior candidate set its "Weir" wordmark in `var(--font-display-wide)` (Archivo Display); this round's brief forbids adding a display font for this candidate, which is a direct conflict with faithfully recreating that one file.
② Changed only the wordmark's `font-[family-name:...]` class, letting it fall through to the route's default `--font-sans` (Pretendard) at `font-semibold`, identical to every other 600-weight label on the page.
③ The brief's font constraint is explicit and new for this round; "faithful recreation" governs structure, data and interaction design, not a font rule that postdates the original candidate and that the recreation is explicitly asked to honor.

**③ Heatmap markup: CSS grid of buttons → one generative SVG**
① The prior candidate's heatmap was a CSS grid of `<button>` elements; this round's archetype spec requires the dominant heatmap to be "built as generative SVG (deterministic, coordinates rounded to 2 decimals)," which the original implementation did not use.
② Rebuilt `Heatmap.tsx` as a single `<svg>`: cell `<rect>`s with `role="button"`/`tabIndex`/`aria-label` replace the button grid, row labels and decorative hour-header text become SVG `<text>` (the label column clipped via one shared `<clipPath>`), and every coordinate passes through one `r2()` helper. Interaction behavior (roving-tabindex arrow-key nav, hover/focus → local `hovered` state, crosshair row/column dimming, one shared `aria-live` caption) is preserved exactly.
③ This satisfies the current archetype's explicit SVG requirement and, as a side effect, makes the "no absolutely-positioned per-cell decoration inflates `scrollWidth`" grid-craft rule moot for this component — SVG children are positioned in the element's own coordinate space, never in the page's layout flow, so there is no absolutely-positioned HTML box to leak.

**④ Peak-cell emphasis without any visible number**
① The brief's safest fix for the reassigned bug is to drop all per-cell visible numeric text, but the prior design used that now-forbidden number specifically to call out the single busiest cell — removing it blind would silently drop that affordance.
② Kept the peak cell visually distinct through a non-text mechanism already in the original logic: it stays undimmed (full opacity) during crosshair hover even when the pointer/focus is on an unrelated row and column, while every other off-axis cell dims to 40%. The peak's exact value and location are still named in the static caption below the grid ("Peak: 1,897 req at POST /v1/payments, 12pm–1pm"), computed from the same `peakCell()` helper the grid uses.
③ This keeps the "which cell is busiest" signal the original design had, satisfies the brief's "no visible per-cell number" instruction literally, and never risks a second `label-content-name-mismatch` because an opacity/dim state is not a text node competing with any `aria-label`.

**⑤ `sr-only` note inside the table's `overflow-x-auto` wrapper**
① The brief documents a related-but-distinct failure mode: an `sr-only` element living inside an `overflow-x-auto`-clipped container needs `position: relative` on itself or its nearest wrapper, or it escapes the clip and paints at unscrolled document coordinates, inflating `scrollWidth` at narrow widths. The prior candidate's `UsageTable.tsx` had exactly this shape (a `sr-only` `<p>` as a direct sibling of the table, inside the `overflow-x-auto` div) without the `relative` fix.
② Added `relative` to that wrapper div (`className="relative overflow-x-auto"`) while touching the file for the heatmap-related changes, rather than leaving a second latent instance of a documented failure mode in a file that was already being edited.
③ The bug this round was reassigned for is specifically the heatmap's label mismatch, not this; but since the brief calls out this exact pattern as having broken two other candidates, leaving it unfixed in a file already open for edits would be a known, avoidable risk rather than genuine fidelity to the original.
