# auto-native-r9 후보 c — Meetup slot grid

**한 줄 컨셉**: 직거래 시간을 맞추는 화면. 격자인 이유는 답해야 하는 질문이 "어느 쪽이 더 좋냐"(리스트가 답하는 질문)가 아니라 **"두 사람의 달력이 어디서 겹치나"**(2축 교차에서만 보이는 질문)이기 때문. 가로 5일(열) × 세로 4시간대(행) — 캘린더 주간 뷰의 관용구.

**네 상태의 비-색 인코딩**: 모든 칸이 같은 문법의 **2바 글리프**를 단다 — 위 바 = 나, 아래 바 = 상대, 채움 = 가능 / 비움 = 불가. 네 상태가 색 이전에 **네 개의 형태**(■■ / ■□ / □■ / □□)로 갈린다. 겹침만 추가로 액센트 채움. 격자 위 범례가 같은 축척의 미니 칸으로 문법을 먼저 가르친다.

**하단 상태기계 밴드 없음** — 고정 크롬이 아예 없다. 상시 증명 셋(프루프 스트립의 겹침 개수 + 가장 이른 겹침 / 요일 헤더 매칭 카운트 필 / 격자의 액센트 칸)이 전부 탭 이전 기본값이고, 액션은 격자 아래 **셀 인스펙터**(스크롤에 흐름)에 있어 언제나 방금 만진 칸에 한정된다.

**인터랙션 7종**

| 조작 | 증명 갱신 |
|---|---|
| 겹침 칸 탭 | ink 채움 + 체크 → 초안 제안. 인스펙터가 확정 문장으로. 겹침을 *발견*에서 *지목*으로 승격 |
| 같은 칸 재탭 | 해제 → 전체 겹침 요약으로 복귀. 증명이 사라지지 않고 개관으로 되돌아감 |
| 비-겹침 칸 탭 | 두 줄 상태행(You — free / Ilhwa — busy)을 바 글리프 + 낱말로 재진술. 왜 여기가 답이 아닌지를 침묵 대신 문장으로 |
| **"I can make it"** | 내 축에 가용성 추가 → 칸이 즉시 겹침 전환, 상단 카운트 +1, 요일 필 +1, 자동 승격. **조작이 증명을 늘림.** 실제로 매칭이 생기는 칸에만 나타남 |
| "Actually, I am busy then" | 내 가용성 제거 → 카운트 −1, 발송 상태도 함께 해제. 편집이 양방향임을 정직하게 유지 |
| "Go to the earliest match" | 막다른 칸에서의 복구 경로. 이미 격자에 보이는 칸이라 새 정보가 아니라 시선 유도 |
| "Send this time" → "Change the time" | 발송 시 헤드라인이 `accessibilityRole="alert"` 로 승격(컨테이너는 `polite`), 칸이 액센트 링 + 하단 4px 언더라인을 얻어 **"보류 중"이 격자 안에 남음** |

**격자 칸 치수 (390pt)**

```
390 − 32(padding) = 358 − 56(시간대 거터) − 20(gap 4 × 5) = 282 ÷ 5 = 56.4pt 폭 × 56pt 높이
```

두 축 모두 최소 터치 44×44 초과(여유 +12.4 / +12.0). `hitSlop` 은 **의도적으로 안 걸었다** — 인접 칸의 탭을 훔치므로. 360pt 안드로이드 50.4pt ✓ / **320pt(SE 1세대) 42.4pt 미달** — 브리프 기준(390)은 충족하나 하한을 자진 신고.

## 브리프에 없던 것

**① 격자 축의 크기** — ② 5일 × 4시간대 = 20칸 ③ 터치 타깃에서 역산(6일이면 46.3pt 로 여유 2.3pt, 4일이면 "겹침이 희소하다"를 보일 표본 부족). **임의**

**② 시간대 경계** — ② 9–12 / 12–3 / 3–6 / 6–9, Morning/Midday/Afternoon/Evening ③ 15·30분 슬롯은 직거래에 과잉 정밀(협상 단위는 시각이 아니라 구간). 밴드 이름 병기는 "12–3"만으로 오전/오후가 모호해서. **관행**

**③ 네 상태의 비-색 문법** — ② 위 바 = 나 / 아래 바 = 상대, 채움 = 가능 ③ 브리프의 "색만 금지"에서 도출. 대안(해칭 두 방향, 사각/원)은 56pt 에서 판독 불가이거나 누가 누군지 자기설명이 안 됨. 두 바는 **범례가 같은 축척으로 문법을 가르칠 수 있는** 유일한 안. **임의(조항에서 도출)**

**④ 어느 축이 편집 가능한가** — ② 상대 축 읽기 전용, 내 축만 편집 ③ 양쪽 다 열면 시뮬레이터지 협상 화면이 아니다. 한쪽만 열어야 "내가 한 칸 열면 매칭이 생긴다"는 인과가 선명. **관행 + 조항 도출**

**⑤ 선택/발송을 격자에 표시하는 방법** — ② 초안 = ink 채움 + 흰 체크 / 발송 = 거기에 액센트 링 + 하단 4px 언더라인 ③ 테두리 색만으로 가르면 그 자체가 색-단독 구분이라 브리프 위반. **형태 차이**를 넣어 회피. **임의**

**⑥ 액션 위치** — ② 고정 밴드 없음, 격자 아래 스크롤되는 인스펙터 ③ 인스펙터는 "방금 만진 칸"에 종속돼 화면의 논증이 될 수 없고 격자가 논증 자리를 유지. 고정 아닌 것도 같은 이유. **금지 조항 도출 + 대안은 임의**

**⑦ 더미 겹침 분포** — ② 겹침 3 / 상대만 5 / 나만 6 / 둘 다 불가 6 ③ 겹침 0이면 상시 증명이 성립 안 하고 8~10이면 격자를 쓸 이유가 사라진다. 3/20 은 "희소하지만 존재한다"를 재현하고, 상대만 5개는 인터랙션 4를 시연할 여지. **임의**

**⑧ 날짜·상대 이름·장소·거래 라인** — ② Wed Aug 19 – Sun Aug 23 2026 / "Ilhwa" / "Hongdae Stn. Exit 3, locker area" / "Sony WH-1000XM5 · ₩289,000 · cash on handoff" ③ `r7/disputes/data.ts` 가 Aug 16 2026 을 일요일로 잡았기에 Aug 19 를 수요일로 맞췄고, 품목·가격도 그 파일의 반환 대상을 이어받아 **같은 세계의 화면**으로 읽히게 함. **다른 작품 참조**

**⑨ 라이브 리전 개수** — ② 하나 — 인스펙터 컨테이너 `polite`, 발송 헤드라인만 `alert` ③ 정본 §3 의 r5/r6c 패턴 그대로. 상단 카운트에도 polite 를 걸면 한 조작에 두 영역이 동시 낭독돼 어느 쪽이 새 정보인지 모른다. **다른 작품 참조**

**⑩ 폰트 웨이트** ★ — ② 400/600/700 정확히 3종, `"800"` 미사용 ③ `page-brief-core` §3 "정확히 3종"에서 도출. **다만 이 레포 기존 native 화면들은 `"800"` 을 흔히 쓰고 있어 선례와 어긋난다.** 어느 쪽이 정본인지 브리프가 말하지 않아 코어를 우선했고, 판정자가 반대로 볼 수 있는 지점으로 자진 표시. **정본 충돌 — §6 질문 대상**

**⑪ `tabular-nums` 위치** — ② 리프 `Text` 5개에만(프루프 카운트·요일 숫자·요일 필·거터 시간범위·인스펙터 한 줄) ③ 다섯 모두 렌더 트리 하위에 ₩ 없음. ₩ 는 `DEAL_LINE` 한 곳뿐이고 그 `Text` 는 `fontVariant` 가 없으며 조상 중 `Text` 가 없다. **정본 함정 조항 도출**

**⑫ 칸 안에 텍스트를 넣을지** — ② 안 넣음. 칸은 글리프만, 요일·시각·상태는 `accessibilityLabel` 이 문장으로 ③ 56pt 칸의 글자는 8~9px 이라 판독 불가에 가깝고 격자의 값은 밀도이지 라벨이 아니다. 스크린리더 손실이 없도록 라벨을 `"Thursday, August 20, 6 PM to 9 PM. Both free."` 로 완결. **임의**

**⑬ `FlatList` 를 무엇에 걸 것인가** — ② 시간대 행(4개)을 `data`, 행 안의 5칸은 `.map()` ③ 정본 §1(리스트는 `FlatList`)과 "격자는 리스트가 아니다"를 절충. 행은 세로 반복 동종 항목이라 `FlatList`, 한 행 안 5칸은 리스트가 아니라 한 레코드의 필드. **정본 절충**

**⑭ 겹침이 0이 됐을 때** — ② 프루프 박스가 액센트 채움 → 흰 바탕 + ink2 테두리, 문구 `"Nothing overlaps yet — open a slot Ilhwa already has"`, 인스펙터가 다음 행동 지시 ③ "0"을 액센트 박스에 담으면 성취처럼 읽혀 표면 톤을 뒤집음. 인터랙션 5 반복으로 실제 도달 가능해 방치 불가. **카탈로그 빈 상태 도출**

**⑮ 발송 후 되돌릴 수 있는가** — ② 있음, "Change the time" ③ 브리프·정본 모두 발송의 종결성을 규정 안 함. 시간 제안은 파괴적 행동이 아니고(환불·삭제와 다름) 상대 응답 전에 바꾸는 것이 관행. 확인 다이얼로그는 안 붙임 — 되돌릴 수 있는 행동에 과잉. **임의**

## 오케스트레이터 주석

- designer 에 Bash 가 없어 `tsc` 미실측. 대신 위험 구문 8종을 레포 내 **이미 컴파일되는 선례**와 1:1 대조(`DisputeCenterScreen.tsx:417·494·512·779·45`, `MatchList.tsx:47` 외 12곳). 게이트 1단계에서 실측된다.
- 세로 리듬 조정은 코디네이터 지시로 중단. 중단 전 적용분은 여백 3곳 축소뿐(`legend.marginTop` 16→12, `headRow.marginTop` 16→12, `readout` 20→16 · minHeight 180→164)이고 **격자 치수·거터·gap·칸 높이 무변경**.
- ⑩이 정본 충돌을 짚었다: native 게이트는 4단계(`tsc·export·render·iframe`)뿐이라 웹의 `weights` 관문이 없다 — "웨이트 정확히 3종"이 native 에서 **아무에게도 안 측정되고 있었다**.
