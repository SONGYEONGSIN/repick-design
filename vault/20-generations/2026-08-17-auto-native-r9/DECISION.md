## 왜 c 가 이겼나 — 세 렌즈가 서로 다른 이유를 댔다

**렌즈 1 (DNA)**: c 는 정본이 "두 번 놓쳤다"고 스스로 기록한 `tabular-nums` × ₩ 함정을 **회피가 아니라 통과**로 넘긴 유일한 후보다. `tabular-nums` 를 5곳에 걸면서 동시에 ₩ 를 인쇄했고, 불변식을 **양쪽 끝에 문서화**했다 — `c/data.ts:155-157` 과 렌더 지점 `c/MeetupSlotGridScreen.tsx:230-232`. 그리고 상태를 **2줄 막대 글리프의 채움 위치**로 인코딩해(`:68-77`) 4상태가 색 이전에 4개 형태로 갈린다 — `page-brief-core` §2 "색만으로 의미 전달 금지"에 대한 **유일한 구조적 응답**.

**렌즈 2 (완성도)**: 390 에서 결함 0인 유일한 후보이자 터치 타깃이 **hitSlop 없이** 통과하는 유일한 후보. 셀 실측 ≈ 60×56 이고, `:668-669` 주석이 왜 hitSlop 을 안 썼는지 적어 뒀다 — *인접 격자 셀의 hitSlop 은 서로 겹쳐 이웃의 탭을 훔친다.* a·b 는 둘 다 hitSlop 으로 미달 크기를 메운다.

**렌즈 3 (차별성)**: 리스트로는 답이 안 되는 질문을 유일하게 가졌다. "겹치는 3개"만 답이면 리스트로 충분하지만, c 의 실제 조작은 **near-miss 전환**이다 — 상대만 비어 있는 셀을 눌러 "I can make it" 하면 즉시 매칭이 되고 카운트가 오른다(`:209-212`, `:454-465`). 어느 셀이 전환 후보인지는 열/행 밀도로만 보인다.

## 이번 라운드가 금지 버킷을 어떻게 다뤘나

`r3`(체크리스트) → `r5`(위저드) → `r6`(아코디언) → `r7`(분쟁) 네 라운드 연속 **하단 상태기계 밴드**가 이겼다. 다섯 번째면 라운드가 아니라 반복이므로 이번 라운드는 그 버킷을 주 구조로 삼는 것을 금지했다.

세 후보가 각자 다르게 응답했고, **밴드를 안 쓴 것 자체는 아무에게도 점수가 되지 않았다** — 렌즈 3 에 "밴드가 하던 일(무엇이 막혔는지 말하기 · 다음 행동으로 데려가기)을 대체 구조가 실제로 하는가"를 판정 조건으로 명시했기 때문이다.

- **c** — 고정 크롬 **0**. 헤더·격자·readout 전부 한 `FlatList` 안에서 스크롤(`:506-520`). 밴드의 두 일을 **쪼개서** 가져갔다: (i) 상단 proof 카운터가 "지금 몇 개가 성립하는가", (ii) 셀별 readout 이 "왜 막혔는가 + 어디로 가야 하나"(`"Only you are open here — Ilhwa has not offered this slot, so proposing it would stall"` + `Go to the earliest match`, `:466-484`). **회피가 아니라 대체.**
- **a** — 상태기계는 없앴고 밴드의 두 임무도 수행한다(막힘 시 primary 가 복구 버튼으로 교체 `:563-573`, 닫힘 고지 `:489-493`). 그러나 **하단 앵커 커밋 크롬의 실루엣이 남았다** — `sheet` 가 잔여 높이를 차지하는 고정 영역이고 `Propose this spot` 이 두 프레임 모두 화면 하단에 앉아 있다. 렌즈 3 판정: *밴드를 시트로 개명한 부분이 있다.*
- **b** — 판정어를 하단이 아니라 **히어로 카드 안**에 넣어 밴드의 "무엇이 문제인가" 역할을 상단으로 옮겼다. 렌즈 3 이 "정직한 대체"로 인정.

## ★ 이번 라운드의 자기 발견 — 금지 버킷을 피하다 라운드 내 중복을 만들었다

**렌즈 3 이 a 와 c 를 골격 형제로 판정했다.** 소재(둘 다 "상대와 만남 조율" — a=어디서, c=언제)와 골격이 함께 겹친다:

> 둘 다 **"항상 켜져 있는 2D 필드에 후보를 배치 + 각 후보가 두 사람 상태를 병렬 인코딩 + 탭하면 아래 패널이 설명하고 커밋"** 이다.
> 병렬 인코딩 a `8·9`(`:400-404`) ↔ c 위/아래 두 막대(`:78-83`) · 인스펙터 a 시트 카드(`:461-517`) ↔ c readout(`:362-502`) · 커밋 a `Propose this spot`(`:561-575`) ↔ c `Send this time to Ilhwa`(`:443-447`)

**원인은 오케스트레이터의 §2 배정이다.** 매크로-골격 버킷 선제 체크는 "직전 라운드의 버킷을 금지"까지만 하고 **이번 라운드 3후보끼리의 버킷 충돌은 안 본다.** 밴드 반복은 막았는데 그 자리에 라운드 내 중복을 새로 만들었다 — 선제 체크가 막으려던 바로 그 낭비다. §5 delta 로 올린다.
