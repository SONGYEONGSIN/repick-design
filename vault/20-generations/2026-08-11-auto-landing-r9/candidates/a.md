# 후보 a — The Standing Brief

**한 줄**: 완성된 영문 요구 문장 한 줄이 페이지 상단을 지배하고, 그 문장의 네 구절이 칩이다. 구절 하나를 갈아끼우면 문장·순위·점수·근거 태그·순위 논증 산문이 한꺼번에 다시 쓰인다. 페이지 전체가 다섯 정수의 순수 함수(`buildReport(BriefState)`).

- 배정: 조작 어휘 = **요구 문장의 구절 교체** / 매크로 골격 = **문장 상단 지배 + 결과 필드** / 다크 · `--font-display-mono`
- 축 조합(Q6 기준): **자연어 문장의 구절 선택 × 문장 재작성 + 결과 필드 재계산** — 기존 6종과 미겹침
- 파일: `page.tsx`(서버·metadata) · `data.ts`(12매물 풀 + 순수 채점) · `ui.tsx`(클라이언트 셸) · `listing-card.tsx` · `silhouette.tsx`

## 인터랙션 (5종 + 마이크로)

| # | 조작 | 동시 갱신 증거면 |
|---|---|---|
| 1 | 구절 칩 4종(condition/category/budget/seller) | rail 헤더·힌트·옵션 세트 |
| 2 | rail 옵션 선택 → 문장 재작성 | ① 문장 자체 ② 카드 4장 순서·match% ③ 카드별 근거 태그 3줄 ④ "why this order" 산문 ⑤ 스탯 3개 ⑥ closest miss 5위·탈락 사유 ⑦ 가치 3분할 세 수치 ⑧ 마감 CTA 브리프 재진술 |
| 3 | reading 칩(strictest ↔ forgiving) | 가중치 세트 교체 → **순위가 실제로 뒤집힘**(strict Kestrel 90 → forgiving Aperture 78 1위) + 산문 + 전 match% |
| 4 | match 막대 · 등급 분포 막대 | `scaleX` transform 트윈 0.42s (width 애니 금지 준수) |
| 5 | 카드 hover 보더 · 칩 `whileTap` 0.97 · 앵커 CTA 2개 | 마이크로 |

**증명 지연 없음** — 최초 렌더에 완성 문장 + 4장 풀태깅 카드 + 산문 + 스탯이 전부 떠 있고, 조작은 재계산만 한다.

designer 자체 점검: `Math.random`/`Date` 0 · 사진 0장(생성형 SVG 실루엣, r7 학습) · 배지 전부 프레임 바깥 행 · 웨이트 400/600/800 3종 명시 · `fontFamily` 호출부마다 리터럴 반복 · 진입은 기존 `rise` 키프레임이라 `whileInView` 미사용(뷰 밖 `opacity:0` 잔존 불가) · 보조텍스트 `#A1A1AA` on `#0B0B0F` = 7.6:1.

## 브리프에 없던 것

1. **점수 산출식 자체** — ① match%가 어떻게 나오는지 정의가 없음("재계산"만 지시) ② base 18 + 카테고리 40/34 + 등급 18/14/3/−12 + 예산 헤드룸 12/9/6(초과 −16/−5) + 판매자 ±8/−13 → clamp 12~97 ③ 임의. 단 두 제약을 만족하도록 역산했다 — (a) strict에서 카테고리 가중치가 나머지 합보다 커야 상위 4장이 항상 동일 카테고리(비카테고리 최고 47 < 카테고리 최저 53) (b) strict↔forgiving에서 1·2위가 실제로 뒤집혀야 조작이 체감된다.
2. **풀 크기와 구성(12 = 3카테고리 × 4)** — ① 카드는 4장이라 했으나 뒤에 몇 개가 있어야 하는지 없음 ② 카테고리당 정확히 4개 ③ 임의. 4개면 상위 4장 = 그 카테고리 전량이 되어 순서 변화가 카테고리 교체가 아닌 **재정렬**로 읽히고, `closest miss`(5위)가 항상 다른 카테고리에서 올라와 경계가 드러난다.
3. **조작 어휘의 UI 형태 — 팝오버 대신 고정 rail** — ① "누르면 대안이 열린다"의 구현 형태 ② 문장 바로 아래 **항상 떠 있는** 옵션 rail의 내용이 바뀜(초기 condition 슬롯 열림) ③ 관행 + 게이트 회피. 칩 앵커 absolute 팝오버는 390px에서 오른쪽 칩이 뷰포트를 넘겨 `scrollWidth`를 오염시킬 확률이 높고, rail은 숨은 상태가 0이라 증명 지연 감점도 원천 차단된다.
4. **다섯 번째 조작(reading 칩)의 존재** — ① 브리프는 후보 a에 조작 어휘 하나만 배정 ② 같은 "구절 교체" 어휘를 가치 섹션 두 번째 문장에 한 번 더 배치 ③ 브리프 3번(가치 3분할 = 조작이 증명 데이터를 실시간 갱신) 요구를 만족시키려면 그 섹션에 조작이 필요한데, 새 어휘를 도입하면 배정을 어기므로 같은 어휘를 재사용했다.
5. **가치 3분할의 "가치"가 무엇인가** — ① 세 항목의 주제 ② 문장을 읽는다(구속 조건) / 등급을 매긴 뒤 올린다(등급 분포) / 요구에 맞춰 값을 매긴다(상한 이하 개수 + 중앙값) ③ 임의. 제품 맥락에서 역산했고 셋 다 브리프 상태의 함수라 장식이 아니라 계산 결과다.
6. **사진 대신 SVG 실루엣** — ① 이미지 사용 여부 ② 3종 솔리드 매스 실루엣(카메라/자전거/코트), 사진 0장 ③ 브리프 허용 + r7 학습. **고정 unsplash ID를 기억에 의존해 적는 순간 깨진 이미지가 될 위험이 실재해** 외부 에셋을 아예 제거했다. 라인아트 금지 조항 때문에 스트로크가 아닌 채움 매스로 그렸다.
7. **소셜프루프의 인물명·수치** — ① 인용자 이름과 통계 ② "Priya S. / Tomas R. / Wren A.", 18,400 · 92% · 4 ③ 임의(가공). 실존 인물명 금지만 명시돼 있어 이니셜 성으로 축약했고, **수치는 검증 불가한 가공값이라 실제 랜딩이면 실측으로 대체돼야 한다**고 스스로 적었다.
8. **caution 톤 색 `#E8A87C`** — ① DNA 팔레트가 4색(bg/fg/muted/accent)뿐이라 "감점 요인" 표시 색이 없음 ② 웜 앰버 1색 추가, 색 단독 전달을 피해 아이콘(`Minus`/`X`) + 문장 항상 병기 ③ 관행. near-monochrome 위반 최소화를 위해 텍스트가 아닌 아이콘 한 글자폭에만 썼다.
9. **CTA의 목적지** — ① 제품이 실재하지 않는데 단일 CTA가 어디로 가는가 ② 히어로 → `#the-field`, 마감 → `#brief` 앵커 ③ 임의. 죽은 `<button>`보다 키보드로 실제 도달 가능한 앵커가 접근성에 안전하고, "문장 ↔ 결과 필드" 왕복이 이 페이지의 논지라 카피와도 일치한다.
10. **`closest miss`(5위 탈락자) 노출** — ① 브리프에 없는 요소 ② 5위 매물명 + 점수 + 첫 실패 항목을 히어로 우측에 상시 표시 ③ r8 학습의 확대 적용. 상위권만 보여주면 재정렬이 **무엇을 밀어냈는지** 보이지 않아 탈락 경계를 증거면으로 추가했다.
