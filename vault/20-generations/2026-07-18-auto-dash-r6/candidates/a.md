## a — Millrace

데이터 파이프라인 오케스트레이션 SaaS(Airflow·Dagster·Prefect급, 워크스페이스: Millrace 데이터 플랫폼팀 · 담당자 Priya Desai)로, 이번 라운드 배정 아키타입인 **DAG/노드-엣지 캔버스**가 화면의 절대 주인공이다 — `nightly_orders_pipeline`의 태스크 14개(extract_orders/customers/inventory 3중 소스 → transform/dedupe/enrich → join → validate → load_warehouse → load_analytics_mart → notify_slack/pagerduty 이중 팬아웃, 그리고 검증 실패로 종단되는 독립 분기 archive_raw_inventory)를 열(스테이지)×레인(병렬 분기) 좌표에 손으로 배치하고, SVG 큐빅 베지어 엣지(좌표 전부 소수 2자리 반올림)로 연결했다 — 물리 시뮬레이션·외부 그래프 라이브러리 없이 순수 결정론적 고정 좌표라 매번 동일하게 렌더된다. 간트 차트(수평 시간축 막대)도 지리 맵도 아니며, 이미 사용된 14종 아키타입(피드/칸반/캘린더/히어로벤토/분할편집기/간트/지도/스프레드시트/마스터-디테일/모니터링타일월/BI위젯캔버스/3페인워치리스트/인박스/미러패널)과도 겹치지 않는다. 캔버스는 뷰포트가 좁을 때만(최소 860px 폭 기준) 카드 내부 가로 스크롤로 전환되며 — 이는 테이블에 적용되는 "데스크톱 가로 스크롤 금지" 규칙과 달리 실제 Airflow류 그래프 뷰가 채택하는 정당한 패턴이라 판단해 채택했고, 1280~1920 전 구간에서 요구되는 ≥16px 여유폭을 확보하도록 노드 반폭(56vb)·컬럼 간격을 역산해 튜닝했다. 상세 패널은 2xl 이상에서만 12-col 그리드(col-span-9/3)로 캔버스 옆에 고정되고 그 아래에서는 세로로 쌓여, 좁은 데스크톱 폭에서 억지로 욱여넣다 카드 밖으로 넘치는 실패를 원천 차단한다. 적용 인터랙션 4종: ① 노드 클릭 → 우측 상세 패널(로그 발췌·오너·재시도·업스트림/다운스트림 칩) 동기화 + 연결 엣지 하이라이트(방향키로도 인접 노드 이동, 필수 핵심 인터랙션) ② 런 히스토리 테이블 실제 정렬(aria-sort, 시작/소요시간/상태)과 상태 세그먼트 필터 ③ 24H/7D/30D/90D 기간 세그먼트 토글이 히어로 성공률 수치+인라인 스탯(평균 소요시간·다음 실행 예정)과 테이블을 동시에 갱신 ④ ⌘K 커맨드 팔레트로 태스크 검색→선택 시 캔버스·패널 동기화. KPI는 4카드 가로줄 대신 히어로 숫자(기간별 성공률)+보조 인라인 스탯 변주로 구성했고, 런 히스토리의 성공/실패/건너뜀 부분합은 태스크 총수 14와 항상 일치하도록 검증했다. 라이트는 순백/zinc-50 캔버스+zinc-200 헤어라인, 다크는 zinc-950/900 표면(보조 텍스트 라이트 zinc-500+/다크 zinc-400+ 대비 규칙 준수)으로 대응했고 페이지 전체 Pretendard 단일 폰트(숫자 tabular-nums, 로그 발췌만 전역 font-mono)로 통일했으며, sr-only는 테이블이 아닌 `<caption>`에만 적용해 알려진 하이드레이션/오버플로 함정을 피했다.
