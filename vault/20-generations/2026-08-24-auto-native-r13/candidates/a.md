# auto-native-r13 후보 a — Payout & Withdraw

**한 줄 컨셉**: 잔액 헤더 + 금액 입력(프리셋/커스텀) + 계좌 표시라는 정적 폼처럼 보이지만, 하단 밴드는 진짜 블로킹 조건(미입력·최소액 미달·잔액 초과)이 있을 때만 상태기계로 말하고, 조건이 풀리면 곧장 평범한 "Withdraw ₩X" 액션바가 되며, 눌렀을 때 인라인 Cancel/Confirm 확인 → Processing… → 잔액이 실제로 줄어드는 성공 카드까지 화면 안에서 종결한다.

## 브리프에 없던 것

**① ₩ 기호와 숫자 사이 간격 처리** — ② `formatWon()`이 `₩ 486,000`처럼 심볼과 숫자 사이에 고정 공백을 넣는 방식(선택지 ①)을 쓰고, 금액 입력창에서도 "₩" 프리픽스 Text와 TextInput을 별도 노드+gap으로 분리했다 ③ evolve/r12/a가 같은 방식을 이미 검증해뒀고(획이 옆 숫자와 붙는 문제 회피), 이 화면은 금액이 화면의 존재 이유라 특히 신중해야 한다고 판단해 재사용. **정본 컨벤션 재사용**

**② 실제로 구현한 블로킹 조건 3종, 뺀 것 2종** — ② 구현: 미입력/최소출금액(₩10,000) 미달/보유잔액 초과. 뺀 것: "은행계좌 미등록"과 "일일 한도 초과" ③ 계좌 미등록 분기는 이 폴더 범위에 계좌 연결 플로우가 없어 만들면 갈 곳 없는 상태가 되고, 일일 한도는 보유잔액(₩486,000)이 한도(₩300만)보다 훨씬 작아 정상 입력 범위에서 절대 도달하지 않는 죽은 로직이 되므로 뺐다 — 델타 지시("진짜 블로킹인지"·"장식 아닌지")를 문자 그대로 따른 결과. **논증 정합**

**③ 확인 단계를 네이티브 Alert가 아니라 밴드 내부 Cancel/Confirm 두 버튼으로** — ② "Withdraw ₩X" 클릭 시 같은 밴드가 확인 문장 + Cancel/Confirm 두 버튼으로 바뀌고, Cancel은 폼으로 복귀, Confirm이 실제 처리를 시작한다 ③ 카탈로그가 "파괴적 행동 전 확인 다이얼로그"를 요구했지만 RN `Alert.alert`는 이 저장소의 스타일드 컴포넌트 관용구 밖이라 접근성 검증이 어렵고, 이미 검증된 밴드/라이브리전 패턴 안에서 확인을 처리하는 쪽이 더 일관적이라고 판단. **논증 정합**

**④ Processing… 은 고정 지연(900ms)으로 보여주고, 에러 분기는 만들지 않음** — ② `useEffect`+`setTimeout(PROCESSING_DELAY_MS)`로 confirm→processing→done 전환을 만들고, done에서 잔액을 실제로 차감한다. 실패/에러 상태는 구현하지 않았다 ③ GENERATION.md §5가 `Math.random`을 금지해 "가끔 실패"를 결정론적으로 만들 방법이 없었고, 입력값에 결부된 인위적 실패 조건(예: 특정 금액이면 실패)은 사용자에게 설명 불가능한 매직 넘버라 오히려 장식적이라 판단해 성공 경로만 결정론적으로 완결시켰다. 델타 ①의 핵심 요구("무음 no-op 금지")는 loading→success 전환 자체로 충족된다고 봄. **논증 정합 (제약 하 결정)**

**⑤ 프리셋 칩은 radio가 아니라 button + selected 상태** — ② `accessibilityRole="button"`에 `accessibilityState={{selected}}`만 얹었다(evolve/r12/a의 사유 행처럼 `role="radio"`는 쓰지 않음) ③ 프리셋은 상호배타적 선택지 자체가 아니라 커스텀 입력칸을 채우는 단축 액션이고, "Max"와 직접 타이핑한 486000이 같은 값이면 둘 다 시각적으로 맞아 보여야 하는 다대일 관계라 radio 그룹 의미론이 맞지 않는다고 판단. **논증 정합**

**⑥ 은행 계좌 섹션에 "Change account"/"Add account" 버튼을 아예 두지 않음** — ② 계좌 카드는 은행명·마스킹된 계좌번호·예금주·Verified 배지만 보여주는 순수 정보 카드다 ③ 델타 ①이 "아직 안 만든 후속 플로우는 무음 placeholder라도 괜찮다"고 허용했지만, 이 화면의 유일한 계좌라 바꿀 대상이 없고 무음 버튼을 놓느니 아예 안 두는 쪽이 렌즈2("갈 곳 없는 CTA")에 더 안전하다고 판단. **논증 정합**

**⑦ Verified 배지는 아이콘(✓)+텍스트 병행, accent 색만으로 전달하지 않음** — ② "✓ Verified"를 accent indigo로 칠하되 체크 글리프와 "Verified" 라벨을 항상 함께 노출 ③ 카탈로그 공통 항목 "색만으로 전달 금지"를 그대로 적용. **정본 규칙 직접 적용**
