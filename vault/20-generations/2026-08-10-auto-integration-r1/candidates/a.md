# a — 두 스키마 사이에서 값이 무엇으로 변해 도착하는가

**컨셉 1줄**: Salesforce에서 Tessera로 가는 연결을 **필드 대조표**로 세우고, 한 레코드가 실제로 어떤 값으로 바뀌어 도착하는지와 **끝내 못 건너오는 6가지**를 같은 화면 기본 상태에 나란히 둔다.

## 이 타입(`integration`)을 무엇으로 정의했나

카탈로그 0건이라 초안을 세웠다. `integration`은 **"이 도구와 우리 제품을 연결하면 무엇이 어떻게 흐르는가"**를 코드를 안 쓰는 사람에게 보이는 화면이다.

- `catalog`와의 경계: 카탈로그는 **고르는** 화면(N개 중 1개), integration은 **이미 고른 하나**의 화면. 그래서 목록·필터·검색이 없고 비교 대상도 없다.
- `developers`와의 경계: 저쪽은 엔드포인트·인증·샘플 요청이 축이다. 이쪽 축은 **필드와 값**이며, 사용자가 조작하는 대상은 요청이 아니라 매핑 한 줄이다.
- 이 타입이 성립하려면 화면에 반드시 있어야 하는 것: ①방향(양방향인가 단방향인가) ②주기 ③필드 대응 ④값 변환의 실제 예 ⑤**옮기지 못하는 것과 그 이유**. ⑤가 없으면 이 페이지는 마케팅 배지로 퇴화한다.

## 구성

1. 헤더 — `Salesforce → Tessera`, 방향·주기·객체·소스 org 4칸 + 요약 3수치(9 / 6 / 6)
2. **Field map** — 9행 대조표(소스 필드 · 가는 길 · 도착 필드 · 이 레코드의 값 · On). 기본 상태에서 이미 `4,200,000 EUR → 4,536,000 USD`, `Apparel → retail`, `18,250.75 → 1825075`가 보인다
3. **One record, end to end** — 같은 Opportunity 하나의 읽은 값 / 저장된 값 두 열
4. **What this connection does not move** — 6항목, 각 항목의 이유 1줄이 기본 노출

## 인터랙션 4종 (전부 국소)

| # | 조작 | 영향 범위 |
|---|---|---|
| 1 | 행 펼치기(`aria-expanded`/`aria-controls`) | 그 행의 상세만 |
| 2 | 필드별 On/Off 체크박스 | 그 필드의 값 칸 + 배송 열의 그 한 줄 |
| 3 | 행 상세 안의 변환 방식 라디오(통화·타임존·세그먼트 3행) | 그 필드의 도착 값 |
| 4 | 미이관 항목별 Why 디스클로저 | 그 항목만 |

전역 입력은 하나도 없다. 한 매핑을 만지면 그 매핑만 바뀐다.

## 브리프에 없던 것

### ① 제품·상대 도구를 무엇으로 할지 — 정하지 않으면 필드 이름을 쓸 수 없다
- **정했다**: 상대 = Salesforce(Account/Contact/Opportunity), 제품 = Tessera(고객·거래 레코드 워크스페이스). 필드는 실존 API 이름(`Account.AnnualRevenue`, `Opportunity.CloseDate`, `IsPersonAccount`)으로 썼다.
- **왜**: "구체적으로 쓰라"는 지시를 만족하려면 양쪽 스키마가 실재해야 손실 사례(34값 피클리스트 → 6 enum, 컴파운드 주소 → 5열)가 지어낸 티가 안 난다. Salesforce는 필드 타입 제약이 널리 알려져 있어 독자가 검증할 수 있다.

### ② "못 옮기는 것"을 어느 층위로 셀 것인가 — 필드 단위인가 능력 단위인가
- **정했다**: 섞었다. 필드(`Account.Description`), 필드군(수식·롤업), 자원(파일), 레코드 종류(person account), **행위**(삭제), **방향**(Tessera→Salesforce 역방향) 6종.
- **왜**: 필드만 세면 "연결이 무엇을 못 하는가"의 절반이 빠진다. 실무에서 사고가 나는 지점은 대개 필드가 아니라 삭제·역방향·레코드 타입 미스매치다. 아키타입이 필드 매핑 우선형이므로 축은 필드지만, 축 밖의 결손을 같은 목록에 넣어야 이 페이지가 정직해진다.

### ③ 손실을 어떻게 표시할 것인가 — 색으로만 두면 규칙 위반이다
- **정했다**: `Collapsed, lossy` 같은 **텍스트 라벨** + `TriangleAlert` 아이콘 + `Not reversible` 문구 3중. 색(violet-100 칩)은 보조.
- **왜**: 코어 §2 "색만으로 의미 전달 금지". 그리고 손실은 이 페이지의 결론이라 배지 하나로 접기엔 정보량이 크다 — 행을 펼치면 "무엇이 어떻게 되돌릴 수 없는지"가 문장으로 나온다.

### ④ 변환 선택지를 어디에 둘 것인가 — 상단 전역 설정 vs 행 내부
- **정했다**: 행 상세 안의 라디오. 통화(USD 환산 / 원 통화 유지), 타임존(UTC 정규화 / org 오프셋 유지), 세그먼트(6개로 접기 / raw 병기).
- **왜**: 금지 목록의 "전역 입력 1개 → 전 섹션 동시 재계산"을 피해야 했고, 실제로도 이 선택은 필드마다 다른 트레이드오프(합산 가능성 vs 원본 보존)라 전역으로 묶는 게 잘못된 모델이다.

### ⑤ 기본 상태에서 얼마나 보일 것인가 — 3렌즈의 "핵심 증명까지의 거리"
- **정했다**: 값 변환 예시를 표의 상시 열로 승격하고, 펼침에는 **규칙과 엣지 케이스만** 남겼다. 미이관 6항목도 이유 1줄이 기본 노출.
- **왜**: 클릭해야 보이면 감점이라는 조건이 명시돼 있었다. "무엇을 옮기고 무엇을 못 옮기는가"는 스크롤만으로 완결되고, 인터랙션은 그 증명을 **더 깊게** 만들 뿐 증명을 **가두지** 않는다.

### ⑥ 결정론 요구와 "시각/환율" 데이터의 충돌
- **정했다**: 모든 시각·환율·집계를 고정 문자열 상수로(`2026-08-09 06:12 UTC`, `1 EUR = 1.08 USD on 2026-08-09`). 대신 그 고정성을 카피로 흡수했다 — "환율은 레코드 옆에 저장되지 않는다"가 곧 손실 항목이 된다.
- **왜**: `Date.now`/`new Date` 금지는 하드게이트다. 시각을 지어내는 대신 **시각 스냅샷의 의미**를 설명하면 결정론이 결함이 아니라 내용이 된다.

### ⑦ 모바일에서 5열 표를 어떻게 할 것인가
- **정했다**: 표를 유지하고 `min-w-[760px] md:min-w-0` + `overflow-x-auto md:overflow-x-visible`. 데스크톱 가로 스크롤 0, 390px에서만 국소 스크롤.
- **왜**: 카드로 쪼개면 "두 스키마를 나란히 둔다"는 아키타입의 축이 무너진다. 코어 §4는 모바일 전용 국소 스크롤을 허용한다. 스크롤 컨테이너 안에는 `sr-only`를 두지 않았다(§2 앵커 함정 회피 — 체크박스 라벨은 `aria-label`로 처리).

### ⑧ 활자 배정의 적용 범위
- **정했다**: `--font-display-mono`는 h1·h2·이터브로우·요약 수치에만. 필드 경로처럼 **작은 코드 문자열은 `--font-mono`**.
- **왜**: `page-brief-repo` §2가 디스플레이 폰트를 "라틴 전용·큰 크기 전용"으로 못박는다. 필드 경로는 작고 밀도가 높아 본문 mono가 맞다. 웨이트는 400/500/600 정확히 3종.

## 자기 점검

- `Math.random`·`Date.now`·`new Date()` 0 · `<img>` 0 · 이모지 0 · `next/font` import 0 · 무작위 이미지 서비스 0
- 폰트 웨이트 3종(기본 400 · `font-medium` · `font-semibold`), `<th>`에는 명시 웨이트를 줘 UA bold 유입 차단
- 라이트 대비: muted 표면(zinc-50/zinc-100/violet-50) 위 보조 텍스트는 전부 **zinc-600 이상**
- 단일 `h1`, h2 3개, h3는 미이관 목록에만. 포커스는 전부 `focus-visible:ring-2` (`outline-none` 단독 없음)
- `transition-*`에는 모두 `motion-reduce:transition-none`, 진입 애니메이션 없음(`opacity:0` 잔존 불가)
- 표: `caption` + `scope="col"`/`scope="row"` + `table-fixed` + % 열 배분(27/19/22/24/8 = 100)
- 접힘 영역은 제거가 아니라 `hidden` 속성 — `aria-controls` 대상 id가 항상 존재
