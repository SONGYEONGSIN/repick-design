# Candidate B — Bundle Offer Builder

Buyers currently negotiate one repick listing at a time; this screen lets a buyer browsing a single seller's shelf multi-select several listings via checkbox-style rows (each carrying its own match%, condition grade, and before/after price) into one combined bundle, watching a live running total, item count, and a deterministic bundle discount (0/5/8/10/12/15% by item count, capped at 6+) update as selections change, then hand that bundle off as a single offer instead of opening N separate negotiation threads.

- **Component**: `BundleOfferBuilderScreen`, exported from `native/src/evolve/r15/b/BundleOfferBuilderScreen.tsx` (data in `native/src/evolve/r15/b/data.ts`).
- **Gate render string**: the exact literal heading text `Build a bundle offer` (rendered as `<Text accessibilityRole="header">` in the page header — search for this string to confirm render).
- **₩ handling**: Option 1 — a literal space between the ₩ glyph and the digit group, produced by `formatKRW()` in `data.ts` (e.g. `₩ 128,000`). Chosen because this screen's running bundle total is the single most re-rendered number on the page (it updates on every checkbox tap), so a mitigation baked into one shared formatter used everywhere a price appears (item rows, savings, band summary, band confirmation) was safer than trusting per-call spacing. `tabular-nums` is used freely alongside it on every price-bearing `Text` per the DNA note.
- **Bottom band, blocked vs. ready**: the band is a real state machine keyed off `selectedIds.length`. **Blocked** (0 items selected): the whole band becomes one `Pressable` with `accessibilityRole="button"`, showing the sentence "Select at least one item to build a bundle" (the changing text carries `accessibilityRole="alert"`, the band itself carries `accessibilityLiveRegion="polite"`) — there is no primary button in this state, only this explanatory tap target. **Ready** (1+ items): the band shows the live summary line (item count · subtotal → discounted bundle price with its %, or just subtotal with no arrow when the 1-item case has 0% discount) plus a real "Review bundle offer" primary button. Pressing it is not a no-op: it flips the band into a third, confirmed state with a visible inline sentence ("Bundle offer drafted: N items at ₩ X...") plus an "Edit selection" button to go back — both changes announced through the same single live region, never two at once. **"Jump to unresolved" interpretation**: since there's no invalid/incomplete field to jump to in the blocked state (the blocker is simply "nothing is selected yet"), tapping the blocked band calls `scrollToOffset({offset: 0})` on the `FlatList` ref — the sensible reading of "guide the user to the actionable spot" when the actionable spot is "the top of the list of things you haven't picked from yet."

Other DNA notes: no hardcoded hex — the two non-token background tints (selected-row wash, pressed-row wash) and the primary button's pressed state are derived at runtime from `tokens.color.accent` / `tokens.color.ink` via a small `withOpacity()` helper rather than introducing new literal colors; the only saturated accent use is the selected-checkbox fill and the savings/discount text, kept sparing per the DNA. Copy is English-only throughout, including data.ts.
