# Candidate c — Safe-Exchange Location Picker

A short selection-and-confirm screen where a buyer/seller picks *where* (not when — `meetup-time` already owns that axis) to hand off an item in person: a `FlatList` of four curated, real-feeling public locations (police-station safe-exchange lobby, mall information desk, transit-station entrance, bank-branch lobby), each card carrying a category, a trust-relevant staffing/monitoring detail, and a fixed distance/travel-time figure with a thin proximity rail as a visual (non-map) cue to relative closeness. Tapping a card marks it selected via a 2px accent border change *plus* a badge that swaps both background/border and its label text from "Select" to "✓ Selected" (never color alone), and a persistent bottom band synthesizes the live instruction — "Meet Alex at [Location] — about N min away" — that flips to a confirmed state on a real primary action, with the whole band live-announced via `accessibilityRole="alert"` inside a single `accessibilityLiveRegion="polite"` container so the exact instant "can I proceed" changes (nothing selected → ready → confirmed) is what screen readers hear, no more and no less.

**(a) Component & path**: `SafeExchangeLocationPickerScreen`, exported from `/home/user/repick-design/native/src/evolve/r15/c/SafeExchangeLocationPickerScreen.tsx`. Data lives alongside it in `/home/user/repick-design/native/src/evolve/r15/c/data.ts`.

**(b) Gate render string**: the literal heading text `"Choose a Safe Exchange Location"` (rendered with `accessibilityRole="header"`) — search for that exact string to confirm the screen rendered.

**(c) ₩ handling**: not applicable — this screen has no currency, pricing, or monetary figures anywhere (only distance-in-miles and travel-minutes), so no ₩ mitigation choice was needed.

**(d) Bottom-band reasoning**: persistent real action bar, not a fake multi-step state machine. This is a single-decision selection+confirm screen — there's no multi-step wizard to gate progress through, so building a "why are you blocked, tap to jump to the next unresolved step" machine would be manufacturing steps that don't exist. What *is* genuine here is a two-state distinction the band earns honestly: before any card is tapped, the band shows the literal blocking reason ("Choose a location below to set your meeting spot.") and the Confirm button is visibly disabled (flat border-colored fill, muted text, `accessibilityState={{disabled:true}}`); once a location is selected, the band's instruction line updates in place to the synthesized meetup line and the button becomes a real, live control. Pressing Confirm is not a no-op — it flips `confirmed` to true, the instruction text changes again ("Confirmed — meet Alex at …"), the button becomes a disabled "✓ Confirmed" state, and the live region announces the change. Selecting a *different* card after confirming un-confirms it (a claim about location X shouldn't silently survive switching to location Y), which is the one piece of real "state machine"-ness this screen legitimately needs and no more.

**(e) Location without a map**: no map library, no tiles, nothing geolocation-derived. Each card carries (1) a plain-language category label ("Police station lobby", "Transit station entrance", etc.) so the *kind* of place stands in for spatial context, (2) a fixed distance-in-miles + travel-minutes figure, and (3) a thin horizontal "proximity rail" — a track filled proportionally to `distanceMiles / PROXIMITY_RAIL_MAX_MILES` (a fixed constant, not derived from any live position) — bracketed by "Closer"/"Farther" legend labels above the list. It's an ordered, well-organized list first and an abstract relative-distance cue second — deliberately not a fake map, so it never has to lie about a specific pin position it doesn't actually have.
