# Vercel — Landing Design Principles

## Voice / Tone
- 극도로 절제된 엔지니어 톤 — 군더더기 형용사 없이 기능/성능을 직설적으로 서술.
- 카피는 짧고 명령형/선언형 (예: "Develop. Preview. Ship."), 리듬감 있는 3단 구성을 자주 사용.
- 유머보다 정밀함, 감성보다 스펙 — "이게 왜 좋은가"를 기술적 근거로 설명.

## Color / Palette
- 순흑(#000000)과 순백(#FFFFFF)의 극단적 모노크롬 대비가 기본 팔레트.
- 컬러는 거의 쓰지 않으며, 쓰더라도 상태 표시(성공/에러) 등 기능적 용도로 최소화.
- 그레이 스케일을 세밀하게 나눠(9~12단계) 보더/배경/텍스트 위계를 색이 아닌 명도로 구분.
- 다크/라이트 모드를 대칭적으로 지원하되 흑백 반전 원칙을 그대로 유지.

## Typography
- Geist Sans(자체 개발 폰트)로 기하학적이고 중립적인 인상 — 라운드도 각도 없는 담백한 글리프.
- Geist Mono를 코드/터미널/버전 넘버 등에 사용해 "개발자 도구" 정체성을 타이포로 표현.
- 헤딩은 굵고 크지만 장식 없이 정직한 크기 대비만으로 위계를 만든다.

## Layout / Spacing
- 그리드 기반의 기하학적 레이아웃 — 카드/섹션 경계가 수학적으로 정렬됨.
- 배경에 격자(grid) 패턴이나 대각선 스캔라인 같은 기하학적 텍스처를 은은하게 사용.
- 네거티브 스페이스(여백)를 적극 활용해 한 화면에 한 메시지만 강조.
- 컴포넌트 보더는 1px 헤어라인, 라운드는 작게(4~8px) — 둥글고 부드러운 느낌 지양.

## Signature details (이 브랜드다움)
- 터미널/CLI 출력, 배포 로그, git diff 같은 "실제 개발 흐름" 비주얼을 랜딩 요소로 사용.
- 흑백 대비를 살린 큼직한 로고/워드마크, 로고 자체가 기하학적 도형처럼 다뤄짐.
- 미세한 노이즈/그레인 텍스처나 격자 배경으로 "정밀 기계" 느낌을 더함.
- 애니메이션은 즉각적이고 정확 — 느린 이징보다 빠르고 딱 떨어지는 전환.

## 랜딩에 훔칠 것 (actionable)
- 팔레트를 흑/백/그레이 스케일로 한정하고 컬러는 상태 표시용으로만 극소량 사용.
- 헤딩 폰트를 기하학적 산세리프(Geist류)로, 코드/숫자 요소에 모노스페이스 폰트를 매칭.
- 배경에 은은한 격자 패턴을 넣어 "정밀함"을 형태로 전달.
- 실제 터미널/로그/코드 스니펫을 목업 없이 그대로 노출해 개발자 신뢰 확보.
- 라운드 코너를 작게(4~8px) 유지하고 보더는 헤어라인 1px로 절제.
